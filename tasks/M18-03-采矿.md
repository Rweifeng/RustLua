# M18-03 采矿

## 状态
BACKLOG

## 类型
[玩法]

## 目标
矿洞楼层、矿石节点、随机地图、掉落表，数据驱动。

## 背景
缺口清单 3.4 要求矿洞楼层、矿石节点、随机地图和掉落表。依赖多地图（M17）与体力工具数值（M18-00）。

## 输入
- `data/mine.json`（楼层/矿石/掉落）、`data/loot_tables.json`
- M17-00 多地图、M18-00 工具/体力
- Tilemap 运行时生成（tilemap.set_cell）

## 不做什么
- 不做矿车/电梯交互细节（先楼梯传送）；
- 不做深层无限生成；
- 不做矿洞怪物。

## 依赖
M17-00、M18-00

## 验收标准
1. 矿洞楼层数据化：每层布局/矿石分布/掉落表，进入下一层随机生成。
2. 矿石节点可被工具（镐）开采，产出矿石进背包，节点被采后持久化。
3. 楼层推进：楼梯/传送点下到下一层，返回上层保留开采状态。
4. 改 mine/loot 表重载生效，深度影响矿石稀有度。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：进矿→采矿石→下楼→返回→开采状态保留；掉落符合表。

## 风险
- 随机地图生成与 Tilemap API 性能 → 楼层规模受限并缓存；
- 开采状态与楼层映射 → 按（楼层,格子）持久化。
