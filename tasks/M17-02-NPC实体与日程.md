# M17-02 NPC 实体与日程

## 状态
BACKLOG

## 类型
[引擎+玩法]

## 目标
新增 `schedule` Lua API（日程表→目标点/状态机）、NPC 实体（数据驱动）、路点移动与动画联动。

## 背景
缺口清单 3.1 要求 NPC 实体、日程、路点/寻路、特殊事件。本任务先做「实体 + 日程 + 路点移动」，寻路留 M18，对话留 M17-03。

## 输入
- `data/npcs.json`（NPC 数据：姓名/形象/家/日程）
- `map` 多地图（M17-00）、`animation`
- M16-02 交互框架（靠近触发）

## 不做什么
- 不做网格寻路（M18 用 `pathfind`，此处用路点/直线移动）；
- 不做对话（M17-03）与好感度（M17-04）；
- 不做 NPC 日程编辑器（M19-03）。

## 依赖
M17-00

## 验收标准
1. `schedule` API：定义「时间→地图/目标点/动作」日程表，NPC 按当前 `calendar` 时间处于正确位置与状态。
2. NPC 为数据驱动实体：从 `data/npcs.json` 生成，含形象/名字/家。
3. 路点移动：NPC 在路点间移动，移动动画与朝向联动，夜间回家。
4. 靠近 NPC 触发交互提示（`interact.prompt`），供 M17-03 对话接入。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
Rust 单测：日程表时间分片正确；实机：不同时刻 NPC 位置符合日程。

## 风险
- 日程与地图加载时序 → 切图后重新解析该图 NPC 日程；
- NPC 卡在障碍物 → 路点直线移动先接受，M18 寻路替换。
