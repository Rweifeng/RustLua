# M12-02 依赖图与失效传播

## 状态

ACCEPTED（代码/自动化/实机验证，2026-08-25）；编辑器 GUI 断链图标与错误红字的视觉呈现经负责人实机复核 PASS。

## 目标

建立 source → artifact → consumer 依赖图：场景/Prefab/Lua 脚本引用提取为边；依赖断链时消费者标 `Invalid`（持久化断链状态），依赖恢复自动撤销；检测循环依赖；assetc 发布检查 `--check-deps` 输出完整失效链路。

## 背景

M12-00/01 统一了状态模型并闭合导入链路，但 `AssetRecord.dependencies` 管道虽已存在却从不被生产代码调用；引用以组件字符串内嵌 `assets/` 路径的真实形态存在。编辑器存在旧缺陷：`refresh()` 在 `register` 时以旧状态构建 `entries`，`reconcile` 后才执行 → 文件删除后 UI 永不显示 Missing。M12-02 建立依赖边并接上失效传播，顺带修复该缺陷。

## 技术方案

- **依赖提取器**（`dependency.rs` 纯函数）：Scene/Prefab 扫 `assets/` 字面量（`;`/`:`/`\n`/`\r` 终止，排除 `__ground_plane__`）；Lua 引号感知状态机——`require("x")`→scripts/x.lua、`scene.load("x")`→scenes/x.scene（仅字面量）、`assets/` 字面量、`--` 注释跳过；大小写回退 `find_by_path_ci`；自环排除。
- **失效传播**（rank-max 不动点，单向、幂等、可撤销）：`Missing/Orphaned=7`、`Invalid=6`、`ImportFailed=5`、`Stale=4`、`Discovered=3`、`Ready=2`；依赖侧 Missing/Orphaned/ImportFailed 折叠为 broken-link 6；`final_rank = max(自身物理态, 最差依赖)`；仅依赖才是拖后腿因子时写 `error` 文案；依赖全健康时撤销 Invalid 回 Ready/Discovered。
- **循环检测**：三色 DFS + 显式路径栈，rotate-to-min-id 去重；cycle error 先写入、传播不覆盖。
- **接线**：editor `refresh()` 时序 `register→reconcile→recompute_edges→propagate_invalidation→save`，reconcile 后用最新状态重建 entries；`pending_imports` 排除 Invalid；`spawn_resource_import` 批次后传播+保存；assetc `scan()` 同时序重建、`import()` 批次后传播+保存；资源面板状态图标（断链红字）。
- **`--check-deps`**：`check_dependencies(project)` 对每个 Invalid 沿依赖下探到断链根，输出 `scenes/main.scene → assets/textures/player.png (缺失)` 完整链路；成环截断标注「循环依赖」。

## 验收标准

- 依赖边提取正确（真实场景行、Lua require/scene.load、注释感知、去重保序、自环排除）；
- 传播正确（缺失依赖→消费者 Invalid、导入失败依赖→Invalid、Stale 依赖→Stale、恢复撤销、自 Missing 保持、级联 A→B→C、循环终止）；
- editor/assetc 接线后断链资源在 UI/scan 中呈现 Invalid 且不进待导入队列，恢复文件后撤销；
- `assetc --check-deps` 健康输出空、断链输出完整链路、成环截断标注。

## 风险

- 提取假边：`assets/` 前缀命中 `xassets/`，与既有 verify_project 行为一致，可接受；
- 动态场景引用不建边：本阶段静态字面量覆盖，常量传播留后续；
- 传播复杂度 O(V²)：每轮扫全图至多 V 轮，V 为记录数（数百级）可接受，规模增长改拓扑序单遍；
- editor entries 旧状态缺陷随 C4 修复，register 时状态为 Discovered 的既有测试已按新时序复核通过。
