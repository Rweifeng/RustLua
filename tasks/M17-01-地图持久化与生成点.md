# M17-01 地图持久化与生成点

## 状态
BACKLOG

## 类型
[引擎+玩法]

## 目标
`PersistentMapState` + `SpawnPoint` + 地图修改（砍树/采石/采集残留）保存；引入 `EntityPersistentId` 让跨场景实体可识别。

## 背景
缺口清单 2.3 要求地图修改结果与世界开关可存；3.2 要求地图持久化、生成点。M16-09 的 `map.state` 已能存 blob，本任务把「地图的持久化状态」与「实体身份」正式化。

## 输入
- M16-09 结构化存档、`map.state`
- `map` 扩展（M17-00）

## 不做什么
- 不做 NPC 状态持久化细节（M17-02/04）；
- 不做存档查看器（M19-06）；
- 不做动态生成的世界对象重生成规则（刷新规则在 M18）。

## 依赖
M16-09、M17-00

## 验收标准
1. 每张地图按名称持久化自身状态（已砍树、已采石、开关状态、移动过的对象）。
2. `EntityPersistentId`：跨场景销毁/重载后能按稳定 ID 恢复实体身份与归属状态。
3. `SpawnPoint`：地图定义出生点，读档后玩家出现在正确生成点。
4. 修改地图 → 存档 → 读档 → 修改保留。
5. 生成点与地图状态均数据驱动（`data/maps.json`）。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
Rust 单测：PersistentId 跨实例映射；实机：砍树→F1→F2→树仍缺失、出生点正确。

## 风险
- 实体 ID 与场景实体库冲突 → PersistentId 独立命名空间，与 EntityId 解耦；
- 地图修改数量膨胀 → 状态表增量存储，避免全量快照。
