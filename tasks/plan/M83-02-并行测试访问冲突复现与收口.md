# 任务：并行测试访问冲突复现与收口

- 任务 ID：M83-02
- 状态：第一阶段已完成，待根因复现与修复
- 关联里程碑：M83
- 创建日期：2026-11-16

## 目标

定位 CI 中 `RUST_TEST_THREADS=1` 所规避的 `STATUS_ACCESS_VIOLATION (0xC0000005)`，在可重复复现并修复前保留串行规避，避免把不稳定性误报为已解决。

## 影响文件

- 预期涉及 `engine/crates/**/tests`、共享全局状态及 `.github/workflows/quality.yml`
- 可能新增专用复现脚本和回归测试

## 风险

- 访问冲突可能由 GPU、窗口、Lua、静态 provider 或测试隔离共同触发；不能通过降低覆盖或删除测试消除信号。
- 复现消耗较大，必须固定工具链、线程数、重复次数及运行环境。

## 验收方式

1. 给出重复次数、线程数和目标集合均固定的复现命令及日志。
2. 得到最小测试组合或明确记录在规定预算内无法复现。
3. 根因修复后，受影响测试在并行模式下重复运行稳定通过；仅随后才可评估取消 CI 单线程设置。
4. 保留失败时的诊断与回归测试。

## 第一阶段记录（2026-11-16）

- 固定环境：`rustc 1.97.1`、`RUST_TEST_THREADS=2`、`RUST_MIN_STACK=67108864`；完整日志为 `artifacts/logs/quality/m83-02-engine-lib-parallel.log`。
- 首轮命令为 `cargo test -p engine --lib --all-features`，计划连续运行 3 次；第 1 次在 4.58 秒后完成测试执行，**没有出现访问冲突**，但被独立的 API 覆盖率缺口阻断：`sample_project_demos_cover_every_lua_api` 缺 `render.set_shadow_caster_distance` 与 `render.set_water_refract_steps` 演示（258 passed / 1 failed）。
- 因该确定性功能失败会阻止剩余 2 次并行复现，本阶段下一步仅跳过这条已知失败测试，继续对其余 engine lib 测试做固定三次并行探针；不得把本次“未出现 AV”解释为问题已解决。
- 排除该单一已知失败后，`cargo test -p engine --lib --all-features -- --skip host::sample_project::sample_project_demos_cover_every_lua_api` 在相同环境连续 **3/3** 次通过：每次 258 passed、0 failed、1 filtered out，未出现 `0xC0000005`。日志为 `artifacts/logs/quality/m83-02-engine-lib-parallel-skipped-known-failure.log`。此结果只说明该有限样本未复现 AV，不足以解除 CI 的 `RUST_TEST_THREADS=1` 缓解策略。

## 未完成项 / 已知限制

- 当前 CI 串行策略是必要缓解措施，不得擅自删除。
- API 覆盖率失败属于既有演示缺口，未在本任务内修复；它会干扰全量 engine lib 的并行复现，故后续探针显式排除并记录。
