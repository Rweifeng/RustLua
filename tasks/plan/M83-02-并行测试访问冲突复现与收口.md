# 任务：并行测试访问冲突复现与收口

- 任务 ID：M83-02
- 状态：第一阶段已完成，待根因复现与修复
- 关联里程碑：M83
- 创建日期：2026-11-16

## 目标

定位 CI 中 `RUST_TEST_THREADS=1` 所规避的 `STATUS_ACCESS_VIOLATION (0xC0000005)`，在可重复复现并修复前保留串行规避，避免把不稳定性误报为已解决。

## 影响文件

- 预期涉及 `engine/crates/**/tests`、共享全局状态及 `.github/workflows/quality.yml`
- 可能新增专用复现脚本和回归测试

## 风险

- 访问冲突可能由 GPU、窗口、Lua、静态 provider 或测试隔离共同触发；不能通过降低覆盖或删除测试消除信号。
- 复现消耗较大，必须固定工具链、线程数、重复次数及运行环境。

## 验收方式

1. 给出重复次数、线程数和目标集合均固定的复现命令及日志。
2. 得到最小测试组合或明确记录在规定预算内无法复现。
3. 根因修复后，受影响测试在并行模式下重复运行稳定通过；仅随后才可评估取消 CI 单线程设置。
4. 保留失败时的诊断与回归测试。

- 固定环境：`rustc 1.97.1`、`RUST_TEST_THREADS=2`、`RUST_MIN_STACK=67108864`；完整日志为 `artifacts/logs/quality/m83-02-engine-lib-parallel.log`。

- 排除该单一已知失败后，`cargo test -p engine --lib --all-features -- --skip host::sample_project::sample_project_demos_cover_every_lua_api` 在相同环境连续 **3/3** 次通过：每次 258 passed、0 failed、1 filtered out，未出现 `0xC0000005`。日志为 `artifacts/logs/quality/m83-02-engine-lib-parallel-skipped-known-failure.log`。此结果只说明该有限样本未复现 AV，不足以解除 CI 的 `RUST_TEST_THREADS=1` 缓解策略。

## 第二阶段记录（2026-11-16，coverage 红已定性并修复；**它不是 AV**）

### 2.1 现象与最初猜测

CI 的 `coverage` job 反复红，且只在部分提交上红（`4a440c93` 绿；只改文档/ps1 的
`44a27bf3`、`1864ce63`、`7868a7ce` 红）。`4b68a60e` 起该步骤把失败行发成 `::error::`
annotation，拿到：

```
[RED] 总行覆盖掉了 0.8pp（阈值 0.5pp）
[RED] crate rustlua-ecs 行覆盖掉了 51.7pp（阈值 2.0pp，源码行 10320）
coverage_regression lines=80.2% baseline=81.0% delta=-0.8pp crates=35
```

单 crate −51.7pp 而全局只 −0.8pp，最初（正确地）被读成"该 crate 的测试在插桩运行里死掉了"，
于是先按本任务的 AV 方向做了两件事：并行复现矩阵（3/3 + 36 轮 2/4/8 线程 **零失败**）、
以及把 `check-coverage.ps1` 的 `RUST_TEST_THREADS` 从 2 改回 1（`cea03c10`，与 build-test 对齐）。

### 2.2 真正原因（2026-11-16 本地插桩复现，已修）

用 CI 同款插桩方式单跑该 crate：

```powershell
cargo llvm-cov -p rustlua-ecs --lib --all-features --no-cfg-coverage -- --test-threads=2
```

**确定性失败**（6/6 复现）：

```
tall_32x24x32_cell2: 步进 6631.8 us/步 超上限，网格实现疑似退化
test particle_wind_grid::tests::wind_grid_step_cost_curve ... FAILED
test result: FAILED. 188 passed; 1 failed
```

`wind_grid_step_cost_curve` 用**绝对墙钟上限 5000 us/步**做"防 O(n²)"兜底；llvm-cov 插桩让
同一段代码慢 5–8 倍 ⇒ 断言必红 ⇒ 该单元测试二进制以 101 退出 ⇒ `rustlua-ecs` 的覆盖率
profile 缺失/被丢弃 ⇒ coverage 门报 −51.7pp。**根因是"绝对时间断言 + 插桩"，不是 AV。**

修法（`engine/crates/rustlua-ecs/src/particle_wind_grid.rs`）：判据改成与机器/插桩无关的相对量——
① 六种形状的**每格成本**跨形状同量级（`max/min ≤ 2.0`，插桩是乘法性的、比值不变；
O(n²) 回归会让大网格每格成本成倍上涨）；
② 每档"开扩散 / 关扩散"耗时比值 ∈ `[1, 12]`（扩散退化会爆）。
绝对读数照旧打印，只作为"定网格分辨率"的证据，不再进断言。

验证：普通模式 `189 passed / 0 failed`；插桩模式（同一命令）`189 passed / 0 failed`。

### 2.3 遗留

- `cea03c10` 的"coverage 改单线程"**不再是必需修复**（根因已定位到测试），保留它只是与
  build-test 的绿色配置对齐、并把并行面收窄；若后续要在意 coverage job 时长，可改回 2 线程，
  但需先确认 CI 上 coverage 转绿。
- 历史上的 `0xC0000005`（build-test 已用单线程规避）**仍未定位**：本阶段 3/3 + 36 轮并行
  复现均未复现，不能宣称该 AV 已解决。
- 下一步：等 CI 在新提交上跑 coverage，若转绿即确认本条收口；若仍红，annotation 会给出新的
  crate/delta，继续按本文件第一阶段的方法定位（不再往 AV 上硬套）。
