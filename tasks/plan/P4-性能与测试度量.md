    coverage.json                  # 覆盖率基线（per-crate）

**分层原则**：`history/*.jsonl` 是事实源；`trend.sqlite` 是可删可重建的索引；

删掉 SQLite 不会丢数据；删掉 `history` 才会。

手填的历史数据只能标 `source.kind=manual`，**不能直接成为门基线**。

### 4.3 环境指纹

```text
env_fingerprint = sha256(
  os | arch | cpu_model | logical_cores | ram_gib |
  rustc | node | python | profile | features | runner_label
)
```

- **时间类**指标（p50/p95/p99、编译 wall time、增量时间）只与**同指纹**的样本比；
  跨指纹只打印不判红。GitHub runner 的 CPU 型号会漂，`runner_label` 只能粗分，
  所以时间类还要 `min_samples >= 3` 且用中位数，不用均值。
- **确定性**指标（draw_calls/instances/triangles、分配字节/次数、exe/wasm/包体字节、
  覆盖率百分比）可以跨指纹比；仍要记录指纹，便于归因。
- `git_dirty=true` 的 run 可入库，但**不能生成/更新 baseline**；基线只能来自干净工作树。

| `3` | **BLOCKED**：工具缺失、环境受限、历史样本不足；**不等于通过** | 无 `cargo-llvm-cov`、无浏览器、`min_samples` 不够 |

`verify.ps1` 对 `3` 打印 `PARTIAL/BLOCKED` 并以 3 退出；CI 的必需 job 把 `3` 当红
（与 P2 的 `-RequireTools` 同哲学：**"没跑"永远不等于"通过"**）。

### 4.5 基线、棘轮与豁免

- **只降不升**默认：覆盖率、性能、包体都以 `metrics/baselines/*` 为参考，超阈值判 `2`。
- **更新基线必须显式**：`--update` 生成新基线，附带 `reason`；
  提交信息写清"为什么这次增长是合理的"；评审看 diff。
- **暂缓项有到期日**：`metrics/allowlist.json`：

```json
{
  "schema": 1,
  "entries": [
    {
      "domain": "binary",
      "subject": "editor.exe",
      "owner": "P4",
      "reason": "新功能一次性增长，计划在 PBR 后回收",
      "expires": "2026-12-31",
      "max_delta_pct": 8
    }
  ]
}
```

到期后门直接判 `2`，不打印黄字放行。豁免必须能指到具体 artifact/metric，不能整域豁免。

     `CARGO_TARGET_DIR=artifacts/metrics/target-compile`，不动 `engine/target`）；

   - 至少 3 次，记录 wall time 的 min/median/max 与方差；冷构建只 nightly。
2. `scripts/metrics/parse-cargo-timings.mjs`：从 `target/cargo-timings/cargo-timing*.html`
   提取 `const UNIT_DATA = [...]` / `const CONCURRENCY_DATA = [...]`，算：
   - `wall_ms`、`critical_path_ms`（max(start+duration)）、`parallelism`；
   - per-crate `duration_ms` 与 top 20 unit；
   - `incremental_units`（本次真正重编的 unit 数）。
3. 指标（`compile-v1`）：
   - `check_cold`、`check_warm`、`test_build_cold`、`release_build_cold`；
   - `incremental_after_clean_package`（`cargo clean -p <crate>` 后 `cargo build -p game`）；
   - `change_radius_assetc` / `change_radius_game`（同一台机、同一 jobs 的 `cargo check` 时间）；
   - 每个都带 `profile/jobs/incremental/target_dir`。
4. 基线 `metrics/baselines/compile-time.json` 只收同指纹的干净 run；PR 不跑冷构建，
   只跑 `check_warm` 并在 artifact 里打印 delta（不判红）；nightly 判红。
5. 自测：`scripts/test/test-cargo-timings.mjs` 用一份固定 HTML fixture，
   断言 `UNIT_DATA` 解析、critical path、坏 JSON 退 1。

**验收**

```powershell

node scripts/metrics/parse-cargo-timings.mjs --check
# compile_ok units=.. wall_ms=.. critical_ms=.. top_crate=..
python scripts/metrics/trend_db.py ingest --input artifacts/metrics/compile-check.json
```

**风险/回退**：冷构建耗时/占盘大；只在 nightly 跑，`-Cold` 必须 `-Yes`，目标目录固定在
`artifacts/`（可删）。编译时间受杀毒/索引/磁盘影响，门只对同指纹中位数判红；
若 CI 方差 >10%，先增加重复次数，不降阈值。

### P4-06 二进制大小趋势

**目标**：给 `game.exe`、`editor.exe`、`assetc.exe`、`game_web_bg.wasm`/JS 建立
"原始 + 压缩 + 分节"的历史，增长必须能解释。

**实施**

1. `scripts/metrics/measure-artifacts.mjs --kind binary`（Node、零依赖）：
   - 输入路径：`engine/target/release/{game,editor,assetc}.exe`、
     `engine/target/wasm32-unknown-unknown/release/game_web.wasm`、wasm-bindgen 产物
     `game_web_bg.wasm` / `game_web.js`（路径可参数化，缺文件标 `missing`）；
   - 每个产物：`bytes_raw`、`bytes_gzip9`、`bytes_brotli11`（Node `zlib`）、
     `sha256`、mtime、`strip` 状态、profile；
   - `llvm-size` 可用时记录 `.text/.rdata/.data` 分节；不可用打印
     `sections=unavailable reason=llvm-size`，不伪造 0；
   - 输出 `binary-v1` JSON + Markdown。
2. 预算/棘轮：exe +3% 或 +128 KiB、wasm +3% 或 +64 KiB；`editor.exe` 可单独放宽到
   +256 KiB（它是工具，用户可接受度不同）；任何豁免走 `allowlist.json` 到期制。
3. CI：`release.yml` 在 `cargo build --release` 后跑一次，作为 release evidence 上传；
   `metrics.yml` nightly 跑一次；PR 只在 `engine/**` 变化时跑（不判红，只报 delta）。
4. 归因：报告按 `exe`/`wasm`/`js` 分开；`wasm` 记录是否 `wasm-bindgen --release`、
   是否 `wasm-opt`（若未来引入），避免把工具链差异算成代码增长。

**验收**

```powershell
node scripts/metrics/measure-artifacts.mjs --kind binary --out artifacts/metrics/binaries.json
# binaries_ok artifacts=5 game=14,495,232 editor=22,673,920 assetc=4,178,432 wasm=.. gzip=.. brotli=..
python scripts/metrics/trend_db.py ingest --input artifacts/metrics/binaries.json
```

**风险/回退**：`strip=true` 后 `llvm-size` 仍可用，但符号级 `cargo bloat` 不可用；
需要符号归因时单独跑 debug/未 strip 构建，不改变 release 口径。文件缺失时 `-RequireAll`
判 1；只跑部分产物时标 `partial=true`，不能拿 partial 更新基线。

### P4-07 资源包大小趋势

**目标**：把 PC/引擎/WebGL/微信（主包、分包、总包）与资源容器的体积做成结构化历史，
并保留现有硬配额门；变化要能归因到 wasm/字体/脚本/资源。

**实施**

1. `scripts/metrics/measure-artifacts.mjs --kind package`：
   - **PC**：`examples/<game>/builds/pc` 总字节/文件数；`RustLua-*-win64.zip` 的 zip 字节与解压和；
   - **引擎绿色版**：`artifacts/packages/RustLua-Engine-*` 目录/zip、samples/fonts 分账；
   - **WebGL**：`builds/webgl` 总字节/文件数，`game_web_bg.wasm`、`game_web.js`、
     字体（`.ttf/.otf`）、`pack/` 资源、gzip/brotli 估算；首屏 `first_screen_pack_ok`
     的 `entries/bytes`（若产物带 `pack.json`）；
   - **微信**：`launcher` 总字节/文件数；按 `game.json` 的 `subpackages[].root` 算主包/分包/
     总包（复用 `package.ps1` 的同一口径，不自己发明）；字体、wasm、脚本、资源分账；
     记录 `main_of_limit`/`total_of_limit` 与配额字节（4 MiB / 20 MiB）；
   - **资源容器**：`.rlb` 文件列表与字节、`pack.json`/`bundle_plan.json` 的组信息（有则记）。
   - 输出 `package-v1` JSON + Markdown；`source` 写打包日志行与文件 hash。
2. 接入：
   - `package.ps1` 成功后调用测量（或由 CI 包装脚本调用），产物落

4. 形态隔离：`full`/`subpackage`/`remote` 不互相比较；同平台同形态才比；
   报告里写 `form`/`asset_pack`/`split`。
5. 自测：`scripts/test/test-package-metrics.mjs` 用临时目录造

## 9. 风险与回滚

| 风险 | 触发症状 | 处置 / 回滚 |
|---|---|---|
| 固定工具链没有 `llvm-tools-preview` | 覆盖率 job 装不上组件 | 用 `rustup component add` 固定到 1.97.1；仍不行则门退 3 并在 CI 标红，**不改成"跳过即通过"** |
| 覆盖率全量太慢 | job 超时 | 先只在 `engine/**` PR + nightly；再按 crate 分片合并 `.profraw`；不降判据、不删测试 |
| 内联测试抬高覆盖率 | 总覆盖看起来很高 | 报告明确写"含测试代码"；per-crate 表仍能暴露盲区；未来要产品代码口径另立任务 |
| cfg 扫描器误报/漏报 | 清单频繁漂移 | 稳定 key 不含行号；扫描器自带 fixture 自测；误报用 `allowlist` 到期豁免，不手改清单 |
| `gpu-web-probe` 被遗忘 | wasm cell 只 check `game_web` | `wasm-cells.json` 显式列它；自测反例专门删它必须红 |
| Linux 依赖缺失 | `cargo check` 在 ubuntu 红 | 先补 apt 依赖；GUI crate 降到 advisory 并写原因；到期仍红按 `promotion.json` 判 2 |
| 矩阵长期黄 | advisory cell 永远不晋升 | `promotion.json` 到期日 + `check-matrix-policy.ps1` 判 2；修好或明确裁定不支持 |
| runner 硬件漂移 | p95/编译时间假红 | 同指纹 + 中位数 + ≥3 样本；时间列可标 advisory，确定性指标仍判红 |
| history 合并冲突 | 两人同时追加 | 按月分片、append-only、按 `run_id` 去重；bot 串行/重试；冲突不手改数字 |
| 基线被手改 | 数字突然"变好" | 基线只由 `--update` 生成，带 `commit/env/reason`；评审看 diff；`git_dirty` 不能更新 |
| 包体抖动 | 同 commit 两次打包差 >2% | 先修可复现性（时间戳/随机名/排序），再判趋势；不把抖动算成代码增长 |
| 新增 CI 分钟超预算 | 队列变长 | 路径过滤 + nightly/weekly + 缓存；成本与判据分开，不删门 |
| 在途工作树被误提交 | 提交混入 P1 改动 | 只 `git add` P4 文件；提交前 `git diff --cached --stat` 复核 |
