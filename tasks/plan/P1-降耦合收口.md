## 目标

把"降耦合"剩下的三条债一次说清并逐条收口。判断标准不是"多拆了一个 crate"，而是：

1. **反向依赖消失**：工具/导入不许拖运行时；运行时不许拖表现层；表现层不许拖脚本层。
2. **改动半径变小**：改编辑器不再重编资源工具（①已证：`assetc` 图 221 → 178），
   改 `ui`/`physics` 不再重编资源导入。
3. **解耦不缩水**：每一条都得有新门（或既有门收紧）钉住，否则下一个人会把它长回来。

### ④ `rustlua-scene` 摘掉表现层依赖（组件编解码注册表）

**影响面已经量过（2026-10-20，`grep rustlua_render::|rustlua_ui::` 逐条看）**——比预估小：
`render`/`ui` 在 scene 里只出现在 **4 个文件、10 条引用**：

| 文件 | 引用 | 用途 |
|---|---|---|
| `typed_scene.rs` | `Light`/`MeshRenderer`/`Quad`/`SpriteComponent`/`UiLayout`/`Container`/`UiText`/`UiImage`/`UiEvents`/`ButtonStateSet`/`RenderMode`（16 处变体） | `.scene` 文本 ↔ 类型化组件 |
| `world_text.rs` | `UiComponentError`/`UiText`/`split_fields` | `WorldText` 复用 ui 的分段解析 |
| `scene_extract.rs` | `Light`/`MeshRenderer`/`GROUND_PLANE_SENTINEL` | 从 `World` 反抽文本（保存/热重载） |
| `char_collect.rs` | `UiText` | 收集字体字符集 |

`TypedComponent` 的 render/ui 变体在 scene **之外**只有 1 处消费者（editor
`panels/scene_view/view_3d.rs`）——所以"枚举擦除成文本负载"这条路可行，不会把类型不安全
扩散到全工程。

**设计（照 `ImporterRegistry` 的先例，但方向相反）**：注册表**空表起步**、由组合根装表，
这跟导入层"空表会静默丢资源"不同——`.scene` 里出现未注册组件必须是**硬错误**（带定位诊断），
不能静默跳过，否则工程文件里的 Sprite 会静默消失。

```rust
// rustlua-scene/src/component_codec.rs
pub trait ComponentCodec: Send + Sync {
    fn name(&self) -> &'static str;                     // "Sprite" / "Light" / ...
    fn parse(&self, value: &str) -> Result<Payload, String>;      // 文本 → 校验过的负载
    fn apply(&self, world: &mut World, entity: Entity, p: &Payload) -> Result<(), String>;
    fn extract(&self, world: &World, entity: Entity) -> Option<String>;   // 反抽（保存用）
    fn text(&self, p: &Payload) -> Option<&str>;         // 供 char_collect / WorldText
    fn assets(&self, p: &Payload) -> Vec<AssetId>;       // 依赖收集（mesh/贴图/字体）
}
pub struct ComponentCodecRegistry { /* name → &'static dyn ComponentCodec */ }
pub fn install_codecs(c: &ComponentCodecRegistry);      // 组合根调用一次
```

`engine`（组合根）在启动时装 `rustlua_render::scene_codecs()` +
`rustlua_ui::scene_codecs()`；scene 自己的 golden 测试用 **dev-dependencies** 装同一张表
（dev-deps 不进 lib 依赖图，架构门只看 `[dependencies]`）。

**分阶段（每阶段都要 `.scene` golden 零 diff）**：

1. **4a 骨架**：新建 `component_codec.rs`（trait + 注册表 + 未装表时的错误），**不改行为**
   ——scene 仍走静态 `match`，只在 `compile_v2` 里加一条"注册表为空时仍可用旧路径"的说明；
   写清"未注册组件是硬错误"的那条测试（用假 codec）。
2. **4b render 下沉**：`rustlua-render` 新增 `scene_codec.rs` 实现 5 个 codec
   （`Light`/`MeshRenderer`/`Quad`/`Sprite`/`RenderMode`）；`typed_scene` 的 render 分支改走
   注册表；删掉 `use rustlua_render::*`。此时 scene 仍依赖 ui。
3. **4c ui 下沉**：6 个 ui codec（`UiLayout`/`Container`/`Text`/`Image`/`UiEvents`/
   `ButtonStates`）+ `world_text`/`char_collect` 改走 codec 的 `text()`；
   `scene_extract` 的 `Light`/`MeshRenderer` 改走 `extract()`。
4. **4d 收口**：`rustlua-scene/Cargo.toml` 删 `rustlua-render`/`rustlua-ui`（挪 dev-deps），

**风险与对策**：

| 风险 | 对策 |
|---|---|
| 空表时 `.scene` 静默丢组件 | 未注册 = 硬错误（诊断带组件名 + 行号），并有专门测试 |

**状态（2026-10-20 晚）：4a–4d 全部交付，④ 已收口。** 实际落地与上面的草案有两处差别，
记下来免得后来人照着草案走错：

1. codec 不是"trait 对象 + `apply`/`extract`"，而是 **`&'static ComponentCodec` 的函数指针表**：
   `ComponentCodec { name, validate: fn(&str) -> Result<(), String>, asset_paths: fn(&str) -> Vec<String> }`。
   原因：`TypedScene` 是**加载边界**，它只需要"这段文本合法吗"和"它引用了哪些资源"；而
   "文本 → world 组件"的落地由 `engine`/`editor` 自己用它本就依赖的类型做，注册表不该抢这个
   职责（抢了就要在叶子 crate 里放 `World`，环立刻回来）。`extract`（world → 文本）同理留在
   各自的 owning crate（`scene_extract` 阶段 4d 整体搬去 `engine`）。
2. 表由**叶子 crate** `crates/rustlua-component-codec` 承载，不是 scene 的子模块：`render`/`ui`
   不能依赖 `scene`，注册表必须有第三个谁都不依赖的落点（照 `rustlua-lua-api` 的先例）。
   `rustlua-scene` 只做 `pub use rustlua_component_codec as component_codec;` 再导出。

**已落地**：`Opaque { payload: String, assets: Vec<(String, Option<AssetId>)> }` 取代 11 个表现层
变体（原文逐字节保留 → `.scene` 往返零 diff）；`render`/`ui` 各出 `scene_codecs()`；装表入口
`engine::host::scene_codecs::install()`（幂等）；编辑器两处 + `wp0_scene_frame` 已接；
`tests/component_codec_requires_install.rs` 用独立进程钉住"未装表 = 硬错误"。

**装表点**（这条是运行期抓出来的，不是设计时想到的）：`engine::host::scene_codecs::install()`
（幂等）挂在 **`RuntimeScene::init`**——`new`/`new_with_layout`/`from_scene`/`from_scene_edit`
全走它，是"场景被实例化"的唯一入口，预制体套用与运行时校验都在下游；编辑器再在 3D 视图懒编译
与字段校验兜底门各调一次（同一函数，重复调用无害）。最初只接了编辑器与示例进程，
`jhyt_m59_ui_prefab` 的黄金对账当场报 "`dlg:box` 的 rect 期望 240,450,800,240、实得 missing"：
`game` 侧没有表 → `UiLayout` 被判非法 → 实体组件缺项。**结论**：装表点要绑"实例化"这个动作，
不要绑"我以为会编译场景的那些调用方"。

**为什么 `scene_extract` 必须去 `engine` 而不是留在 scene 的 dev-dependencies**：它的产出是
`MeshRenderer`/`Light`/`Camera3D`，对拍门要同时比"typed 路径"和"旧提取路径"，这只有组合根看得见。
留在 scene 做 dev-dep 也能编译，但那条 `scene → render` 的**库**边会在 dev-dep 的伪装下继续存在
（新人看见 `[dev-dependencies] rustlua-render` 就会以为可以随手 `use`），门也抓不到。

**教训（值得抄进下一次拆分层）**：搬 `char_collect` 时最先撞到的不是代码，是**依赖方向**——
它读 `.scene`/`.prefab`（scene）又解析 `Text`/`WorldText`（ui），两者都是它的上游，
所以它**只能**住在两者都依赖的第三层（导入层）。这类"两张上游的交叉读者"是聚合层依赖的常见来源。

### ⑤ `ScriptState` 中枢 + 剩余 14 个 API 模块

- 31 个字段按 owning crate 拆成 `Handle<…>`（`audio`/`input` 已示范：能力单元归
  `RuntimeScene`，`ScriptState` 只留 `Handle`）。
- 16 个 API 模块依序下沉，顺序按"依赖少 → 依赖多"：`mod` → `save` → `prefab` →
  `globals` → `ui_nav` → `ui` → `transform` → `camera` → `entity` → `renderable` →
  `animation` → `world_data` → `tilemap` → `inventory` → `physics` → `ui_panel`。
- **每下沉一个都必须 `api_surface_snapshot` 零 diff**（这是这条线唯一的防回归锚）。

**⑤-1 已落地（2026-10-20）：存档域从 `ScriptState` 里搬出去。**

做法（这是 ⑤ 的样板，后面 15 个模块照着走）：

1. **能力单元归位**：`SaveState { data, path, slot }` 曾是 `script/mod.rs` 里的内联结构，现在
   是 `rustlua_gameplay::save_store::SaveStore` —— 存档**格式**（`save::encode/decode`）本来
   就在那个 crate，数据保管方却一直在 VM 宿主，这是"两边都改不动"的典型。
   `ScriptState.save` 变成 `Handle<SaveStore>`（`rustlua-lua-api` 的能力单元）。
2. **借用变窄**：`save.write` 以前是 `lua_borrow_mut()?.save.data.insert(..)` —— 借用整份
   `ScriptState`；现在是 `save.borrow_mut()?.insert(..)`，只借存档那一小块。副作用是真修了一个
   诊断问题：以前重入时报的是"脚本状态被重入"，与真正原因无关。
3. **装配点补名字**：`Handle` 的 `what` 只用于重入报错，而 `ScriptState::default()`（派生）只能
   给出 `<unnamed>`，所以在 `runtime.rs` 的构造点写成
   `ScriptState { save: SaveStore::handle(), ..ScriptState::default() }`。
   `lua-api` 里加了 `impl<T: Default> Default for Handle<T>`，只为让 31 字段的状态还能派生
   `Default`——手写三十行 `Default` 每加一个字段就得改，那是另一种债。
4. **零 Lua 面变化**：`api_surface_snapshot` 零 diff（`cargo test -p rustlua-scripting` 110 + 1 绿
   即证明），存档行为由 `jhyt_m22_save_isolation`（16 个 provider、8 行数据）端到端复验。

**下一步（⑤-2）**：`save.rs`/`world_data.rs` 两个绑定整体搬到 `rustlua-gameplay`
（`save_lua` 模块，加 `mlua` + `lua-api`，和 `audio_lua`/`input_lua` 同形），届时 `ScriptState`
再少一个 `Rc<RefCell<…>>`-派生的借用面；`values.rs`（Lua↔JSON）随绑定走。之后按
`transform`（403）→ `camera`（399）→ `entity`（328）→ … 顺序推进，每步都要
`api_surface_snapshot` 零 diff。

**为什么先挑存档域**：它是 16 个模块里唯一"状态只有一个键值表 + 两个可选字段"的
（其余都要动 `World` / UI 焦点 / 物理世界）。先把它做成样板，代价最小的那次试错能暴露
机制问题——事实上立刻暴露了一个：`Handle::borrow()` 的 guard 不能跨 `let...else` 存活
（临时值被 drop），所以 `map.spawn` 那处改成"先 clone 出两个 `String` 再解析"。

## 风险与回滚

| 风险 | 触发症状 | 回滚 / 处置 |
|---|---|---|
| ③ 拆 crate 时 `assetc`/`editor` 的 `use rustlua_assets::importer::…` 漏改 | 编译期缺符号，范围可枚举 | 一次性全改完再编译（`cargo check -p assetc -p editor`），**不**留 re-export 兜底——那等于把边留在原地 |
| ③ 让运行时的 `Importer` trait 也被搬走 | `rustlua-scene::asset_import` 编译失败（它要 trait 来建注册表） | trait 必须留在运行时侧；只有实现搬走 |
| ④ 编解码注册表改出 `.scene` 字节差异 | 现有 `.scene` round-trip 用例（`scene::tests`）或示例 golden 出现 diff | 先补"注册表装表前后 dump 一致"的断言再改分派，确保是搬运不是重写 |
| ⑤ `api_surface_snapshot` 出现 diff | 快照文件变化 | 立刻停：说明函数集/签名变了，不是纯下沉。先修到零 diff 再继续下一个模块 |
| 架构门忽然变红且"说不清哪来的" | `root_edges >= 3` 断言失败 | 说明扫描器又退化了（不是代码坏了）：先修扫描器 |

## 明确不做

- **不为了拆而徒增 crate**：③ 只拆出一个 crate（导入层）；④ 不新建 crate（下沉到已有
  owning crate + 一个注册表）；⑤ 不新建 crate（`audio`/`input` 的先例已证明不需要）。
- **不动 `rustlua-lua-api`**：它是叶子契约层，加任何依赖都会打破 `lua_contract_crate_stays_a_leaf`。
- **不追 feature 开关**：平台分支用 target 条件依赖（②已证），feature 会跨 target 合并。
- **不顺手改 MVP 功能**：本任务只动结构与依赖边；红门示例（`jhyt_m17_shop` 等）不在范围内。
