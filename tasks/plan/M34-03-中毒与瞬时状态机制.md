## 目标

毒蝎（`scripts/data/enemies.lua`）的注释写着"中毒状态由 combat/effect 侧结算"，
但全工程 `poison` 只出现在美术 id `poison_scorpion` 上，combat/effects 里没有任何结算；
`ui/hud.lua` 也自认"其余状态机制未实现 → 不画但已就绪"（贴图在 `skin.lua` 备着）。
本任务把**按固定步结算的瞬时状态**（DOT / 减速 / 沉默）做成一个有名字的东西，
让毒蝎那条注释变成真话，并让 HUD 的状态图标第一次被驱动。—— 已落实，实测见"验收方式"。

## 实现要点（原计划的四条约束与落实结果）

1. **计时单位只有"固定步"**：已落实，且钉成两条断言（门 ⑧ 章）。`systems/status.lua` 全文
   不读 `time.delta()` / `clock.now()` / `math.random`，推进只在 `M.tick(actor)` 被调用时发生，
   调用方是 `combat.tick()`（`main.lua` 每固定步一次）。
2. **分层规则写死**：已落实，写成两个文件头的镜像说明 —— `player/stats.lua` 说"按**游戏日**过期的
   属性增益在这层"，`systems/status.lua` 说"按**固定步**结算的状态在那边"。混用的后果写在 status
   头部（把 DOT 塞进 buff = 按日结算掉血）。
3. **瞬时状态不进存档**：已落实，但"清"的入口比计划多（见"实测更正"3）。实测：provider 名单 16 项
   不含 `status`，存档正文扫不到 `steps_left` / `next_in` / `tick_steps`（门 ⑥ 章），
   读档后气血 76 原样回来、账本为空。
4. **DOT 可致死但不绕过死亡流程**：已落实，并多做一步 —— `set_player_hp(0)` 那条调试入口原本是
   **第二条死亡实现**，本批收编成同一收口的第二个调用方（"实测更正"8）。

## 实测更正（与计划不一致处，逐条给依据）

1. **验收 ③ 的"减速确实降低位移"没做**：全仓没有任何减速来源（`data/enemies.lua` 与
   `data/skills.lua` 都没有 slow/silence 类字段，已 grep 确认），本批只落 `poison` 一种。
   账本与 HUD 循环都不认种类名，所以加减速的形状是"数据一条 + 一张图 + 移动侧一个消费方"，
   不改机制。留在"未完成项"。
2. **`data/registry_check.lua 补校验` 的落点写错了**：`status` 的校验写在 `data/combat.lua` 自己的
   `validate_all` 里。`registry_check.lua` 只服务**纯表注册表**（`pairs()` 会被 `player/inventory.lua`
   误当物品定义的那类，见该文件头），combat 不属于它。
3. **"读档清状态"不是一处而是四处**：`combat.reset()`（新档）→ `status.reset()`；
   `combat.restore()`（读档）/ `combat.respawn()`（R 键重开）/ `fall_player()`（战败那一刻）
   各调 `status.clear(PLAYER_ACTOR)`。少任何一处都会留下具体故障：死人身上继续掉血、
   或者复活后毒跟着人回庄（§6.3 的口径是"回庄后生命/体力/内力回满"）。
4. **发现并修掉一条既有 HUD 缺陷**：状态图标**从来没有被隐藏的路径** —— `clear_dynamic` 只覆盖
   `ui_text` 登记的 id，而贴图走的是 `skin.icon` → `ui_state.images`，且只在 `M.reset()` 跑一次。
   所以"毒早过了图标还亮着"（以及 buff 到期、天气转晴后图标残留）是本批之前就存在的真 bug，
   被门 ④ 章"到期读回 nil"这条断言逼出来。修法是每帧对未激活的键显式 `ui.clear`。
5. **`state.last_action` 是瞬时通道，写不进"持续一句话"**：`ui/input.lua` 每步按当前动作改写它
   （移动分支与硬直分支），`main.lua` 的更新顺序是 `combat.tick → … → input.update`，
   于是**真实咬中的那一步读到的是 `hurt`**（门 ② 章按实际结果断言，不假装文案赢了），
   文字反馈只在"挂上状态且本步没有别的动作"时出现（①′ 章的合成路径证明写入确实发生）。
   持续可见反馈因此是图标；这一条边界写进了 `status.lua` 的 `write_feedback` 注释。
6. **帧率无关（验收 ②）的口径要说清，别把 `set_delta` 当成"30 FPS 开关"**：headless 里
   `set_delta`（`rustlua-scripting/src/script/mod.rs:511`）只改 `time.delta()` 的读数
   （`api/globals.rs:46`）与 `logical_ms`；真正的 30 FPS 是宿主 `game_app.rs` 的
   `FixedTimeStep::new(60, 8)` 一帧跑两个固定步。门里因此钉两半，合起来才是那条验收：
   ⑧ 章把每步喂给 Lua 的 delta 拨成 33ms / 8ms 各跑 600 步（两轮都是 5 跳、都正常到期），
   再去掉注释扫 `time.delta` / `clock.now` / `math.random` 命中 0 处。
   另外同章钉了 4×150 分片推进 + 片间查询 + 游戏内时钟 8 倍速（`clock.set_rate(8)`）仍是 5 跳。
7. **施加入口在受击方（`combat.apply_damage`），不在 `enemy.lua` 的命中处**：命中与施加在同一处
   才知道攻击者身份与是否被无敌帧整口吸收（无敌帧分支先 return，所以"挡了一下就整下都挡住"，
   状态也一起吃掉 —— 这是有意的）。`enemy.lua` 因此只加 11 行，与 M34-04 的冲突面缩到注入
   注册表那一行（原计划风险 ③ 想要的就是这个）。
8. **`set_player_hp(0)` 原来是第二条死亡实现**：本批改调 `fall_player("debug", "-", 0)`，
   于是它连带拿到"清瞬时状态 + 冻结受击反馈 + 倒地"，日志形状不变（`death/debug/-`）。
   门 ⑦ 章钉这条：调试置血前先挂毒 → 战败 → 账本为空。
9. **docs/33 §10 的"治疗"行实测与数据不符**：`data/items.lua` 的回复药 `use = { energy = 40 }`
   回的是体力，设计案那行写"恢复 35 生命"。本批不动数值（属物品/数值批次），但门 ① 章把
   §10 五行的**归属**逐条打印（坚定/轻功无敌 → M34-04；治疗/内息恢复 → 物品 `use`，不是状态账本），
   免得后人以为五行都已落地。§10 表本批一行未改。
10. **新增中文表的对账放在自己门里，不扩 `jhyt_m24_numeric_alignment`**：与既有约定同口径 ——
    §6.3 受击反馈表由最近的消费者 `jhyt_m25_combat_feedback` 解析，§10 状态表因此由
    `jhyt_m34_status` ① 章解析（行数、每行字段、换算步数、"这行归谁"都机器比；
    表里新加一行而数据侧没登记就门红）。

## 是否动引擎

**没动 Rust**（与计划的裁定一致）。触发条件仍写在计划原文里（需要跨图/异步存活的状态，
或第二宿主上 Lua 每帧 tick 成为实测热点）。本批没有遇到其中之一：门 ③ 章实测换图账本不清，
但那是"毒跟人走"，不需要引擎侧存活；⑧ 章的扫描说明结算零真实时间读取。

## 未完成项 / 已知限制

- **只落了 `poison` 一种状态**（更正 1）：减速/沉默没有来源、也没有消费方，机制形状支持但内容里没有。
