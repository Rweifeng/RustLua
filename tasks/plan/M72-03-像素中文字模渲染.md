## 目标

让中文以 1 位硬边点阵渲染，替掉现在压在像素美术上的平滑矢量 Noto Sans。
这是单条观感收益最大的一项——`project.toml` 原来 `text_render_mode = "vector"` + `NotoSansSC-VF.ttf`，
而引擎只有 `auto / vector / sdf` 三档（`editor/src/panels/project_settings.rs:37-39`）。

## 字体选型（已定，2026-10-08 定稿）

**缝合像素字体 Fusion Pixel Font · 12px Monospaced · TTF · tag `2026.09.25`**

- 授权：**SIL Open Font License 1.1**。⚠ 本节原写 **MIT**，那是只看 GitHub API
  `license.spdx_id` 的**误判**——那个字段描述的是**源码仓库**（构建脚本），发布包内附的是
  `OFL.txt`，且 TTF 的 nameID 13/14 自证 OFL-1.1。上游版权行**没有** Reserved Font Name，
  所以子集化与改名不受条款 3 约束；条款 4/5 要求我们的子集继续用 OFL-1.1（**不得**记成 MIT 再分发）。
  核验记录与复现命令：`examples/game_jhyt/assets/fonts/LICENSE-FusionPixel.txt`、`docs/58` §11。
- 只入**一款**：标题用整数倍 2× 放大，不引第二款字体（两款像素字混用会立刻露馅）。
  `project.toml` 因此把 `font_fallback` 置空——点阵与平滑矢量混排一眼就穿。
- monospaced 而非 proportional：UI 网格对齐是本轮 P3 的主要诉求。

## 现状（实测，2026-10-08 更正）

- 栅格化：`ab_glyph` 出轮廓 → `bymsdfgen_core::generate_sdf` 转 MSDF
  （`rustlua-render/src/font.rs`）。**这条对点阵字体是错的**：MSDF 会把 1-texel 笔画糊成灰边。
- 固定尺寸 `RASTER_SCALE = 96` px/em；显示尺寸 `EM_PX*scale`，`tex_scale = base_px / RASTER_SCALE`。
- **quad 角原本用 float 次像素定位、从不吸附**（只有 UI image 吸附）→ 像素字会糊。
- 着色器**已有一条硬阈值路径**：`sdf==2` = `select(0,1,d>=0.5)` + Nearest 采样，
  原来只服务 ASCII 5×7 位图，CJK 走不到（没有外部位图字体导入器）。
- 子集化通道现成：`font_subset::subset_ttf`（TrueType glyf 子集器，丢 `gvar/fvar` → 静态字重），
  打包期由 `assetc/src/lib.rs:745` 调用（读 `project.toml` 的 `font =`，不是写死文件名）。
- 字表**不是** plan 期估的 471 字：`jhyt_m30_cjk_text` ② 实测 `char_collect` 收到 **4,623** 字符，
  运行时语料 **1,731 条 / 1,118 个**不同字符；裁出的子集 **597,932** 字节。

## 风险（回看）

- **12px 能否落整数格**：不再是推算——③ 实测 4 个字形在 12px 下逐 texel 采样次数恒为 1、四边角全整数。
  `RASTER_SCALE=96` 与 12px 的 8 倍关系成立，但**判定用的是二值覆盖率反推出的 `raster_scale=12`**。
- **非整数倍字号**（13/14/15/18/22/24）：吸附保证边角整数，但 14px 档实测"某 texel 采两次=160"
  ⇒ 点阵被重排。灰阶仍然 0（不发糊），只是笔画粗细会跳。**归 M72-10 的字号档位表**。
- 缺字：`chars.txt` 不是手工清单（`char_collect` 收），所以风险变成"**上游全量也没有**"那一类
  （`›` `−` `✓` `鳜` 四例）——已按"改文案不加字体"处理。
- 三宿主：桌面 headless 已验，**Web/微信真机未验**（归 M72-12）。
