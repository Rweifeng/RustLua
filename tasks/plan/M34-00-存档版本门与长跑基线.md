## 实现要点

1. **整批回滚优先于半恢复**：先把当前内存快照 capture 到临时层，逐 provider 恢复并**收集**错误（不 `return false`）；
   任一 provider 失败则回滚到临时层并返回失败清单（哪个 provider、什么错），调用方（`main.lua on_create`）
   据此把"存档部分不可用"显示成中文一行而不是继续玩坏数据。
   若实现上回滚成本过高，退化方案是"失败 provider 用默认值 + 明确 warn"，但**必须写进实现记录并给出为什么**。
2. **每个 loader 开头补版本门**：`version` 不认识的（高于当前或字段缺失且非首版）→ 拒绝该 provider、
   保留原文件、`log.warn` 带 provider 名；不 clamp、不猜字段。与 docs/34 B-2 的引擎口径（旧档拒绝且不覆盖）一致。
3. **新门 `jhyt_m34_save_gates`（负向为主，成功路径交给 soak）**：
   - A 章 map.state 版本门：building / crafting / gather 各跑"拒绝 + 同一份数据改回当前版本即读回"两侧，
     这样红只可能来自版本判定，不会把别的偶然因素当成门的功劳。
   - B 章快照版本门：capture 后把 `providers.buildings.version` 改成 99 → `restore` 返回 false 且 reason 带
     `bad_version`；内存里建筑一座不少；**磁盘存档文件字节不变**（拒绝读档不得顺手重写存档）。
   - C 章半恢复负向：注册一个会 `error` 的 provider → restore 失败后，排在它前面**已经写进内存**的
     `state.money` 必须回到 restore 前的值；把 error 去掉，同一份快照必须整批恢复成功。
   - D 章逐字段相等的读档循环：100 次 `save()` → `load()`，每次把 capture 的快照规范化成排序字符串，
     与第 1 次逐字符比较（soak 的 C2 只比 `day>=30` 与地图名，比不到字段）。
4. **登记**：新用例进 `scripts/verify.ps1` 的 MVP 清单（`:842` 对"盘上有但未登记"直接 throw）。

## 风险

- 回滚点是一次全量 capture（读档路径多一次快照拷贝）——实测：D 章 100 次磁盘往返（含每次全量
  capture + dump + 回滚点）计时打印在尾行前一行，验收时对照 soak 的 per_step_ms 读数，别口头保证"没变慢"。
- 版本门会让**未来**改 schema 后的老档读不回来（这正是目的）；因此写侧一律走 `STATE_VERSION` 常量、
  字段名不动（gather 保留既有的 `state_version`，不改名为 `version`，否则现存存档当场失效）。
