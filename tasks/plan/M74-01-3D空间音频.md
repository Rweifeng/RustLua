## 目标

让**任何一次播放**都能带"这个声音在世界里的哪个位置"：引擎按听者位姿算出增益与声像，
桌面用真实空间化播放，web/微信按能力降级为"只改音量"。一句话验收：听者往右走，
左侧的火堆声变小、右侧的溪流声变大——并且这件事在 headless 用例里能用数字断言。

## 关键设计：模型权威、平台尽力

两端能力不同（桌面能做等功率声像，web/微信只有 `volume`），所以设计必须先把"听感"的
**唯一来源**钉在引擎侧，平台只负责应用：

```text
Listener { position, forward, up }        // 宿主每帧从相机灌入
SpatialModel { min_distance, max_distance }
evaluate(emitter, listener, model) -> SpatialParams { gain, pan }   // 纯函数，无设备
```

- `gain`：`min_distance` 内为 1；`[min, max]` 线性衰减到 0；`> max` 为 0。**不用**反平方
  （反平方在 2D 小地图上衰减太快，听感上"隔一堵墙就没了"，且难调）。
- `pan`：`right = normalize(cross(forward, up))`，`pan = clamp(dot(normalize(emitter - listener), right), -1, 1)`
  （等功率声像的两端取 `√((1∓pan)/2)`）。距离为 0 时 `pan = 0`。
- **平台应用**：
  - 桌面：`SpatialSink` 播，`set_volume(bus_gain × gain)`，并把 `pan` **折回位置**——
    `set_emitter_position(listener + right × pan × k + forward × k)` 再喂给 rodio（`k` 取固定值，
    例如 0.5 m：折回后到两耳的距离近似不变，于是 **rodio 自己的距离衰减不会被二次叠加**，
    衰减只由我们算的 `gain` 决定）。
    为什么不直接把真实坐标交给 rodio：那样桌面走 rodio 自己的距离/声像模型、web 走我们的，
    两端听感分叉且**查不出原因**。折回位置能让平台模型与我们的模型同向，同时保留 rodio 的
    等功率实现。
  - web/微信：`AudioRequest` 增 `spatial: Option<SpatialEmission { gain, pan }>`；
    provider 把 `gain` 乘进 `volume`，`pan` **显式标注未应用**（`debug!` 一行，不静默）。
    真要做到两端一致，得把 web 播放通道换成 WebAudio + `PannerNode`——那是另一件
    （本任务的"明确不做"，见末节）。
- **2D 项目照样能用**：`audio.play_at(name, x, y)` 的 `y` 只参与距离，`pan` 看 `x`；
  `Listener` 由相机在 2D 下给 `forward = +Z`、`up = +Y`，于是"屏幕左右"就是"耳朵左右"。

## 风险与回滚

- **公开 trait 扩字段**：`AudioRequest` 加字段会让仓外实现编译失败（仓内只有 1 个 wasm provider，
  改一处即可）。回滚档：字段用 `Option` 且默认 `None` = 今天语义，`play_spatial` 与 `play_on` 并存。
- **`SpatialSink` 的回收**：rodio 的 `SpatialSink` 与 `Sink` 是不同类型，回收表得收成 enum；
  若 `try_new` 在无设备机器上失败，维持既有"警告 + 静默降级"（不 panic）。
- **两端听感不同**（web 无 pan）：这是**已知且显式**的降级，不做"假装一致"。
- **不要**让空间化进入 BGM 路径：`music` 仍是 2D 总线，否则切场景时的听感变化会被误判成 bug。

## 明确不做（写清楚，避免"看起来没做完"）

- WebAudio `PannerNode` / HRTF：要换掉 web 播放通道（`HTMLAudioElement` → `AudioBufferSourceNode`），
  动的是 `game_web` 的音频出口与微信真机行为，成本与现有 1 周估算是**两件事**。
- 混响区、遮挡（occlusion）、多听者：需要场景几何与射线，属另一个能力。
- 3D 音频的"距离模型参数化进设置面板"：先固定常量 + 每调用点可选覆盖，看实际需要再说。

**实测发现（计划里没有的那条）**：rodio 0.19 的 `Spatial` 自己带距离衰减
（`rodio-0.19.0/src/source/spatial.rs:64-65`：`(1.0/left_dist_sq).min(1.0)`）。
所以折回位置的常数 `k` 不是"随便取"，而是**必须**落进 rodio 的"1 m 内不衰减"区间——
`FOLD_DISTANCE = 0.5 m` + `EAR_OFFSET = 0.1 m` 下折回距离最大 0.7071 m。
这条由 `folded_positions_stay_inside_rodios_no_attenuation_range` 与示例 ④ 段（五档 pan 逐档
打印距离）钉住；写计划时只写了"近似不变"，实测才知道是硬约束。

**第二处实测发现（计划里也没写）**：宿主接线不能"顺手再解析一次相机"。第一版直接调
`active_camera3d()`，`host::runtime_scene::tests::frame_view::script_steps_invalidate_the_frame_view`
当场红（`camera3d_resolutions` 从 2 变 3）——那条账本存在的意义就是"一帧不要把相机算两遍"。
改法是 `frame_data.rs` 新增 `frame_camera3d()`（读已定帧视图里缓存的相机），宿主优先复用它，
headless 才解析。这正是"测试账本发现设计漏洞"的一例：如果没有那条断言，桌面端每帧会多一次
相机解析而没人发现。

- **人耳未验**：`k`、两耳间距、线性模型的 `min/max` 都要真机听感定标（数值全绿 ≠ 听起来对）。
- **wasm 侧未跑到**：`cargo check -p rustlua-audio --target wasm32-unknown-unknown` 在这份依赖树上

  `cargo check -p game_web --target wasm32-unknown-unknown`（本包的验证方式）。
  `HTMLAudioElement`/`InnerAudioContext` 的"声像未应用"只在代码里显式记了 `debug!`，
