## 1. 要解决的问题

编辑器已具备商业引擎对标的类型化命令总线（`EditorCommand` → `dispatch`，
`engine/crates/editor/src/command_router.rs:37`）、事务/撤销、schema 驱动 Inspector、插件注册表
（`rustlua-infra/src/editor_plugins.rs:7`，`PLUGIN_API_VERSION=1`）与 GUI 证据 harness
（`editor/src/gui_evidence.rs`）。但**没有任何 AI/LLM/MCP 接入面**（全仓 grep 无命中）。

市场已收敛到 MCP：AI 客户端经标准协议读场景/组件/控制台、经确认执行编辑器动作。RustLua 的断层是：

1. **能力未暴露**：33 条 `EditorCommand` 与 Lua 探针（`eval_json`，`rustlua-scripting/src/script/mod.rs:738`）
   只在进程内可用，外部 AI 看不见、够不着。
2. **上下文未机器化**：Lua API 有 `lua_api_surface.json` 快照与文档桩，但没有作为 MCP resources 供 AI 拉取，
   LLM 写 Lua 只能靠幻觉。
3. **无 AI 专用门**：tool 契约漂移、AI 动作非确定性都没有门兜底，无法进 `verify.ps1`。

M75 的目标不是「加个聊天框」，而是**把已有能力经 MCP 暴露成可审计、可回放、可进门的 tool 面**，
再在其上按需叠加内置面板与代理式工作流。

## 3. 各工作包详述

### M75-01 能力层骨架 + 只读 MCP server（P1，档 A）

- **目标**：新增 crate `rustlua-editor-ai`，以 `AiBridgePlugin : EditorPlugin` 挂进 `PluginRegistry`；
  进程内起 MCP server（stdio + 可选本地 TCP）；实现全部**读 tool** 与 **resources**。
- **影响文件**：
  - 新增 `engine/crates/rustlua-editor-ai/`（Cargo.toml + src）；登记进 `engine/Cargo.toml` workspace members。
  - `engine/crates/editor/src/main.rs`（`EditorApp` 注册 `AiBridgePlugin`）。
  - `engine/crates/editor/Cargo.toml`（feature gate：`ai-bridge`，仅原生 editor 启用）。
  - 新增 `ai_tool_surface.json` 基线 + 探针（仿 `rustlua-scripting/src/api_surface_snapshot/`）。
  - `scripts/verify/verify.ps1`（接 tool 面快照门）。
- **读 tool（T0）**：`get_scene_tree`、`get_selection`、`get_inspector_schema`、`list_components`、
  `read_console`、`list_lua_api`/`get_lua_api`、`eval_lua_readonly`、`capture_screenshot`、`get_project_config`
  （数据源逐一见 docs/71 §7.3，均已核实存在）。
- **resources**：`lua_api_surface.json` + 生成文档桩 + scene schema + `project.toml`。
- **前置探针（开工第 1–2 天）**：量 `rmcp` 依赖树对 editor 增量编译时间的影响；超预算则退化为自实现
  最小 JSON-RPC 2.0（stdio）。选型结论回写本文件与 docs/71 §12.1。
- **验收门**：
  - [ ] 外部 MCP 客户端（Qoder/Claude Code）连上，`get_scene_tree`/`list_lua_api`/`read_console` 返回真数据
  - [ ] `ai_tool_surface.json` 快照门上线，改 tool 签名先红后刷（跑一次反面对照证明它会红）
  - [ ] feature gate 关闭时 editor 构建不含 `rustlua-editor-ai`（量一次二进制体积差）
  - [ ] `cargo build -p editor`（debug）通过；架构棘轮测试仍绿
- **风险与退路**：`rmcp` 依赖膨胀 → 自实现最小协议；MCP server 阻塞 UI 线程 → server 跑独立线程，
  经 channel 回主线程执行 tool（写动作尤其必须在主线程，因 `EditorApp` 非 Send）。

### M75-02 写 MCP + 确认·事务网关 + Lua 生成闭环（P2，档 A）

- **目标**：实现**写 tool**，全部经确认·事务网关落 `EditorCommand`；打通 Lua 脚本生成闭环。
- **影响文件**：`rustlua-editor-ai/src/`（tool handlers + 网关）；`editor/src/command_router.rs`（如需显式化选区相对命令）；
  `editor/src/actions/`（确认 UI）；`ai_tool_surface.json`（新增写 tool）；回放 fixture 目录 + 门脚本。
- **写 tool**：docs/71 §7.2 的 23 个（A1 文档 / A2 历史 / A3 运行 / A4 实体 / A5 组件 / A6 字段 / A7 Prefab）。
- **确认·事务网关**：写动作一律 confirm → `edit_transaction` → 一条 Undo；对 MCP 客户端与内置面板**同等生效**。
- **选区相对命令显式化**（docs/71 §12.2 待裁定）：`delete_entity`→`delete_entities(ids[])`、
  `set_component_fields` 用显式 `entities[]` 而非 `on_selection`；作为本包内联改造或 P1 前置小任务。
- **Lua 生成闭环**：`write_lua_script(path, code)` → `eval_json` 求值校验 → `lua_api_surface` 探针对签名 →
  失败回错误给 AI 自动修 → 通过才落盘。
- **T3 无头安全策略**：`new_scene`（清 Undo 栈）、`open_scene`（脏文档挂起）在无确认通道时**拒绝**而非静默执行/挂死。
- **验收门**：
  - [ ] `create_entity` + `add_component` + `set_component_fields` 经确认落一条 Undo，`undo` 可完整收回
  - [ ] Lua 生成闭环：故意给错 API 名 → 门红并回错误 → AI 修对 → 落盘（跑反面对照）
  - [ ] **确定性回放门**：录一段 tool 序列为 fixture，CI 无 LLM 重放，逐 patch 比对绿
  - [ ] `new_scene`/`open_scene` 无头拒绝策略有测试覆盖
  - [ ] `cargo clippy --workspace --all-targets --all-features -- -D warnings` 通过
- **风险与退路**：写动作跨线程执行 → 强制主线程执行 + channel；回放非确定（含时间戳/随机 id）→ fixture 归一化。

- **验收门**：
  - [ ] 端到端：一句自然语言 → 引擎真生成物件 → Playtest agent 跑 MVP 无头回归自测通过
