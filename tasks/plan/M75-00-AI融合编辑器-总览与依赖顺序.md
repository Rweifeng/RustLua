## 1. 要解决的问题

编辑器已具备商业引擎对标的类型化命令总线（`EditorCommand` → `dispatch`，
`engine/crates/editor/src/command_router.rs:37`）、事务/撤销、schema 驱动 Inspector、插件注册表
（`rustlua-infra/src/editor_plugins.rs:7`，`PLUGIN_API_VERSION=1`）与 GUI 证据 harness
（`editor/src/gui_evidence.rs`）。**立项时全仓没有任何 AI/LLM/MCP 接入面**（全仓 grep 无命中；
M75-01/02 已补上，见 §11）。

市场已收敛到 MCP：AI 客户端经标准协议读场景/组件/控制台、经确认执行编辑器动作。RustLua 的断层是：

1. **能力未暴露**：33 条 `EditorCommand` 与 Lua 探针（`eval_json`，`rustlua-scripting/src/script/mod.rs:738`）
   只在进程内可用，外部 AI 看不见、够不着。
2. **上下文未机器化**：Lua API 有 `lua_api_surface.json` 快照与文档桩，但没有作为 MCP resources 供 AI 拉取，
   LLM 写 Lua 只能靠幻觉。
3. **无 AI 专用门**：tool 契约漂移、AI 动作非确定性都没有门兜底，无法进 `verify.ps1`。

M75 的目标不是「加个聊天框」，而是**把已有能力经 MCP 暴露成可审计、可回放、可进门的 tool 面**，
再在其上按需叠加内置面板与代理式工作流。

### 11.4 M75-03 内置 Assistant 面板（2026-10-22 重开并交付）

- **接线方式**：`DockTab::Assistant` 默认插在属性右侧同一叶（属性保持活动，旧版首帧几何不变）；
  View 菜单「AI 助手」可隐藏/恢复；`Panel_visible` 6→7 键；`EditorLayout` 新增 `assistant`

  并登记为内存基线，避免打开项目第一帧误判成改动而自动写盘。
- **请求与工具循环**：后台线程调 `Provider::complete`，结果经 channel 回 UI，`request_repaint`
  唤醒空闲窗口；每轮最多 8 次模型请求。读工具立即执行；写工具进确认卡，批准后走
  `execute_tool(&mut EditorAiHost, policy, …)`——与外部 MCP 客户端同一入口、同一 registry。
  历史中 assistant/tool 严格配对，超轮数也补 tool 错误结果。
- **密钥边界**：`api_key` 只存 `AssistantState` 内存；`ProviderConfig` 只在发请求时读取；
  curl 配置从 stdin 传入；布局快照类型上无 key 字段。
- **设置落盘节流**：服务商/Base URL/模型来自文本框，每击键都会变。设置走 500ms 稳定窗口：
  输入期间只记 `assistant_dirty_since`、不写盘；`maybe_persist_layout_on_change` 返回到期时长，
  帧末 `request_repaint_after` 保证停止输入后仍有一帧来合并落盘；关窗时若仍有挂起设置，
  `on_exit` 补一次 `persist_layout`（dock 树 300ms 节流不变）。
