## 目标

把 `UiSpec` 确定性编译成现有 `EditorCommand` 批次，并把 `ui_*` 工具从"规格"接到真实执行体：
校验 → 预览 → 提案 → 接受（一次事务/一条 Undo）→ 检查点。AI 永远不直接写 `.scene`。

- `engine/crates/rustlua-ui-spec/src/compiler.rs`（新增：纯函数编译）
- `engine/crates/rustlua-ui-spec/src/diff.rs`（新增：Spec/场景语义 diff）

- `scripts/verify/verify.ps1`（回放门）

## 交付项

1. **编译器**：Spec → 命令列表（创建/设置组件/父子关系/事件/样式），输入含能力矩阵与目标文档；
   同输入同输出（命令序列字节等价）。
2. **UI 文档宿主**：`.ui.json` 的打开/保存/revision 递增/回读 Spec；revision 与文件内容哈希绑定。
3. **工具**（内部 API 强类型 + MCP 编解码同源）：
   - T0 `ui_export_spec`（当前场景/文档 → Spec）、`ui_validate_spec`、`ui_preview_spec`（离屏 PNG）
   - T1 `ui_apply_spec`（新文档或整文档替换）、`ui_apply_patch`（增量 + base_revision 校验）
   - T0 `ui_list_assets`（读取资产清单与 provenance）
   - 内部 API 返回 `Result<UiToolOutcome, Diagnostic>`；MCP 侧字段逐一映射，不另写业务分支。
4. **提案/检查点**：提案对象含 diff/预览/诊断/成本/expires_at；接受走事务，一次 Undo；拒绝不改工作区。
5. **回放门**：录制请求 → 期望命令/场景 diff，CI 离线回放稳定通过。

## 验收方式

```powershell
cargo test -p rustlua-ui-spec
cargo test -p rustlua-editor-ai
cargo test -p editor ui_spec
cargo build -p editor
```

反面对照：过期 `base_revision`、未知 key、重复 key、删除根、修改 `key`、未支持能力字段——六类都必须有
单测证明被拒绝。确定性：同一 Spec 编译两次，命令序列断言相等。

## 风险

- 现有 `EditorCommand` 是逐字段命令，整文档替换可能产生大量命令；用事务批处理，但 Undo 仍为一条。
- 场景回读 Spec 的语义等价需要明确"可丢失字段"清单，否则 diff 噪声大。
- 工具执行体必须复用 M75 的确认网关，不能绕开 T2 确认。

### 2026-10-24：全部交付项落地

    拒绝是 no-op。
