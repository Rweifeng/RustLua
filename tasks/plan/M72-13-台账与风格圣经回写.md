## 三处已知假账的核对结果：**两处成立、一处是任务文件自己的前提错了**

1. **NPC 那条：方向对、数字错。** plan 写"16 条 NPC **全部**带 `character =`"——实测
   `grep -c "character = " scripts/data/npcs.lua` 在 HEAD 副本上是 **10 / 16**
   （`assets/art/characters/` 12 个目录 = 2 主角 + 10 NPC）。
   `docs/58` 原来那句"6 个 NPC 是 `__white__` tint 色块"**确实过期**（`scripts/world/npc.lua:160` 优先读
   `character`，`__white__` 只是兜底），但补正时不能把它反向写成"16 条全有真图"——
   真实缺口是**三个互不相干的**：表情档数只有 3、立绘覆盖 5/16、序列帧覆盖 10/16，
   且 **5 ⊂ 10**（我第一版把它写成"两条不重合"，也是错的，已按实测改回）。
2. **图标计数：成立，但两个旧数都不是"现在的数"。** `docs/58` 的"93 在盘 / 85 真图"与
   `docs/60` §7 的"64 张 32×32 纯色块"自相矛盾——**两边都作废**：实测 92 张、被引用缺口 0、
   **纯色块 0**（最少一张 4 档 RGBA、中位数 196.5 档），当年那 64 张纯色占位确实存在过，
   是后续轮次被生成器出的真形态图替换掉而**没人回写**。判据与命令写在 `docs/58` §6。
3. **帧数/方向：口径分歧成立，但 plan 给的"门本身是既有红"是假的。**
   `engine/crates/game/examples/jhyt_m21_appearance.rs:101-107` 断的是 **`clips != 56`**、
   注释就写着"8 向 × 7 动作"，不是 plan 说的"写死 `clips != 28` 即 4×7"——所以**这条门是绿的，
   不存在"改口径还是改数字"的两难**，只剩文档侧的 4 方向/6 帧/NPC 3 帧三处旧口径。
   已逐条裁定"以实现为准"：`51`（4 方向 → 8）、`57` §3.2、`54` §6.1；
   经脉 `54` 的 6 脉 → 实交付 **12**（`grep -c '^\s*id = ' scripts/data/meridian.lua` → 12），
   结局 `54` 的 4 → 实交付 **5**（`jhyt_m58_ending.rs:45` 断 `5.0`）。

**plan 里另外两条前提也被实测推翻**（如实登记，不静默改写）：

- "本轮新增了一项第三方素材：**Fusion Pixel Font（MIT，经 GitHub API `license.spdx_id` 确认）**"——
  **MIT 是误判**：`spdx_id` 描述的是源码仓库（构建脚本），发布包内附 `OFL.txt`，且 TTF 的
  nameID 13/14 自证 "SIL Open Font License, Version 1.1"。授权表按 **OFL-1.1** 登记，
  上游无 Reserved Font Name（故子集化不受条款 3 约束，条款 4/5 要求子集继续用 OFL-1.1）。
- "`scripts/check_asset_baseline.ps1` 的 OK112/MISSING107 是复现不出来的口头数字"——
  **脚本是入库的**：`git ls-files examples/game_jhyt/scripts/check_asset_baseline.ps1` 有输出，

  "双向判别"（先判文件在不在库、再判读数对不对），而不是照抄任何一个数。
