## 目标

把"这棵树在其他平台/浏览器上还行不行"拆成**可复核的证据层**：哪些是编译、哪些是真实运行、哪些只是环境受限的跳过；并把 advisory → blocking 的升档从"感觉可以了"变成一条有判据的流程。

事实源：`metrics/promotion.json`（档位/负责人/理由/`review_by`）；`matrix.yml` 里的

### 1.2 运行时证据（在 `.github/workflows/quality.yml` 的 `web-evidence` job，不在矩阵）

| 证据层 | 脚本 | 判据 | 环境受限时 |
|---|---|---|---|
| Web 平台契约层 + 产物启动层 | `verify.ps1 -Web` | exit 0 才算过；页面能跑却无画面/引导失败是 1 | 显式打印跳过原因，exit 2/3 |
| wasm Lua 运行期（no-modules 桥 + gpu2d 宿主画布探针） | `verify-wasm-lua.ps1` | `exit=0` 才算过 | `exit=3` 环境受限 |

**三态语义是这套体系的优点**：跳过（3）≠ 通过（0）。但**连续跳过等于没有证据**，
而目前没有任何"跳过率"统计——这是本任务要补的第一件事（见 §三-1）。

### 1.3 已知的不对称

- Windows 是唯一"编译 + 全量测试 + 运行时证据"三合一的平台；
- Linux/macOS 只有 advisory 编译；
- wasm 的运行时证据依赖 runner 上是否有浏览器/zig，**可以长期静默跳过而不判红**；
- 真机（Android / 微信）只有历史证据，无自动化；`docs/52` 已明确边界。

## 二、升档判据（写死，避免"感觉可以"）

`promotion.json` 的 `comment` 已写"连续 2 次 main 绿 + 无 flaky 记录"，这里补成可执行版本：

1. 目标 cell 在**同一个 `main` 提交族**（连续 2 次 push，或 1 次 push + 1 次
   `workflow_dispatch`）上首次全绿，且两次之间没有该 cell 的红；
2. 期间没有该 cell 的 flaky 记录（`scripts/verify/flaky-skips.json` 与 job 重跑史）；
3. 改档位必须**同笔**完成三处：
   - `metrics/promotion.json`：`tier` → `blocking`、删 `review_by`、`reason` 写清依据；
   - `.github/workflows/matrix.yml`：该 cell 的 `tier: blocking` + `experimental: false`；
   - 本文档 §一 的表格同步；
4. 全程不降低任何已有 blocking cell 的门槛。

**不满足判据时允许的动作只有"修 workflow"**：Linux 缺系统库就先补 apt 依赖
（见 `matrix.yml:113-117` 已有的 `libasound2-dev` 等），而不是把 cell 记为"平台不支持"。

## 三、缺口与优先级

1. **`-Web` / wasm-lua / webgl-EH 的跳过率没有账本**（P1）。
   现在三层都能以 3 跳过且不会红。建议：把每次 job 的三态结论落进
   `metrics/history/*.jsonl`（已有度量历史库），并由 `check-metrics.ps1` 断言
   "连续 N 次 main 的 web-evidence 至少一次 exit=0"——否则"浏览器证据"只是名义存在。
2. **Linux/macOS 只有编译**（P2）。升 blocking 前值得先加一条
   `cargo test --workspace --all-features --no-fail-fast` 的**advisory** cell；
   有了稳定读数再谈阻断。
3. **Android/微信真机不可自动化**（已知边界）。保持"历史证据 + 产物层静态门"，
   不要用产物层绿灯冒充真机通过（`docs/52` 口径）。

### 三-A、已被证实的第 0 条缺口：CI runner 没有 GPU，WebGL 证据每 push 必红（2026-11-16 已修）

`run 43821083086`（`4a440c93`）的 `web-evidence` job 注解原文：

```
[RED] webgl_bundle_scene_verify_failed boot=pending scene_verify=absent
      detail= world= gpu=initializing
```

不是产物坏了，是**无头 Edge 在无 GPU 的 runner 上起不来 WebGL2 上下文**：`gpu=initializing`
永不落定 ⇒ `boot=pending` ⇒ 门判红，且这个红从旧提交一直存在（`d9dd65bc` 同一 job 也红）。

修法（保持"真跑"而不是放宽判据）：

- `scripts/verify/verify-webgl-bundle.ps1`：无头浏览器参数增加
  `--enable-unsafe-swiftshader` + `--use-angle=swiftshader`（与早已这么做的
  `gpu-web-probe.ps1:166-171` 同口径），由 `RUSTLUA_SOFTWARE_GL=1` 开启；
- `.github/workflows/quality.yml` 的 `Web platform evidence` 步骤设置该环境变量。

**为什么不无条件开**：开发者本机有真实 GPU，强制软件光栅会把 90 s 的真实时钟等待拖成
超时假红。**为什么不改成 exit 3 跳过**：那等于把"浏览器证据"退回名义存在——软件光栅能给出
真实的首帧/绘制/API 契约读数，只是慢。

验证口径：下一次 push 的 `web-evidence` job 若仍红，注解必须**不再是** `gpu=initializing`
（而是具体断言），否则说明 SwiftShader 在 runner 上也起不来，需另找方案。


## 四、验收方式

```powershell
# 本机只有 Windows PowerShell 5.1（无 pwsh），与 README 的口径一致；CI 的 runner 用 pwsh。
# 档位与到期裁定（blocking 3 / advisory 4）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify\check-matrix-policy.ps1 -Check
# 平台 cell 与 verify.ps1 的命令对拍（防止两处漂移）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify\verify.ps1 -Quick   # 含 platform parity 段
```

升档动作的验收：改档后**故意让该 cell 红一次**（例如临时加一行编译错误）并确认
workflow 判红，再还原——证明"blocking"真的阻断，而不是只改了字面档位。
