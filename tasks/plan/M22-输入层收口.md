```

```

**必须保留的正确设计**（`docs/37` §4 已点名，任何重构都要保留对应测试）：

| 不变量 | 证据 |

## 3. 目标 / 非目标

**目标**

1. 四条宿主路径（独立 `game`、编辑器 Play 预览、headless、未来的 Web）在键鼠与手柄上**语义一致**，差异只允许存在于「平台事件 → 引擎键身份」的转换层。
2. 键位身份与物理布局无关；改键可表达修饰键/组合键与全键域。
3. 手柄支持槽位（本地多人与设备切换）、热插拔不串扰、震动。
4. 摇杆具备与键盘同义的按下/松开边沿；菜单导航手感**与帧率无关**。
5. Lua 侧不再需要为「当前设备」「阈值/重复」做每帧扫描。
6. `core` 不再依赖 `host` 的类型。

**非目标**

- 不更换 `GamepadBackend` 的抽象与现有方法签名，不把 XInput 换成 gilrs 作为主路径（gilrs 仍留作可选实现，离线依赖约束见 `docs/33:63-81`）。
- 不做陀螺仪、触屏、输入法/文本输入。
- 不改存档格式、不改场景/预制体格式。
- 不做上下文分组 `ActionMap`（W6，需先决策）、不改 `save_version`。

## 5. 方案要点

### W1 物理键身份（价值最高，破坏面最大）

1. **引擎新增 `core::input::KeyCode`**：与 winit `PhysicalKey::Code` 一一对应的枚举（`KeyA..KeyZ`、`Digit0..9`、`Space`、`Escape`、`Tab`、`Enter`、`F1..F12`、`Arrow*`、`Minus/Equal/Comma/Period/Slash/Semicolon/Quote/Backquote/BracketLeft/BracketRight/Backslash`、`ShiftLeft/ShiftRight/ControlLeft/AltLeft` 等），提供 `ALL`（全表数组）、`to_text`（`key:KeyE`、`key:Digit1`、`key:ArrowUp`）、`from_text`。
2. **`Binding::Key(KeyCode)`** 替换 `Binding::Key(InputKey)`；`InputSnapshot` 的 `held_keys/pressed_keys/released_keys` 改为 `HashSet<KeyCode>`；`ACTION_MAP_VERSION` 升 `rustlua-actions-v2`。
3. **v1 → v2 迁移（必须一次 PR 内完成，否则玩家改键丢失）**：`ActionMap::from_text` 同时接受 v1 头，用一张 QWERTY 换算表（`key:e` → `KeyCode::KeyE`、`key:1` → `Digit1`、`key:up` → `ArrowUp`、`key:other:1048577` → `ArrowUp`、`key:+`/`key:-` → `Equal`/`Minus`），并允许**读 v1 写 v2**：写盘时统一输出 v2；迁移产生的近似（如 `+` 落 `Equal`）经 `input.diagnostics()` 可定位。
4. **宿主只做类型转换**：`game_app::map_key` 读 `event.physical_key`（`PhysicalKey::Code`）；`game_view::preview_input_key` 读 egui 0.33 的 `physical_key`。`PREVIEW_KEYS` 删掉手写镜像，改为 `KeyCode::ALL.iter().filter_map(egui_key_for)` 生成，保证覆盖自动跟随引擎键表。
5. **单一来源 + 对齐测试**：`host/keymap.rs` 提供 `KeyCode ⇄ winit KeyCode ⇄ egui Key` 两张表；新增 `engine_key_table_covers_all_preview_keys`（编辑器侧）、`map_key_covers_all_key_codes`（game 侧）、`binding_text_round_trips_for_every_key_code`（引擎侧）。
6. **Lua 兼容**：`input.is_down("w")` 先按 `KeyCode` 文本解析，再按 v1 字符名字（`"w"`/`"1"`/`"up"`/`"f1"`）解析，**未知名报错**（`api_error`），不再静默落 `Other(0)`——与 `Binding::parse` 同严格度。改造前先 `grep` 统计仓库内全部 `input.is_down("...")` 字面量，确认都在解析表内。

**验收标准**：AZERTY 模拟用例（`physical=KeyW` + `logical="z"` 仍触发 `move_up`）；v1 设置文件读入后 `to_text()` 为 v2 且 `from_text` 往返等价；`jhyt_*` 全部 headless 回归逐项等价（示例测试里直接喂键的调用点同步为 `KeyCode`）。

**风险**：波及引擎 + 两个宿主 + Lua `parse_key` + 14 个 `jhyt_*` 示例的测试代码 + 玩家设置文件。缓解：v1 只读兼容 + 迁移诊断 + 一次 PR 完成（禁止分两次合入）。

### W2 手柄槽位、热插拔与震动

> **实现修正（批 2 落地后回写）**：`poll_all` 默认实现让既有后端零改动；活动槽位改为**粘性**
> 选择（显式指定 → 粘住当前 → 第一个已连接），比原计划的「默认只消费 slot 0」更贴近现状语义
> （原来就是「第一个已连接」）；`input.pad_*(slot)` 与本地双人**未落地**（`InputSnapshot` 仍是
> 一份按钮/轴状态，需要更大改动，列入待决策）。落地细节见 §11。

1. **后端保持 `poll()` 不变**（不动 `FakeBackend` 与 `host::gamepad` 既有 13 项测试），新增带默认实现的 `poll_all(&mut self) -> [Option<GamepadFrame>; 4]`（默认把 `poll()` 放在 slot 0，非 Windows 的 `UnsupportedBackend` 返回全 `None`）；`XInputBackend` 覆写为逐用户采样（含 `XInputGetState` 的 `ERROR_DEVICE_NOT_CONNECTED` 分类）。
2. **`GamepadPoller` 改 `last: [GamepadFrame; 4]`**，逐槽位维护状态（消除设备切换时的假释放）。**默认只消费 slot 0**，行为与今天逐帧等价；新增 `set_active_slot(slot)` / `active_slot()` 供本地双人，Lua 侧 `input.pad_*` 增加可选 `slot` 参数（缺省 0，既有调用不受影响）。
3. **震动**：`GamepadBackend::set_rumble(&mut self, slot: u8, low: f32, high: f32)`（默认空实现），`XInputBackend` 调 `XInputSetState`；poller 维护 `rumble_until: [Option<Instant>; 4]` 状态机（XInput 是"设置即持续"，必须有定时器归零），Lua 新增 `input.rumble(low, high, ms)`。
4. `docs/33` §6 的「不支持震动」条目随之更新。

**验收标准**：`FakeBackend` 支持多槽脚本帧；新增单测（槽位切换不产生假释放、断连只清该槽、`set_rumble` 调用记录与到期归零）；`jhyt_m20_gamepad` 增补双人/切换/震动章节。

### W3 轴边沿数字化 + 时间制重复 + 径向死区 + 设备判定

> **实现修正（批 1 落地后回写）**：连发**只对模拟量绑定**生效（数字键/DPad 按住仍是一次按下 = 一步，
> 保持 M20-08 语义，见 `jhyt_m20_gamepad` 验收）；「已按住但没有按下边沿」**不补步**（否则同一根
> 摇杆同时驱动 `move_*` 与 `ui_*` 时会双步，示例第 ⑹ 章暴露）；`nav_threshold` 作为**设备层轴判定
> 阈值**注入（`RuntimeScene` 每帧同步），因此该设置仍然生效。落地细节见 §10。

1. **轴滞回边沿放在 `GamepadPoller`**（跨帧状态本就归它管，且兼容编辑器"每帧重建快照"的既有测试）：以 `AXIS_DIGITAL_ON = 0.5` / `AXIS_DIGITAL_OFF = 0.4` 滞回，比较 `self.last.axes` 与 `frame.axes`，按下/松开边沿写入 `InputSnapshot` 新增的 `pressed_axes/released_axes: HashSet<(u8, AxisDirection)>`；`action_just_pressed/just_released` 的 `GamepadAxis` 分支改查它们（`core/input.rs:743`、`754`），`action_is_down`/`action_axis` 保持现有模拟语义不变（不改手感、不改既有断言）。
2. **时间制重复**：`ScriptState` 增 `action_repeat_state`（首按时间 + 上次重复时间，来自 `time` 逻辑帧时钟），新增 Lua `input.action_repeat(name)`（键盘与手柄同义）。`[input]` 段新增 `nav_delay_ms`/`nav_repeat_ms`（默认 350/90），旧 `delay_frames`/`repeat_frames` 保留**可读**并按 `×1000/60` 换算 + 诊断，写入用新键。`ui/input.lua` 的 `ui_step()` 与对话/商店/背包导航改调它（删 Lua 帧计数 16/8）。
3. **径向死区**：新增 `apply_stick_deadzone_radial(x, y, deadzone)`（模长 ≤ 死区归零，否则 `(mag-dz)/(1-dz)` 缩放且保持方向），`axes_from_raw_with` 的四个摇杆轴改用它；`GamepadDeadzone` 结构**不变**（仍是 `{stick, trigger}`），避免设置文件迁移；逐轴函数保留供单轴绑定与测试。
4. **设备判定下沉**：`InputSnapshot` 增 `last_device`（`Keyboard`/`Gamepad`），`key_event`/`mouse_event` 置键盘，poller 检测到按钮边沿或轴显著变化时置手柄；Lua 新增 `input.last_device()`。`ui/hints.lua` 的 `detect_device()`（每帧 36 动作扫描）删除，`M.device()` 改读引擎值。
