  键盘导航端到端与三宿主 golden 未测，见「未完成项」）

## 目标

把 UI 运行时从"只分发 click"补到可用闭环：hover/pressed/focus/click 路由与冒泡、`ButtonStates` 消费、
`UiBindings` resolve、`UiAnimation` 应用、`ScrollView` 裁剪与滚动、稳定 `UiKey`。

## 现状证据

- 事件只有 click 分支：`engine/crates/rustlua-ui/src/ui_events.rs:142`（`click_functions` 过滤 Click）。
- `UiAnimation` 只告警：`engine/crates/rustlua-scripting/src/script/scene_spawn.rs:532`。
- `ButtonStates`、`UiBindings` 无运行期消费方（全仓 grep 仅有定义与序列化）。
- 无裁剪/滚动/虚拟列表组件路径。

- `engine/crates/rustlua-ui/src/ui_events.rs`、`ui_layout.rs`、`ui_animation.rs`、`ui_bindings.rs`

## 交付项

1. **输入路由**：统一命中测试 → 捕获/冒泡；hover 进出、pressed 按下/抬起、focus 切换（Tab/Enter/Esc 最小集）。
2. **状态系统**：`ButtonStates` 的 normal/hover/pressed/disabled 由路由驱动；禁用节点不参与命中。
3. **绑定运行时**：`UiBindings` 单向/双向 resolve；源缺失用 `default`；每帧只在源变化时写目标。
4. **动画**：`UiAnimation` 轨道（入场/状态/提示）接入现有 player；与 `rustlua-animation` 的采样语义一致。
5. **裁剪与滚动**：`ScrollView` 裁剪矩形、内容尺寸、滚轮/拖动、越界回弹；虚拟列表留 M6。
6. **UiKey**：由 Spec 节点 key 编译成稳定标识，供 golden/工具定位；实体缺失时给出诊断而不是静默。

## 验收方式

- `cargo test -p rustlua-ui`；新增交互单测：命中顺序、冒泡、禁用、hover 往返、绑定双向、动画采样。
- 三宿主 golden：注入同一事件序列（hover→press→release→click），对比事件/状态/绘制序列。
- `scripts/verify/verify.ps1 -MvpOnly` 与既有 UI 屏黄金不回归；改前先跑一次留读数。

## 风险

- 交互改动影响所有现有 UI 屏：先建 golden 基线，再逐项改。
- 裁剪需要渲染器支持 scissor/裁剪矩形，三宿主实现路径不同；先桌面 + Web，微信单独验。
- 动画与现有 `AnimationPlayer` 的时钟/暂停语义要对齐，避免编辑器 Play 与运行时不一致。

### 2026-10-24：宿主接线（本批）

- **同一份几何**：`RuntimeScene::ui_hit_data` 成为唯一命中来源，`compute_click_targets`
  改为从它派生（`click_targets_from`）。点击矩形、hover 矩形、绘制矩形不再各算一套。
  文件：`engine/crates/engine/src/host/runtime_scene/mesh_ui.rs`。
- **交互树**：新增 `engine/crates/engine/src/host/runtime_scene/ui_input.rs`。
  按 `ui_scene_nodes.parent` 建立"最近的同类祖先"链，数据签名不变时不重建；
  key = 实体名（重名加槽位后缀，派发仍用原名）。
- **输入路由**：`ui_click_dispatch` 系统在开关打开时改走交互树：
  `pointer_move → 按下(pointer_down + activate) → 抬起(丢弃重复 click) → 滚轮`，
  派发阶段只取 Target/Bubble（捕获阶段仍产出给工具/测试，不重复调 Lua）。
  Click 沿用既有"按下即 click"契约。
- **事件派发**：`LuaRuntime::process_ui_event(name, event, functions)` 新增；
  Click 仍额外投实体 `on_interact`，行为与旧点击路径一致。
- **状态消费**：`ButtonStates` 此前**不进运行时世界**（只有编辑器读）。现在随场景 spawn
  为 `ButtonStateSet` 组件；交互树按 `disabled_state` 禁用节点，视觉状态写进
  `ui_visual_states`，`push_scene_ui_images` 按状态取 `ButtonStates` 的贴图覆盖
  （未启用交互/无覆盖时保留作者贴图，逐字节不变）。
- **键盘导航**：Tab/Shift+Tab/Enter/Esc 接到 `UiInteraction::key`，默认关闭
  （`set_ui_keyboard_nav`），避免 Tab/Enter 在玩法脚本里被 UI 焦点截胡。
- **默认关闭**：`set_ui_interaction_enabled(true)` 才切换路径。既有场景的契约是
  "只分发 click / 按下即 click / 所有重叠目标都派发"，直接改默认会动所有 UI 屏；
  开关关闭时调度器仍走 `process_ui_clicks`，逐字节不变。

### 2026-10-24：绑定 / 动画 / 滚动宿主侧收口（本批）

- **绑定运行时**（`engine/crates/engine/src/host/runtime_scene/ui_bindings.rs`）：
  `ui_bindings_resolve` 每步收集世界里所有 `UiBindings`（组件随场景 spawn 进世界），
  合并成 `BindingSet` 后 resolve；只在源变化时写目标（静止帧不覆盖手改值），源缺失走
  `default`，目标/组件缺失给诊断而不是 panic。落点：`text.text` → 场景 `Text`；
  `image.visible` → 隐藏名集合（绘制与命中同源跳过，不改作者颜色）；`progress.value` →
  同名 `ui.bar`（不存在时诊断，不凭空造条）。双向绑定经 `push_ui_binding` 写回源，单向
  写回报错。
- **动画发布**：`animation_player_advance` 采样 `AnimPath::UiAnimation(property)` 的标量，
  由宿主发布到视图模型 `anim.<实体名>.<属性>`（每帧整段覆盖 `anim.*`），绑定可像普通源
  一样消费；`scene_spawn.rs` 不再对 `UiAnimation.*` 告警。
- **`ScrollView` 宿主侧**：新增 `rustlua_ui::ui_scroll_view::ScrollView`（只有轴向，内容
  尺寸由布局树算）、`ScrollView` 组件 schema 与 spawn 接线。`ui_scroll.rs::apply_scroll_layout`
  在布局解算之后：算内容包围盒 → 建 `UiScroll`（轴/内容/视口）→ 夹偏移并写回 →
  平移子孙矩形 → 生成每个节点的裁剪矩形。滚轮/拖动由交互树自己的 `UiScroll` 平移；
  交互树拿到的是**扣回滚动位移**的内容空间矩形（`UiHitData::tree_rect`），避免平移两遍。
- **裁剪（无 scissor 的 CPU 路径）**：`SceneDraw` 没有裁剪字段，因此图像按可见子矩形
  裁 UV（九宫格逐格裁），文字按 6 顶点一组过滤字形（部分重叠整块取舍）；裁剪节点内的
  矢量文字退回 SDF/点阵路径。命中框按视口收窄，完全滚出的实体不进命中集/交互树。

## 未完成项 / 已知限制

- **键盘导航无端到端门**：只有纯模块测试；`set_ui_keyboard_nav(true)` 的实际浏览器/真机
  表现未测。
- **三宿主 golden 未跑**：注入同一事件序列对比事件/状态/绘制序列的计划未做（PC/Web/微信
  均为"未测"）；裁剪是三宿主共用同一份 CPU 网格（无 scissor 字段），但只在本机单测验过。
- **滚轮边沿按帧消费**：一次 `run_script_steps(n>1)` 里滚轮只在第一步生效（`finish_frame`
  清边沿，与引擎既有键鼠边沿语义一致）；宿主每渲染帧调一次即可。
- **拖动越界回弹被夹紧**：交互树有橡皮筋（0.35 系数），但宿主布局每帧把偏移夹回
  `[0, max]` 并写回，松手前的越界量下一帧就归位——没有弹簧动画。
- **滚动偏移不入交互树签名**：树在结构/矩形/事件变化时重建，滚动靠节点自身累计；内容变短
  时树内偏移要等下一次滚轮/拖动才夹回上限。
- **文字裁剪是整字形取舍**：部分压在视口边上的字形整块保留或丢掉；矢量文字在裁剪节点内
  退回 SDF/点阵（字形轮廓不逐段裁）。
- 交互树每步在签名变化时重建；签名计算本身每步 O(节点数) 且会序列化事件/状态串，
  UI 节点多的场景需要后续改成布局/世界修订号。
