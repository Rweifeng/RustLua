## 设计要点

1. **只换载体，不动几何**。`hud.prefab` 头部注释写得很清楚：行序 = 绘制序 = 实体槽位升序，
   且要复刻迁移前动态层的 id 字典序（`ScriptState` 是 `BTreeMap`，`mesh_ui.rs:239` 迭代 `.values()`），
   门 `covering_account` 的排序键依赖它。**换贴图不许改槽位号与行序**。
   → **本包违了这条一次，且是经用户裁定后违的**：slot2/slot3 对调（面板底在前、金轨在后）。
   理由与背书方式见 B 段第 4 条——这是本包唯一一处行序改动，也是唯一的"门量不到的画面变化"。
2. 特别注意注释里那条坑：`bar_fill` 必须排在 `bar_frame` **之前**（fill 先画、边框盖在填充上），
   换切图时若把 fill 也换成带底的九宫格，会盖死边框或反之。
3. `HudBox` 换成九宫格后，原来的 `color=…0.620` 半透明要保留 → 依赖 M64a 那条
   "实体层 Image 的 color 接 RGBA 单字段"（`95921e9`），已具备。
4. 状态片 `HudChip1..6` 是**彩色小方块**，换切图要确认换成什么：
   倾向换成 `ui_status_*` 图标（已有 7 张）而不是继续色块——色块读不出"中毒/流血"。
   → **裁定为不换图标**（见下），但换成了**可染色的九宫格小标签**，保留每行的分类色。

## 实现记录

### A 段：换哪张图是量出来的，不是挑出来的

1. **面板底 HudBox**（300×180）→ `common/ui_panel_main_9s.png` + `nine_slice=16,16,16,16`，
   **染色 0.080,0.090,0.120,**0.620** 原样保留**（经用户裁定）。
   这张就是弹窗那条达标的线本体，96×96 源、四边 16px → 300×180 的拉伸芯是 268×148，占 89%/82%，
   所以"换上去还是原来那个框"是字面成立的。
2. **HudRain（全屏雨罩，1280×720）保留 `__white__`**，是 `__white__` 从 10 减到 1 之后剩下的那一块。
   理由：它不是一个 UI 面板，是一层**全屏半透明染色**（`color=0.160,0.220,0.340,0.220`，a=0.22）。
   给它配任何带边框的切图都会往屏幕四周画出一条不该存在的 16px 木框；而九宫格在这种尺寸下
   四条边各只贡献 16px、其余全是拉伸芯，等价于白图但多一次采样。**已写进 `hud.prefab` 头部注释的保留清单。**
3. **HudChip1..6（6×16）与 HudAccent（300×3）素材库里没有能用的**——常规九宫格是 6px 边距
   （`ui_slot_9s` 系），塞进 6px 宽的矩形里拉伸芯是 **0×**，四边直接对撞。所以这两块**新生成**
   （经用户裁定），按 `pixel_kit` 的既有风格写进 `tools/gen_ui_art.py` 的 `slice_table()["hud"]`：
   - `hud_chip()`：**8×8**，`nine_slice=2,2,2,2`，芯 `#EDEDED`、上/左高光 `#FFFFFF`、
     下/右暗边 `#9E9E9E`、外框 INK900。目标 6×16 → 拉伸芯 **2×12**（每轴都 > 0，这就是 2 而不是 3 或 6）。
     底色近白是刻意的：**它是可染色的底**，六行分类色由 `color=` 相乘落上去。
   - `hud_accent()`：**16×3**，`nine_slice=4,4,1,1`，三行 `#E4C078`/`#C9A05A`/`#4A3628`
     ＋左右端 INK900 收口帽。目标 300×3 → 拉伸芯 **292×1**。竖向边距只能各 1px：源高就是 3。
   - 两张**整图 min alpha = 255**（无透明），中心实测分别 (237,237,237,255) / (201,160,90,255)。
   - `assets/art/ui/` 101 → **103** 张；`manifest.json` 重生成，`assets` 清单 **98** 条（含这 2 条）。

### C 段：门 `jhyt_m70_hud_prefab` 的三处改动

1. **① 捕获口径加两列**：`Kind::Panel` 的 body 从 `xywh,color` 变成
   `xywh,texture,nine_slice,color`（`Reading` 的 Panel 分支现在**要求**有 Image 组件，
   没有就点名报错），动态层的对照读数则固定写成 `,__white__,-,`。
   不换这一条，"画面真的换贴图了"在黄金表里是**不可见的**——这是本包最需要门看见的事。
2. **③ 的不透明判定改了语义**：`OPAQUE_TEXTURES` 加进 `ui_panel_main_9s.png` /
   `ui_hud_accent_9s.png` / `ui_hud_chip_9s.png`（按注释里的中心 RGBA 实测），同时
   `Reading::opaque()` 改成**贴图在表里 `且` 染色 alpha ≥ 0.99** 才算能盖人
   （色与图相乘才是落到帧上的不透明度）。
   于是面板底 0.620、色标 0.950 **仍然算盖不住人**，金轨 300×3 不透明但它里面没人 ⇒
   **"被盖住"读数换贴图前后都是 3 块，一条没多一条没少**。这是"换贴图没有偷偷改变遮挡事实"的证据。
3. **新增"导轨档"**（`submission_order()`，常量 `PANEL_TEXTURE`/`RAIL_TEXTURE`）：
   在真实 `mesh.draws` 分段里找面板底段与金轨段，**金轨必须提交在面板底之后**，
   否则报错点名"这一档是 M72-09 裁定要换的行序，现在实测是反的"；
   两段任一找不到也报错（"说明贴图没换上或换错了"），**不给它沉默通过的空间**。
   这档是把"黄金表量不到的行序变化"钉在实测上的唯一手段。
