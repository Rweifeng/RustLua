## 三个宿主各自要验什么

| 宿主 | 通道 | 已知坑 |
|---|---|---|
| 桌面 | 直接跑 `game --project`，整屏 `CopyFromScreen` | 编辑器窗口目验走 `gui_evidence`（`editor/src/gui_evidence.rs`），整屏才用 CopyFromScreen |
| 编辑器 Play | `gui_evidence` 真窗口 dump 11 张 PNG | evidence 不碰 `show_*` 开关，要临时 env 钩子；`main.scene` 无碰撞数据要换 `village.scene` |
| Web / 微信 | 活体走 `__RUSTLUA_LUA_BRIDGE`（探针必须 `tostring`）+ `getImageData` 差分；无头退 wechat harness | `ui-elements`/`drawn` **不计 prefab 实体**（对它瞎）；gate 要跑在 terser 后那份上；微信 harness 的 drawn 门不认 canvas 变换 |

## 本包要显式回答的问题

1. **像素中文在三个宿主都清晰吗**？微信真机是最低档设备，历史上连 `TextEncoder`/`WebAssembly`
   都缺过（`#950` 那批）。字体子集在打包链上会不会被裁掉、Web 宿主字体加载路径与桌面不同。
2. **多格图集在 WebGL 宿主的 UV 与采样对吗**？`FilterMode::Nearest` + 无 mipmap 是三宿主共同要求，
   但 wasm 侧纹理上传路径不同。
3. **装饰散布 + 多格建筑之后，真机帧率还够吗**？M72-05 只测了桌面前置。
   微信小游戏是本轮最大的性能未知数（实体数涨一个数量级 + 图集变大）。
4. **绘制顺序在两侧一致吗**？原生读 `mesh.draws` 下标、微信读假 ctx 的 `drawImage` src 序列；
   探针 Y 要围着相机中心取否则被剔除；世界 +y 朝上 ⇒ 遮挡是 y 越小越靠前
   （**写反了两边门都绿**，这是踩过的坑）。
