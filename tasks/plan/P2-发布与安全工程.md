## 1. 要解决的问题

发布会话目前只回答"包能不能跑"，不回答下面四个问题：

1. **这棵树的依赖有没有已知漏洞/许可证越界/来源越界？**（无 audit / deny 门）
2. **这个发布产物里到底装了什么？**（无 SBOM，无法给下游或事后审计）
3. **发布是不是只有"某台机器上的某个人"会做？**（无 tag 触发、无产物上传、无校验和）
4. **Windows 用户怎么确认 exe 没被换过？**（无 Authenticode 签名）
5. **6 条 vendored fork（5 条在 `[patch]`/lock，1 条 tool-only）离上游多远、补丁有没有悄悄漂移？**
   （只有补丁在位门，没有上游同步报告）
6. **工具链漂了怎么办？**（`stable` 浮动，CI 与本机可能不是同一个 rustc）

本任务把这六件事做成**可重复、可判红、可离线复核**的工程门，而不是写一份流程文档。

## 2. 范围与非目标

### 2.1 做

| # | 交付 | 判据（必须能一条命令复核） |
|---|---|---|
| ① | 工具链锁定 | `rust-toolchain.toml` 是精确 `X.Y.Z`；CI 与本地同版本；有门钉住 |
| ② | `cargo audit` | 固定版本工具 + `engine/.cargo/audit.toml`；CI 与本地同一入口 |
| ③ | `cargo deny` | `engine/deny.toml`（advisories / licenses / bans / sources）；CI 与本地同一入口 |
| ④ | SBOM | CycloneDX 1.5 JSON，含全部 workspace + registry 包、PURL、许可证、SHA-256；可离线复核 |
| ⑤ | 发布产物上传 + tag/release 自动化 | `v*` tag 触发；构建 PC 包与引擎包；上传 Actions artifact；创建 GitHub Release 并附资产与 `SHA256SUMS` |
| ⑥ | Windows 代码签名 | 有证书则签名 + 验证；无证书**显式跳过并告警**，绝不伪装成功；本地可自签自测 |
| ⑦ | 依赖 fork 上游同步报告 | 读 `[patch.crates-io]` + fork 清单，离线比对 vendored 树与 crates.io 同版本源码；可选在线查最新版；产出 Markdown/JSON 报告 |
| ⑧ | 文档与索引 | `docs/69`、`docs/README`、根 README、`docs/34`、`scripts/README`、CHANGELOG |

### 2.2 不做（明确边界）

- **不修依赖漏洞本身**：审计发现的问题只登记、分级、给处置建议；升级 wgpu/egui 等大依赖不在本任务。
- **不改业务代码、不碰在途工作树**：当前工作树有大量未提交的引擎/资源改动；本任务只新增
  CI/脚本/配置/文档，提交时只暂存本任务文件。
- **不做 WebGL/微信自动发布**：两条链路依赖 zig / 微信 appid / 平台上传凭据，继续手工；
  本任务只把 PC 与引擎绿色版纳入自动发布，并在文档写明另外两条为什么不在内。
- **不做公证（notarization）与 EV 证书采购**：代码签名只接 Authenticode；证书来源由仓库
  Secrets 提供，采购与 HSM 流程不在代码范围。
- **不引入第二套依赖解析器**：SBOM 与 fork 报告只读 `cargo metadata` / `Cargo.lock` / 本地
  registry 缓存，不重新实现 Cargo 的解析。
- **不删除任何现有门**：新门是加法；`verify.ps1` 的既有语义不变。

## 4. 实施顺序（每步独立可回滚）

### 第一步：工具链锁定（①）

- `engine/rust-toolchain.toml`：`channel = "1.97.1"`；保留 `components` 与 `profile = "minimal"`；
  注释写明"改版本必须同时改 `.github/workflows/*.yml` 的 `dtolnay/rust-toolchain@<版本>`，
  由 `check-toolchain-lock.ps1` 判红"。
- 新增 `scripts/verify/check-toolchain-lock.ps1`：
  - 解析 `engine/rust-toolchain.toml`，要求 `channel` 匹配 `^\d+\.\d+\.\d+$`；
  - 扫描 `.github/workflows/*.yml` 中所有 `dtolnay/rust-toolchain@X`，要求 `X == channel`
    （`@master` + `toolchain:` 形式也支持，但必须同值）；
  - 校验 `scripts/release/tools.json` 里安全工具版本是精确 semver；
  - 校验所有 workflow 的 `actions/setup-node` 版本与 `scripts/release/tools.json.node` 一致；
  - 失败逐条打印 `[FAIL]`，成功打印 `toolchain_lock_ok rust=… node=…`。
- CI 所有 job 的 `dtolnay/rust-toolchain@stable` 改成 `@1.97.1`（保留 components/targets）。

### 第二步：安全工具固定版本（②③ 的地基）

- 新增 `scripts/release/tools.json`（单一事实源）：
  ```json
  {
    "schema": 1,
    "rust": "1.97.1",
    "node": "20",
    "cargoAudit": "0.22.2",
    "cargoDeny": "0.20.2",
    "cargoCyclonedx": "0.5.9"
  }
  ```
- 新增 `scripts/release/install-security-tools.ps1`：按 `tools.json` 安装到 `CARGO_HOME/bin`
  （`cargo install --locked --version`），已装同版本则跳过；`-Check` 只读校验。
  本地/CI 共用；CI 也可用预编译 action，但**版本必须等于 tools.json**。
- 新增 `scripts/verify/check-security.ps1`：
  - `cargo audit --file engine/Cargo.lock`（在 `engine/` 下，读 `engine/.cargo/audit.toml`），
    输出 JSON 到 `artifacts/logs/security/audit-<stamp>.json`；
  - `cargo deny --manifest-path engine/Cargo.toml check`（读 `engine/deny.toml`），
    输出到 `artifacts/logs/security/deny-<stamp>.log`；
  - `-RequireTools` 时工具缺失 = exit 1；否则 exit 3 并打印 `security_blocked reason=tool_missing`；
  - 任一检查判红 = exit 1；全绿 = `security_ok audit=… deny=…`。
- `engine/.cargo/audit.toml`：只放**有到期日和理由**的 ignore；初始为空（先看真实读数）。
- `engine/deny.toml`：`advisories`（yanked=deny）、`licenses`（按实际依赖生成 allow 列表，
  含 `Unicode-3.0`/`Zlib`/`BSD-3-Clause`/`ISC`/`CC0-1.0`/`MPL-2.0` 等）、`bans`
  （wildcards=deny）、`sources`（只允许 crates.io 与 path）。

### 第三步：依赖 fork 上游同步报告（⑦，先于 SBOM，因为都依赖 metadata）

- 新增 `engine/vendor/FORKS.json`：每个 fork 一条
  `{ crate, path, baseVersion, upstreamRepo, upstreamRef, patched, notes }`；
  `baseVersion` 必须与 `vendor/<name>/Cargo.toml.orig` 的 `package.version`、
  `engine/Cargo.lock`、`[patch.crates-io]` 三方一致。
- 新增 `scripts/repo/fork-sync-report.mjs`（Node、零依赖）：
  - **离线模式（默认）**：读 `FORKS.json` + `Cargo.lock` + `Cargo.toml`；
    在 `$CARGO_HOME/registry/src/*` 找同名同版本的上游源码，逐文件 SHA-256 比对，
    输出 `added / modified / removed` 文件清单与行数统计；找不到上游源码时该 fork 标
    `upstream_source=missing`（显式，不绿色）。
  - **在线模式（`--online`）**：调 crates.io API 查每个 crate 最新稳定版，输出
    `base -> latest` 与 `major/minor/patch` 漂移；网络失败标 `unknown` 并 exit 3。
  - `--check`：只判结构不变量（清单/版本/补丁标记/上游源码存在），任何漂移 exit 1；
    `--write <路径>` 落 Markdown + JSON（默认 `artifacts/reports/fork-sync-<stamp>.md`）。
- 报告内容固定为：fork 版本、上游仓库/引用、补丁文件清单、相对上游的增删改、
  最近一次核对日期、建议动作（继续持有 / 升级 / 上游已修可删 patch）。
- 接入 `check-security.ps1`（离线 `--check`）与 CI 的 `security` job；在线报告只在
  `workflow_dispatch` 或月度定时任务里跑，避免网络抖动把常规门判红。

### 第四步：SBOM（④）

- 格式：**CycloneDX 1.5 JSON**；一个文件描述整个 workspace。
- 实现为 `scripts/release/gen-sbom.mjs`（Node、零依赖；`.ps1` 不便于 JSON 排序/哈希）：
  - 输入 `cargo metadata --format-version 1` + `engine/Cargo.lock`；可用 `--cargo-config` 走
    本地镜像；
  - `metadata.component`：`RustLua` + 版本（`engine/Cargo.toml` workspace version）
    + git commit + 工具链版本；
  - `components`：所有非 workspace 的 registry 包，`type=library`、`bom-ref=pkg:cargo/<name>@<version>`、
    `purl`、`licenses`（SPDX 表达式保留 `expression`）、`hashes`（取 Cargo.lock 的 `checksum`，SHA-256）；
    每个 fork 额外带 `cargo:source=vendored-fork` / `cargo:patched` / `cargo:fork-base-version`；
  - `dependencies`：按 `cargo metadata` 的 `resolve.nodes[].deps` 输出依赖边；
  - 输出排序稳定（name、version）；时间戳可用 `SOURCE_DATE_EPOCH` 固定；
  - `--check` 模式：重算并断言"每个 lock 包都在 SBOM 里、哈希一致、PURL 唯一、JSON 可解析、
    fork property 齐全"；缺输出文件直接判红。
- `cargo-cyclonedx 0.5.9` 的交叉件**不进发布门**：它按 crate 生成，范围不是整个 workspace；
  只在文档里留命令，作为独立实现的对照（见 docs/69 §5.3）。

### 第五步：签名（⑥）

- 新增 `scripts/release/sign-windows.ps1`：
  - 证书来源三选一：`-PfxPath` + `-PfxPassword`（或 `RUSTLUA_SIGN_PFX_PASSWORD`）、
    `-Thumbprint`（证书存储）、`-Certificate`（PS 对象，测试用）；
  - 优先 `signtool.exe`（PATH → Windows Kits 最新 x64），参数
    `/fd SHA256 /tr <RFC3161 URL> /td SHA256`；找不到时回退
    `Set-AuthenticodeSignature -TimestampServer`（并打印 `sign_tool=authenticode`）；
  - 签 `.exe`/`.dll`/`.msi`（递归目录），逐个验证；
  - `-DryRun` 只打印命令；`-SelfTest` 用 CurrentUser 自签证书签一个临时 exe 并验证，
    结束后删除证书与临时文件（本机可跑，作为真实证据）；
  - 无证书：`-RequireSignature` → exit 1；否则 exit 3 + `signing_skipped` 告警。
- Release workflow 在打包后调用；证书来自 Secrets：
  `WINDOWS_CERT_PFX_BASE64`、`WINDOWS_CERT_PASSWORD`；仓库变量
  `RUSTLUA_REQUIRE_SIGNING=1` 时缺失即判红。签名后重新生成 `SHA256SUMS`。

### 第六步：tag / release 自动化 + 产物上传（⑤）

- 实现为单个 Windows job（避免跨 job 传大包；签名、哈希、notes 在同一份字节上完成）：
  - 触发：`push: tags: ["v*"]` + `workflow_dispatch`（输入 tag 与 `dry_run`，默认 dry-run）；
  - `permissions: contents: write`；
  - 顺序：固定 Rust → `cargo build --release -p game -p editor -p assetc` → `gen-sbom.mjs`
    → `check-security.ps1 -RequireTools` → 安全门反例 → `package-engine.ps1 -SkipBuild`
    → `package.ps1 -SkipBuild` → 可选 `sign-windows.ps1` → 强制签名策略 → zip
    → `SHA256SUMS.txt` → `release-notes.ps1` → `actions/upload-artifact` → `gh release create`；
  - 无 `continue-on-error`；签名缺失按 `RUSTLUA_REQUIRE_SIGNING` 裁决。
- `release-notes.ps1`：优先取 `CHANGELOG.md` 的 `## v<version>` / `## <version>` 段；
  找不到时退到最新 `Unreleased` 并在 notes 里**明写**；两者都没有则只列构建证据与资产（不编造）。
- `tag-release.ps1`（本地）：校验版本与 `engine/Cargo.toml` 一致 / 工作树干净（`-AllowDirty` 才放）/
  tag 不存在 / CHANGELOG 缺段告警 → annotated tag；默认 dry-run，`-Apply` 只打本地，`-Push` 才推送。
  安全门不在这里重复跑：tag 触发的 `release.yml` 会跑；本地 dry-run 不要求工具/网络。
- 产物命名：`RustLua-<version>-win64.zip`、`RustLua-Engine-<version>-win64.zip`、
  `RustLua-<version>.cdx.json`、`SHA256SUMS.txt`。

## 6. 风险与回滚

| 风险 | 触发症状 | 处置 / 回滚 |
|---|---|---|
| 固定工具链导致 CI 镜像没有 1.97.1 | `rustup` 安装失败 | 保留 `@1.97.1` ref，失败即红并回退到上一个可用精确版本；**不允许改回 `stable` 掩盖** |
| cargo-audit 发现存量漏洞 | `security` job 红 | 先登记 `audit.toml`（带 `RUSTSEC` 编号、到期日、理由、负责人），再排升级；不删门 |
| cargo-deny 许可证列表过严 | 新依赖引入即红 | 只加**实际出现且合规**的 SPDX id；每次加必须能指到包名 |
| SBOM 与 Cargo.lock 漂移 | `-Check` 红 | 重新生成并审 diff；拒绝手改 SBOM |
| 签名证书泄露 | Secrets 泄露 | 立刻吊销/换证书；workflow 只从 Secrets 读，日志不打印 PFX/密码 |
| tag 误触发发布 | 推送了非发布 tag | workflow 先校验 tag 与 `engine/Cargo.toml` 版本一致；不通过即停 |
| 仓库无 Secrets 时 release 红 | 首次 tag 运行 | `RUSTLUA_REQUIRE_SIGNING` 未设置时只告警并产出未签名包；文档写明如何转成强制 |
| 在途工作树被误提交 | 提交混入无关改动 | 只 `git add` 本任务文件；提交前 `git diff --cached --stat` 复核 |

**踩坑与修正**

1. 新 `.ps1` 无 UTF-8 BOM：PowerShell 5.1 把中文注释按 ANSI 读，解析在 `}` 处报
   `Unexpected token '}'`；每次 `edit` 后都要重新加 BOM（`UTF8Encoding($true)`），再用 PS 5.1
   parser 复核。本批所有新脚本与改过的 `verify.ps1` 已加 BOM。
2. `cargo-audit` 0.22 的 `[yanked]` 只接受 `enabled`/`update_index`；写 `ignore` 会报
   `unknown field`，改为 `enabled = true`。
3. `cargo-deny` 的 ignore 只接受 `id`/`reason`，不接受 `expiry`；复核日期写进 `reason`。
4. `cargo-deny` 的 `db-path` 必须是包含 `advisory-db-<hash>` 的父目录；`db-urls = file://...`
   会报 `advisory database url doesn't have a domain name`。cargo-audit 的 `--db` 则要 RustSec
   仓库本身（`crates/` + `rust/`，没有 `advisories/`）。
5. audit 发现 `ruzstd 0.8.3` 的 RUSTSEC-2026-0344（解压炸弹），升 0.9.1；`StreamingDecoder`
   调用点 API 兼容，SBOM 重新生成。
6. 签名自测最初用 `whoami.exe`（已被 Microsoft 签名，双签名），篡改检测读到的是另一张证书；
   改用未签名的 `engine/target/debug/game.exe`，并在文件中段翻一个字节，得到 `HashMismatch`。
   翻尾部会命中证书表，得到 `NotSigned`，不是"篡改检测失败"。
7. `release-notes` 首次把 `## Unreleased ...` 原样带进发布页；已改为统一 `## 变更` 标题，
   并在退到 Unreleased 时明写原因。
8. `tag-release` 最初默认直接打 tag；已改为**默认 dry-run**，`-Apply` 本地、`-Push` 推送。
9. 干净 `CARGO_HOME` 不会下载被 `[patch.crates-io]` 替换的注册表源码，fork 门在 CI 会 BLOCKED。
   新增 `--fetch-missing` / `check-security -FetchForkUpstream`：按 `FORKS.json` 从 static.crates.io
   取 `.crate`，用 Node 内置 zlib 解 tar 到 `registry/src/fork-upstream`（拒绝绝对路径/`..`），只用于 diff。
   `wasm-bindgen-cli` 是 `inLock=false`、`patched=false` 的工具源码，标 `not-applicable`，不强制上游 diff。
