## 目标

`scripts/data/skills.lua` 现有 5 条招式（`strike`/`palm_gust`/`crescent_slash`/`iron_palm`/`leopard_step`），
**全部是伤害招式**——字段只有 `windup/active/range/width/hitstun/knockback`，没有位移、减伤或回复。
`docs/33` §6.1 的三行（追风步 = 位移 3 格 + 无敌 0.25 秒、守心诀 = 正面减伤 70%、回风掌）
现在挂在 `jhyt_m24_numeric_alignment` ⑤ 的 **`SKILL_ROWS_WITHOUT_DATA` 白名单**里
（该白名单的设计意图写在示例头注释 §3：新增一行而不补数据就会失败）。本任务把前两行从白名单里**删掉**。
另一条真缺口：`defense` 属性是**死键**——只出现在 `stats.lua:25,28-29`（`BASE_DEFAULTS.defense = 1`、
`STAT_KEYS/VALID_STATS`）和 `data/registry_check.lua:18`，`systems/combat.lua` 全文不读它，
所以防具/防御对结果零影响（已 grep 确认）。

## 实现要点

1. **位移走既有通路**：轻功用 `transform`/`physics.set_position`（Web/微信 harness 里
   `physics.set_position` 真搬人是已验证事实，见 `docs/34-质量门与发布清单.md:86`），
   **落点被墙要夹到可走格**——这正好是 `9277524`（WebGL 补固体格碰撞与 `tilemap.set_solid`）刚立的语义。
2. **无敌 0.25 秒 = 15 固定步**，全部数值在数据表里（docs/33 §6.1 与 §"坚定/轻功无敌"表），代码不写常量。
3. **减伤比例与防御值不要双重扣**：正面减伤（守心诀/格挡）与 `defense`（防具）是两条独立通路，
   先减防后乘比例还是相反，必须写进 docs/33 并让用例断言具体数字（"2+8=10"那种逐格比对口径）。
4. **白名单同步是验收的一部分**：删 `SKILL_ROWS_WITHOUT_DATA` 的两行 = 数据必须存在，否则
   `jhyt_m24_numeric_alignment` ⑤ 红。这条改动要单独一笔，红好定位。
5. **召唤要有上界**：Boss 召唤物数量、存活时长、死亡后不残留（`entity.destroy` 与 PersistId 清理），
   用例直接断言"场上敌人数量 ≤ N"。

- ② 与 M34-03 同改 `combat.lua`/`enemy.lua`；两条**串行**，或 04a 只做位移、04b 再进伤害公式。

  别只说"应该能跑"）。

## 验收方式

- `cargo run -q -p game --example jhyt_m34_skills`，章节至少：
  ① 追风步：消耗内力 15、位移 = 3 格（断言坐标差），贴墙时夹到可走格，期间 15 步不受伤害；
  ② 守心诀：正面命中减伤 70%（数值按 docs/33 表逐格断言），背面命中不减免；
  ③ 打坐回复 = docs/33 §3 的 +5 内力（m24 已锁这一格，走真实按键路径）；
  ④ 防御结算：给敌人 `damage` 固定值，穿/不穿防具两次结果差 = `defense`，且 `docs/33` 数值表被同步；
  ⑤ 山魈二阶段出现冲撞与召唤，场上敌人数量不越过上界；
  ⑥ **帧率无关**：同一输入序列在 30/60/120 FPS 下伤害与位移步数一致；
  ⑦ `jhyt_m24_numeric_alignment` ⑤ 的白名单里已无"追风步/守心诀"，①–⑧ 全绿。
- `scripts/verify.ps1 -MvpOnly` 全绿；`docs/18-lua-api.md` 若暴露新绑定则同步（本任务预期不新增引擎绑定）。
