# M16-04 农田网格与耕地状态

## 状态
DONE

## 类型
[引擎+玩法]

## 目标
用 Tilemap 元数据与视觉格落地耕地/浇水状态，可持久化；彻底移除硬编码 `soil_positions`。

## 背景
`main.lua` 用内存表 `tilled/watered` + 固定坐标判定耕地。缺口清单 2.4 要求网格化耕地，且每块耕地的状态要能存档（2.3）。

## 输入
- `tilemap.set_cell / set_meta / get_meta / set_solid`（18-lua-api.md）
- `map.state` 分地图持久化
- `engine/crates/engine/src/core/tilemap.rs`

## 不做什么
- 不做作物生长（M16-06）；
- 不做耕田机渲染升级；
- 不做任意位置可开垦判定规则调优（先沿用固定农田区块，判定数据化即可）。

## 依赖
M16-00

## 验收标准
1. 耕地状态存 Tilemap meta（`tilled=1` / `watered=1`），视觉格 `set_cell` 同步展示。
2. 场景重载后耕地与浇水状态从 `map.state` 恢复。
3. 代码中不再存在 `soil_positions` 硬编码；可开垦范围数据化。
4. 浇水视觉与状态一致（浇过水的格有明显区分）。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：锄一块地 → F1 存档 → 重载 → 耕地仍在且视觉正确。

## 风险
- Tilemap meta 语义混杂（耕地 vs 地图属性）→ 约定 key 前缀命名并写入数据文档；
- meta 持久化跨场景链路未打通 → 以 `map.state` 为唯一持久通道。
