# M16-11 数据表导入管线

## 状态
DONE

## 类型
[引擎+工程]

## 目标
建立 `game_farm/data/` 数据表约定：JSON schema 校验、`data.load` 缓存与报错、`item.define` 迁移到数据表。

## 背景
`data.load/reload/cache_clear` API 已具备但无校验；物品定义硬编码在 `main.lua`。此任务是所有数据驱动内容（作物/商店/NPC/钓鱼/配方）的共同地基，必须先行。

## 输入
- `data` API（18-lua-api.md）
- `engine/crates/engine/src/core/script.rs`
- `game_farm/scripts/main.lua`（待迁移的 item.define）

## 不做什么
- 不做内容编辑器（M19-01）；
- 不做本地化/掉落表/配方表（M18-09）；
- 不做数据热重载 UI。

## 依赖
M16-00

## 验收标准
1. `data/` 目录约定建立：`data/<domain>.json` + schema 声明；`data.load` 加载后校验，非法数据报错定位到文件与字段。
2. `item.define` 改为从 `data/items.json` 加载；`main.lua` 不再出现物品定义。
3. `reload` / `cache_clear` 后数据更新，运行中引用旧数据的模块安全（不崩、可重取）。
4. schema 校验有单测：坏字段 / 缺字段 / 类型错误分别报出定位信息。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
Rust 单测：坏数据报错定位；实机：改 items.json 重载生效。

## 风险
- schema 先于数据导致阻塞 → schema 从数据反推，先宽容后收紧；
- 运行中重载引用失效 → 定义「重载后所有取数走 `data.get`」约定。
