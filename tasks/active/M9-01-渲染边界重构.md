# M9-01 渲染边界重构

## 状态

READY

## 目标

将 `game_runner/src/main.rs`（2995 行）中渲染相关职责抽到独立模块，建立明确边界：GPU 资源、RenderPass（2D/3D 与 depth）、实例化与剔除数据缓冲、Camera/Depth 生命周期。重构只移动与组织代码，不改变渲染行为。

## 背景

M8 风险登记将「3D 改造堆积在 game_runner 单文件」标记为 P1。继续扩展 3D 能力（Gizmo、3D 游戏、更多 pass）之前，必须先把渲染职责从主入口拆分出来，否则后续改动会在单文件中继续堆积。

## 不做什么

- 不改变渲染行为、画面或性能；
- 不引入渲染图、多线程渲染或 GPU-driven indirect；
- 不修改场景格式、Lua API 或公共组件接口。

## 技术方案

将 `game_runner/src/main.rs`（2995 行）按渲染边界拆成 7 个文件，只搬代码不改行为：

```text
src/
├── main.rs          → 入口（85 行）：CLI 解析、项目校验、日志/崩溃处理、事件循环、mod 声明
├── cli.rs           → Arguments/parse_arguments/find_project_root/verify_project/extract_* + 6 个单测
├── shader.rs        → 3 段 WGSL：TEXTURED_SHADER / MESH3D_SHADER / SHADOW_SHADER
├── frame.rs         → 帧数据结构：OverlayVertex/SceneDraw/SceneMesh/FontAtlasPixels/
│                       Scene3d/Scene3dDrawable + 哨兵路径常量（__white__ 等）
├── renderer.rs      → Renderer + GPU 资源（pipeline/buffer/bind_group/depth/shadow_map）
│                       + 2D/3D pass + 剔除/实例化 + 纹理上传 + RenderOutcome
├── runtime_scene.rs → RuntimeScene：场景→帧数据桥（Lua 步进、2D 顶点/粒子/UI/图块、
│                       3D drawable 收集、sprite_vertex/screen_rect_ndc）
└── game_app.rs      → GameApp + winit 事件处理 + map_key/map_mouse_button + 调试 overlay
```

依赖方向：`cli/shader/frame` 为叶子；`renderer ← frame, shader`；`runtime_scene ← frame`；
`game_app ← renderer, runtime_scene, frame`；`main ← cli, game_app`。跨模块类型/方法加 `pub`，
共享帧类型的字段改为 `pub`（内部 crate，无外部 API 影响）。
