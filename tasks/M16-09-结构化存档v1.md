# M16-09 结构化存档 v1

## 状态
DONE

## 类型
[引擎+玩法]

## 目标
存档升级为结构化：`SaveVersion` + `on_migrate` 迁移钩子 + `WorldSnapshot`（玩家/背包/农田/作物/日历/商店资金），按槽位读写。

## 背景
`save` 现有 key-value + `blob_*` + `map.state`，无版本与迁移。缺口清单 2.3 要求日期时间、玩家、耕地、作物、箱子/机器、NPC 好感度、地图修改全部可存。本任务先覆盖垂直切片所需字段，实体持久化 ID 与 NPC 字段留到 M17。

## 输入
- `engine/crates/engine/src/core/save.rs`、`blob_*`、`map.state`
- M16-04 农田状态、M16-06 作物、M16-08 日历

## 不做什么
- 不做存档查看器/编辑器（M19-06）；
- 不做多槽位管理 UI（先单槽）；
- 不做 EntityPersistentId（M17-01）；
- 不做 NPC/任务等后续状态字段。

## 依赖
M16-04、M16-06、M16-08

## 验收标准
1. 存档带 `SaveVersion`；读到旧版本自动调用 Lua `on_migrate(from,to)`，迁移失败明确报错并保留原档。
2. `WorldSnapshot` 一次性序列化：日历（日/季节/年/时钟）、玩家（位置/背包/金钱/体力/工具）、每块耕地格、每株作物（品种/阶段/浇水）、商店资金。
3. F1 保存、F2 读档后实机状态完全一致（含耕地视觉与日历）。
4. 迁移单测：构造 v1 档 → 迁移到 v2 → 字段正确、无 panic。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：完整一天操作 → F1 → 改档或重载 → F2，逐项核对状态一致。

## 风险
- 格式演进破坏旧档 → 自本任务起强制版本号 + 迁移，禁止破坏性修改；
- blob 序列化 Lua 表边界情况（稀疏表）→ 单测覆盖。
