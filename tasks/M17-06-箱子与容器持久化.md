# M17-06 箱子与容器持久化

## 状态
BACKLOG

## 类型
[玩法]

## 目标
地图关联容器（箱子/仓库）内容跨存档、跨切图存续。

## 背景
缺口清单 2.3 要求箱子与机器状态可存；`container` API 已支持「实体关联背包」，本任务把容器与地图持久化绑定。

## 输入
- `container` API（18-lua-api.md）
- M17-01 地图持久化、M16-09 存档
- `data/maps.json`（容器出生点）

## 不做什么
- 不做加工机器（M18-05）；
- 不做容器 UI 大改（沿用 M16-07 拖拽）；
- 不做 NPC 私箱逻辑。

## 依赖
M17-01

## 验收标准
1. 地图上的箱子内容随地图状态持久化：切图往返、存档往返均保留。
2. 空箱子/新箱子有默认初始内容配置（数据驱动）。
3. 容器与实体解绑后（实体销毁）内容可迁移到 PersistentId 保存。
4. 容量/锁（后续玩法用）字段在数据定义中预留。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：往箱子放物品→切图→回来→物品在；F1/F2 往返一致。

## 风险
- 容器内容与地图 blob 体积 → 增量存储 + 内容数量上限；
- 切图竞态 → 保存钩子在切图前完成。
