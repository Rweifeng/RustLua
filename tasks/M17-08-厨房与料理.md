# M17-08 厨房与料理

## 状态
BACKLOG

## 类型
[玩法]

## 目标
料理配方数据（`data/recipes.json`）、厨房交互、做菜产出、食物恢复效果。

## 背景
缺口清单 3.x 提到「厨房」。料理是体力恢复（M18-00）的前置玩法，也是资源消耗的一个出口。

## 输入
- `data/recipes.json`（配方：输入物品/数量 → 输出物品）
- `inv` 扣原料加产物、`container`（厨房设备）
- `item` 定义（含 `use` 恢复效果，M16-07 已有使用钩子）

## 不做什么
- 不做料理动画；
- 不做料理品质随机；
- 不做食谱解锁/学习系统（先全解锁）。

## 依赖
M16-07

## 验收标准
1. 配方数据驱动：`recipes.json` 定义多道料理（输入→输出），改配方重载生效。
2. 在厨房设备前交互打开料理面板，按配方扣原料出成品。
3. 食物「使用」恢复体力（接入 M16-07 use 钩子），恢复量来自 item 定义。
4. 原料不足/成品栏满有明确提示，状态不回滚错乱。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：收集原料→厨房做菜→食用回体力；改配方重载生效。

## 风险
- 配方与物品耦合 → 配方只引用 item id，本体在 items.json；
- 做菜数量选择 UI → 沿用 M16-07 拆分交互。
