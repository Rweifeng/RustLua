# M20-01 CI 质量门扩展

## 状态
BACKLOG

## 类型
[工程]

## 目标
CI 触发范围覆盖 `game/**`、`docs/**`、`tasks/**`；门禁增加 `git diff --check`、`game_runner --check`、`editor --check`；Lua 脚本资源缺失从静默跳过改为失败。

## 背景
复盘结论 §7 指出：CI 只触发 `engine/**` 等，改 `game/**`/`docs/**`/`tasks/**` 不触发；缺少 `git diff --check` 等项目级门禁。农场玩法大量改动在 `game_farm/scripts/**` 与 `data/**`，必须纳入。

## 输入
- `.github/workflows/quality.yml`
- 复盘结论 §7 建议
- game_farm 脚本/数据

## 不做什么
- 不做编辑器 GUI/GPU 实机自动化（保留手动验收门）；
- 不做性能门禁（M20-02）；
- 不改单元测试覆盖面以外的 Rust 逻辑。

## 依赖
所有里程碑（在 M19 之后收口）

## 验收标准
1. 改 `game_farm/**`、`docs/**`、`tasks/**` 任一文件触发 CI，触发范围用空提交验证。
2. CI 新增 `git diff --check`，违反（EOF 空行等）即失败。
3. `game_runner --check` 与 `editor --check` 进入 CI；项目目录检查失败即红灯。
4. Lua 脚本/数据资源缺失测试不再静默跳过（缺失即失败）。
5. CI 全绿时 `cargo test --workspace --all-features` 与发布 build 均通过。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
CI 验证：空提交到 game_farm/docs 各触发一次，观察 job 触发与门禁结果。

## 风险
- 触发范围放宽导致 CI 排队 → 保持并行 job 上限；
- `--check` 门禁误报 → 先本地跑通再上 CI。

## AI 输出（实施后填写）
- 已完成内容、修改文件、验证结果、已知问题、下一步建议。
