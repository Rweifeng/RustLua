# M16-05 作物与种子数据表

## 状态
DONE

## 类型
[数据+玩法]

## 目标
`data/crops.json` 与 `data/seeds.json` 定义三种作物：生长阶段数、季节限制、售价、品质、掉落；种子作为物品定义接入。

## 背景
`main.lua` 里作物阶段 0~2 硬编码，番茄售价写死在收获代码里。缺口清单 2.4 要求季节限制、生长阶段、枯萎、品质、收获掉落全部数据驱动。

## 输入
- `data.load`（18-lua-api.md）
- `item.define` 物品定义
- M16-11 数据管线（schema 校验先行）

## 不做什么
- 不做生长逻辑（M16-06）；
- 不做掉落表多样性（M18-09）；
- 不做本地化（M18-09）。

## 依赖
M16-00、M16-11

## 验收标准
1. `data/crops.json` 定义 ≥3 种作物：阶段数、可生长季节、售价/品质区间、收获掉落物。
2. `data/seeds.json` 定义对应种子物品（`seed_*`），含买价/堆叠/图标。
3. 数据缺失或非法时启动报错（定位到文件与字段），不静默。
4. 作物数据可被 `farm.lua` 查询（`crop.def(name)` 之类），改 JSON 重载后生效。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
冒烟：`data.load("crops")` 返回合法表；构造坏 JSON 断言报错信息含文件名。

## 风险
- 数据与 schema 漂移 → M16-11 提供校验兜底；
- 作物品种过多超出阶段范围 → 先 3 种，结构留扩展位。
