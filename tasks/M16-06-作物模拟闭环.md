# M16-06 作物模拟闭环

## 状态
DONE

## 类型
[玩法]

## 目标
播种 → 生长 → 浇水 → 收获 → 枯萎 全闭环，基于 `calendar/day` 每日结算，产物进背包，格子清空。此任务是垂直切片的「心脏」。

## 背景
`main.lua` 的 sleep 里手动 `stage+1`，与 clock 未接轨。缺口清单 2.4 的核心闭环「移动→锄地→播种→浇水→睡觉→生长→收获→出售」在此形成。

## 输入
- M16-03 工具（ToolAction）、M16-04 格子、M16-05 数据、M16-08 calendar/day
- `inv` 物品入包

## 不做什么
- 不做品质/掉落表多样性（M18-09）；
- 不做过季之外的枯萎规则扩展；
- 不做多季节连续生长。

## 依赖
M16-03、M16-04、M16-05、M16-08

## 验收标准
1. 播种扣种子，格子记录品种与阶段；浇水当日有效。
2. 睡觉跨天后按「昨日是否浇水」推进生长阶段（数据驱动阶段数）。
3. 达到成熟可收获：产物进背包、格子清空、状态清除。
4. 季节不匹配或过季不浇水 → 枯萎，格子可重建。
5. 改 `crops.json` 阶段数后，重载生效、行为随之变化（验证数据驱动）。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：从播种到收获全流程记录操作序列复现；改数据重载验证。

## 风险
- 每日结算时机与 DayLifecycle 耦合 → 只在 `on_day_start` 结算一次，避免帧级重复；
- 枯萎判定与浇水状态先后顺序 → 定义明确顺序（先结算生长，再判定枯萎）。
