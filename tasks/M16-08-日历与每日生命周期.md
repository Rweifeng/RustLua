# M16-08 日历与每日生命周期

## 状态
DONE

## 类型
[引擎]

## 目标
新增 `calendar`（日期/季节/年/事件钩子）与 `day`（每日开始/结束、睡觉次日、体力恢复编排）Lua API，与现有 `GameClock` 分离。

## 背景
引擎已有 `GameClock` 与 `clock` 模块（now/rate/pause/add/set/sleep_to_morning）。缺口清单 2.2 要求日期、季节、年份、每日开始/结束事件、睡觉切换、体力恢复、商店营业时间、NPC 日程。本任务先解决「日期/季节/年 + 每日生命周期」这一地基，日程/营业时间留给 M17。

## 输入
- `engine/crates/engine/src/core/gameplay.rs`（GameClock）
- `clock` API（18-lua-api.md）

## 不做什么
- 不做节日/特殊日期（M17-09）；
- 不做天气（M17-07）；
- 不做 NPC 日程调度（M17-02）；
- 不做真实帧同步之外的复杂时间逻辑。

## 依赖
M16-00

## 验收标准
1. `calendar` API：`now` 返回 日/季节/年；`add`/`set` 跨季节、跨年推进正确。
2. `day` API：`sleep_to_next_day` 触发全局回调 `on_day_end` → 结算 → `on_day_start`，Lua 可订阅。
3. 体力恢复规则由 `day` 生命周期提供回调，具体恢复量由玩法配置（默认睡醒回满）。
4. 时间流速与真实帧分离（沿用 `clock.set_rate`）。
5. 季节对游戏影响留出钩子（如 `calendar.season()` 供作物判定），具体规则由玩法消费。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
Rust 单测：季节推进、跨年、`on_day_start/end` 回调顺序；实机：按 T 睡觉跨天回调触发。

## 风险
- 回调时机与作物结算（M16-06）耦合 → 统一以 `on_day_start` 为结算锚点；
- 季节/月/日映射规则自创 → 文档明确「春/夏/秋/冬 + 28 天/季」约定。
