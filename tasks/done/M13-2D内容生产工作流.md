# M13 2D 内容生产工作流

## 状态

ACCEPTED（按本次最小闭环范围归档，2026-08-25）；原始规划中的高级增强项未纳入本次验收，转后续迭代。

## 目标

按 [30-编辑器可靠性-2D工作流-资源系统闭环实施计划](../docs/30-编辑器可靠性-2D工作流-资源系统闭环实施计划.md)
收口 `M13-00` ~ `M13-06` 的当前可生产范围，让编辑器能够在不手改 scene / prefab 文件的前提下，完成
Sprite、Tilemap、Animation、2D 排序、Prefab、UI 的创建、编辑、保存、重开与运行。

## 背景

M12 归档后，项目的主要问题已经不是“有没有 2D 运行时能力”，而是这些能力是否真正进入编辑器日常生产链路：

- Sprite 组件格式过于松散，运行时和 Inspector 语义容易漂移；
- Tilemap 只能在 Inspector 里改数据，缺少 Scene View 直接绘制；
- 2D 排序、批量对齐、Prefab override 和 UI anchor 缺少可用工作流；
- Prefab 只有实例化，没有源编辑、写回和传播闭环；
- UI 仍偏运行时能力，编辑器里缺少最小布局生产路径。

因此本次 M13 归档的重点不是把所有高级编辑器功能一次做满，而是先形成一个真实可用的 2D 内容生产最小闭环。

## 不做什么

- 不把图集区域可视化选择、Tilemap 填充/吸管/矩形、动画事件标记、视图书签、UI 样式资源系统描述为已完成；
- 不重写场景格式、Prefab 格式或运行时渲染架构；
- 不把后续端到端样板项目验证（M14）提前并入本次归档。

## 技术方案

- **M13-00 2D 数据模型收敛**
  - 用 `SpriteComponent` 统一 `texture / size / pivot / tint / sorting`；
  - 运行时、Inspector、场景保存统一用同一套组件字符串。
- **M13-01 Sprite 编辑与批量创建**
  - 菜单快速创建 Sprite；
  - Inspector 结构化编辑 Sprite；
  - 多选等间距、排序 order 调整和按 Y 重排。
- **M13-02 Tilemap 编辑器**
  - Inspector 编辑 Tilemap 数据；
  - Scene View `TilePaint` 直接绘制 / 擦除并写回场景。
- **M13-03 2D 动画编辑器**
  - `AnimationStateMachine` 默认状态 + Clip 列表结构化编辑；
  - 运行时推进、Lua 查询与切换保持一致。
- **M13-04 2D 场景工具和排序**
  - Scene View Select / Move / Rotate / Scale / TilePaint；
  - 对齐、等间距、Sprite 排序工具进入工具栏。
- **M13-05 Prefab 与 2D 内容复用**
  - Prefab 创建、实例化、override 差异展示；
  - 重新应用源、写回源并更新实例；
  - 支持直接打开/保存 `.prefab` 形成最小编辑模式。
- **M13-06 2D UI 生产最小闭环**
  - Text / Image / Button 支持 `Screen / Canvas` 与 anchor；
  - 运行时点击命中与布局一致；
  - Inspector 可直接编辑 UI 布局字段。

## 验收标准

- Sprite / Tilemap / Animation / UI 不需手写组件字符串即可在编辑器里创建和保存；
- Tilemap 可在 Scene View 直接绘制并写回场景；
- 2D 多选对齐、等间距和 Sprite 排序可撤销；
- Prefab 支持实例化、override 可见、源编辑、重新应用和写回传播；
- UI 支持 `Canvas / Screen`、anchor、点击命中一致；
- `editor --check`、`game --check` 和相关自动化测试通过。
