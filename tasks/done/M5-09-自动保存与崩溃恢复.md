﻿# M5-09：自动保存与崩溃恢复

- 状态：PASS（恢复系统库层）
- 完成日期：2026-08-21
- 所属里程碑：M5 编辑器 MVP
- 前置任务：M5-02 项目与场景文档模型

## 1. 目标

为编辑器提供自动保存恢复快照、启动扫描、损坏校验、恢复/丢弃和正式保存后的清理能力。恢复失败时不得覆盖正式场景文件。

## 2. 实施内容

### 2.1 恢复文件管理

在 `engine/crates/editor/src/recovery.rs` 新增：

- `RecoveryManager`：管理恢复目录；
- `RecoveryCandidate`：表示可恢复场景；
- `RecoveryScan`：返回有效候选和无效文件问题；
- `RecoveryIssue`：提供损坏恢复文件的路径和可解释错误；
- `RecoveryError`：区分 I/O、场景格式和恢复元数据错误。

恢复文件保存以下信息：

- `recovery_version`：恢复文件格式版本；
- `timestamp_ns`：恢复快照时间；
- `original_path_hex`：原始场景路径；
- `checksum`：payload FNV-1a 校验值；
- `payload_hex`：经过十六进制编码的场景文本。

恢复内容写入独立 `.recovery` 文件，不直接触碰正式场景文件。

### 2.2 自动保存调度

新增 `AutoSaveController`：

- `on_edit`：dirty 文档编辑后立即生成恢复快照；
- `tick`：按配置间隔生成恢复快照；
- 非 dirty 文档不写恢复文件；
- 支持修改间隔和重置计时。

### 2.3 恢复与清理

`RecoveryManager` 支持：

- `scan`：扫描并按时间倒序排列有效恢复文件；
- `recover`：恢复为 dirty 的 `SceneDocument` 并保留原路径；
- `discard`：丢弃指定恢复文件；
- `clear_for` / `clear_all`：清理恢复文件；
- `save_document`：正式保存成功后清理对应恢复快照。

损坏、版本不匹配、校验失败或场景解析失败的恢复文件只进入 `invalid` 列表，不会替换正式文件。

### 2.4 公开 API

在 `engine/crates/editor/src/lib.rs` 导出：

```rust
AutoSaveController
RecoveryCandidate
RecoveryError
RecoveryIssue
RecoveryManager
RecoveryScan
```

## 3. 测试

新增测试覆盖：

- `autosave_scan_and_recover_preserves_original_path`
  - 自动保存、扫描、恢复、原始路径和 dirty 状态；
- `checksum_or_scene_corruption_is_reported_without_touching_main_file`
  - 恢复内容损坏时报告错误且正式场景内容保持不变；
- `version_mismatch_is_rejected_and_clear_for_removes_valid_snapshot`
  - 版本不兼容拒绝，成功快照可以清理；
- 自动保存调度器的编辑触发和时间间隔行为；
- 正式保存成功后恢复文件清理。
