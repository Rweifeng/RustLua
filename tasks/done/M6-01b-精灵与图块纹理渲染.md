# M6-01b：精灵与图块纹理渲染（替换调色板）

- 状态：ACCEPTED
- 验收日期：2026-08-21
- 所属里程碑：M6 2D 游戏能力与样板游戏
- 前置任务：M6-01 Tilemap（此任务补齐 M6-01 记录的"纹理图集未接入"限制）

## 目标

让精灵与图块真正从纹理资源采样渲染（含 UV 映射），替换此前硬编码的调色板纯色块。这是 M3 纹理/精灵能力到窗口运行时的补全，也是后续美术资产接入的地基。

## 背景

M6-00/01 的运行时渲染管线是纯色 overlay（`OverlayVertex{position,color}`，无纹理采样），精灵与图块颜色来自代码内 `TILE_PALETTE`。场景 Sprite 组件的纹理路径被忽略；图块无纹理概念。本任务把它们替换为真实纹理渲染。

## 输入

- `engine/crates/game_runner/src/main.rs`（渲染管线）
- `engine/crates/engine_core/src/sprite.rs`、`tilemap.rs`、`script.rs`
- `game/assets/`（纹理资源）、`game/scenes/main.scene`

## 不做什么

- 图集/精灵表动态打包（tileset 已按列 UV 采样，够用）
- 纹理过滤/混合高级选项（固定最近邻 + alpha 混合）
- 编辑器纹理预览

## 技术方案

1. **纹理采样管线**：`OverlayVertex` 增加 uv；WGSL 着色器 `textureSample(tex, samp, uv) * color`；bind group(0) 绑定纹理+采样器；移除纯色管线，性能 overlay 改用白色 1x1 纹理。
2. **纹理缓存**：`Renderer` 按路径加载 PNG（`TextureAsset::load_png`，sRGB）上传 GPU，`bind_group_for` 惰性加载去重；加载失败回退白色并 `tracing::warn`。
3. **按纹理分组绘制**：`SceneMesh{vertices, draws, paths}`——draw 携带纹理 id（0=白色，i>0=paths[i-1]），每 draw 绑定对应 bind group 后绘制子范围；图块仍同纹理同 layer 合批。
4. **精灵纹理**：`instantiate_scene` 为精灵插入 `SpriteAsset(path)`（来自场景 Sprite 组件值），tint 改白色；渲染器按 `SpriteAsset` 路径采样。
5. **图块纹理**：`Tilemap` 新增 `texture` 字段（默认 `assets/tileset.png`，序列化含 `texture=`），`tile_uv(column)` 按 tileset 列计算 UV，每列一种颜色。
6. **资产**：`scripts/gen-textures.ps1` 生成 `game/assets/tileset.png`（6 色 192x32）与 `player.png`（白色十字 32x32）。

## 修改范围

## 风险与应对

| 风险 | 应对 |
|---|---|
| 纹理加载失败导致花屏 | `bind_group_for` 回退白色并告警，进程不崩溃 |
| 多纹理破坏图块合批 | 每图块集同纹理同层合批，draw_ranges 验证远小于图块数 |
| wgpu 绑定布局不匹配 | 单 pipeline + 单 bind group layout，每 draw 仅换纹理 |
| 纹理上传泄漏 | 纹理由 bind group 持有引用，缓存 Vec 生命周期管理 |
