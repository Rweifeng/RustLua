# 任务：M27-01 资产拖放（OS 外部拖入 + 内部拖放收口）

- 任务 ID：M27-01
- 状态：实现完成，待验收（代码未提交）

## 目标

支持从 Windows 资源管理器把文件/文件夹拖入编辑器窗口完成导入或生成实体；
内部（面板间）拖放收口到与外部同一套 payload 协议，放置目标有明确高亮反馈。

## 影响文件

- `engine/crates/editor/src/main.rs`：`update()` 开头消费 `ctx.input(|i| i.raw.dropped_files)`
  （eframe 0.33 起外部文件以事件形式进入 `RawInput`，**必须在自己重开 input 前取走**）
- `engine/crates/editor/src/dnd.rs`（新建）：统一拖放载荷类型 `DropPayload`
  （`ExternalFiles(Vec<PathBuf>)` / `AssetRef(String)` / `EntityRef(SceneEntityId)`），
  及"文件 → 意图"判定（可导入资产后缀 vs 场景/prefab 文件 vs 非法）
- `import.rs` / `resource_ops.rs` / `resource_refresh.rs`：外部落文件复用现有导入管线，不新开写盘路径
- `panels/scene_view.rs`：`:57-87` 现有内部 drop 改接 `DropPayload`；新增消费外部事件分支
  （拖 prefab → 实例化，复用 `spawn_dropped_resource` `:2827`；拖图片 → 建 Image 实体）
- `panels/resource_browser.rs`：行 `ui.data` 挂 `AssetRef` payload 发起内部拖拽；接收
  `ExternalFiles` 到目录树节点 = 移动/复制到该文件夹（走 resource_ops，进 Undo）
- `panels/hierarchy.rs`：接收 `AssetRef`（prefab）→ 作为子节点实例化；节点重排拖拽若已有则改接 payload

## 实现要点

1. **Windows 路径细节**：`dropped_files[].path` 可能为 `Some(\\?\UNC verbatim)` 且带 `file_name`
   仅为提示——统一过 `crate::util::strip_verbatim_prefix`（`util.rs` 已有）；
   无 path 只有 `bytes` 的条目（浏览器来源）第一版直接拒绝并在状态栏说明。
2. **批量与原子性**：一次拖入 N 个文件按一个事件批次处理；导入失败逐文件报告、不中断其余；
   实体生成类落点（Scene/Hierarchy）只产生**恰好一条 Undo**（对齐 `scene_drag.rs` 提交层纪律）。
3. **Play 模式**：与现有纪律一致，Play 中一律拒绝并给出状态栏提示。
4. **视觉反馈**：hover 期间在目标区画 2px 高亮边框 + 角落显示将被执行的动作文案
   （"导入 3 个文件" / "实例化 prefab" / "移动到 assets/ui"）；非法目标画红色且松手无副作用。
5. **架构棘轮**：拖放事件采集在面板内，提交动作照旧发 typed action 给 command_router；
   `dnd.rs` 不持文档引用。

## 风险

- eframe 在某些 Windows 焦点路径下会丢 drop 事件（tao 已知问题）：验收含连拖 20 次的丢失率观察，
  超阈值再评估 `windows-sys` Shell 兜底（依赖已在 editor crate 里）。
- 文件夹拖入递归深度与符号链接：限制深度 ≤4，跳过 reparse point，防止拖 `C:\` 卡死。

## 实现记录（2026-10-02）

### 落点矩阵是一张表，不是一堆 if

`dnd::plan(&DragSource, DropZone) -> DropAction` 是唯一的判定处：**4 个来源 × 4 个落点**，
其中 9 格合法、7 格是 `DropAction::Reject(reason)`。面板不再自己猜"这里能收什么"，
只负责三件事：采集事件、把 `plan` 的结果画成角标、把动作交给提交层。
拒绝也走同一条路径（红框 + 原因文案 + 零副作用），所以"为什么不行"和"会做什么"是同一份数据。

类型收口是这次的前提：迁移前三条拖放链各自用 `String`（资源浏览器/工具栏）与
`SceneEntityId`（层级重排），而 egui 的 `dnd_drop_zone::<T, _>` **按 `T` 过滤**，
两条链互相看不见对方的载荷——"资产拖到层级行""资产拖到 Inspector 字段"在协议上就不可达。
统一成 `DropPayload::{Asset, Widget, Entity}` 后这些组合才存在。

| 落点 | 实现位置 | 释放判定 |
| --- | --- | --- |
| 2D/3D 画布 | `panels/scene_view.rs` | `dnd_drop_zone::<DropPayload, _>` |
| 层级行 | `panels/hierarchy.rs` | 同上（行内 `Frame::default()`，不改行高） |
| 资源浏览器 | `panels/resource_browser.rs::draw_resource_drop_zone` | `ui.interact(..).dnd_release_payload` |
| Inspector 资源引用字段行 | `panels/schema_inspector.rs::inspector_field_drop` | 同上 |

后两块**故意不用** `dnd_drop_zone`：它会包一层 `Frame` 改变行布局（Inspector 行高受门槛断言
管着），而它的释放半侧 `response.dnd_release_payload::<T>()` 就等于
"指针在内 && 本帧抬起 ⇒ `take_payload::<T>()`"，可以脱离 drop zone 单独用。
两处都只在**确实有拖拽进行时**才登记 hover 区——一个常年罩住内容的 hover actor 会抢走
下面控件的 tooltip 与右键命中。

### 系统拖放没有坐标，所以要一帧的生命周期

`egui::DroppedFile` 在 0.33 里**没有 `pos` 字段**，落点只能取事件到达那一帧的
`input.pointer.hover_pos()`。于是帧首 `begin_dnd_frame` 收下成 `ExternalDrop{files, position, ..}`，
四块互不重叠的区域各自 `claim_external_drop`（谁先包住指针谁认领，认领不到就放回），
帧末 `sweep_dnd_frame` 给没落点的拖放一句"释放位置不在可放置的面板内，未做任何改动"。
`hovered_files` 跨帧保留（`RawInput::take()` 只 clone 不搬走），所以高亮文案在**松手之前**
就能显示真实路径与真实动作，而不是等松手才知道。

### 批量与原子性

- `scene_ops::spawn_dropped_batch`：整批**一次** `history.execute`；需要读盘的
  （预制体解析、源纹理尺寸）在动手之前全读完，任一文件读不动就整批拒绝、文档零改动。
  单实体用 `set_single`、多实体用 `set_many` 全选中，Inspector 停在第一个。
- `import::import_external_files`：三条不变量——永不覆盖（重名让路 `x-1.png`）、
  工程内拖入不产生副本、部分失败逐条报告不影响成功项。复制完只**请求后台刷新**，不同步扫描。
- Play 锁定在**写盘之前**（`ingest_and_spawn` 先拒后拷；Inspector 在 Play 中仍然认领拖放，
  否则帧末扫尾会把原因误报成"落点不在面板内"）。

### 与原计划的差异

1. **资源浏览器"拖到目录节点 = 移动/复制到该文件夹"没做。** 移动/重命名都要重写全工程的引用，
   不该由一次松手触发；这一格现在是 `Reject("资产已在资源库中，拖到场景或属性面板才有动作")`，
   外部文件则一律按资源家族落进 `assets/<textures|models|prefabs|…>`（重名自动让路）。
2. `DropPayload` 没有 `ExternalFiles` 变体：系统拖放不经过 egui 的 DnD 存储，
   用外层 `DragSource::{Internal, External}` 合成同一张表。
3. `panels/scene_view.rs` 的 `spawn_dropped_resource` 已删除（三个 `spawn_*_from_drop`
   在 M27-01 之前就被 `spawn_dropped_batch` 取代，它是指向不存在函数的死代码）。
4. `resource_ops.rs` / `resource_refresh.rs` 未改动：入库复用 `refresh_resources()` 后台管线。

### 证据

- 单测：`dnd.rs` 8 条（矩阵逐格、文案非空、深度/总量上限、重名让路）、`scene_ops.rs` 3 条
  （两文件一条 Undo 且整体回退、一个读不动整批拒绝、Play 拒于碰文档之前）、
  `import.rs` 3 条（不覆盖、工程内不复制、目录跳过与未开项目拒绝）、
  `schema_inspector.rs` 1 条（引用字段落点的三种结算）。
- GUI smoke（`--gui-smoke`，35 项全绿）新增 6 条 dnd 用例：资产→画布、资产→层级行（子节点）、
  实体→画布（拒绝零改动 + 说明）、资产→资源浏览器（拒绝零改动 + 说明）、
  外部文件→资源浏览器入库、外部混合批次→画布（导入两个 + 建一个 + 一条 Undo + 重名让路）、
  无落点拖放的扫尾说明。注入方式是 `frame_with_payload`（内部载荷）与
  `frame_with_dropped_files`（`RawInput::dropped_files` + `PointerMoved` 同一帧）。
- `EditorApp::resource_browser_rect`：与 `scene_canvas_rect` 同一用途，给 smoke 一个真实落点。

## 未完成项 / 已知限制

- **真实窗口的连拖丢失率还没测**（计划里的风险项：tao 在个别焦点路径会丢 drop 事件）。
  需要人手在真窗口里连拖 20 次观察，超阈值再评估 `windows-sys` Shell 兜底 → 归 M27-03。
- 从浏览器拖入的"只有字节没有路径"条目：第一版拒绝并在状态栏计数说明（`bytes_only`），不落盘。
