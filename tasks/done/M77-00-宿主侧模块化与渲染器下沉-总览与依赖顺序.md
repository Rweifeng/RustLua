## M77-01：`rustlua-gpu` 独立成 crate（本批头刀）

**目标**：新建 workspace 成员 `rustlua-gpu`（wgpu 实现侧），把 `engine/src/host/renderer/`
全部源文件与测试搬进去；`engine` 的 `[dependencies]` 摘掉 `wgpu`（含 wasm/原生两段声明与
`webgl` 特性转发），变成真正的"纯组合根"。

**受益人（写清楚，防止为拆而拆）**：

- `gpu-web-probe`、离线基准工具、未来的专用渲染工具不再为拿渲染器拖上整个 engine；
  `cargo tree -p gpu-web-probe` 里 engine 出图。
- 渲染器的改动半径与 engine 组合根解耦：改 PBR/粒子不再让 game/game_web/editor 的 engine
  依赖侧重编（增量编译收益在 renderer 下游，不在 engine 下游）。
- M77-02 的 offscreen renderer 合并、M77-03 的 `ui_measure` 回收都以它为前提。

**买不到的部分**：wgpu 编译总时长不变，只是换了归属；engine 对 editor/game 仍是必要依赖
（运行时装配还住在里面）。

**开工前置盘点（先产清单，再动代码）**：

1. `host/renderer/` 引用了哪些 engine 内部项（`host/frame` 帧结构、`runtime_scene` 类型、
   `sample_project` 夹具、`shader*`、`profile_capture`）：逐项标注三档去向——
   **随渲染器一起搬**（只有 renderer 消费）、**下沉为参数/结构**（进 `rustlua-render` 或
   `rustlua-frame-abi`）、**留 engine 经入参传入**。
2. renderer 的 20 余条测试对 `sample_project.rs` 的依赖：夹具去向定为 `rustlua-gpu` 的
   dev 侧或共享 test-fixture，**不得**留在 engine 生产路径再反向被 dev 引用。
3. `engine/Cargo.toml` 里 wgpu 特性注释（webgl 按需开、wasm 最小后端两段声明、
   `web-time` 替换）整体迁到 `rustlua-gpu`，注释跟着代码走。

**步骤**（照 WP12"纯搬运"方法）：

1. 建 `crates/rustlua-gpu`，按行段"纯搬运"移入 `host/renderer/`，跨模块可见性从 `pub(super)`
   放宽到 `pub(crate)`/`pub`，最后 `cargo fmt`。
2. engine 侧调用点（`host/frame.rs`、`host/mod.rs`、`runtime_scene`、`web_surface`）改为依赖
   `rustlua-gpu`；**不留兼容 shim**（不做 `pub use` 门面再导出，调用点同批改完——章程对
   兼容层的口径：确需兼容要写明消费者、期限和退出条件，本批没有）。
3. `architecture_edges.rs`：`BUDGET` 增加 `rustlua-gpu` 行（正向依赖清单以盘点结果为准，
   上限 = `rustlua-render/animation/assets/camera/component-codec/ecs/infra/lua-api/math` +
   wgpu/winit 之外的最小集）；`COMPOSITION_ROOTS` 判定 rustlua-gpu 是库不是根，写进注释。
4. 宿主侧：editor/game/game_web/gpu-web-probe 对 wgpu 的直接声明逐个复核——能经
   `rustlua-gpu` 拿的收掉重复声明（game/Cargo.toml:16 与 editor/Cargo.toml:21 各有一条裸
   `wgpu = "27"`，先查真实用途再删，别顺手）。

**验收门**：

- `cargo tree -p engine -e normal` 对 `wgpu` **零命中**（新门：写进
  `architecture_edges.rs` 或 `check-decoupling.ps1`，二选一，同批立）。
- `cargo tree -p gpu-web-probe -e normal` 对 `engine` 零命中（若 04 判"做"则允许经
  runtime crate，否则经 rustlua-gpu 直连）。
- 全量门（含 `-Benchmarks`、`-Web`）与 HEAD 基线逐项对账；`game_web` wasm 产物字节数与
  发布包体积**必须复测并记录差值**（wgpu 归属移动不该改字节，改了就要归因）。
- **反面对照（新门必跑一次）**：给 `engine/Cargo.toml` 临时加回 `wgpu.workspace = true` →
  新门必须红；跑完恢复。

**风险**：

- shader 源字节恒等门（LF 制、autocrlf 会毁）：搬 `shaders/` 相关引用路径时同批检查
  `.gitattributes`。
- wasm 特性接缝：`webgl`/最小后端两段 target 声明搬错会让浏览器产物静默涨/缩——判成败

- GPU 时间戳/独显探针依赖 `host/renderer/timestamp*.rs` 与真设备：搬迁后先跑
  `cargo test -p rustlua-gpu -- --test-threads=1`（并发跑 host::renderer 组会假红，
  见项目记忆）。

### M77-02 裁定：**本批不做 crate 级拆分**（按判据的上限读数即不达标）

**读数（2026-10-24，主工作区 warm `target/`，全部只读测量，未建 worktree）**：

| 读数 | 值 | 口径 |
|---|---|---|
| `editor/src` 总行数 | 86,076（115 个 `.rs`） | `find crates/editor/src -name '*.rs' \| xargs wc -l` |
| `panels/` | 35,539 行 / 45 文件 = **41.3%** | 同上，限 `panels/` |
| 计划点名的 core+services 20 个模块 | 13,164 行 = **15.3%** | core 6,954（document 850、document_space 52、history 548、patch_history 528、command_router 1,362、schema_fields 1,844、schema_audit 420、selection 336、geometry 194、layout 820）+ services 6,210（import 724、resource_refresh 176、resource_ops 382、file_watcher 705、shader_watch 602、publish 795、play_sync 554、runtime_sync 609、play_control 667、preview_session 996）。这 20 个都是**单层 flat 文件**（无同名目录），拆分不涉及二级模块搬迁 |
| 拆分后仍留在 `editor` bin 的 | 37,373 行（43.4%）＋ panels 41.3% = **84.7%** | 上两行相减 |
| `cargo build -p editor`（touch `panels/inspector.rs`） | **19s** | 触发点选 panels，即拆分**唯一能受益**的场景 |
| `cargo build -p editor`（touch 全部 115 个文件） | **23s** | 整 crate 重编的上界——"少编一些文件"在这台机器上只值 4s |
| `cargo check -p editor`（同样 touch 一个文件） | 6s | 说明 19s 里约 **13s 是 codegen+link**，不是解析/搬运 |
| `cargo build -p editor`（touch `rustlua-input/src/input.rs`） | 33s | 依赖侧一动，input → gameplay → scripting → engine → editor 全链重编；叶子二进制重编的绝对下限（19s）与 crate 内部怎么切无关 |
| 谁依赖 `editor` | **0 个 crate** | `grep -rn 'editor' crates/*/Cargo.toml` 只命中注释行 |

**为什么这组读数足以判"不做"**：判据是"收益 ≥20% 才拆"，而计划口径自己给出的**可搬上限是
15.3% 的行数**（20 个模块 13,164 行 ÷ 86,076）。把行数直接当成编译耗时的线性上限已经是**最
乐观**假设——真实收益还要再扣两块：bin 仍要为它自己的 84.7% 做 codegen，而这个 crate 的重编

两份 metadata、并把跨 crate 的单态化推到 bin 侧。按最乐观假设算，19 秒的编辑周期最多省

### M77-04 裁定：**不做**（不建 `rustlua-runtime`）

复测口径（2026-10-24，M77-01 落地之后）：`crates/<宿主>/src|examples|tests` 里对
`RuntimeScene` / `runtime_scene::` / `apply_scene_environment` / `RuntimeSpawnedEntity` 的命中，
以及该宿主从 `engine::` 取用的**其它**模块——因为"拆出 runtime crate"的唯一收益是
**让某个宿主不再需要 `engine`**，只要它还用着 engine 的别的模块，收益就是 0。

| 候选 | 实际消费 runtime_scene 的符号 | 还从 `engine` 拿什么 | 是不是"去 engine"受益人 |
|---|---|---|---|

读数：真实"去 engine"消费者 **1 个**（判据要 ≥2）。

另外两条成本，独立看也足以否掉这次拆分：

1. `runtime_scene` 并不是"叶子"，它反向用了 engine 的另外三个模块——`crate::host::gamepad`
   13 处（手柄轮询要 `windows-sys` 目标依赖）、`crate::host::scene_extract` 1 处、
   `crate::host::scene_codecs` 1 处（`scene.rs:603` 的 `install()` 装表接缝）。独立成 crate
   就得把这三个一起搬：`gamepad` 是平台层、`scene_extract` 恰恰是 P1 ④ 才从 `rustlua-scene`
   搬进 engine 的（搬回一个 runtime crate 等于把那次收口再翻一遍），而 `scene_codecs::install()`
   本来就是"组合根把 codec 接给 scene"的接缝——把它搬进"库"里，装表的一方反而要不认识装表。
2. `docs/66` §M73 的衔接口径写死了"不另建第二套运行时装配"：`game_web` 的
   `EngineCore`/`EngineHost` 已经自成一套，它要的是**同一个** `RuntimeScene`，而不是一个
   只服务它一家的 crate。

**结论**：本批不动 `host/runtime_scene/`，不新建 crate，不预先起 M77-06 的号。

- 出现**第二个**非 engine 的运行时宿主（例：微信小游戏宿主要复用同一套逐帧装配，而不是

**两条判读护栏（写下来防止误读）**：

1. **`webgpu_available=true` 不等于 WebGPU 能用**。软件光栅那一趟顶层 `webgpu_available` 也是 `true`
   ——它就是 `js_sys::Reflect::has(navigator, "gpu")`（`lib.rs:65-68`，源码注释自己写着"只说明浏览器
   认识 WebGPU，不代表一定能拿到适配器"），但 `configs.auto.phase` 停在 `request_adapter` 并报"没有 adapter"。
   ⇒ 判 WebGPU 可用性必须读 `configs.auto` 的 `phase` / `error`，不能读顶层那个布尔。
2. **`auto` 档第二次 `requestDevice` 报 `adapter is "consumed"` 是探针的通道限制，不是设备失败**
   ——WebGPU 规定一个 adapter 只能建一个 device，而 `lib.rs:189-212` 在同一档里连着发
   `Limits::default()` 与 `downlevel_webgl2_defaults()` 两次请求。⇒ `auto` 只有**第一次**
   （default）的读数有效，它的 downlevel 档在真 WebGPU 上**量不到**；这条只有在真 adapter 上才看得见
   （软件光栅那趟 `auto` 停在 `request_adapter`，压根没走到第二次请求）。`gl_only` 那档不受影响
   （wgpu 的 GL 后端自己重取 adapter，两次请求都留下了读数）。

**这条买不到什么**：这台机器只给得出**集成显卡**（Iris Xe）这一张 adapter，独显/`PowerPreference::High`
路径仍未测；render 档 2d 上限 16384 与 backend 档设备侧 2048 **不是矛盾**——两档请求 limits 的形状不同：
render 档用 `downlevel_webgl2_defaults().using_resolution(adapter_limits)`（`lib.rs:641`），源码注释
（`lib.rs:633-635`）自己就写着"直接写 `downlevel_webgl2_defaults()` 会把 2D 上限从适配器的 8,192 压到
2,048，而字体图集按长到 4,096 设计——那是白白降级"，所以这一档 2d 跟着适配器到 16384；backend 档
`gl_only` 第二次请求发的是**裸** `downlevel_webgl2_defaults()`（`lib.rs:206-212`），wgpu 给这一档定的
2d 就是 2048。别把它们当成同一个数看；`cpu_frame_us` 一次采样不构成任何回归判据
（时间维度的门走 `compare-baseline.ps1`，见 §M77-02 验收读数）；微信小游戏宿主**依然没有读数**——
真机/开发者工具是另一条通道，不是浏览器标志能换出来的东西。
