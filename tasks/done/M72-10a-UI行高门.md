# 任务：M72-10a UI 行高门（Console 窄宽换行）

- 任务 ID：M72-10a（M72-10 的收口子任务，只修 `layout_row_height_gate`）
- 状态：**已完成并归档（2026-10-21）**
- 关联：M72-10 / `docs/55` §8 / `perf_baseline.rs` 的 `layout_row_height_gate`
- 依赖：无（不碰九宫格、换字、图标三项）

## 为什么单独开

`scripts/verify/verify.ps1` 的 editor performance baseline 修复前在
`layout_row_height_gate` 判红：

```text
console density=compact ppi=1 zoom=1 width=160:
行内容 30.00 > 行高 17.12（会重叠/裁字）
scenarios=31 failed=1
```

这条红不是 M74-03 引入的，但它把仓库总门挡住了。单独开此子任务，避免把 UI
布局修复混进 compute 任务。

## 根因（已定位）

`engine/crates/editor/src/panels/console.rs::draw_log_line` 的注释写的是
“单行行高固定：不换行（超出宽度裁切）”，实际却用了
`egui::TextWrapMode::Wrap`。窄面板（160/320pt）下日志行折成两行，内容高度
变成 30pt，超过 `console_row_height` 的 17.12pt。门测到的就是这个矛盾。

## 修法

1. `draw_log_line` 改为 `TextWrapMode::Truncate`，让行严格单行、超出裁切，
   与虚拟滚动的固定行高契约一致。原有“>80 字符才挂悬停提示”的行为保持不变
   （窄面板下短行被裁时没有 tooltip，这是已知限制，不在本门内扩大改动面）。
2. 加一条单元测试：窄宽度下 `draw_log_line` 的实际高度不超过
   `console_row_height`，防止以后把 `Truncate` 改回 `Wrap`。

## 验收

- `cargo test -p editor panels::console`：新增与既有行高测试全绿。
- `cargo run -p editor -- --perf-baseline --perf-report <tmp>`：
  `scenarios=31 failed=0 result=OK`，`layout_row_height_gate` 为 ok。
- `cargo clippy -p editor --all-targets -- -D warnings`。
- 再跑完整 `scripts/verify/verify.ps1`，总门不再停在行高门。

## 明确不做

- 不处理 M72-10 的九宫格边距、全 UI 换字、图标画质三项。
- 不改 Hierarchy 门（它当前已通过）；只修 Console 的换行模式。
- 不调整 `layout_row_height_gate` 的判据来“绕过”红门。
