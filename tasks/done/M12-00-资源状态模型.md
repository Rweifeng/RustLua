# M12-00 资源状态模型统一

## 状态

ACCEPTED（代码/自动化/实机验证，2026-08-25）；编辑器后台导入的 GUI 视觉呈现与进度窗取消点击仍待负责人实机复核（见 M12-01）。

## 目标

统一资源类型与生命周期状态模型：删除编辑器私有 `ResourceKind`，落地 engine 级 `ResourceKind`（9 族）；用 `ResourceState`（6 持久化 + 3 瞬态）替换旧 `ImportStatus`（4 态）；资源数据库升级 Schema v2（12 列 TSV），自动迁移 v1；`register` 修复版本漂移；`reconcile` 依据磁盘 mtime 驱动状态迁移；`content_hash` 与 `last_modified` 分离（hash 管缓存复用、mtime 管变更检测）。

## 背景

M11 之前资源状态只有 4 态 `ImportStatus`，且 `assetc::import` 从不回写 DB → 状态永远是 registered（存储漂移）；编辑器与引擎各有一套类型枚举；importer_version 双源不一致；register 重复注册不刷新版本。M12 阶段 1 第一步统一模型，为 Importer 注册与增量导入打基础。

## 技术方案

- 新增 `engine/src/core/resource_kind.rs`：`ResourceKind` 9 变体（Texture/Audio/LuaScript/Scene/Prefab/Atlas/Model/Font/Other），`from_path`（永不 Err）/`label`（中文）/`token`（持久化）/`parse`，`Hash` derive；
- `ResourceState`：`Discovered/Ready/ImportFailed/Stale/Missing/Orphaned`（持久化）+ `ImportQueued/Importing/Removed`（瞬态），`is_durable()` 区分，save 对瞬态写 `durable_fallback()`；
- `AssetRecord` 新增 kind/content_hash/last_modified/last_success/last_error_at；DB v2 头 `# rustlua-resource-db-v2`，12 列；
- `open_recoverable`：损坏库改名 `.corrupt-<ts>` 返回空库；
- `register` 已存在路径也刷新 kind/version（修复版本漂移）；
- 拆 `mark_ready(id, cache_path, content_hash)` / `mark_failed(id, error)`；
- `reconcile`：mtime 变更→Stale、路径消失→Missing、移出扫描根→Orphaned、恢复→Ready/Discovered；Windows 反斜杠扫描路径归一化对齐 register 正斜杠键。
