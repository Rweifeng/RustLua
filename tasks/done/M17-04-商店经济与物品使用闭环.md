## 目标
补齐金币、购买、出售、物品使用、商店营业时间和库存刷新的最小经济循环，并接入背包与任务奖励。

## 风险

- 交易必须原子执行，金币、库存和背包任一条件失败都不能产生半完成状态。
- 背包满、余额不足、商店未营业要有明确反馈。
- 物品使用效果要与存档快照一致，不能只删除物品而不应用效果。

## 实现记录

- **引擎能力零改动（验收项①）**：引擎侧已提供 `item.define`/`inv.*`/`ui.*`/`clock.now`/`interaction` 所需能力，本任务未修改任何 Rust 核心代码。新增一座商店 = 在 `data/shops.lua` 加一条记录；新增一件可售/可使用物品 = 在 `data/items.lua` 加 `buy`/`sell`/`use` 字段。
- **`data/shops.lua` 纯数据注册表**：`zhao_stall`（云泽村·货摊，店主 `npc_zhao_tiesuanpan`，地点 `village_stall`，`hours={open=480, close=1080}`）；`stock`（`seed_rice` 12/限购 10、`seed_lingzhi` 25/限购 5、`heal_pill` 60/限购 3）、`buys={"rice","lingzhi"}`。价格对齐设计案 §5.2。
- **套利阻断**：`stock`（种子/消耗品）与 `buys`（收获物）按物品互斥，`validate_all` 对「同一物品既在售又收购」报告 `与在售商品重复（可套利）`。故本店只卖种子/药、只收收获物，价格方向天然不可套利。
- **原子购买（硬风险①）**：`shop.buy` 顺序为「未知商店 → 数量正数 → 营业中 → 商品在售 → 每日限购 → 余额充足 → `inv.add`」，以 `inv.add` 返回的 **leftover** 判定容量：`leftover > 0` 时把已加入的部分 `inv.remove` **回滚**并返回 `full`。任何一步失败都在扣款前返回，金币/背包不变（无半完成状态）。
- **原子出售（硬风险①）**：`shop.sell` 顺序为「未知商店 → 数量正数 → 营业中 → 本店收购 → `sell` 价 > 0 → 持有足够 → `inv.remove`」，以 `inv.remove` 的**实际移除数**校验：若与请求数不等则把已移除部分 `inv.add` **回滚**并返回 `not_enough`。
- **明确反馈（硬风险②）**：`M.buy`/`M.sell` 统一返回 `(ok, reason)`，reason 覆盖 `unknown_shop`/`bad_count`/`closed`/`not_sold`/`not_bought`/`limit`/`poor`/`full`/`not_enough`；面板把这些映射为中文提示（`REASON_TEXT`），店主交互在未营业时 `can_interact` 失败并给出 `未营业` 提示（`state.last_action == "closed"`，不进入面板）。
- **营业时间**：`M.is_open` 以 `clock.now().minute_of_day` 落在左闭右开窗口 `[open, close)` 判定；缺省 `hours` 视为全天；`close <= open`（含跨午夜）在加载期校验失败。赵铁算盘的货摊窗口与其日程（`480..1080` @ `village_stall`）一致。
- **每日库存刷新**：`used[shop][item]` 记录当日已购数量，`M.stock()` 派生出 `remaining = limit - used`；`M.on_day_start()` 清零（由 `main.on_day_start` 调用），因此每日限购按「游戏日」而非「现实时间」刷新。
- **物品使用（硬风险③）**：`inventory.M.use` 改为「物品存在 → 读效果 → 应用效果 → 确认确实生效 → 消耗 1 个」。效果来自 Lua 侧 `data.items[id].use`（`energy`/`inner_power`，上下限夹取到 100）；**引擎 `item.define` 会忽略未知字段，故不能从 `item.def` 回读 `use`**。无 `use` 字段（种子/收获物/工具）或效果已满（达到上限）时返回 `no_effect` 且**不消耗**物品，绝不出现「只删物品不生效」。效果写入 `state.energy`/`state.inner_power`，与 `state.capture()` 快照一致，随存档恢复。
- **商店 UI（纯键盘）**：`shp:*` 动态 id；`E` 交互开面板并进入 `Shop` 模式，数字键 `1..9` 选择行、`F` 切换购买/出售页、`+`/`-` 调整数量、`空格` 确认、`Esc` 关闭并复位 `Playing`。出售页只列出「本店收购且背包持有 > 0」的物品。场景切换会清空动态 UI，故每次操作后整体重绘（`M.render` 幂等）。
- **交互优先级**：`shop_keeper`（priority=20）> `dialogue_npc`（10）> `farm`（0），故店主旁同时存在对话与商店目标时优先开店。
- **加载期校验（硬风险①）**：`shop.validate_all` 校验注册表非空、`id` 一致、`name`、`keeper` 引用 NPC、`place` 引用地点、`hours` 边界、`stock` 非空且物品存在/单价正数/无重复上架/`limit` 正数、`buys` 非空且物品存在/`sell` 正数/不与在售重复。由 `main.validate_content()` 在 boot 时调用，issues 逐条 `log.warn`。
- **存档**：`shop.capture`/`restore` 持久化 `used`（当日限购计数，仅保留 > 0 项），经 `save_manager.register("shop", ...)` 接入；`main.new_game` 调 `shop.reset()` 清态，`enter_playable_map` 调 `shop.ensure_target()` + `shop.close_ui()`。
- **物品定义字段**：`item` API 的 `define` 仅消费 `name/description/kind/texture/stack/buy/sell`，`use` 为 Lua 侧扩展字段（被引擎忽略，仅供 `inventory.use` 读取）。
