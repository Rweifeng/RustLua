# M14-01 端到端编辑器工作流

## 状态

PHASE ARCHIVED（自动化基线已完成，GUI 实机流转待继续）。

## 目标

围绕 `game_test_2d_production/` 跑通 `M14` 的端到端工作流主链，并把能稳定自动化的部分先固化为回归：

- 样板工程可被 `assetc`、`editor`、`engine runtime` 长期作为真实样本使用；
- 真实场景 / Prefab / 打包链路具备自动化样板回归；
- 为后续 GUI 级验收提供稳定底座，避免只靠一次性手工验证。

## 当前进展

- 已完成：
  - `assetc`：新增样板工程回归，覆盖 `import`、`check_dependencies`、`package`；
  - `editor`：新增样板场景 / Prefab 文档打开与保存 roundtrip 回归，并补上基于真实样板场景的 `PlaySession start/stop` 隔离回归；
  - `editor interaction`：新增样板 Prefab 拖入、重新应用源 Prefab、写回源 Prefab 回归，直接覆盖一段更接近 GUI 的编辑器工作流；
  - `editor interaction`：新增样板 `TilePaint -> 保存 -> 重开` 回归，覆盖 Tilemap 绘制与场景持久化主链；
  - `editor interaction`：新增样板动画 Inspector 编辑、UI Text/Button 调整并重开回归；
  - `game view`：新增样板 `Play` 启动成功回归，以及 `Play/Stop` 停止侧回归，覆盖预览创建、视图切换、编辑快照恢复、输入状态清空；
  - `game view`：新增 `bridge_preview_input` 回归，覆盖 Game 视图键鼠与滚轮输入到运行时输入快照的映射；
  - `engine`：新增样板菜单场景 UI 实例化、生产场景运行时实例化回归；
  - `engine script`：新增真实 `main.lua` 回归，覆盖菜单 update、开始按钮进生产场景、F1 存档、F4 返回菜单；
  - 修复样板脚本点击分发：`on_click(name)` 使用实体名而非按钮 label，保证菜单/返回菜单按钮在真实运行时生效；
  - 修复 Prefab 写回源流程的实体 ID 归一化问题，避免样板实例使用场景内实体 ID 时被误判为“结构不一致”；
  - 全量验证：`cargo fmt --all`、`cargo test --workspace --all-features` 通过。
- 待继续：
  - 用带 GPU 的编辑器实机走一遍 Play 启动预览与 Game 视图交互链；
  - 形成 `M14-01` 最终人工验收证据。
