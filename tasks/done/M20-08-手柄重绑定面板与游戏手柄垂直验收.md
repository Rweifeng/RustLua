## 目标

把动作映射变成可交付给玩家的能力：编辑器内提供可视化重绑定与死区配置，样板游戏 `game_jhyt` 从「物理键直读」迁移到命名动作，并用手柄把移动/交互/战斗/背包/对话/商店/暂停全流程走通。

## 方案要点

1. **编辑器面板**：
   - 按动作列出全部绑定文本（`Binding::to_text`），支持「点击 → 捕获下一次输入」的改绑，捕获窗口内同时识别键盘与手柄（手柄按钮与轴方向都要能捕获）；
   - 冲突提示：同一物理输入重复绑定到不同动作时高亮并给出可读诊断（沿用 `ActionMapError::DuplicateBinding`）；
   - 死区配置：左摇杆/扳机死区滑条，写入设置文件；
   - 「恢复默认」= `ActionMap::with_defaults()`，需二次确认；
   - 保存前校验，写入失败给出明确错误，不静默丢失。
2. **game_jhyt 迁移**：
   - 移动改为 `input.action_axis("move_left","move_right")` / `("move_down","move_up")`，保持速度与归一化逻辑不变；
   - 交互/攻击/武学/送礼/建造/拆除/升级/睡眠/修炼/背包/暂停全部改走 `input.action_pressed(...)`；
   - 对话与商店的选项选择继续支持数字键，手柄侧以 DPad/摇杆 + 确认/取消动作驱动（需要 UI 焦点导航配合，复用 M20-07 的 `FocusRing`）；
   - **兼容性硬要求**：迁移后键盘操作与现状逐项等价，`jhyt_m17*` / `jhyt_m18*` 全部 headless 回归继续通过；若 headless 用例直接喂物理键，动作层的默认绑定必须让它等价通过。
3. **可复现验收脚本**：沿用工程既有 headless 范式（`engine/crates/game/examples/jhyt_*.rs`）新增 `jhyt_m20_gamepad.rs`，用 `FakeGamepad`（M20-06 提供）在无真实设备的情况下驱动手柄事件序列，覆盖：
   - 手柄左摇杆移动与朝向；
   - A 交互（农田/建筑/出口）、B 取消、肩键切换背包/暂停；
   - 对话/商店手柄导航与确认；
   - 战斗中手柄普攻/武学、战败后重开；
   - 一句话总结：headless 能证明「动作层 ↔ 玩法」正确，真实手柄一次实机确认「设备 ↔ 动作层」正确（M20-06 已覆盖设备层）。
4. **文档**：`docs/18-lua-api.md` 增补动作 API 与默认绑定表；使用手册写清「如何改键、如何接手柄、支持哪些手柄、死区怎么调」。

## 风险

- **headless 回归破坏是最大风险**：`input.lua` 是 `jhyt` 全部输入的唯一入口，任何语义偏差会同时打挂 M16/M17/M18 的验收脚本；迁移必须逐动作对照，先加等价性测试再改实现。
- 编辑器 `project_settings.rs` 已承载字体/渲染模式等配置，新增输入配置需保持既有保序读改写与「字体变化触发重建」等既有副作用不被破坏。
- 捕获式改绑容易与编辑器自身的快捷键（egui 面板快捷键、F 键等）冲突，需要一个明确的「捕获模式」隔离层。
- 手柄轴捕获可能抖动（摇杆回中漂移），需一次性去抖与明确的确认动作。
- 真实手柄型号差异（Xbox/PS/Switch）会影响按钮编号；若实机发现编号不符，只能按 gilrs 映射数据库记录限制，不做设备专有分支。

## 验收方式

- `cargo test -p editor`：面板读写的纯逻辑测试（改绑、冲突、恢复默认、死区写入往返）。
- `cargo run -p game --example jhyt_m20_gamepad`：headless 手柄验收全绿，并输出逐场景断言结果。
- 回归：`cargo test -p game`（含 `jhyt_m17*` / `jhyt_m18*`）、`cargo run -p game --example jhyt_smoke` 全绿。
- 手工步骤（必须真机执行一次并留存日志）：
  1. 编辑器打开 `examples/game_jhyt`，在项目设置里把手柄 A 绑定到交互、X 绑定到普攻；
  2. Play 模式与独立 game 运行时各跑一次：左摇杆移动、A 交互、X 攻击、肩键开背包/暂停、对话与商店用手柄选择确认、Esc/B 关闭；
  3. 拔插手柄各一次，确认不粘键、不崩溃、焦点回到键鼠后仍可操作。
- `scripts/verify.ps1 -Mvp` 通过。
