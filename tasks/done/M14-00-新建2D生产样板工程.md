# M14-00 新建 2D 生产样板工程

## 状态

ACCEPTED，2026-08-25。

## 目标

创建独立的 `game_test_2d_production/` 样板工程，作为 `M14` 端到端验证的固定样板：

- 提供主菜单、100x100 Tilemap、玩家三态动画、两种敌人 Prefab、10 个拾取物、HUD、BGM/音效、Lua 玩法与存档；
- 保持为独立游戏项目结构，可直接被 `editor --check`、`game --check`、`assetc package` 使用；
- 为后续 `M14-01 ~ M14-04` 的编辑器工作流、断链修复、Play/Stop、发布回归提供稳定输入。

## 输入

- `docs/30-编辑器可靠性-2D工作流-资源系统闭环实施计划.md`
- `game_test/` 现有 2D 资源与 Lua 玩法脚本
- `engine/crates/editor`、`engine/crates/assetc`、`engine/crates/game`

## 输出

- 新工程：`game_test_2d_production/`
- Prefab：`assets/prefabs/slime_green.prefab`、`assets/prefabs/slime_red.prefab`
- 场景：`scenes/menu.scene`、`scenes/production.scene`
- Lua：`scripts/main.lua`、`menu.lua`、`gameplay.lua`、`player.lua`、`enemies.lua`、`coins.lua`、`hud.lua`、`save_manager.lua`、`state.lua`
- 验收证据：`docs/acceptance-evidence/m14/m14-00-2d-production-sample.md`

## 技术方案

- 用 `game_test/` 中已验证的纹理、音频、字体作为样板资源来源，但不复制 `.cache/`、`.temp/` 等工作目录；
- 新建 `menu.scene`，直接使用 `Text / Image / Button` 组件作为样板 UI 入口；
- 新建 `production.scene`，包含：
  - 100x100 Tilemap；
  - 玩家实体（Sprite + Animation + Collider）；
  - 两类敌人 Prefab 实例元数据；
  - 10 个拾取物；
  - 返回菜单按钮；
- Lua 主入口按场景分流：菜单场景处理按钮点击和读档进入，生产场景处理移动、攻击、拾取、敌人追击、HUD、存档与重开；
- 用 `assetc scan/import/check-deps/package`、`editor --check`、`game --check`、`game --pack --check` 作为本任务验收主线。

## 验收标准

- `game_test_2d_production/` 是独立可打开的游戏工程；
- 资源导入、依赖检查、编辑器检查、运行时检查、发布包检查全部通过；
- 样板工程覆盖 `M14` 规划里的核心对象：菜单、Tilemap、动画、Prefab、拾取物、UI、Lua、音频、存档、发布；
- 结果已记录到 `docs/acceptance-evidence/m14/`。

## 风险与限制

- 本任务交付的是 `M14` 的样板输入与自动化基线，不等于 `M14-01 ~ M14-04` 已全部归档；
- 样板中的 Prefab 实例元数据是为了让后续编辑器回归可以直接复现 Prefab 工作流；
- 目前自动化验收覆盖目录结构、资源导入、依赖链路和发布包完整性，GUI 级人工流转将放在后续 `M14-01` 与 `M14-04` 继续补齐。

## 结论

`M14-00` 已完成。仓库现在有了一个独立、可导入、可检查、可打包的 2D 生产样板工程，可直接作为后续端到端工作流验收的固定样本。
