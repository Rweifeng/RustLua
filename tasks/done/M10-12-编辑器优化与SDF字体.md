# M10-12 编辑器优化与 TMP 风格 SDF 字体

## 状态

REVIEW（代码与自动化验证）；真实 GUI/GPU 视觉、发布包字体路径和长期稳定性待专项验收。

## 目标

记录 `v0.10-editor` 基线之后的编辑器优化和文本渲染增量：完善 Game/Scene/Inspector/资源浏览器等编辑体验，并将运行时文本链路升级为动态字体、TMP 风格布局和 GPU SDF 绘制。

## 背景

## 技术方案

### 编辑器优化

- 调整 editor 面板和状态模块之间的数据传递；
- 优化 Game View、Scene View、Inspector、资源浏览器、工具栏和输入桥接；
- 继续复用 `engine_host::Renderer` 和 `RuntimeScene` 的 offscreen 路径；
- 使用项目 revision 和缓存避免不必要的场景重建/渲染。

### SDF 文本链路

- `FontAtlas` 使用 `ab_glyph` 从项目字体资源生成固定尺寸 SDF glyph；
- `text.rs` 构建 TMP 风格文本布局和混合 ASCII/CJK mesh；
- `RuntimeScene` 将 UI 文本转换为带 SDF 标记的 draw；
- `Renderer` 创建 SDF 距离纹理、绑定组和线性采样器；
- `shader.rs` 使用 smoothstep 等逻辑将距离场转换为抗锯齿文本边缘；
- 字体资源缺失时保留 bitmap fallback 路径。

## 已知风险与限制

- 字体测试或 UI 场景测试在资源缺失时存在静默跳过风险；
- `FontAtlas::load` 当前使用 `Box::leak`，反复重建 RuntimeScene 可能造成长期内存增长；
- glyph 图集固定为 256 个 slot，动态 CJK 文本可能触达容量上限；
- editor Scene View 使用 offscreen → readback → egui 上传路径，尚无完整的 DPI/resize/长会话性能数据；
- 3D Scene View 存在半分辨率缓存恢复和 readback 失败后缓存失效风险；
- 内嵌预览输入快照可能重复产生 `just_pressed` 边沿；
- 发布脚本、编辑器 UI 字体和运行时项目字体存在多条路径，尚未通过 clean-package 字体检查；
- 没有独立的中文 SDF 截图或 GPU 像素基准，因此当前状态不应标记为完整 GUI/GPU 验收通过。
