## 目标

整合山庄、云泽村、青云山道三张地图、NPC、种田、任务、商店、采集、战斗、制作和睡觉存档，

## 实现记录

### 1. 采集系统（纯数据驱动，新增）

- `examples/game_jhyt/scripts/data/gather.lua`（version = 1 + `validate_all`）：
  按地图声明采集点（id / map / cell / item / count / minutes / requires / respawn_days），
  校验地图存在、cell 在 0..39 × 0..21、item 存在、count 正整数、minutes ≥ 0、
  requires 引用已知物品/工具、respawn_days 非负整数、id 全局唯一。
- `examples/game_jhyt/scripts/gather.lua`：
  - `ensure_target()` 在 `interaction` 里懒注册 `gather` 目标（priority 5，介于农田 0 与设施 10）；
  - query 用「玩家面前格」（`grid.facing_cell`，TILE = 32）+ `map_manager.current()` 匹配节点，
    返回 `{cell, distance = 1, facing = 1}`；
  - `can_interact` / `prompt`：可采 → 「E: 采集 <物品名>」；已采未刷新 → 「（已采集 · <物品名>）」；
    缺前置（`requires`）→ 「需要<工具名>」；
  - `act(facing)`：`inv.add` 的 leftover 判定（一件没装下 → 拒绝且不消耗节点；部分装下 → 按实际量记账）
    → `map.state("gather")` 记录（`state_version = 1` + `day` + `nodes[id].day`）→
    `state.last_action = "gather_"..item` → `state.labor_minutes += minutes` → `pcall` 播 `sfx_harvest`；
  - 刷新语义：`clock.now().day - day >= respawn_days` 视为已刷新（惰性清除、幂等）；
    `respawn_days = 0` 一次性；
  - `on_enter` / `capture` / `restore` / `reset` / `on_day_start` 只写内存与 `map.state`，**不操作实体**；
  - 只读辅助 `nodes(map_id)` / `available(facing)` / `gathered()` / `is_gathered(id)`。
- `scripts/interaction.lua`：`ensure_builtins()` 末尾 `pcall(require, "gather")` 成功则 `gather.ensure_target()`
  （缺文件/加载失败静默跳过）。
- **只累计 `labor_minutes`，不推进 clock**（与农田 MVP 取舍一致）。

### 4. 交互缺陷修复（`scripts/interaction.lua`）

实测缺陷：站在农田旁与 NPC 说话时，`farm`（priority 0）以 `distance = 1` 排第一，
`interact` 落在它身上（`need_hoe` / `not_farmland`），NPC 对话打不开。
修复：候选内部两段式排序 —— **先按 priority 降序，同级再按原顺序（距离→朝向→优先级→注册顺序）**；
不可交互者排最后，只作为「全部失败」的原因来源。`M.query()` 原始顺序与既有失败原因保持不变。

### 5. 起始资源调整（`scripts/inventory.lua`）

灵芝菌种 5 → 8、稻种 3 → 4。理由：灵芝 `growth_days = 7`、稻谷 4，农田当日不可收，
单日通关的 6 株灵芝必须由山道采集（5）+ 田里补足；起始量给出「误种一次仍可完成」的余量
（数值校核见 `docs/46` §10）。
