## 技术方案

### 阶段 3 的数据安全半边：外部改动不被静默覆盖

- `SceneDocument.disk_signature` + `DiskStatus::{Untracked, Unchanged, Modified, Removed}`：
  加载/保存后各记一次文件签名（长度 + mtime，不读内容），未命名与崩溃恢复文档恒为 `Untracked`。
- `EditorApp::save_scene()` 在 `Modified`/`Removed` 时**拒绝写入**（磁盘内容原样保留、文档保持 dirty、
  沿用 E06 失败语义）；`save_scene_force()` + 菜单「强制保存（覆盖外部修改）」是显式出口。
- 观察器发现外部改动命中当前文档时立刻提示（不必等 Ctrl+S）。
- 测试：`save_refuses_to_overwrite_an_externally_modified_scene`（干净保存→识别→拒绝且不写→
  强制覆盖→签名刷新）、`unnamed_document_never_reports_a_disk_conflict`。

### ER-03 的 patch 原型（阶段 1 的交付物之一）

- 新增 `patch_history.rs`：`EditPatch` / `FieldChange` / `PatchHistory`，把字段级编辑表示成补丁，
  undo/redo 只回放补丁而不克隆文档；语义与快照历史对齐（空操作不入栈、新编辑清空 redo、
  相邻同类变换合并、预算丢最旧并计数）。
- `--perf-baseline` 新增 `patch_history_memory_1k_edits`：1,000 实体 / 1,000 次字段编辑下，
  补丁保留 216,000 字节 vs 快照下界 397,890,000 字节（**0.054%**），且 Undo/Redo **逐字节等价**。
- 边界如实写在模块文档与 docs/58 §5.1：**只覆盖字段级编辑**，不覆盖结构变更，生产路径未切换。

## 已知限制

- **8 小时 soak 按用户决定暂缓**（阶段 0 验收里唯一未关门的一条，且是**人的决定**而非技术阻塞）：
  命令、10 秒采样、增量落盘、谷值判据与 `scripts/analyze-soak.ps1` 复算脚本全部就绪。
  可用的长会话证据是**单实例**的 30 分钟 Play/Stop 档：预热后谷值 +4.7 MiB（阈值 37 MiB）
  → `no_sustained_growth`。
- **两次并发长档失败已归因，属无效样本**：8 小时档（49 分钟）与归因档（8 分钟）是我**同时**跑的，
  两者都在工作集涨到 1.8-2.5 GiB 后退出；`_bin/crash.log` 记录的是
  `Failed to create staging buffer for index data` @ `egui-wgpu/src/renderer.rs:958`，
  紧邻日志为 `Acquiring a texture failed`。新加的 egui 纹理账全程恒为 1.0 MiB（排除 egui 纹理）。
  成因是两个编辑器在 2 GB 显存上 churn 每轮约 10 MB 的 Play 贴图 → WDDM 回退 + 分配失败。
  **不能**据此认为"编辑器跑 49 分钟必崩"。
- **真实健壮性缺口（新登记）**：GPU 分配失败会以 **panic** 收场，编辑器直接退出，
  没有降级路径、也没有把现场落到崩溃日志之外的诊断里。对应计划 §8 的 GPU 实机门
  （设备丢失/初始化失败）；离线自包含策略下无法就地给 egui-wgpu 打补丁，
  后续应做"GPU 失败纳入会话级诊断 + 退出前落盘现场"。
- GUI smoke 是**合成帧**（无 GPU 后备缓冲、无真实重绘节奏），真实窗口那一半是脚本化采集而非
  "点击真实窗口并断言"的端到端自动化；
- DPI 覆盖是 egui 层 `pixels_per_point`，不是修改操作系统缩放（几何等价，光栅化细节有差异）；
- 停靠布局是轻量版（宽度/可见性/模式/工具/密度），不是可任意重排的停靠系统（计划 §2.2 明确不自研）；
- 外部 `.scene` 冲突没有比较/合并对话框；诊断跳转没有内置源码查看器；
- Undo 仍是快照历史 + 内存预算；Prefab 嵌套展开与 Variant 未做（计划要求后置）。

完整清单见 [docs/58 §9](../../docs/58-编辑器重构阶段0-3收口与验收.md)。
