## 背景

M11 归档后，资源系统的主要问题不再是“有没有资源浏览器”，而是资源状态漂移、导入链路不闭合、依赖断链不可见：

- editor / engine 各有一套资源类型定义；
- `assetc::import` 不回写数据库，状态容易长期停在旧值；
- editor 刷新只能注册资源，不能稳定完成后台导入；
- 场景 / Prefab / Lua 的引用不会生成依赖边，缺失资源时消费者不会转成断链状态；
- 发布前无法输出完整的 consumer → dependency 失效链路。

因此本次 M12 归档聚焦三个已完成任务：

- `M12-00`：资源状态模型统一；
- `M12-01`：Importer 增量导入；
- `M12-02`：依赖图与失效传播。

## 技术方案

- **M12-00 资源状态模型统一**
  - `engine` 侧新增统一 `ResourceKind`（9 族）；
  - `ResourceState` 采用 6 个持久化状态 + 3 个瞬态状态；
  - 资源数据库升级到 TSV v2，支持 v1 自动迁移、损坏库 recoverable 打开；
  - `reconcile` 依据磁盘 mtime 推导 `Discovered / Stale / Missing / Orphaned / Ready`。
- **M12-01 Importer 增量导入**
  - 引入 `Importer` trait、注册表和 batch runner；
  - `assetc` 导入回写 DB，单坏资源不阻断整批；
  - editor 刷新后生成 pending imports，后台线程自动导入并回到最终状态；
  - `ImportCache` 以 `content_hash + importer version + kind` 复用缓存。
- **M12-02 依赖图与失效传播**
  - 从 Scene / Prefab / Lua 中提取资源引用，建立依赖边；
  - 依赖异常时把消费者转成 `Invalid / Stale`，依赖恢复后自动撤销；
  - 支持循环依赖检测；
  - `assetc --check-deps` 输出完整断链路径，editor 资源面板显示断链状态。
