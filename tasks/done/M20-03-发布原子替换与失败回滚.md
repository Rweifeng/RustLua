## 风险

- Windows 文件占用和杀毒软件可能导致替换失败；必须保留旧版本并输出明确原因。
- 原子替换策略不能破坏现有 P2PK1 资源格式和发布目录布局。
- 中断恢复需要区分临时目录、备份目录和最终目录，避免误删用户资源。

## 实现记录

- **staging 优先构建**：`package.ps1` 在解析出最终发布目录后，改为在
  `<release>/.staging-<时间戳>-<随机>` 内完成**全部**内容生成（assetc 打包、运行器/字体/文档拷贝、
  release.toml、deps.txt、build-info.txt、run.txt、pack 自检），最终目录在整个构建期**不被触碰**。
- **原子替换**（`Complete-ReleaseSwap`）：旧内容整体重命名进 `.backup-<时间戳>-<随机>`（同卷重命名，原子），
  再把 staging 顶层项重命名进最终目录，最后删除 backup 与 staging。成功摘要打印
  `==> Release swapped in: N entries replaced, M entries moved aside`。
- **失败回滚**：交换过程中任一步失败（文件占用、磁盘错误等）→ 新内容退回 staging、旧内容从 backup 放回原位、
  删除 backup，并以 `release swap failed (old release restored at <dir>): <原因>` 抛错；
  staging 保留以便诊断。构建阶段（交换之前）失败 → 丢弃 staging，打印
  `==> Release failed before swap; existing release kept at <dir>`，最终目录完全不受影响。
- **遗留清理**：每次发布开始时 `Clear-StaleReleaseStaging`（默认 24 小时阈值、只按 `.staging-`/`.backup-`
  前缀匹配）清理中断遗留目录，并在日志中列出被清理项；自检临时目录清理为**尽力而为**（5 次退避重试 +
  告警指出路径），不再因文件占用导致发布失败。
- **可诊断日志**：保留既有 `==>` 阶段标记（编辑器发布面板据此显示确定进度），新增 staging 路径、交换摘要、
  回滚告警与遗留目录提示，均为面板可见行。
- **`-SkipBuild`**：复用 `target/release` 既有产物，用于快速重复发布与回归（缺产物时明确报错）。
- **布局/格式不变**：最终目录仍为 `game.exe + fonts/ + pack/ + release.toml + run.txt + deps.txt (+ index.html/pkg/web-runtime.js)`，
  P2PK1 资源包与清单格式未改。

## 验收方式

- 发布成功后检查目录完整性、资源索引和启动结果。
- 模拟资源缺失、文件占用、磁盘错误和中断，验证旧版本可继续启动。
- 重复发布、发布失败后重试和清理遗留临时目录均可复现。
- 在编辑器发布面板中验证进度、错误和回滚状态可见。
