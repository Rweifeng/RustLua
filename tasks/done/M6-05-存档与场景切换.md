# M6-05：存档与场景切换

- 状态：ACCEPTED
- 验收日期：2026-08-22
- 所属里程碑：M6 2D 游戏能力与样板游戏
- 前置任务：M6-04 UI/音频/粒子（提供跨场景 UI/血条基础）

## 目标

提供版本化存档（新游戏/保存/读取/覆盖，损坏存档不崩溃）与场景切换（资源/脚本生命周期正确，`scene.load` 真实重载关卡）。核心玩法价值：F1 存档、F2 读档、F4 主/竞技场切换，hp 跨场景保持。

## 背景

`save` 与 `scene` Lua API 之前是占位（内存 map、只存场景名）。M6-05 把它们变成真实能力：存档落盘（版本化 + 原子写入）、场景真实切换（清 World/物理/粒子 → 实例化新场景 → 重跑 `on_create`）。

## 输入

- `engine/crates/engine_core/src/save.rs`（新模块）
- `engine/crates/engine_core/src/script.rs`（Lua API 与切换生命周期）
- `engine/crates/game_runner/src/main.rs`（固定步应用切换）
- `game/scenes/arena.scene`（新场景）、`game/scripts/main.lua`

## 不做什么

- 多存档槽/云存档（单槽，路径可配）
- 存档加密/校验和（版本号 + 行格式校验足够）
- 场景热重载编辑器工具

## 技术方案

1. **存档**（`save.rs`）：版本化文本格式 `save_version=<n>\n<key>\t<value>\n`；`encode`/`decode`；坏版本（`UnsupportedVersion`）或坏行（`Malformed`）返回错误不 panic。
2. **存档 Lua API**：`save.write(key,value)`、`save.read(key)`（内存 map）、`save.commit()`（`encode` + 原子写 `save_path`）、`save.load()`（读文件 + `decode`；无存档返回 false，损坏忽略并告警）。
3. **场景切换**：`scene.load(name)` 检查 `<project>/scenes/<name>.scene` 存在后设置 `scene_pending_load`（返回布尔）；`LuaRuntime::process_scene_transition` 在每固定步后应用——清 `world`/`physics`/`particles`/`names`/`health`/`ui`，实例化新场景，重跑脚本 `on_create`（新实体句柄刷新）。存档与音频跨场景保留。
4. **路径配置**：`set_project_root`、`set_save_path`；game_runner 在 `RuntimeScene::new` 设置 `<project>` 与 `<project>/.p2/save.sav`。
5. **键位**：`parse_key`/`map_key` 增加 f1/f2/f4 → `InputKey::Other(1/2/4)`。
6. **游戏工程**：新建 `arena.scene`（8x5 竞技场，不同墙布局、无触发器）；main.lua F1 存档（hp+scene）、F2 读档（恢复 hp + 切回存档场景）、F4 主/竞技场切换；`on_create` 从存档恢复 hp。

## 风险与应对

| 风险 | 应对 |
|---|---|
| 存档写坏主文件 | 原子写（临时文件 + rename），decode 失败保留旧数据 |
| 场景切换后实体句柄失效 | 重跑 on_create 刷新局部缓存（map/trigger id）；update 每帧重新 find player |
| 切换时 runner 读旧世界 | 切换在固定步内 call_update 之后应用，渲染读最新 world |
| F 键 winit 映射差异 | `InputKey::Other` 代码点 + `parse_key`/`map_key` 双向对齐，集成测试兜底 |
