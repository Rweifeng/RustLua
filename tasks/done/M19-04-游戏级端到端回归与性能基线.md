## 实现记录

`jhyt_m19_soak` 是 M19-04 的**唯一执行入口**（一个示例内分章，逐章断言，任一失败即非零退出）：

1. **M19-04a 帧率一致性**：同一脚本化动作序列（翻土 → 播种 → 浇水）分别在 `dt=1/30`、`1/60`、`1/120`
   下驱动独立 runtime，比较**规则状态快照**（农田地块、任务状态、金钱/体力/背包计数、存档摘要），
   要求逐字段相同。实测三者完全相同 → 证明固定步模拟下表现层（帧率）不影响规则。
2. **M19-04b 30 天长跑**：循环 30 次「一日劳作 + 睡觉」，睡觉走**真实 `day.sleep()` 路径**
   （`on_day_end` 存档 → 凌晨推进 → 清晨 `on_day_start` 日结算再存档），逐日断言
   日计数递进、体力重置为 100、累计收获 `> 0`，并检查无状态漂移。实测 `day=31`、`harvested_total=465`。
3. **M19-04c 读档循环**：
   - 20 次**真实 runtime 读档**：每次新建 runtime → 执行工程脚本 → `scene.load('main')` →
     `process_scene_transition()` → 点标题「继续」→ 断言 `scene.reload() == "manor"`；
   - `save_manager.validate_long_run(30, 100)` → 3000 次**快照恢复**（纯 Lua 路径，明确不冒充真实读档）。
4. **M19-04c2 磁盘往返（100 次）**：在同一 runtime 上循环 100 次
   `save_manager.save()` → `save_manager.load()`，走真实写盘 + `save.commit()` 原子提交 + 读回恢复；
   末轮断言天数未回退（`day >= 30`）且地图仍是 `manor`。补齐验收条款里「100 次存档/读档循环」的字面要求。
5. **M19-04d 性能/稳定性基线**：1800 个固定步计时得到 `per_step_ms`，并采集 NPC 注册表/建筑/农田地块/
   背包物品总数与存档摘要，打印单行 `jhyt_m19_soak_baseline …` 并写入
   `artifacts/baselines/m19-soak.json`（`task`/`source`/`per_step_ms`/`soak_days`/`harvested_total`/
   `real_load_cycles`/`disk_save_load_cycles`/`snapshot_restores`/`line`）。
6. **发布目录隔离**：复用 `scripts/package.ps1 -SelfTest`——把发布包复制到**含空格、无源码/target/.cache**
   的临时目录，再跑 `game.exe --pack pack --check`（退出码 0 即发布包完整且不依赖开发机路径）。

判定原则（写入 `docs/36`）：结果全部基于**规则状态**比对，不依赖显卡/音频设备/浏览器；环境缺失项
（WASM 构建、真实手柄）必须标注「环境受限未执行」，不得记为通过。

## 验收方式

- 核心剧本 headless 回归通过（`jhyt_m19_slice`，见 `tasks/done/M19-01-*.md`）。
- 30/60/120 FPS 规则结果一致（`jhyt_m19_soak` 第 1 章）。
- 30 天无状态漂移 + 100 次存档/读档循环通过（第 2/3/4 章）。
- 干净发行目录启动（`package.ps1 -SelfTest`）。
- 输出帧时间、模拟时间、资源数量和存档摘要等性能/稳定性基线（第 5 章 + JSON 落盘）。
- `cargo fmt`/`clippy`/`test`/`build` 全绿。
