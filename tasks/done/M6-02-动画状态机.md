# M6-02：动画状态机

- 状态：ACCEPTED
- 验收日期：2026-08-22
- 所属里程碑：M6 2D 游戏能力与样板游戏
- 前置任务：M6-01b 精灵与图块纹理渲染（提供 UV 采样管线）

## 目标

为实体提供命名动画状态机：待机、移动、攻击、受击、死亡状态，每个状态对应一个帧条带剪辑（帧率、循环策略）；Lua 可读取和切换状态；状态切换条件可测试；非循环剪辑结束事件仅触发一次；渲染器按当前帧 UV 采样播放。

## 背景

M6-01b 建立了纹理采样渲染管线（精灵按路径采样、图块按 tileset 列 UV）。但没有"随时间播放不同帧"的概念——精灵只有一张静态纹理。动画状态机在此之上加入时间维度与状态管理。

## 输入

- `engine/crates/engine_core/src/animation.rs`（新模块）
- `engine/crates/engine_core/src/script.rs`（Lua API 与场景实例化）
- `engine/crates/game_runner/src/main.rs`（渲染与推进）
- `game/assets/`（帧条带）、`game/scenes/main.scene`、`game/scripts/main.lua`

## 不做什么

- 骨骼动画、曲线插值（仅帧条带序列帧）
- 编辑器动画编辑工具
- 物理驱动的状态切换（hit 由 M6-03 碰撞触发）

## 技术方案

1. **数据模型**（`animation.rs`）：`AnimationClip { name, sheet, cols, frame_rate, looped }`——每个状态一张 `1×cols` 帧条带；`AnimationStateMachine { default, clips, current, time, ended, completed }`。
2. **帧推进**：`advance(dt)` 累计时间；循环剪辑 `frame = floor(time*fps) % cols`，非循环剪辑夹紧到最后一帧；非循环剪辑跨越结束边界时 `ended=true`（`completed` 标志保证**每完成仅触发一次**，`set_state` 重置）。
3. **序列化**：`default=<name>;clip:<name>:<sheet>:<cols>:<fps>:<looped>`，round-trip。
4. **Lua API**：`animation.get`（当前状态）、`animation.set`（切换，返回是否发生切换）、`animation.frame`（当前帧）、`animation.ended`（结束事件，读后清除）。
5. **渲染**：精灵带 Animation 时用当前帧 UV 采样其剪辑 sheet；否则用 SpriteAsset 全幅 UV。每固定步在 `run_script_steps` 推进所有动画。
6. **游戏工程**：main.scene Player 加 Animation 组件（idle/move/attack/hit/death）；main.lua D→move、Space→attack（一次性动画播完后自动回退 idle/move）；`scripts/gen-textures.ps1` 生成四张帧条带（每帧白色条位置标记帧号）。

## 风险与应对

| 风险 | 应对 |
|---|---|
| 结束事件每帧重发 | `completed` 标志记录本次完成已触发，set_state 重置 |
| `advance` 借用冲突 | 提前复制 looped/duration 再改 self.time |
| 动画 UV 与纹理不匹配 | 每剪辑独立 sheet 条带（1×cols），UV 按列归一化 |
| 多状态切换时序 | Lua 每次 update 先查当前状态，一次性动画播完才回退 |
