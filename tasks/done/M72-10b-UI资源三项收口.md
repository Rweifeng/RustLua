## 为什么单独开

`done/M72-10` 归档时留了三项没写进代码：

1. **九宫格边距契约**：`assets/prefabs/ui/` 里 14 行 `_9s` 贴图没带
   `nine_slice=`，`hud/ui_bar_frame_9s.png` 被当普通整块拉伸画 3 次；
   `ui_asset_census.py` 的 prefab 侧只扫 `assets/prefabs/*.prefab`，漏掉
   `ui/` 子目录，所以把这 14 行读成了 0。
2. **全 UI 换字**：`project.toml` 已把全局字体定为 Fusion Pixel 12px，
   `jhyt_m72_pixel_font` 门已存在；要确认它今天仍绿，并把“全 UI 走同一款
   点阵字体”作为门写进收口记录。
3. **图标画质**：92 张物品图标里“纯色块”命中 0，但 M72-10 没有定
   “画质”的机器判据。本包定一个**像素画技术契约**（尺寸/alpha/量化/非纯色/
   最小信息量/非噪点），不把“好不好看”伪装成机器门；审美精修仍归外部委托。

## 事实基线（2026-10-21 实测）

```text
# 14 行缺 nine_slice：
hud.prefab      3 行 ui_bar_frame_9s.png（entity 14/17/20）
inventory.prefab 11 行（1 行 ui_slot_selected_9s + 10 行 ui_slot_9s）
# manifest 边距：
ui_bar_frame_9s = 4,4,4,4
ui_slot_9s / ui_slot_selected_9s = 6,6,6,6
```

`ui_asset_census.py` 的 `census_prefab_margins()` 用
`ROOT.glob("assets/prefabs/*.prefab")`，只扫顶层；`reference_text()` 同样
只扫顶层，导致“prefab 组件带 nine_slice 0”的假读数。

## 收口账

### A. 九宫格（已修）

1. 14 行补齐：`hud.prefab` 3 行 `ui_bar_frame_9s=4,4,4,4`；`inventory.prefab`
   11 行 `ui_slot_selected_9s=6,6,6,6` + `ui_slot_9s=6,6,6,6`。
2. `ui_asset_census.py` 的 prefab 扫描改为 `assets/prefabs/**/*.prefab`，
   `reference_text()` 同步递归。
3. 三条 `ui_bar_fill_*` 在清单里改回 `nine_slice: null`：它们是横向填充条，
   本来就不该按九宫格拉伸；这是“改清单而不是改画面”。
4. `manifest.json` 的 `root`/`path` 去掉盘上不存在的 `jianghu` 段
   （98/98 原样命中）；生成器 `asset_path()`/`build_manifest()` 同步修正，
   避免下次重生成再写回去。
5. 新增 `--gate`：
   - 每个 prefab 里被引用的 `_9s` 贴图必须带 `nine_slice=`；
   - 取值必须等于 manifest 的 `nine_slice`；
   - prefab 的 `UiLayout.offsets` 宽/高必须 ≥ 左右/上下边距之和；
   - `skin.lua` 的 21 条硬写 slice 也必须等于同一份清单；
   - 输出 `jhyt_m72_nine_slice_margin_ok`。
6. `jhyt_m70_hud_golden.tsv` 3 行、`jhyt_m67_inventory_golden.tsv` 11 行按新
   边距重刷；两道 prefab 门复跑绿。

### B. 全 UI 换字（已验证）

1. 不新增字体，不改 `project.toml`；确认全局 `font=` 仍是
   `FusionPixel-12px-Monospaced-zhHans.ttf`、`font_fallback=""`。
2. 复跑 `jhyt_m72_pixel_font`：`jhyt_m72_pixel_font_ok`，75 个 UI 字形四边形、
   灰阶 0、缺字 0、1,611 字、1024² 图集。
3. 收口口径：所有 UI 文本都走全局字体，项目内没有第二套字体/逐控件
   `font=` 覆盖；逐屏“好不好看”的目验不是本包能机器判的，不写成门。

### C. 图标（技术契约 + peach 补图）

1. 新增 `--gate` 的图标技术契约（全部可机器判）：

   | 判据 | 阈值 | 理由 |
   |---|---|---|
   | 尺寸 | `32x32` | `docs/31` §3.3 / `gen_item_icons.py` 的产出规格 |
   | alpha | 只允许 `{0,255}` | 硬边像素画，反 AA |
   | 每通道档数 | `≤64`（6bit） | 当前 93/93 达标；避免渐变噪声 |
   | 非纯色块 | `distinct_opaque > 2` | 不许用色块冒充图标 |
   | 最小信息量 | `opaque_px ≥ 32` | 至少 32 个不透明像素 |
   | 非噪点 | `singleton_share ≤ 0.98` | 不允许几乎每像素一色 |

   输出 `jhyt_m72_icon_quality_ok`；另打印 `reuse < 1.05` 的观察名单，
   但**不作为门的失败条件**——那张列表是审美/重绘委托的输入，不是机器能判的
   “画得好”。

2. 补 `assets/art/items/peach.png`（32×32 像素桃）：
   - `data/items.lua:peach` 不再借 `rice.png`；
   - `data/items_fish.lua` 的 `fish_icons.peach` 补齐；
   - `gen_item_icons.py` 增加 `icon_peach()` 与 `ICONS` 条目，下次重生成仍能
     逐张重画。
3. `jhyt_m23_data_validation` 的 236 条资源引用检查通过；`jhyt_m45_fishing`
   23 条鱼种照常通过。
