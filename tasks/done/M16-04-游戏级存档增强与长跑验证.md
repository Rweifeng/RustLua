## 目标
在现有 `save_manager` 注册中心基础上补齐玩家位置、地图状态、快照版本、存档摘要和多次读档验证，确保跨天、切图前置状态可安全扩展。

## 影响文件

- `examples/game_jhyt/scripts/save_manager.lua`
- `examples/game_jhyt/scripts/main.lua`
- `examples/game_jhyt/scripts/player.lua`
- `examples/game_jhyt/scripts/farm.lua`

## 风险

- 不擅自替换现有 `save.blob_*` 兼容层；统一引擎 `world.save/load` 另立任务。
- 快照字段新增必须提供默认值，并保留旧版本明确拒绝或游戏侧迁移策略。
- 玩家实体由 PersistId 恢复时，位置恢复时序必须在场景实例化之后执行。

## 实现记录

- `save_manager` 将快照版本提升为 2，保留原 `save.blob_write/read` 键 `jianghu_youtian.state`，同时写入顶层 provider 字段和 `providers` 命名容器，便于兼容已有 blob 读取路径。
- 版本 1 明确拒绝；未知版本、损坏快照、场景摘要缺失均拒绝并输出 `[save][load/read/restore]` 可定位日志。
- 保存捕获、blob 写入和 commit 失败均不会报告成功；仅在 commit 成功后更新摘要。引擎 commit 的原子语义用于保留原有效存档。
- 注册中心按名称保持稳定顺序，同名同函数重复注册幂等，不重复执行或追加注册项。
- 存档包含 `state`（金钱、能量、内功、选中种子、季节、天气等）、`inventory`（槽位/装备）、`clock`（日期/分钟）、`farm`（农田地块明细）和 `scene`（当前场景、地图名、地图状态摘要）。
- 玩家位置在 `JianghuPlayer` 场景实例化后通过稳定实体名重新绑定并调用 `transform.set` 恢复。当前引擎 Lua API 未暴露 PersistId 查询/设置接口，因此采用最小安全 `{entity,x,y}` 快照，限制为当前 `main` 场景，不能跨实体迁移。
- 提供 `save_manager.summary(snapshot)`、`save_manager.last_summary()` 摘要接口和 `save_manager.validate_long_run(days, loads)` 纯 Lua 快照恢复循环入口；默认 30 天、每天 100 次，共 3000 次恢复。
