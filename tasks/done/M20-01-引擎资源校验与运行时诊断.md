## 目标

补齐 Lua 脚本语法校验、领域数据加载诊断和关键资源错误定位，避免错误资源进入运行时后才失败。

- `engine/crates/engine/src/core/importer.rs`（Lua/JSON/RON 导入期校验 + UTF-8 BOM 诊断）
- `engine/crates/engine/src/core/resource_db.rs`（未改：诊断经既有 `mark_failed` 记录，导入失败原因原样进入资源库状态）

## 风险

- Lua 语法检查可能改变现有宽松导入行为；应仅在导入校验阶段报告错误，不改变合法脚本运行语义。
- 领域数据错误信息必须保持文件、对象 ID、字段路径可定位；必要时保留兼容默认值并明确告警。

## 实现记录

- **导入期 Lua 语法校验**（`importer.rs::validate_lua_syntax`）：用 mlua 只编译不执行（`load(...).into_function()`），不改变合法脚本的运行语义；诊断形如 `<文件>: Lua 语法错误: syntax error: [string "<文件>"]:<行>: <消息>`。补齐了原 `ScriptImporter::validate` 的「语法校验留 M12-04」占位。
- **JSON / RON 校验**：`.json` 走 `serde_json` 严格解析（错误自带行列）；`.ron` 在**不新增依赖**（离线环境无法拉取 crates）的前提下做结构级校验——分隔符/字符串配平 + 行列定位诊断，文档中明确标注「完整 RON 语法解析待引入 `ron` 依赖后替换」。`.scene` 保持既有解析校验。
- **UTF-8 BOM 可操作诊断**：Lua 解析器对 BOM 只报 `unexpected symbol near '<\239>'`；现改为「含 UTF-8 BOM，请另存为「UTF-8 无 BOM」」。这是实测踩到的真实问题（PowerShell/记事本另存为 UTF-8 会带 BOM，导致脚本被拒且原因难懂）。
- **领域数据统一校验入口**（工程侧 `scripts/validate_data.lua`）：`check({strict=true})` 返回 `""` 或换行分隔的问题列表（每条 `[模块] 文件:对象.字段: 原因`）。`main.lua` 的 `validate_content`、`game --check` / `editor --check` 三方共用同一实现，规则仍全部来自各模块 `validate_all`（不在 Rust 侧硬编码 NPC/任务语义）。`strict` 模式下缺少 `validate_all` 也会报错，防止新增数据模块忘记登记校验。
- **发布前检查扩展**（`game/src/cli.rs`）：
  - `verify_script_syntax`：遍历 `scripts/**/*.lua`，共用 `ImporterRegistry` 的导入期校验器（诊断与编辑器扫描、assetc 导入完全同源）；
  - `verify_domain_data`：若工程提供 `scripts/validate_data.lua`，以「执行该入口文件」建立 `require` 搜索路径（不启动游戏），再执行 `require('validate_data').check()` 收集问题；未提供该模块的工程自动跳过（通用工程不受影响）。
- **编辑器资源扫描**：编辑器导入路径本就使用 `ImporterRegistry::builtin()` + `run_import_batch_with_progress`（`editor/src/import.rs`、`resource_browser_state.rs`），因此脚本/JSON/RON 校验与诊断自动生效；M19-03 的域数据面板复用同一 `validate_data` 入口（已同步）。
- **关键资源错误定位**：场景引用资源缺失的诊断保留（含资源相对路径、去重），与脚本/数据诊断在 `--check` 中一并输出并以非零退出码阻断发布。

## 验收方式

- 使用合法和非法 Lua、JSON、RON、领域数据样本执行导入与加载测试。
- 验证错误包含文件路径、对象 ID 和字段路径。
- 在 `game_jhyt` 启动、编辑器资源扫描和发布前检查中复现诊断结果。

## 未完成项 / 已知限制

- 暂不改造 ECS 和 Scene 的底层字符串存储结构。
- 暂不引入新的公共场景格式；`.`ron` 为结构级校验（无 `ron` 依赖），完整语法解析待依赖可用后替换。
- Lua 源文件按「UTF-8 无 BOM」约定：当前对 BOM 给出可操作诊断而非自动剥离；运行期脚本加载器（`script.rs`）同样不接受 BOM，若后续要自动容忍 BOM 需在加载器与校验器同时处理（记为后续改进）。
- 领域数据校验入口是**约定式**（`scripts/validate_data.lua` + `check()` 返回问题字符串）：未按约定提供入口的工程只做脚本语法与资源引用检查。
