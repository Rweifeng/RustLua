# 删除旧 JS 世界：删除面清单与依赖顺序

> 口径：本清单是**只读分析**的产物（未改任何文件），用于驱动"删掉旧 JS/Canvas2D 世界"这一步。
> 结论全部带 `文件:行号`。**先改门，再删读数的生产者，最后删文件**（见 §4 B8）——反过来做会得到一堆静默放行的门。

## 0. 一句话结论

删旧世界**不是**一次文件删除，而是三件事的合成：

1. **浏览器的默认入口必须先交给 Rust 宿主**（今天 `gpu2d` 不是默认特征，`plugins/webgl/index.html` 在探不到 `gpu_host_run` 时退回旧世界，而那正是默认产物的形态）⇒ 否则删完默认产物**没人画**；
2. **微信侧必须有一个不依赖旧运行时的输入生产者**（今天 `FrameInput` 的唯一写者是 `lua_bridge.rs` 的 `lua_input_frame`，而它唯一的调用者是 `web-runtime.js`）⇒ 否则删完世界**不再接受输入**，且不崩溃、不报错；
3. **一批只服务旧世界的门/读数必须先有引擎侧替代**（§5 的 N1–N8），否则"删掉"与"门静默放行"同时发生。

收益是**确定的**：主包 −257 KB（§6）。

## 4. 删除的依赖顺序（关键路径）

- **B1（浏览器）删 `sampleDrawnPixels`/`data-rustlua-drawn` 前**，必须先有 Rust 侧非黑屏判据。`gpu_host.rs:312` 只写 `data-rustlua-gpu`，**不写** `data-rustlua-drawn`（全仓唯一写者是 `web-runtime.js:7479`）；而 `verify.ps1:842-844` 硬判 `drawnSamples <= 0` → throw。**Y** = ① 默认 webgl 产物带 GPU 宿主；② 黑屏判据改读 Rust 侧（present 后像素回读，或复用 `host_runtime::read_pixel_sample` 同一实现）。
- **B2（浏览器）删补丁层前**先接受 `-ApiContract`/`-DriveJhyt` 失去写者（`verify.ps1:902-905,932-935` 都经旧世界；`verify-webgl-bundle.ps1:870-898,993-1012` 已按"JS 宿主未参与 ⇒ 跳过"写好）。引擎侧只有 `-WorldDo/-WorldExpr/-InputScript` 可替代；**逐 API 行为对拍没有引擎侧替代**。
- **B3（微信）删 `lua_boot()` 前**先把 vfs reader provider 安装独立出来：预装只有 `lua_boot_with_reader`（`:482-485`）一个入口，它顺带 `boot_runtime` 建了一整台 `LuaRuntime`＋275 个 API。**Y** = 新增只装 provider 的导出（或让 `engine_host_begin` 收 reader）。
- **B4（微信，真正卡住整件事的一条）删 `createWebInput`:1028 / `getInputFramePacker`:5260 / `applyInputFrame`:5349 / `game.js:24` 前**，必须先有微信侧独立的 `FrameInput` 生产者。证据链：`wechat-adapter.js:2076` 恒传 `undefined` → `host_runtime.rs:644-649` scene 档从 `lua_bridge::latest_frame_input()` 取 → `LATEST_FRAME` 唯一写者是 `lua_bridge.rs:641` → 唯一调用者是 `web-runtime.js:5334`。**旧运行时不跑 ⇒ 微信宿主的世界永远收不到输入**（`FrameInput::default()`），不崩溃、不报错、`presented` 照涨，只是人钉死。**Y（缺一不可）**：① 微信侧新输入生产者（现成的 Rust 生产者在 `frame_input.rs:207-372 FrameInputProducer`，但只在 `gpu_host.rs:271,698` 的浏览器 DOM 路径被驱动）；② `input.press_position` 引擎侧补齐（被 `examples/game_jhyt/scripts/ui/virtual_pad.lua:598-604` 用 `pcall` 取，缺了回落实时光标）；③ 输入读数新归属（否则 `verify-wechat-minigame.ps1:676-679` 直接红）。
- **B5（微信）删 `markBoot` 前**必须有别人写 `data-rustlua-boot=ok`：adapter 只写 `failed`（`:3655-3656`、`:4076-4077`），`ok` 的唯一写者是旧世界。
- **B6（微信）删全局 rAF 包装（`:3816-3833`）前**，必须把 `afterFrame`（`:2811-2858`）挂到宿主自泵上，否则覆盖层/进度条/失败条/像素自检/`publishDiag` 全部失驱动。
- **B7（无前置）**：分包/字体/远端/FS 路由/生命周期都是适配层自持，与旧世界无耦合。
- **B8（通用顺序）**：**先改门（§5），再删读数的生产者，最后删文件。**

## 7. 风险清单（会静默坏的）

- **R1 微信世界不再接受输入（最高）**：见 B4。守卫 = `moved=dx,dy` ＋新增输入指纹；**不要**用 `engine_host_input_applied`（会变成恒 0 的假信号）。
- **R2 读数由"有值"变"缺席"，多数读者把缺席当正常**：`diagSnapshot:2549-2556` 把若干读数缺省成 `off`；`verify-webgl-bundle.ps1` 多处只在 `-eq 0` 判红 ⇒ 会**静默放行**。守卫 = 把"字段必须存在"写进门。
- **R3 `data-rustlua-boot` 永远落不到 `ok`**（见 B5）⇒ 看门狗/落定类用例反向失真。
- **R4 `--host-canvas offscreen` 的前提与原子模式互斥**：该用例断言 `offscreen_ops=0`，而原子模式**故意**把 2d 改道到 `wx.createCanvas()` 的返回值。按静态推演它会报"上屏画布上没有任何绘制调用"。**未执行复核**（harness 会临时改写 `remote-assets.json`）⇒ 必须先复核这条，它决定 B6 之后这套门还能不能留。
- **R5 浏览器默认产物从"旧世界画"变"没人画"**：`package.ps1:557` 只在 `-Gpu2d` 时编 GPU 宿主；`index.html:176-183` 是唯一保护。**并且 frame-owner 门的 `else` 分支没有正面证据**：`verify-webgl-bundle.ps1:641-643` 在 `jsHostSkipped=false` 时无条件打印 "frame owner ok: legacy JS world" ⇒ 必须改成要求 `data-rustlua-gpu` 存在。
- **R6 多触点虚拟控件退化**：`input.press_position` 是补丁自造名，缺了回落实时光标 ⇒"按住摇杆＋另一手点按钮"命中错位，**不报错**。
- **R7 "补丁层遮蔽引擎 API"的唯一机检会消失**：删 `web-runtime.js` 后 `check-web-api-overrides.mjs` exit 3 ⇒ 必须同删 `plugins/webgl/lua_api_overrides.json` 或改成"必须为空"的断言。
- **R8 音频双后端**：旧世界 `installLuaAudioBridge` 是真实播放后端，引擎对应 `audio_sink.rs`。删后 `data-rustlua-audio` 缺席，微信侧需要等价计数读数。
- **R9 抽源码的静态门静默空转**：`web-fixed-step-test.js`、`web-u64-hash-test.js` 从 web-runtime.js 抽源码跑 ⇒ 删文件时要**同步删脚本与调用点**，不留"跳过"。

## 9. 观测阻塞（本轮新发现，它排在 N2 前面）

**结论：N2 / N3 / N4 这类"scene 档真的跑起来了"的断言，今天在离线环境里根本写不出来。**

证据链：

1. `host_runtime::engine_host_state()` 的 `scene` 块（含本帧消费的输入指纹，`host_runtime.rs:650-660`）是 scene 档唯一的输入证据来源；
2. 它在适配层只有两个出口：`api.engineHostState`（`wechat-adapter.js:4467-4476`）与 `wx.__rustluaEngineHostState`（`:4524`）；
3. **门与 harness 都没有调用它**——`scripts/wechat-minigame-harness.js` 里 `engine_host_state` 出现 **0 次**，自报行里只有适配层自己那份 `diag().engine_host`（status/source/reason/frames/...）；
4. 而且**即使调用也读不到 scene 块**：离线 harness 的假画布给不出 WebGL2 ⇒ `engine_host_begin` 必然失败 ⇒ `HOST` 是 `None` ⇒ `engine_host_state()` 直接返回 `host: not-begun`。今天门里能观测到的只有 `engine_host=failed` + 具名 reason。

**这条阻塞的后果**：删旧世界最危险的一条（R1：输入没了而读数全绿）**恰恰是最没有门可依的一条**。在它被解开之前，任何"输入所有权搬到宿主"的改动都只能靠真机验证。

**两条解法（按性价比排序）**：
