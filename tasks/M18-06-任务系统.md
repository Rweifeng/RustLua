# M18-06 任务系统

## 状态
BACKLOG

## 类型
[玩法]

## 目标
任务数据（`data/quests.json`）、任务追踪、完成与奖励，数据驱动。

## 背景
缺口清单 4.1 提到任务数据；任务是对玩家目标的编排，也是存档（2.3 任务/剧情状态）的一部分。

## 输入
- `data/quests.json`（目标/条件/奖励/前置）
- M17-03 对话（触发/交付）、M18-00 数值
- M16-09 存档（任务进度持久化）

## 不做什么
- 不做任务编辑器（M19）；
- 不做任务链图（先线性前置）；
- 不做重复/每日任务刷。

## 依赖
M18-00、M17-03

## 验收标准
1. 任务数据化：目标（收集 N 个物品/完成动作/到达地点）、条件、奖励、前置任务。
2. 任务进度实时追踪并持久化（读档继续，不重置）。
3. 通过对话或面板交付，完成触发奖励（物品/金钱/好感度）。
4. 改 quests.json 重载生效，缺失条目明确报错。

## 测试命令
```powershell
cargo fmt --all -- --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && cargo build --workspace --release
```
实机：接任务→完成条件→交付→奖励入包→读档进度保留。

## 风险
- 任务条件与事件系统（M17-09）耦合 → 任务条件监听事件总线，不直接轮询；
- 进度丢失 → 任务状态入 WorldSnapshot 并单测往返。
