# 70 性能与测试度量

> 状态：P4（2026-10）——覆盖率 / wasm 条件编译 / 平台矩阵 / 趋势库 / 编译 / 二进制 / 包体，
> 从"这次 vs 上次"升级为"可重复、可判红、可离线复核、有历史"的度量。
> 配套计划：[tasks/plan/P4-性能与测试度量.md](../tasks/plan/P4-性能与测试度量.md)。

## 0. 哲学

- **没跑 ≠ 通过**：任何一步打印 `BLOCKED`/`skipped` 都不是通过；退出码 `3` 是显式环境受限，
  必须在答复里写原因。
- **基线只由 `--update` 生成**：带 `-Reason` + 干净工作树；基线 diff 进评审，`git_dirty` 不能更新。
- **时间类指标同指纹 + ≥3 样本中位数**；确定性指标（覆盖率/几何量/字节数）跨指纹可比。
- **`history/*.jsonl` 是事实源**，`trend.sqlite` 可重建，`baselines/*` 人工确认。
- **不新增 Rust 依赖、不引入外部 SaaS**：扫描器是 Node 零依赖，趋势库是 Python stdlib `sqlite3`。

## 2. 退出码契约（所有门统一）

| 码 | 含义 | 示例 |
|---|---|---|
| 0 | 通过 | `cfg_coverage_ok wasm_attrs=48 covered=48` |
| 1 | 判红/错误 | 测试失败、坏 schema、清单漂移、缺必需文件 |
| 2 | 回归/过期 | 覆盖掉 0.5pp、p95 +5%、豁免过期 |
| 3 | BLOCKED（≠通过） | 缺工具、缺基线、缺历史样本 |

## 3. 七个域

### 3.1 Rust 代码覆盖率（P4-01）

- 采集：`cargo llvm-cov --workspace --all-features --locked --no-fail-fast
  --ignore-filename-regex 'vendor[\\/]|target[\\/]' --json --summary-only`（从 `engine/` 跑）。
- 归一化：`node scripts/metrics/coverage-summary.mjs` → `coverage-v1`（overall + per-crate 表，
  **口径含测试代码**，报告必须写明）。
- 门：`scripts/verify/check-coverage.ps1`——总行覆盖掉 `>0.5pp` 判 2；单 crate（源码行 ≥200）
  掉 `>2.0pp` 判 2；缺工具/缺基线退 3；测试失败退 1（`--no-fail-fast` 不掩盖红测试）。
- 自测：`scripts/test/test-coverage-gate.ps1`（5 用例）。

### 3.2 wasm 条件编译覆盖（P4-02）

- 扫描：`node scripts/metrics/cfg-inventory.mjs`——剥离注释/字符串/字符字面量后提取
  `#[cfg]`/`#[cfg_attr]`/`cfg!`；稳定 key 不含行号；`--check` 防漂移。
- 当前实况（2026-10-20 扫描器输出，计划文件的 84/35 是开工前快照，以清单为准）：
  `wasm_attrs=48`、`wasm_macros=4`、`not_wasm_attrs=37`；539 rs 文件、398 站点
  （`metrics/inventory/cfg-sites.json` 是跟踪事实源，工作树漂移会以 `--check` 判红）。
- 覆盖断言：每个 wasm 站点所在 crate ∈ wasm cell 直接包或 `cargo tree --target wasm32` 闭包；
  `gpu-web-probe` 必须被显式 check（独立 wasm 探针，不在 `game_web` 闭包）；
  `assetc/editor/game/rustlua-assets-import` 是设计上的 native-only，登记豁免即可。
- 门：`scripts/verify/check-cfg-coverage.ps1`；自测 4 反例 + 基座（`scripts/test/test-cfg-coverage.ps1`）。

### 3.3 多平台矩阵（P4-03）

- workflow：`.github/workflows/matrix.yml`——7 cell（Windows ×3 blocking；Linux/macOS ×4 advisory）。
- 档位事实源：`metrics/promotion.json`；`scripts/verify/check-matrix-policy.ps1 -List/-Check/-Summarize`。
- 晋升判据：advisory 在 `main` 连续 2 次绿 + 无 flaky → `experimental=false`；到期仍黄/红判 2。
- 运行期宿主矩阵不重复造：桌面 = `verify.ps1 -Mvp`，WebGL = `verify-webgl-bundle.ps1`，
  微信 = `verify-wechat-minigame.ps1`；本项只证明编译。

### 3.4 趋势库（P4-04）

- `scripts/metrics/trend_db.py`：`rebuild/ingest/report/check/query/prune`；
  表 `runs/samples/artifacts/schema_migrations`；`samples` 上 `(domain, workload, metric, created_at)` 索引。
- 适配器：`wp0_3d_stress`（wp0-v3）、`wp0_scene_frame`/`wp0_ecs_storage`、
  `ecs_stress`/`sprite_stress`/`tilemap_stress`（通用 perf JSON）、`jhyt_m19_soak`、
  `editor_perf`（31 场景文本，解析失败标 `unparsed` 退 1）、`coverage-v1`/`compile-v1`/`binary-v1`/`package-v1`。
- 每个适配器写 `source.path` + `sha256`；`run_id` 由稳定内容生成（排除 ts），幂等可去重。
- 判红：同指纹最近 `min_samples`（默认 3）个 run 的中位数为参考；p95 +5%、p99 +10%、
  `cpu_peak_bytes` +10%；几何量/分配次数任何变化判 2（docs/54 红线）；覆盖 −0.5pp / 单 crate −2.0pp；
  样本不足退 3。

### 3.5 编译时间（P4-05）

- `scripts/metrics/measure-build.ps1`：`-Mode check|test|release`、`-Cold`（必须 `-Yes`）、
  `-Incremental <crate>`；专用 `CARGO_TARGET_DIR=artifacts/metrics/target-compile`；≥3 次 min/median/max。
- `scripts/metrics/parse-cargo-timings.mjs`：从 `cargo-timing*.html` 的 `UNIT_DATA`/`CONCURRENCY_DATA`
  算 wall/critical/parallelism/per-crate。
- 门：冷构建只 nightly；PR 只跑 `check_warm` 并打印 delta（不判红）；同指纹 ≥3 样本才判。

### 3.6/3.7 二进制与包体（P4-06/07）

- `scripts/metrics/measure-artifacts.mjs --kind binary`：game/editor/assetc exe + game_web wasm/js；
  `bytes_raw`/`bytes_gzip9`/`bytes_brotli11`/`sha256`/mtime；`llvm-size` 分节（不可用打印
  `sections=unavailable`，不伪造 0）。缺文件标 `missing`，`-RequireAll` 判 1；`partial=true` 不更新基线。
- `--kind package`：PC / 引擎绿色版 / WebGL（wasm/js/字体/pack 分账）/ 微信（`game.json` 口径
  主包 = 总 − 分包，4MiB/20MiB 配额）/ `.rlb` 资源容器。
- 门槛：exe +3% 或 +128 KiB、wasm +3% 或 +64 KiB、editor +256 KiB；总包/主包 +3%；组件 +10% 附归因。

## 4. 基线更新流程

1. 跑采集/测量 → 产出 JSON（`artifacts/metrics/`）。
2. 人工审阅报告（`trend_db.py report` / 覆盖率 summary）。
3. `git status` 必须干净；`--update` 带 `-Reason "..."`（如"首份覆盖率基线"）。
4. 基线 diff 进评审；`metrics/history/` 的写入由 CI bot 或人工 merge。

## 5. 豁免怎么写（allowlist）

`metrics/allowlist.json` 的 `entries`：每条 `{id, domain, reason, owner, review_by}`；
`review_by` 过期 → 判 2，无黄期。豁免不是无限期的：到期要么修好、要么重新确认。

## 6. 哪些数字跨机可比、哪些只是记录

| 域 | 跨机可比？ | 说明 |
|---|---|---|
| 覆盖率（lines/functions/regions %） | 是 | 确定性，同基线比 |
| 几何量/分配次数（draw_calls/instances/alloc_count） | 是 | 确定性，docs/54 红线 |
| 字节数（binary/package） | 是 | 同 commit 打包方差 >2% 先修可复现性 |
| p95/p99/cpu_peak（perf） | 同指纹 | runner 硬件漂移→时间列可标 advisory，几何/字节仍判红 |
| 编译时间（wall_ms） | 同指纹 | 受杀毒/索引影响，只对中位数判红 |

## 7. 与旧口径的关系

- `baselines/m19-soak.json` 是旧单份基线的代表：P4 把它迁进趋势库（适配器 `jhyt_m19_soak`），
  不删除旧文件、不修改数字，注明迁移来源。
- `verify.ps1 -Benchmarks` 的 3D committed 基线：先读 `metrics/baselines/wp0-3d-stress.json`，
  再回退 `baselines/wp0-3d-stress.committed.json`。

## 8. 命令速查（本地）

```powershell
# 工具与基线
pwsh -NoProfile -File scripts/release/install-metrics-tools.ps1 -Check
pwsh -NoProfile -File scripts/verify/check-toolchain-lock.ps1

# 覆盖率（采集在 engine/ 目录跑）

# 趋势库
python scripts/metrics/trend_db.py rebuild --history metrics/history --db artifacts/metrics/trend.sqlite
python scripts/metrics/trend_db.py ingest --input artifacts/metrics --history metrics/history
python scripts/metrics/trend_db.py report --domain all --since 90d
python scripts/metrics/trend_db.py check --policy metrics/policy.json
python scripts/test/test-trend-db.py

# 编译时间（冷构建必须 -Yes）
pwsh -NoProfile -File scripts/metrics/measure-build.ps1 -Mode check -Cold -Yes -Out artifacts/metrics/compile-check.json
node scripts/metrics/parse-cargo-timings.mjs --check
node scripts/test/test-cargo-timings.mjs

# 二进制与包体
node scripts/metrics/measure-artifacts.mjs --kind binary --out artifacts/metrics/binaries.json
node scripts/metrics/measure-artifacts.mjs --kind package --project examples/game_jhyt --out artifacts/metrics/packages.json
node scripts/test/test-package-metrics.mjs

# 总门
pwsh -NoProfile -File scripts/verify/verify.ps1 -Metrics
```
