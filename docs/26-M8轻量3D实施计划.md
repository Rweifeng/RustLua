# M8 轻量 3D 实施计划

- 项目：P2 Rust + Lua 游戏引擎
- 制定日期：2026-08-22
- 当前基线：`v0.7`
- 状态：READY

## 1. 当前判断

M6 2D 样板游戏和 M7 工程化/发布已完成，当前 `HEAD` 为 `v0.7`。已有可复现的 Windows Release 发布包、资源扫描/缓存/打包、崩溃日志和性能基线。

3D 尚未开始：

- `game_runner` 当前使用仅有颜色输出的 2D 纹理管线，RenderPipeline 没有深度附件；
- `engine_core` 尚无 `Vec3`、四元数、矩阵、Mesh、Camera3D 和材质模型；
- `assetc` 可以识别 `gltf/glb` 扩展名，但尚未解析顶点、索引、材质或动画；
- 场景格式、Lua API、编辑器 Inspector 尚无 3D 组件；
- 当前游戏资产目录没有 glTF/GLB 样例资产。

因此 M8 的第一目标不是直接做完整 3D 编辑器，而是完成一条可发布的最小链路：

`GLB → CPU 资源 → GPU Mesh/材质 → Camera3D + Depth → 光照/阴影 → Lua 控制的 3D Demo → 发布包`

## 2. 范围与非目标

### 目标

1. 支持 glTF 2.0 `.gltf` 和 `.glb` 的静态 Mesh、材质、纹理和节点层级；
2. 增加右手/坐标约定明确的 3D 数学、Transform3D 和透视 Camera3D；
3. 支持深度测试、基础方向光、基础阴影和金属度/粗糙度材质；
4. 支持一个最小骨骼动画、视锥剔除和相同 Mesh 实例化；
5. 将 3D 资源接入 assetc、场景、Lua、编辑器检查和 Windows 发布包；
6. 用一个可移动角色、静态场景、动态光源、阴影和动画完成 3D Demo。

### 非目标

- 不做完整 PBR 生产级材质、后处理、反射探针、地形编辑器和复杂 DCC 工作流；
- 不重写现有 2D 场景格式，不破坏 `v0.7` 项目和发布路径；
- 不做多人、主机平台、移动平台或通用渲染图框架；
- 不在没有性能数据前引入多线程渲染、GPU-driven indirect 或自研 glTF 解析器。

## 3. 实施顺序

```text
M8-00 基线与技术决策
  → M8-01 Math3D / Transform3D / Camera3D
  → M8-02 glTF/GLB CPU 导入与资源缓存
  → M8-03 Mesh / Material GPU 上传
  → M8-04 Depth + 3D Render Pass
  → M8-05 光照、阴影与基础 PBR
  → M8-06 场景、Lua 与编辑器接入
  → M8-07 骨骼动画
  → M8-08 视锥剔除与实例化
  → M8-09 3D Demo、性能和发布验收
```

M8-07 与 M8-08 在 M8-05 通过后可并行开发；M8-09 依赖全部能力完成。

## 4. 任务与验收

### M8-00 基线与技术决策

确认 `v0.7` 标签、工作区质量门、发布包可运行；新增 ADR，明确坐标系、矩阵约定、深度范围、单位、颜色空间、资源所有权和 glTF 库选型；准备一个可再分发的 CC0 或自制 GLB 测试资产，并记录许可。

**验收**：质量门通过；旧 2D Demo 和发布包不回归；ADR、测试资产和第三方许可记录齐全。

### M8-01 Math3D / Transform3D / Camera3D

在 `engine_core` 增加 Vec3、Quat、Mat4、Transform3D、透视投影、LookAt、世界/视图/裁剪空间转换和视锥平面提取。优先使用成熟数学库或小而完整的纯 Rust 模块，避免把矩阵计算塞进 `game_runner`。

**验收**：单位矩阵、平移/旋转/缩放、四元数归一化、投影边界、相机往返和视锥分类均有单测；非法 near/far、FOV、宽高比明确拒绝。

### M8-02 glTF/GLB CPU 导入与资源缓存

在 `engine_core` 建立与渲染无关的导入模型，使用成熟 glTF 解析库读取节点、Mesh primitive、POSITION/NORMAL/UV/索引、材质引用、纹理引用和动画通道；补充 assetc 的导入/错误报告和 ImportCache 版本号。

**验收**：`.gltf`、`.glb`、缺失 buffer、非法 accessor、无索引 primitive 和不支持扩展都有测试；导入失败非零且包含文件/节点原因；源未变化复用缓存，导入器版本变化可重建。

### M8-03 Mesh / Material GPU 上传

实现 Mesh 顶点/索引缓冲、材质绑定、纹理颜色空间和资源生命周期；将 2D 与 3D 上传路径隔离在明确的 Renderer 资源边界内，避免继续扩大 `game_runner/src/main.rs` 的单文件职责。

**验收**：静态三角形和测试 GLB 能创建 GPU 资源并绘制；索引越界、空 Mesh、超大缓冲有清晰错误；CPU 导入结果与 GPU 缓冲数量一致。

### M8-04 Depth + 3D Render Pass

增加 depth texture、depth view 和 resize 重建；建立 3D pipeline，使用模型/视图/投影矩阵和深度比较；保留现有 2D pass 的顺序和行为，明确 2D/3D 的深度状态。

**验收**：前后遮挡顺序由深度决定而非提交顺序；窗口 resize 后深度附件有效；无深度资源、设备限制和 surface 恢复分支不 panic；离屏测试或 Demo 证据可复现。

### M8-05 光照、阴影与基础 PBR

先实现方向光和 Lambert/基础金属度-粗糙度 BRDF，再增加 shadow map 和光空间矩阵。颜色纹理按 sRGB、法线/金属度/粗糙度按线性数据处理。RenderDoc 检查关键 Pass 和深度资源。

**验收**：方向光改变会影响模型明暗；阴影随角色/光源变化；材质通道绑定正确；RenderDoc 或等价 GPU 证据记录关键 Pass；旧 2D 渲染不受影响。

### M8-06 场景、Lua 与编辑器接入

扩展场景模型和版本迁移，加入 Transform3D、MeshRenderer、Camera3D、Light 组件；为 Lua 提供创建/查询/变换/相机和光源的最小 API；编辑器 Inspector 先支持查看和编辑，不做 3D Gizmo；assetc package 和 `--pack` 保持兼容。

**验收**：旧场景可加载；新场景保存/加载 roundtrip；Lua 可移动角色和切换相机；编辑器 `--check`、发布包和缺失资源错误均通过；格式版本和迁移测试齐全。

### M8-07 骨骼动画

导入 glTF skin、joint hierarchy 和 animation sampler/channel；CPU 或 GPU 选择以可解释的性能数据为依据，先支持一个动画状态和循环播放，再接入 Lua 查询状态。

**验收**：动画时间推进、循环、暂停和非法关节引用有单测；Demo 中角色确实运动；停止/重启/切场景不残留旧动画状态。

### M8-08 视锥剔除与实例化

使用 M8-01 的包围盒/包围球和 Camera3D 视锥做 CPU 剔除；对相同 Mesh/材质提供实例数据缓冲，先保证结果正确再测量收益。

**验收**：视锥内外分类边界有单测；剔除不会改变可见结果；实例数、绘制数和 CPU/GPU 时间有基线；无剔除/无实例化回退路径可用。

### M8-09 3D Demo、性能和发布验收

制作可移动角色、静态场景、动态光源、基础材质、阴影、一个动画和调试 overlay；接入 assetc package、Release 构建、目录隔离和含空格路径测试；新增 M8 验收矩阵和证据目录。

**验收**：Release 发布包可运行；角色移动、深度遮挡、光照、阴影、动画和相机全部可复现；至少记录 100/1000 Mesh 实例、场景加载、CPU/GPU 帧耗时和 Draw Call；无 P0/P1；创建 `v0.8-3d-foundation` 标签。

## 5. 第一阶段执行清单

1. 将 `docs/25-M6收尾与M7工程化实施计划.md` 标记为历史计划，不改写其当时基线描述；
2. 在 `docs/04-acceptance-matrix.md` 增加 M8 行，并明确未完成项为 `PENDING`；
3. 补一条 M8 坐标/渲染 ADR 和测试资产许可记录；
4. 建立 `tasks/active/`，先创建 `M8-00` 和 `M8-01` 任务文件；
5. 先完成 Math3D 与 Camera3D 的纯 CPU 单测，再接触 wgpu 和 glTF；
6. 每个任务完成后执行 fmt、clippy、workspace test、Debug/Release build，并归档证据。

## 6. 质量门与停止条件

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
cargo build --workspace
cargo build --workspace --release
git diff --check
cargo run -p assetc -- --project C:\GitHub\p2\game --check
cargo run -p game_runner -- --project C:\GitHub\p2\game --check
```

出现以下任一情况时暂停扩展功能并先修复：旧 2D 回归、场景格式无法向后兼容、GPU 资源错误只能 panic、导入失败无法定位、或性能没有可比较的基线。

## 7. 主要风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 3D 改造继续堆积在 game_runner 单文件 | P1 | 先抽出导入模型、GPU 资源和 RenderPass 边界 |
| glTF 扩展和真实资产复杂度超出范围 | P1 | 首版锁定静态 PBR + 一个 skin，明确 unsupported 错误 |
| 场景格式破坏 v0.7 | P0 | 版本递增、迁移测试、旧 2D 场景回归 |
| 深度/阴影导致 2D 回归 | P1 | 独立 2D/3D pass 和 depth state，保留 2D Demo |
| GPU 性能无法跨机器比较 | P2 | 同机记录 CPU/GPU/Draw Call，报告硬件和驱动信息 |
| 测试资产许可不清 | P2 | 只使用自制或 CC0 资产，并在 THIRD_PARTY.md 登记 |

## 8. 通过条件

M8-00 至 M8-09 全部 PASS；旧 2D 项目和 `v0.7` 发布路径兼容；Debug/Release 质量门通过；3D Demo 可发布运行；glTF、深度、光照、阴影、动画、剔除和实例化均有自动化或可复现证据；完成 `v0.8-3d-foundation` 标签。
