# Alpha / Beta / Release Candidate 质量门与发布清单（M20-05）

本文定义 `game_jhyt` 从 Alpha 到 Beta 再到 Release Candidate 的**质量门、内容冻结、
缺陷分级、性能基线与发布清单**。它是可复现的检查表：每一阶段都必须留下命令与输出证据。

## 1. 缺陷分级与阻断条件

| 级别 | 定义 | 示例 | 阻断 |
|---|---|---|---|
| **P0** | 无法开始/继续游玩、数据损坏、崩溃、发布包不可启动 | 新档无法进入玩法地图；读档崩溃；发布目录缺 `pack/manifest.txt`；`game.exe --pack … --check` 失败 | 阻断任何阶段 |
| **P1** | 核心剧本被卡住、规则错误、存档丢失、关键平台不可用 | 种子买不到导致无法种植；订单无法交付；30 天/100 次读档失败；桌面发行包启动失败 | 阻断 Alpha/Beta/RC 出门 |
| **P2** | 体验缺陷、缺失的非核心内容、已知限制 | 天气无随机排程；无手柄震动；鼠标框选未实现（发布包内改键落点问题见 §5 已知限制 4，已由 M31 修复） | 允许记录后放行 |

判定原则：**不允许用表现层修补掩盖规则错误**；发现 P0/P1 时阻断验收，**不得通过删除或放宽测试**降级通过。
测试结果不可复现（依赖硬件/浏览器/时间）时，必须标注为「环境受限未执行」并给出复现命令与预期，
不得记为通过。

### 已知限制清单（P2，随发布说明给出）

1. **天气恒为晴**：`scripts/weather.lua` 的 `set()` 无调用方（无随机天气排程），雨天才走的分支
   （NPC 日程 `rain_place`、农田 `rain_watered`）只能手动注入状态验证。
2. **浏览器内玩法未实现（M31/P3 实测定位，非"未验证"）**：`scripts/verify-webgl.ps1` 的浏览器契约
   检查通过（Edge 153 无头、`webgl2=true`、manifest 662 项、启动场景与首资源可取、缺失 404）；
   本机已装 `wasm32-unknown-unknown` + `wasm-bindgen`，`package.ps1 -Platform webgl` 产出
   `pkg/game_web.js`（17.0 KB）+ `pkg/game_web_bg.wasm`（39.6 KB，`webgl_package_ok files=6`）。
   新增产物层验收 `scripts/verify-webgl-bundle.ps1` 后确认：wasm **真实加载**、页面**进入 Lua 执行**，
   但 `game_jhyt` 随即停在未实现的宿主 API 上——
   `[string "scripts/main.lua"]:6545: attempt to index a nil value (global 'item')`，
   缺失 17 个桌面引擎顶层全局（`app, asset, calendar, clock, container, data, day, event, grid,
   interact, inv, item, light, map, shop, sprite, tag`）；`web-runtime.js` 目前是演示级子集。
   结论与两条修法见 `docs/32` §4、`docs/37` 4-24。**PC 发行不受影响**；WebGL 按"实验性、不承诺
   浏览器内可玩"处理，发布说明必须照此写明。
3. **真实手柄实机未验证**：本机无 XInput 设备（`jhyt_m31_pc_release` 采样
   `connected=false slots=[]`），动作层由 `jhyt_m20_gamepad` 用 `FakeBackend` 覆盖，
   设备插拔步骤未执行（`docs/33`、`tasks/done/M20-06-*.md`）。
4. **~~发布包内改键落点~~（已修复，M31/P3）**：发布包形态（`<exe>/pack` + 同级

   （`%APPDATA%\<publish_name>`，`RUSTLUA_USER_DIR` 可覆盖），包内字节不再被玩家数据污染；
   首次运行播种默认值，升级不覆盖玩家设置。开发工程形态不变（见 `docs/50`）。
5. **手柄型号差异**：固定 `0..15` 按钮 / `0..5` 轴抽象编号契约，不做设备专有按键提示或映射表；
