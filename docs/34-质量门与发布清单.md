# Alpha / Beta / Release Candidate 质量门与发布清单（M20-05）

本文定义 `game_jhyt` 从 Alpha 到 Beta 再到 Release Candidate 的**质量门、内容冻结、
缺陷分级、性能基线与发布清单**。它是可复现的检查表：每一阶段都必须留下命令与输出证据。

## 1. 缺陷分级与阻断条件

| 级别 | 定义 | 示例 | 阻断 |
|---|---|---|---|
| **P0** | 无法开始/继续游玩、数据损坏、崩溃、发布包不可启动 | 新档无法进入玩法地图；读档崩溃；发布目录缺 `pack/manifest.txt`；`game.exe --pack … --check` 失败 | 阻断任何阶段 |
| **P1** | 核心剧本被卡住、规则错误、存档丢失、关键平台不可用 | 种子买不到导致无法种植；订单无法交付；30 天/100 次读档失败；桌面发行包启动失败 | 阻断 Alpha/Beta/RC 出门 |
| **P2** | 体验缺陷、缺失的非核心内容、已知限制 | 天气无随机排程；无手柄震动；鼠标框选未实现（发布包内改键落点问题见 §5 已知限制 4，已由 M31 修复） | 允许记录后放行 |

判定原则：**不允许用表现层修补掩盖规则错误**；发现 P0/P1 时阻断验收，**不得通过删除或放宽测试**降级通过。
测试结果不可复现（依赖硬件/浏览器/时间）时，必须标注为「环境受限未执行」并给出复现命令与预期，
不得记为通过。

### 3.5 本地 pre-commit 门（优化项 11）

CI 的 `lint` job 是 `build-test` / `gates` / `web-evidence` 三个 job 的 `needs` 前置，它一红整条流水线
什么都不跑。而 lint 失败（`cargo fmt --all -- --check`、`clippy -D warnings`、行尾空白）是纯本地就能
判定的，推到 CI 才发现的代价是"提交—等—红—改—再推"一整轮。本次把这三条搬到提交前。

**机制**：`git config core.hooksPath git-hooks`，让 git 从仓库里那份**被跟踪、能 review**的目录取钩子，
而不是各人 `.git/hooks/` 下互不可见的副本。

为什么不选清单里另外两个候选（都是当场比过本机事实后否掉的）：

- `cargo-husky`：要把第三方 build script 作为 dev-dependency 塞进 workspace 成员，而 `engine/Cargo.toml`
  目前是虚拟清单（只有 `[workspace]`，没有 root package），得先造一个宿主 crate；且 hook 由依赖的
  build script 在编译期写入，行为不透明——"为什么我 .git/hooks 里多了东西"没人解释得了。
- `pre-commit` 框架：生态标准、扩展性好，但队友必须先 `pip install pre-commit`，首次运行还要联网建
  虚拟环境。本机事实是 Python 3.14 在、`pre-commit` 不在，且仓库所有门禁的既有口径是
  `scripts/*.ps1` + 退出码（0/1/3）。为一个 fmt+clippy 引入第二套依赖管理不值得。
  代价也说清楚：原生 hook **要每人跑一次安装脚本**，装没装从结果上看不出来——所以配了 `-Status` 体检，
  并且把 hook 自身的逻辑送进了 CI（见下）。

**跑什么**（与 `quality.yml` 的 lint job 一一对应，命令串由 `scripts/test/test-git-hooks.ps1` §C 反查 CI 原文比对，
CI 改了参数而 hook 没跟上会直接判红）：

| 步 | 命令 | 本机实测（热缓存） |
|---|---|---|
| 暂存区空白/冲突标记 | `git diff --cached --check` | <0.1s |
| 格式 | `cargo fmt --all -- --check` | 7.4s |
| 静态检查 | `cargo clippy --workspace --all-targets -- -D warnings` | 9.0s |

**作用域：`rustlua.scope`，默认 `commit`**（本条是与 CI 最要紧的一处对齐，2026-10-06 补）。CI 的 lint job
检查的是**这个提交**——它 checkout 出那个 commit 再看内容；而 fmt / clippy 这两条命令看到的是**整棵工作树**。
单人独占一棵树时两者几乎等价，但本仓的实际工作方式是**多会话共享一棵树**，差别就致命了：

- 现象：另一个会话的在途/未跟踪文件（如 `engine/crates/game/examples/jhyt_m6x_*_prefab.rs`）格式不合格，
  于是**我的**提交被挡住——而 CI 对我这个提交是绿的。
- 代价不是"多等一会儿"，而是训练所有人去按 `RUSTLUA_SKIP_PRECOMMIT=1`。门禁一旦被习惯性绕过就名存实亡，
  而"没人跑得起门"正是缺陷能在 HEAD 里活过多个提交的土壤（§6 已记过一次同款事故「门禁波动（并行会话）」）。

两种口径：

| `rustlua.scope` | 行为 |
|---|---|
| `commit`（默认） | 只有**本次提交里的**文件才判红；提交之外的失败逐条点名，结论按 `PARTIAL` 措辞报告——不冒充"通过"，也不越权替别人的在途活儿判红 |
| `worktree` | 旧口径：工作树里任何一处失败都拦提交（想把整棵树焊干净时用） |

切换 `git config rustlua.scope worktree` / 还原 `git config --unset rustlua.scope`；非法值显式报警并回落
`commit`，不静默降级。判据由 §B 的三条反面对照钉住：提交之外的未格式化 `.rs` **不拦**（B7）、同一场景下
`worktree` **重新拦住**（B8）、暂存区自己的未格式化 `.rs` **仍然判红且点名文件**（B9）。

除作用域外，另有两处与 CI 的刻意差异，都是为了防止"太慢所以被人关掉"：

1. clippy 默认 **不带** `--all-features`（`rustlua.clippy=fast`）。实测热缓存下 fast 9.0s / full 9.2s 几乎
   无差，但全 feature 图冷缓存首轮 50.9s——差异只在缓存冷时伤人。要和 CI 逐字对齐：
   `git config rustlua.clippy full`；极端情况只要 fmt：`= off`（此时结论打 `PARTIAL`，不冒充 `ok`）。
2. 本次暂存没碰 `engine/**` 的 `.rs/.toml/.lock` 时整段跳过——改文档、改示例 Lua 不该等 16 秒。
   代价见下面"已知边界"最后一条。

**已知边界**（写清楚，不假装完美）：

- cargo 读的是**工作区**，不是暂存区。原生 hook 不做 stash（编译失败会把人的改动留在 stash 里），
  所以当同一文件"已暂存 + 又有未暂存改动"时，hook 会先打印受影响文件名单，再给出结论。作用域机制
  （见上）把这条限制的后果收窄到"只有本次提交里的文件才判红"，但同一文件的暂存/工作区漂移仍是窄口子：
  `commit` 口径下判红用的是工作区版本，理论上可能比暂存版本严——方向偏严，不会漏放。
- 找不到 `cargo` 时**判红而不是放行**（跑不了的门禁不能算测过）。GUI 客户端的 PATH 里没有 cargo 是
  真实场景，正解是命令行提交或 `git config rustlua.hooks off` 明确关掉，两种都会留下话。
- 逃生门 `RUSTLUA_SKIP_PRECOMMIT=1` / `git commit --no-verify` / `rustlua.hooks off` 都只把失败留给 CI，
  输出的措辞按"跳过（SKIPPED）"而不是"通过"来写。
- CI 的 `Diff check` 步写的是 `git diff --check`（工作区 vs 索引），在干净检出上恒真；本地这一条查的是
  `--cached`，否则查的根本不是将要提交的内容。
- **"没碰 Rust 就跳过"只保证本次提交没引入新问题，不保证 CI 绿**：`quality.yml` 的触发路径含
  `docs/**`、`tasks/**`，所以纯文档推送仍会跑全量 fmt/clippy，仓库里既有的格式债照样让那种推送变红。
  要把旧账一起验就跑 `scripts/verify/verify.ps1`（本地门只负责"本次提交"这一格）。

**首次安装**：`powershell -NoProfile -File scripts/repo/install-git-hooks.ps1`（会顺手把 hook 的行尾修回 LF——
Git for Windows 装在 `C:\Program Files\Git\etc\gitconfig` 的 `core.autocrlf=true` 会把 sh 脚本检出成 CRLF，
表现为"hook 装了却每次提交都报 `bad interpreter: /bin/sh^M`"；`.gitattributes` 用 `git-hooks/* text eol=lf`
从源头钉住）。macOS/Linux 还需要索引里的执行位：文件进版本库后再跑一次安装脚本会自动 `--chmod=+x`。

**这次装完就抓到一次真问题**：在 `engine/crates/engine/src/core/lod.rs` 的未提交改动里，
一条 `#[error("…")]` 超行宽，`cargo fmt --all -- --check` 判红（本机 rustfmt 1.9.0-stable / rustc 1.98.0）。
按 CI 的口径这次提交会在 `Format` 步红掉、连带三个下游 job 全部不跑——正是本项要消掉的循环。

## 临时产物：统一写 `.temp/`（已忽略）

**约定**：门/脚本/示例产生的**临时产物**（dump、抓图、对账中间文件等）一律写**项目根的 `.temp/`**，
不要写仓库根——根目录出现 `.tmp_*` 会让 `git status` 变脏、也容易误提交。

- `.temp/` 已被忽略（`.gitignore` 的 `**/.temp/`）✓；目录不存在时由写入方按需创建。
- **例外（不要搬）**：编辑器**原子保存**用的 `.document.json.<token>.tmp` 之类，是目标文件**同目录**的
  临时兄弟文件——搬走就破坏了同目录原子重命名，它们**必须**留在原处。

## 现场纪律（打包与编辑）

这两条是 **B8（删旧世界）** 期间各花掉半小时才定位的，写在这里因为它们**不是一次性知识**。

### 一、打包前必须让开发者工具彻底退出（不然产物是陈旧的）

- 症状：`package.ps1` 看起来跑完了（甚至有 `wechat_minigame_package_ok`），但**产物没更新**；
  实测现场是 `.staging-*` 残留 + 原子交换回滚。这一点现在是**被门守住的**：
  `release-atomic.ps1` 在动任何文件之前做**锁探测**（把发布根下每个条目挪走再挪回来），
  命中就抛具名错误 `release dir is locked (probe ... 挪不动)`，**不再静默回滚**。
- 纪律：打包前 `cli.bat quit`；**必要时硬杀** `wechatdevtools` / `wxfilewatcher*` 并等几秒。
- 另一半是**探针读不到上报**（`verdict=no-report`）：同样先清场再重试 —— 驱动自带的 `cli quit`
  **不够**，残留实例会让冷启拿不到项目。

### 二、编辑 `.ps1` 之后必须确认 UTF-8 BOM 还在

- 症状：文件丢了 BOM 之后，**PowerShell 5.1 按 ANSI 解析**，文件里的中文会打断字符串字面量，
  一次报出**上百个解析错误**，而且报错位置离真因很远（实测 123 个，第一条落在第 141 行的无关标记上）。
- 门：`scripts/verify/check-docs.ps1` 的 `ps1_bom_ok`（当前 33 个文件）就是为它存在的；改完 `.ps1` 一律
  **补回 BOM 并重跑这条门**。
- 提醒：某些编辑工具（含本仓协作时用到的 `edit` 类工具）**不会保留 BOM**，所以这不是"编辑器怪癖"，
  而是一条**每次都要做的动作**。

> 顺带一条同类教训（注释与代码脱节）：B3 曾因一段**过期的文档注释**（声称 JS 侧还在打包 164 B）
> 让一条**早就可以删**的 legacy 分支多活了一阵；删代码时请把指向它的注释一起处理。
