# Alpha / Beta / Release Candidate 质量门与发布清单（M20-05）

本文定义 `game_jhyt` 从 Alpha 到 Beta 再到 Release Candidate 的**质量门、内容冻结、
缺陷分级、性能基线与发布清单**。它是可复现的检查表：每一阶段都必须留下命令与输出证据。

## 1. 缺陷分级与阻断条件

| 级别 | 定义 | 示例 | 阻断 |
|---|---|---|---|
| **P0** | 无法开始/继续游玩、数据损坏、崩溃、发布包不可启动 | 新档无法进入玩法地图；读档崩溃；发布目录缺 `pack/manifest.txt`；`game.exe --pack … --check` 失败 | 阻断任何阶段 |
| **P1** | 核心剧本被卡住、规则错误、存档丢失、关键平台不可用 | 种子买不到导致无法种植；订单无法交付；30 天/100 次读档失败；桌面发行包启动失败 | 阻断 Alpha/Beta/RC 出门 |
| **P2** | 体验缺陷、缺失的非核心内容、已知限制 | 天气无随机排程；无手柄震动；鼠标框选未实现；发布包内改键写入 `<release>/pack/settings.toml`（重发布会被覆盖，需迁移到用户目录，见 `docs/35` §6；工程根 `settings.toml` 现会随 `package.ps1` 复制进包，仅「工程 → 发布包」方向） | 允许记录后放行 |

判定原则：**不允许用表现层修补掩盖规则错误**；发现 P0/P1 时阻断验收，**不得通过删除或放宽测试**降级通过。
测试结果不可复现（依赖硬件/浏览器/时间）时，必须标注为「环境受限未执行」并给出复现命令与预期，
不得记为通过。

## 2. 阶段门槛

### Alpha（功能完整可玩通）

进入条件：M19-01/M19-02/M19-04 的交付物齐备。

- [ ] 核心剧本 headless 回归通过（`jhyt_m19_slice`，见 §3）
- [ ] 三张地图 + NPC/种田/任务/商店/采集/战斗/制作/睡觉存档全链路可达
- [ ] HUD/背包/对话/任务/商店/暂停可用（键盘；手柄按 M20-08 结果）
- [ ] 无 P0；P1 全部有关闭计划与负责人
- [ ] `cargo fmt/clippy/test/build` 全绿

### Beta（内容冻结 + 性能基线）

进入条件：Alpha 出门 + 内容冻结（冻结后只修缺陷，不新增地图/核心系统/第二条主线）。

- [ ] 30/60/120 FPS 规则结果一致（`jhyt_m19_soak`）
- [ ] 30 天长跑无状态漂移 + 100 次读档循环通过（磁盘往返 100 次 + 真实 runtime 20 次 + 快照 3000 次）
- [ ] 干净发行目录启动（`package.ps1 -SelfTest`，含空格路径、无源码/target）
- [ ] 性能基线落盘（`artifacts/baselines/m19-soak.json`，字段见 §4）
- [ ] 无 P0/P1

### Release Candidate（回归全绿 + 发布清单）

进入条件：Beta 出门 + 发布清单 §5 全部勾选。

- [ ] `scripts/verify.ps1` 全绿（fmt/clippy/test/build/git diff check/game --check/editor --check）
- [ ] `scripts/verify.ps1 -Mvp` 全绿（headless 套件 + 干净目录自测）
- [ ] `scripts/test-release-atomic.ps1` → `release_atomic_ok cases=4`（原子发布/回滚）
- [ ] 浏览器集成回归（`scripts/verify-webgl.ps1`）：平台契约通过；WASM 构建受限时明确标注
- [ ] 任务文档（`tasks/done/*`）实现记录/验收证据/限制完整；CHANGELOG 已更新
- [ ] 无未解决 P0/P1（P2 允许带清单发布）

### 已知限制清单（P2，随发布说明给出）

1. **天气恒为晴**：`scripts/weather.lua` 的 `set()` 无调用方（无随机天气排程），雨天才走的分支
   （NPC 日程 `rain_place`、农田 `rain_watered`）只能手动注入状态验证。
2. **浏览器内玩法未验证**：本机离线无法安装 `wasm32-unknown-unknown`，`game_web` 未构建；
   仅平台契约层通过（`docs/32`）。
3. **真实手柄实机未验证**：无物理设备；动作层由 `jhyt_m20_gamepad` 用 `FakeBackend` 覆盖，
   设备插拔步骤未执行（`docs/33`、`tasks/done/M20-06-*.md`）。
4. **发布包内改键落点**：`game.exe --pack pack` 时工程根为 `<release>/pack`，
   `settings.toml` 写到 pack 内，重新发布会覆盖（`docs/35` §6）。
5. **手柄型号差异**：固定 `0..15` 按钮 / `0..5` 轴抽象编号契约，不做设备专有按键提示或映射表；
   无震动、陀螺仪、触屏。
6. **编辑器出口/地点编辑**：降级为只读覆盖层 + 校验 + `文件:行` 定位（`docs/25` §14.7）。
7. **RON 校验强度**：仅做分隔符/字符串配平与行列定位，完整语法解析待引入 `ron` 依赖（M20-01）。
8. **订单 `order_rice` 的发布 NPC**：改为 `npc_lin_xiaoman`（原 `zhao_tiesuanpan` 是商店 keeper，
   `shop.lua` 的交互 priority/range 会抢先，导致其对话不可达）；彻底解决需要「上下文键/焦点」设计（M19-01）。

## 7. 与各任务的关系

本任务**只定义并执行质量门**，不替代玩法/编辑器/平台任务的实现：

- 核心剧本与内容 → M19-01；UI/音频/引导 → M19-02；编辑器工具 → M19-03
- 回归与性能基线 → M19-04；资源校验与诊断 → M20-01；输入/音频/UI 导航 → M20-02
- 发布原子性与回滚 → M20-03；浏览器集成 → M20-04；手柄设备层/映射/面板 → M20-06/07/08
