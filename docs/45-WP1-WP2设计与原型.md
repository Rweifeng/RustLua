# WP1 / WP2：设计与最小原型

## 定位

本阶段在 WP0 证据门完成后启动，但不立即切换现有 RuntimeScene。原型用于验证 typed compile 和父优先空间传播的 API、错误语义及兼容边界。

## WP1 Typed Scene

新增 `core::typed_scene`：

- `TypedScene::compile_v2(&Scene)` 是源格式到运行时 typed 数据的单一边界；
- 已知组件使用 `ComponentId` 和 `TypedComponent`；
- 当前 prototype 覆盖真实源场景出现过的**全部 17 个组件名**（2026-09-17 对 26 个源场景普查）：Transform、Transform3D、Camera3D、Light、MeshRenderer、UiLayout、Container、Text、Image、UiEvents、ButtonStates、Sprite、Tilemap、Collider、Collider3d、Animation、Animation3D；
- MeshRenderer 在编译期生成 `AssetId`；**注意**当前仍按 `path` 单串播种，与资源库的 `path:importer_version` 口径并不相等（见门槛 3）；
- 预计算 parent-first topology；
- 诊断包含 entity id、entity name、component 与 parse error；
- 未知/Lua 动态组件保留在源 Scene，不在原型中静默解释；
- 原型不替换 v2 保存格式，不覆盖源文件。

## WP2 Local / Global Transform

新增 `core::spatial_transform`：

- `LocalTransform { translation: Vec3, rotation: Quat, scale: Vec3 }`；
- `GlobalTransform(Mat4)` 只作为派生缓存；
- 2D 映射到 XY、绕 Z、Z=0、scale.z=1；
- 3D Transform3D 可无损映射；
- `propagate_all` 先实现 correctness-first 的全量父优先传播；
- 明确 missing parent、cycle、invalid local 错误；
- 深度 100 链已由测试覆盖。

兼容原则：旧 v2 的 parent 当前不自动解释成局部空间。只有显式迁移或新 typed 场景启用 SpatialParent 后才走新传播，避免旧项目世界位置突变。

下一步门槛：

1. 深度 1/10/100 benchmark；
2. 旧单实体模型矩阵与新 GlobalTransform 对拍；
3. reparent keep-world API；
4. 非均匀缩放产生剪切时拒绝 TRS 反解；
5. dirty/version 增量传播 prototype；
6. 3D golden、物理回写、骨骼 palette 全量回归后才能接入 runtime。

## 当前结论

原型证明两个工作包可以在不修改 v2 磁盘格式、不替换现有运行时的前提下渐进实施。下一批应先扩大对拍和 benchmark，而不是直接删除字符串场景路径或旧 Transform 类型。
