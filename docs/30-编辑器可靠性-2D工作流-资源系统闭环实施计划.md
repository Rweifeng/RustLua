# 编辑器可靠性、2D 内容生产工作流与资源系统闭环实施计划

- 项目：P2 Rust + Lua 游戏引擎
- 计划版本：0.1.0
- 制定日期：2026-08-24
- 适用基线：当前工作区 `p2`，M0-M9 基础能力已实现，M10 编辑器强化代码已落地但部分真实 GUI/GPU 验收仍待补齐
- 计划状态：READY
- 目标版本建议：`v0.14-editor-production-loop`

> 本计划不以“功能数量最多”为目标，而以一个独立开发者能够持续使用的闭环为目标：
>
> **导入资源 → 在资源浏览器中确认状态 → 拖入场景 → 编辑 2D 内容 → 保存/撤销/恢复 → Play 预览 → 修改 Lua → 重新导入 → 发布并复核资源。**

---

## 1. 总体目标

### 1.1 目标结果

完成后，项目应具备以下稳定工作流：

1. 新建或打开一个游戏工程；
2. 将 PNG、字体、音频、Lua、场景和 Prefab 放入工程目录；
3. 资源自动被发现、导入、缓存，并在资源浏览器中显示状态；
4. 导入失败时，用户能看到失败原因、受影响资源和修复建议；
5. 将纹理拖入 2D 场景即可创建 Sprite；
6. 在 2D Scene View 中完成移动、缩放、旋转、对齐、吸附、多选和层级编辑；
7. 使用 Tilemap 编辑器绘制地图，并区分视觉层与碰撞层；
8. 创建、编辑、实例化和更新 Prefab；
9. Play 时在编辑器 Game View 内真实运行 Lua、物理、UI、音频和场景逻辑；
10. Play/Stop 不污染编辑态；
11. 编辑器崩溃或异常退出后可以恢复最近一次有效编辑；
12. 资源修改后只重新导入必要内容，运行时不加载过期缓存；
13. 发布前可以检查缺失资源、断链引用、脚本错误和包体内容；
14. 每个关键流程都有自动化测试、手工步骤和可归档证据。

### 1.2 非目标

本阶段明确不做：

- UE5 级材质节点编辑器、Nanite、Lumen；
- 完整蓝图或可视化编程系统；
- 多人协作编辑；
- 主机平台；
- 全格式资产导入；
- 复杂 3D 地形、NavMesh、VFX Graph；
- 大型开放世界流式加载；
- 重写现有 Rust/Lua 核心架构；
- 为了“看起来完成”而绕过真实 GUI/GPU 验收。

## 2. 当前基线与主要问题

### 2.1 已有基础

当前项目已经具备：

- `engine_core`：ECS、2D/3D 组件、场景、Prefab、资源数据库、导入缓存、Lua、物理、动画、UI、音频、粒子；
- `engine_host`：RuntimeScene、Renderer、2D/3D 场景提取、offscreen 渲染；
- `editor`：Hierarchy、Inspector、Scene View、Game View、Resource Browser、Console、Undo/Redo、恢复、Gizmo、Prefab；
- `assetc`：资源扫描、导入、清理、列表和发布打包；
- `game_test`：可运行的 2D/3D 场景、Lua 脚本和资源样例；
- 自动化质量门、Debug/Release 构建和已有验收矩阵。

### 2.2 需要优先解决的问题

以下问题必须在继续扩展大功能前处理：

| 编号 | 问题 | 级别 | 影响 |
|---|---|---:|---|
| R-01 | Play 初始化失败后可能仍进入 Play 状态 | P0 | 编辑器状态与实际运行状态不一致 |
| R-02 | Game View 输入 snapshot 的边沿可能跨 tick 重复触发 | P0 | 点击、一次性动作和 UI 事件重复执行 |
| R-03 | Scene View 半分辨率缓存可能在拖拽结束后继续命中 | P1 | 编辑器视图长期模糊 |
| R-04 | readback 失败后缓存可能未失效 | P1 | 视图显示旧画面且不再重绘 |
| R-05 | 编辑器与运行时存在重复的 3D 场景解释路径 | P1 | 组件、相机、材质和脚本状态可能分叉 |
| R-06 | SDF 字体加载存在内存生命周期风险 | P1 | 长时间编辑或热重载可能泄漏 |
| R-07 | M10-11/M10-12/M10-13 的实现、矩阵和真实证据不同步 | P1 | 无法可信判断是否可发布 |
| R-08 | CI 未完整覆盖 `game/**`、GUI/GPU 检查和发布包自测 | P1 | 资源和场景改动可能绕过质量门 |
| R-09 | 资源缺失/断链部分场景仍可能静默降级 | P1 | 用户看到空白对象而不是明确错误 |
| R-10 | 2D 运行时能力已有，但编辑器生产工具不足 | P1 | 不能高效制作新内容 |

## 3. 设计原则

1. **先可靠，再扩展**：P0/P1 稳定性问题未关闭，不增加新的大编辑器功能。
2. **单一事实来源**：场景解析、资源解析、运行时提取和编辑器预览尽量共用同一套底层数据路径。
3. **编辑态与运行态隔离**：Play 永远运行场景副本，Stop 必须可恢复编辑态。
4. **资源状态可见**：扫描、导入、缓存、失败、过期、断链都必须能够在编辑器中观察。
5. **命令化编辑**：用户可见的场景修改都通过可撤销命令完成，禁止面板直接散落修改文档。
6. **2D 优先闭环**：先将 Sprite、Tilemap、Animation、UI 和 Prefab 做成可生产链路，再扩展 3D。
7. **异步任务可取消**：导入、缩略图、发布检查和 GPU readback 不阻塞编辑器主线程。
8. **失败可恢复**：导入失败、GPU 失败、脚本失败、崩溃恢复都要有明确状态和回滚路径。
9. **每个功能都有证据**：自动测试不能替代真实 GUI/GPU/DPI/resize/发布包验证。
10. **不改变公共格式而不迁移**：场景、Prefab、资源数据库和导入缓存变更必须带版本和迁移测试。

## 4. 目标架构

```text
                 ┌──────────────────────────┐
                 │        Editor UI          │
                 │ Hierarchy / Inspector     │
                 │ Scene / Game / Resources  │
                 └────────────┬─────────────┘
                              │ EditorCommand
                 ┌────────────▼─────────────┐
                 │   Editor Document Layer   │
                 │ scene document / history  │
                 │ dirty / recovery / locks  │
                 └──────┬───────────┬────────┘
                        │           │
          ┌─────────────▼───┐   ┌──▼────────────────┐
          │ Resource Service │   │ Runtime Preview   │
          │ scan/import/cache│   │ PlaySession       │
          │ dependency/status│   │ RuntimeScene      │
          └─────────────┬───┘   │ Renderer/offscreen│
                        │       └──┬────────────────┘
                 ┌──────▼──────────▼─────┐
                 │ Shared Core Extraction │
                 │ scene / asset / 2D API │
                 └──────────┬─────────────┘
                            │
                 ┌──────────▼─────────────┐
                 │ engine_core / host     │
                 │ Rust runtime + Lua     │
                 └────────────────────────┘
```

### 4.1 新增或收敛的逻辑边界

建议将后续实现收敛到以下服务边界，名称可根据现有代码调整：

- `EditorCommand`：所有编辑操作的统一入口；
- `DocumentState`：当前场景、dirty、selection、history、recovery；
- `ResourceService`：扫描、导入、缓存、状态、依赖和失效；
- `PreviewSession`：Play/Stop 生命周期、输入快照、错误状态和隔离副本；
- `SceneExtract`：编辑器视图和运行时预览共用的场景提取；
- `TwoDTools`：2D 视图、Sprite、Tilemap、动画和排序工具；
- `ValidationReport`：资源、场景、脚本和发布检查的统一结果格式。

## 6. M11：编辑器可靠性收口

### M11-00 基线冻结与故障复现包

- 固定 Git 基线和 Rust 工具链；
- 建立最小 2D 编辑器测试工程；
- 记录窗口尺寸、DPI、GPU、驱动、Debug/Release 信息；
- 为 R-01 至 R-10 建立最小复现步骤；
- 统一 acceptance evidence 命名和元数据；
- 实际未验证项目必须标记 `PENDING`，不得标记 `PASS`。

**验收：** 每个 P0/P1 有复现步骤、日志位置和预期结果；另一台机器可复核。

### M11-01 PlaySession 状态机

建立 `Editing → Starting → Playing / StartFailed → Stopping → Editing`，并处理 `RuntimeError`。

- 初始化全部成功后才能进入 Playing；
- 初始化失败不可进入 Playing；
- Stop 释放临时世界、输入、GPU 纹理和 Lua 状态；
- 运行时异常可安全 Stop；
- Play/Stop 重复 100 次不污染编辑态。

**验收：** 成功、资源缺失、脚本错误、GPU 初始化失败、重复 Play/Stop 均有自动化测试和用户可读错误。

### M11-02 输入快照与帧边界

- 区分 held / just_pressed / just_released；
- 在模拟帧边界消费 transient edge；
- Game View 失焦清理输入；
- Play/Stop 清空输入；
- 覆盖 60Hz、30Hz、低帧率、多 simulation tick 和 resize。

**验收：** 一次点击只触发一次；按住按键不重复触发一次性动作；失焦无卡键。

### M11-03 Offscreen/readback/缓存一致性

- 实际渲染尺寸、逻辑 viewport、DPI、质量档位进入 cache key；
- 拖拽结束恢复目标分辨率；
- readback 成功后才提交缓存；失败清缓存并显示错误；
- 统一处理设备丢失、resize、纹理重建；
- 增加 GPU 资源创建/复用/销毁统计。

**验收：** 100%/150%/200% DPI、resize、拖拽、人工 readback 失败后均能恢复；长时间打开编辑器 GPU 资源不持续增长。

### M11-04 场景解析与运行时提取统一

- 统一编辑器与运行时 drawable/component 提取；
- 编辑器相机作为视图覆盖，不修改场景数据；
- 统一相机、灯光、动画、材质、资源解析；
- 不支持组件生成诊断而非静默忽略。

**验收：** 正式运行器、Game View、Scene View 对同一场景的实体/资源数量和关键状态一致。

### M11-05 恢复、内存与错误可见性

- 修复 SDF 字体 owned buffer 和 glyph 缓存生命周期；
- recovery 带版本、校验和、时间；
- 恢复失败不覆盖主场景；
- 资源、脚本、GPU、场景错误统一进入 Console/Diagnostics；
- 错误包含项目、场景、资源、实体、阶段和建议动作。

**验收：** 字体热重载和场景切换无持续内存增长；损坏 recovery 可安全丢弃；P0/P1 可定位来源。

### M11-06 实机 GUI/GPU 质量门

覆盖 Debug/Release、100%/150% DPI、启动/resize/最小化/恢复、2D/3D/Game View、Play/Stop、脚本错误、资源缺失、保存/重启/恢复和 Release 包启动。

**验收：** 每项有日志、截图、录屏或发布 artifact；本地记录 GPU/DPI/窗口环境；M11 无 P0。

## 7. M12：资源系统闭环

> 归档说明：当前已归档 `M12-00`、`M12-01`、`M12-02`。`M12-03` ~ `M12-05` 未纳入本次归档，转后续迭代。

### M12-00 资源状态模型统一

建议状态：

```text
Discovered → ImportQueued → Importing → Ready
                              ↘ ImportFailed
Ready → Stale / Missing / Orphaned → Removed
```

记录 source path、UUID、type、content hash、importer version、dependencies、last success、last error。

**验收：** 修改、移动、删除、恢复资源后状态正确；重启可恢复；数据库损坏可重建。

### M12-01 Importer 注册与增量导入

- 定义 `Importer` trait 或等价适配层；
- 首阶段支持 PNG/JPG、TTF/OTF、WAV/OGG、GLTF/GLB、Lua、scene/prefab；
- content hash 相同复用缓存；importer version 变化自动失效；
- 失败重试、取消、临时产物原子提交；
- 导入任务不阻塞 UI。

**验收：** 首次导入、无变化重启、单资源变化、批量变化有耗时和数量记录；失败无半成品缓存。

### M12-02 依赖图与失效传播

- 建立 source → artifact → consumer 依赖图；
- 纹理、图集、Sprite、场景、Prefab、脚本和发布包的失效传播；
- 显示“为什么重新导入”；
- 检测循环依赖。

**验收：** 只重导必要资源；删除依赖后显示 Missing/Invalid；发布检查列出完整链路。

### M12-03 资源浏览器生产化

- 状态/类型图标；
- 纹理缩略图、音频时长、字体预览、场景/Prefab 预览；
- 过滤、双击打开、拖放创建 Sprite/Prefab；
- 右键重导入、定位文件、复制 UUID、查看依赖；
- 异步、可取消缩略图任务。

**验收：** 1000 个资源仍可交互；状态自动刷新；拖放可撤销；移动/重命名引用正确。

### M12-04 资源校验与发布前检查

统一 `ValidationReport`，检查缺失、ImportFailed、Stale、断链、脚本入口、字体 glyph、格式、包内外资源、路径和迁移兼容性。

**验收：** 编辑器、`assetc`、CI 使用同一套检查；P0/P1 阻断发布；输出 JSON 和文本。

### M12-05 资源数据库迁移和恢复

- schema version；
- 迁移前备份；
- 迁移失败回滚；
- 从源文件重建数据库；
- orphan 清理预览；
- 旧场景、Prefab、cache 迁移测试。

**验收：** 旧版本工程可迁移；中断迁移可恢复；数据库丢失可重建；不删除用户源文件。

## 8. M13：2D 内容生产工作流

> 归档说明：当前已按最小可生产闭环归档 `M13-00` ~ `M13-06`。编辑器已具备 Sprite、Tilemap、Animation、
> 2D 排序、Prefab、UI 的基础生产链路，可在不手改 scene/prefab 文件的前提下完成基础 2D 内容制作。
> 原始规划中的高级增强项（图集区域选择、Tilemap 填充/吸管/矩形、动画事件、视图书签/快照、UI 样式资源）
> 未纳入本次归档，转后续增强。

### M13-00 2D 数据模型收敛

冻结 Sprite、Tilemap、Animation、Camera2D、UI 和 Prefab 的序列化及运行时语义，每种组件有版本和迁移测试。

### M13-01 Sprite 编辑与批量创建

- 资源拖放创建 Sprite；
- 图集区域选择；
- pivot、尺寸、颜色、排序编辑；
- 批量替换、对齐和等间距；
- 显示边界、pivot、排序层；
- 缺失资源显示占位和诊断。

**验收：** 空场景到可运行 Sprite 少于 2 分钟；批量编辑可撤销；保存/重启/运行/发布一致。

### M13-02 Tilemap 编辑器

第一阶段支持正交网格、单 TileSet/Atlas、视觉层/碰撞层、画笔、橡皮、矩形、吸管、填充、吸附、图层显隐锁定、保存加载、批量渲染和 Rapier 2D 碰撞导出。

**验收：** 不手写场景文件完成可玩地图；100x100 编辑可用；Undo/Redo；运行时不为每 Tile 产生独立 Draw Call；碰撞与显示一致。

### M13-03 2D 动画编辑器

- 从图集/纹理序列创建 Clip；
- 帧顺序、时长、循环；
- 预览、暂停、逐帧；
- idle/move/attack/hit/death；
- 场景绑定；
- Lua 读取/切换/ended；
- 音效和脚本标记事件。

**验收：** 角色可通过编辑器完成 idle/move/attack；预览与 Play 一致；不需手写动画数据。

### M13-04 2D 场景工具和排序

- 正交导航、网格和吸附；
- Move/Rotate/Scale；
- 多选、对齐、等间距；
- Sorting Layer、Z Index；
- 框选、锁定、隐藏、选择过滤；
- 书签和视图快照。

**验收：** 常见编辑不依赖手改数值；全部可撤销；500 对象多选不崩；视图相机不影响运行相机。

### M13-05 Prefab 与 2D 内容复用

支持从 Sprite、敌人、拾取物、UI 创建 Prefab，拖入实例化、override 显示、源修改传播、断链诊断和 Prefab 编辑模式。

**验收：** 创建敌人 Prefab 并实例化 20 个；源修改按策略更新；局部 override 不被错误覆盖。

### M13-06 2D UI 生产最小闭环

支持 Canvas/Screen 层、Text/Image/Button、基础锚点布局、多分辨率预览、Lua 点击绑定、样式资源和 UI Prefab。

**验收：** 可编辑主菜单、HUD、胜负面板；100%/150% DPI 不重叠；按钮只触发一次；UI 可保存复用发布。

## 9. M14：端到端样板项目验证

> 当前进度：`M14-00` 已完成，样板工程落地为 `game_test_2d_production/`，并已通过
> `assetc scan/import/check-deps/package`、`editor --check`、`game --check`、`game --pack --check`
