## 0. 重构目标与不可违反的约束

本计划基于 [docs/39-引擎核心先进性与性能等级复核](39-引擎核心先进性与性能等级复核.md) 及源码探测结果制定。
目标不是简单合并组件，而是建立**可测量、可回滚、逐阶段交付**的运行时架构。

### 目标

1. 运行时热路径 typed 化，减少字符串、哈希、分配和重复解析；
2. ECS 由当前中小规模友好实现逐步升级到 cache-friendly 的高吞吐存储；
3. 2D 从"屏幕 Overlay 优先"提升为完整世界 2D：层级、相机、精灵、瓦片、粒子、文字、动画、输入与编辑器工具统一；
4. 保持现有 3D 能力与行为：mesh、材质、glTF、骨骼、阴影、深度、相机、CPU 剔除、实例化不回退；
5. 所有性能结论必须有固定场景、固定硬件、p50/p95/p99 与前后对照，不用推测代替基准。

### 3D 不回退门

每个阶段必须通过全套 3D 场景回归：相机投影、look-at、射线、视锥、深度、阴影、材质、动画、模型矩阵、
场景加载、编辑器预览、`demo3d` 快照。新增统一抽象不得要求 3D 使用 2D 的角度、像素 zoom、排序或无深度规则。

3D 只做兼容适配与性能保护，不在本计划中扩展 PBR、光照、LOD 资产制作等新能力。任一 3D 指标下降超过基线 5%
或出现画面/数据差异，阶段不得合并。

## 1. 总体架构

```text
磁盘/编辑器格式
    ↓ 版本迁移 + typed compile
TypedScene / AssetGraph
    ↓ 逻辑 ECS（LocalTransform、组件、父子关系）
GlobalTransform / SpatialIndex
    ↓ Extract
RenderWorld / RenderSnapshot（按视图、材质、层、深度分组）
    ↓ GPU upload
2D Sprite/Tile/Particle + 3D Mesh + Screen UI 专用 pipeline
```

目标不是让所有组件共用一个 shader，而是让数据、空间、相机、提取和性能度量共享一套清晰边界。

## 3. 逐项详细计划

每个工作包按"现状 → 成熟引擎方案 → 如何优化/实施 → 结果对比 → 验收指标 → 风险/回滚"六段记录。

### WP0：性能基准、Profiler 与不回退测试

- **现状**：已有固定步 `0.15–0.41 ms/step`、长跑、读档与规则确定性基线，但缺 CPU/GPU 分解、ECS 微基准、
  大规模 2D/3D 场景、分配次数与渲染提交指标。
- **成熟引擎方案**：分帧 profiler、可重复阶梯场景、CPU/GPU timestamp、资源与分配统计、
  RenderDoc/Chrome trace 类导出，以及独立的 ECS benchmark。
- **实施**：新增 benchmark crate 或 examples，覆盖 ECS 操作、Transform 深度 1/10/100、
  1k/10k/50k/100k Sprite、100/1k/10k Mesh、骨骼、阴影、透明、Lua、场景加载与首帧。
  统一采集 p50/p95/p99、CPU/GPU frame、draw call、instance、三角形、分配次数、峰值内存、纹理/缓冲字节。
  建立纯 2D、纯 3D、混合 2D/3D、UI 密集、编辑器大场景 fixture。
- **验收指标**：同机重复基线误差 ≤5%；每个优化 PR 附前后报告；3D 场景画面/快照不变；
  现有 [docs/34](34-质量门与发布清单.md)/[docs/36](36-游戏级回归与性能基线.md) 质量门继续通过。
- **风险/回滚**：Profiler 影响性能、GPU 计时跨后端不一致 → 独立 feature、采样模式与关闭开关隔离；
  异常时只回滚测量接入，不影响运行时。

### WP1：Typed Scene、资源句柄与加载编译

- **现状**：`Scene` 使用版本 2 的 `BTreeMap<String,String>`；Transform、Camera、Mesh 等在装载/提取时解析字符串，
  存在查找、分配与重复解析风险。
- **成熟引擎方案**：加载期反序列化 typed asset，使用稳定 ID/句柄、依赖图、版本迁移、异步 CPU 解码与 GPU 上传队列；
  编辑器格式与运行时格式分离。
- **实施**：保留可读场景格式作为源格式，新增 v3 编译边界 `TypedScene`：组件名使用 ComponentId/枚举，
  资源使用 AssetId/Handle，预解析材质、mesh、相机、Transform 与 parent 拓扑。运行帧禁止 `from_component_str`、
  临时 String 与资源路径查找。保留源文件位置用于错误诊断；热加载生成 typed snapshot 后原子替换。
- **验收指标**：v2 可迁移到 v3 且迁移幂等；错误包含实体/组件/源位置；运行帧字符串解析=0；
  重复资源不重复解码/上传；2D/3D demo 场景内容与相机不变。
- **风险/回滚**：Lua 动态组件、热加载与自定义组件兼容复杂 → 按场景启用 typed 编译，编译失败回退解释器；
  旧 v2 只读保留，禁止失败时覆盖源文件。

### WP2：统一 Transform、GlobalTransform 与层级传播

- **现状**：2D `Transform` 是 Vec2+角度，3D `Transform3D` 是 Vec3+Quat；有 parent/children，
  但没有通用父优先世界矩阵传播，提取器按单实体 TRS 工作。
- **成熟引擎方案**：LocalTransform + GlobalTransform，父优先拓扑传播，dirty/version 子树更新，
  世界矩阵作为派生缓存；矩阵与局部 TRS 不互相重复作为真源。
- **实施**：统一局部 `Transform { Vec3, Quat, Vec3 }`，新增非序列化 `GlobalTransform { Mat4 }` 与明确的
  SpatialParent；2D API 提供 XY、绕 Z、Vec2 便利方法但保留 Z；统一 finite、单位四元数、缩放规则。
  先全量正确传播，再做 dirty/version 增量更新。旧 v2 场景默认保持现有世界位置，不自动把 parent 当局部空间；
  提供显式迁移选项。
- **验收指标**：层级深度 1/10/100 矩阵误差在阈值内；换父可保持世界位置；循环父链有诊断；
  剪切不被错误分解；非法矩阵不得上传 GPU；3D 模型矩阵、骨骼 palette、物理回写回归。
- **风险/回滚**：旧场景 parent 语义可能被误解，非均匀缩放会产生剪切 → 保留旧提取开关、v2 只读迁移器与差异报告；
  任何无法无损表达的实体拒绝迁移。

### WP3：热路径 ECS dense/sparse 存储

- **现状**：`World` 使用 `HashMap<EntityId,T>`、有序 Entity Vec、TypeId/trait object/downcast；
  查询可能复用 Vec，有序插删有 O(n) 成本。
- **成熟引擎方案**：archetype/chunk（Bevy 类）或 sparse-set（Flecs/EnTT 类），借用迭代器、代际实体、
  批量命令缓冲，稳定顺序只在边界产生。
- **实施**：先不动所有组件；把 Transform、Sprite、Velocity、PhysicsProxy 换成 `DenseStorage<T>` + sparse entity index。
  查询返回借用 View/Iterator，不产生 entity Vec；提供批量 insert/remove/despawn 命令。实体继续使用 generation 防 stale handle。
  逻辑确定性需要排序时在 snapshot/序列化边界排序，热遍历不强制有序。
- **验收指标**：旧/新 storage 对拍；快照与规则确定性一致；10k/100k 基准；内存峰值记录；
  3D 组件仍可使用旧或新 storage 且画面不变。
- **风险/回滚**：Rust 借用、实体顺序与删除语义复杂 → 按组件 feature flag 双路径；新 storage 失败可回退 HashMap；
  序列化不绑定内存 storage。

### WP4：2D 核心能力重构

- **现状**：2D Transform、Camera2D、Sprite/Batch、Tilemap、粒子、文字与 2D physics 已存在，
  但空间、渲染、输入与编辑器仍以 2D 专用路径为主，2D 通常作为 3D 后的无深度 overlay，缺少统一世界空间能力。
- **成熟引擎方案**：世界/屏幕坐标分离、层级 Transform、正交相机控制器、Sprite/Tilemap 批处理、texture atlas、
  sorting layer/order、粒子实例化、动画状态机、碰撞查询、viewport/Canvas、编辑器 gizmo 与稳定 picking。
- **实施要点**：① 2D 使用统一 Transform 与 XY 便利 API，明确 pivot/anchor/z/rotation/scale 语义；
  ② Camera2D 作为正交控制器保留 center/rotation/zoom/bounds/follow/dead-zone/平滑与相机抖动；
  ③ Sprite 增加 pivot、九宫格/区域、flip、颜色、层、排序键、材质句柄与批处理实例数据，atlas 使用稳定 region ID；
  ④ Tilemap 使用 chunk dirty 更新、可见 chunk 提取、层/碰撞分离与批量网格，避免每帧逐 tile 解析；
  ⑤ 粒子使用 SoA/实例 buffer、池化与固定步，支持颜色/尺寸/旋转曲线；
  ⑥ 文字区分屏幕 UI 与世界文字，字体 atlas/glyph cache/裁剪/批处理保持现有管线；
  ⑦ 2D 动画采用 clip/state/事件边界，帧更新只改 typed instance；
  ⑧ 输入统一 screen→world，2D 为射线与 XY/指定平面交点，编辑器 picking 使用同一投影；
  ⑨ 引入 World2D、Legacy2DOverlay、ScreenUI 三种显式层，旧项目默认走 Legacy2DOverlay。
- **验收指标**：1k/10k/50k Sprite、100+ Tilemap chunk、1k/10k 粒子场景；Sprite 与 Mesh 可选共享深度；
  旧 overlay 像素回归；Camera2D roundtrip 误差阈值；编辑器拖动/旋转/框选/撤销一致；2D 规则与 3D 全量回归。
- **风险/回滚**：像素对齐、透明排序、DPI、世界 Sprite 与 UI 混淆 → 新 World2D 使用显式开关，旧场景保留 overlay；
  不支持的组合报诊断，不静默改变绘制结果。

### WP5：统一 Camera、Projection 与 RenderView

- **现状**：Camera2D 有像素 zoom/bounds；Camera3D 有 position/target/up、透视、射线与视锥；
  Renderer 从 Scene3d 只拿 3D 相机，2D 另有投影与绑定。
- **成熟引擎方案**：Camera 数据描述投影、viewport、可见层、清屏、顺序与启用状态；相机姿态来自 Transform；
  每帧生成 RenderView，渲染器消费快照而不回查 ECS。
- **实施**：引入 `Projection::Orthographic`、`Projection::Perspective`、viewport、visibility mask、clear policy、
  render order 与 `RenderView`；保留 Camera2D controller 的 zoom/bounds；Camera3D 的 look-at 转为 Transform pose。
  相机选择、编辑器 override、默认回退统一；姿态冲突给诊断。相机可跨 2D 与 3D，但不强制 shader/深度规则相同。
- **验收指标**：旧 2D `world_to_screen`/`screen_to_world` 等价；旧 3D projection/ray/frustum 等价；
  viewport resize/DPI/离屏一致；多相机选择确定；3D 画面无回退。
- **风险/回滚**：look-at 与旧 Transform 冲突、角度单位错误 → 保留旧 Camera2D/Camera3D facade 与 RenderView adapter；
  逐场景启用。

### WP6：RenderWorld、批处理与可见性

- **现状**：已有 mesh cache、材质/纹理 cache、静态实例化、CPU bounds/culling、阴影与 2D 顶点 buffer；
  但 2D 无深度，3D/2D 提取分离，缺层级空间索引与 typed render snapshot。
- **成熟引擎方案**：逻辑 World 与 RenderWorld 分离，Extract 阶段生成不可变 render snapshot；
  按 mesh/material/pipeline 排序批次；层级 bounds、BVH/网格索引、LOD、实例 buffer，必要时 indirect draw。
- **实施**：先把运行时 typed 组件提取成 `RenderSnapshot`，Renderer 不解析场景字符串、不遍历 ECS；
  按 RenderView、layer、depth policy、material、mesh 分组；Sprite 使用独立 quad pipeline，Mesh 继续现有 pipeline。
  增加层级 bounds 与轻量空间索引；先做 CPU 视锥/LOD，再按 profile 评估遮挡与 indirect；
  2D transparent 的排序规则显式化；ScreenUI 保持无深度。
- **验收指标**：10k/100k Sprite 与 10k Mesh 阶梯；可见率 10% 时 culling CPU ≤现状 30% 目标；
  draw/instance/三角形指标可观测；透明边缘、阴影与 3D 深度、2D overlay 回归；GPU/CPU frame 不超过 WP0 预算。
- **风险/回滚**：误剔除、透明排序错误、wgpu 后端差异 → 保留旧全量提取与 CPU culling 开关；
  indirect/遮挡默认关闭直到通过多后端验证。

### WP7：2D 物理、动画、输入与同步

- **现状**：Rapier2D/3D 分离合理，但 Transform/Velocity/物理回写路径分别实现，2D 与 3D 统一空间后存在重复写入风险。
- **成熟引擎方案**：物理后端保持专用，组件通过明确同步阶段与 authority policy 对接；动态刚体由物理回写，
  静态/运动学由游戏变换同步；显示插值不反写模拟状态。
- **实施**：定义 `PhysicsAuthority` 与同步策略；统一 scheduler 阶段为
  脚本 → 控制器 → 静态/运动学同步 → 物理 → 动态回写 → GlobalTransform → RenderSnapshot；
  2D 提供 collider debug draw、查询、触发器、层/掩码、连续碰撞配置；3D 路径只做适配；
  动画写 LocalTransform 或专用 pose，禁止与物理无序抢写。
- **验收指标**：30/60/120 FPS 状态一致；teleport、动态/运动学、碰撞事件、父节点、暂停/恢复在 2D/3D 不重复驱动；
  3D demo 与既有物理测试不回退。
- **风险/回滚**：回写时机变化造成玩法漂移 → 旧同步模式 feature flag、固定步对拍与场景级迁移；
  出现差异先保留旧 authority。

### WP8：调度并行化

- **现状**：阶段与拓扑设计较好，但系统回调是单线程 `FnMut`，Lua 状态不可随意跨线程。
- **成熟引擎方案**：系统声明读写集，构建并行 DAG/任务批次，使用线程池与命令缓冲；脚本、渲染提交保留主线程边界。
- **实施**：先为系统增加 Read/Write 组件与资源声明；冲突系统自动串行；
  把 Transform propagation、动画采样、剔除、资源解码与 typed compile 并行。Lua 保持主线程，
  结果通过确定性 command buffer 合并。调度器保留单线程模式用于回归。
- **验收指标**：无数据竞争；单/多线程快照 hash 一致；30/60/120 FPS 规则一致；线程池失败自动退回单线程；3D frame 不变。
- **风险/回滚**：锁争用、非确定性、Lua 线程安全 → 默认单线程，按系统白名单启用；任何系统都可禁用并行。

### WP9：编辑器、Lua、迁移与发布收口

- **现状**：编辑器存在独立 Transform/Transform3D/Camera3D 字段、编码器、撤销命令与预览状态；Lua 同样存在分离接口。
- **成熟引擎方案**：Inspector 使用统一 schema，编辑器与运行时共享 typed component definition；
  旧 API 通过版本化 facade 与弃用周期兼容；迁移工具支持 dry-run、备份、原子写入与错误定位。
- **实施**：一个 Transform 面板按 2D/3D 编辑模式展示；一个 Camera 面板按 Projection 展示。
  统一撤销/重做、Prefab override、复制粘贴、批量编辑与 Play 预览。Lua 提供统一 API，
  同时保留 `transform3d`/`camera` facade；组件改名给弃用告警。新增迁移命令、报告、备份与一键回滚。
- **验收指标**：旧项目可打开/运行/保存；迁移失败不覆盖源文件；Inspector、Gizmo、撤销与预览一致；
  `cargo fmt/clippy/test/build`、游戏级回归、发布隔离（[docs/50](50-发布包与用户数据目录.md)）与
  Web 平台契约（[docs/32](32-webgl-浏览器平台验收.md)）通过。
- **风险/回滚**：用户数据格式破坏、Prefab override 丢失 → 格式只增不覆盖、备份原子交换、
  旧 facade 保留一个兼容周期；无法表达的剪切/负缩放明确拒绝降级。

## 4. 结果对比总表

| 项目 | 当前 | 重构后目标 |
|---|---|---|
| ECS 热组件 | HashMap + Vec + 类型擦除 | dense/sparse 或 archetype，零复制查询 |
| 场景运行时 | 字符串组件解析 | typed compile + 稳定 ID/句柄 |
| 空间 | Transform/Transform3D 分离，无通用世界传播 | LocalTransform + GlobalTransform + dirty propagation |
| 2D | 2D 专用路径/无深度 overlay 为主 | World2D、LegacyOverlay、ScreenUI 明确分层 |
| Camera | Camera2D/Camera3D 分离选择和矩阵 | Camera + Projection + RenderView，保留模式语义 |
| Sprite/Tilemap | 基础批处理与逐路径更新 | atlas/实例 buffer、tile chunk dirty、世界空间可选深度 |
| 3D | 已有深度、阴影、缓存、实例化、CPU culling | 保持上述能力，改为 typed snapshot；不减少功能 |
| 调度 | 确定性单线程 | 单线程默认 + 可验证的并行数据系统 |
| 资源 | 可读格式与缓存，热路径证据不足 | 异步依赖图、typed cache、分帧 GPU upload |
| 质量证据 | 规则/长跑/发布较好，渲染基准不足 | CPU/GPU/内存/ECS/2D/3D 阶梯基准进入质量门 |

## 5. 阶段门与回滚制度

每个工作包必须提交：

1. 设计说明与不变量；
2. 旧/新路径对拍；
3. 性能前后报告；
4. 2D 回归与纯 3D 不回退报告；
5. 场景/Lua/Prefab 迁移工具或兼容说明；
6. 一键禁用开关与回滚说明；
7. `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、
   `cargo test --workspace`、`cargo build --workspace` 及已有质量门输出。

禁止以下做法：

- 没有 profile 就重写所有 ECS；
- 将内部 Rust 类型 alias 当成两个可兼容 ECS 组件；
- 直接把旧 parent 当局部坐标；
- 把 2D sorting layer 当作 3D 深度；
- 让 UI 使用世界 Transform；
- 以删除或放宽测试解决回归；
- 以规则固定步耗时冒充 GPU 帧率。

## 6. 推荐资源与时间

以一名熟悉代码的工程师估算，完整重构约 35–60 人日，P0 完成后重估；WP4 2D 与 WP6 渲染的实际成本取决于世界
Sprite 的目标范围。建议先完成 WP0，再决定是否需要 WP3 的 archetype 级改造。

- 第一里程碑：WP0 + WP1 + WP2 —— 性能画像、typed 场景与统一空间基础；
- 第二里程碑：WP3 + WP4 + WP5 —— 热点性能、完整 2D 与统一相机视图；
- 第三里程碑：WP6 + WP7 —— 世界空间提取、2D/3D 混合与物理同步；
- 第四里程碑：WP8 + WP9 —— 并行化、编辑器、Lua、迁移与发布收口。

## 7. 最终判断

全面重构可行，但应理解为**兼容迁移驱动的分阶段重构**，而不是一次性重写。最大收益来自 typed runtime、
热路径 ECS dense 化、统一 GlobalTransform、2D 世界空间能力与可观测性；最大风险来自旧场景层级语义、
物理 authority、透明排序、Prefab/Lua 兼容与 3D 回归。

建议立即启动 WP0，随后优化 WP1/WP2。只有在基准证明 HashMap ECS 或渲染提取成为主要瓶颈后，
才扩大 WP3/WP6 的改造范围。

## 9. 技术选择原则：成熟方案之外的折中

成熟引擎方案只作为参考基线，不作为自动路线。每个工作包至少比较：现状、成熟方案 A、
本仓的改进方案 B，并从性能、延迟、内存、确定性、实现复杂度、可维护性、迁移成本与 3D 回归风险八个维度
综合打分；两者接近时优先选实现更简单、文档更强、可维护性更高的一侧，不以"追新"为理由引入复杂度。

### 9.1 当前推荐与本仓折中

| 领域 | 参考方案 | 本计划折中选择 | 选择理由 |
|---|---|---|---|
| ECS | 全面 archetype/chunk 或 sparse-set | **渐进 ECS**：先做热的 dense/sparse，低频/冷组件保留抽象层 | 避免一次性重写迁移风险；cache 收益集中在 Transform/Sprite/Velocity |
| 场景运行时 | 直接使用运行时结构或全量 ECS | **源格式 + typed compile + 派生 RenderSnapshot** | 保留编辑可读性，同时让热路径无字符串；渲染与逻辑线程边界清晰 |
| Transform | 每帧全量传播或通用层级系统 | **Local TRS + Global Mat4 + dirty subtree/version** | 先保层级正确性与 2D/3D 统一，再按 profile 决定是否引入更复杂调度 |
| 2D 数学 | 完全复用 3D Mat4 或完全独立 | **复用 Vec/Quat/Mat4 底层 + 2D 专用便利路径** | 2D 热路径少 2D 冗余计算，3D 保持精度；不强行把 2D 塞进 3D |
| Camera | 统一 Camera 结构或让两者完全分离 | **统一 Camera/Projection/RenderView，但保留控制器** | 统一 viewport/选择/可见层，保留 Camera2D zoom/bounds 与 Camera3D look-at 语义 |
| Sprite | 每次 draw、通用 batch 或全 GPU-driven | **Atlas + material-key batch + instance buffer**；GPU-driven 待基准证明后评估 | 满足当前 2D 项目规模，wgpu 侧复杂度可控 |
| Tilemap | 每帧重建网格或全 GPU tile shader | **chunk mesh + dirty rebuild + 可选实例化** | 对动态编辑与静态大图兼顾；GPU tile shader 容易破坏碰撞/编辑器一致性 |
| 粒子 | 全 CPU 或直接 GPU 粒子 | **CPU SoA/pool 为确定性基线，GPU 作为可选路径** | 玩法与回归需要确定性；只有规模压力出现时才启用 GPU |
| 文字 | 位图或 SDF 全量文本引擎 | **MSDF/SDF atlas + glyph/layout cache + 分场景文本层** | 复用现有 SDF 管线；复杂 shaping 与双语文排作为后续独立课题 |
| 物理 | 替换为单一 2D/3D 引擎 | **保留 Rapier2D/3D，统一 authority/sync contract** | 不承担替换风险；重点是消除重复写入与固定步与渲染解耦 |
| 可见性 | 全量 CPU、BVH、节点剔除或 GPU indirect | **2D chunk 可见 + 3D 层级空间索引 + CPU culling**；indirect 后置 | 先解决已知瓶颈（2D 与 3D 现状），未证实的收益不引入 GPU 路径 |
| 调度 | 全量多线程或按依赖图与脚本隔离 | **确定性主线程 + 可并行数据系统 + command buffer** | 最小化 Lua 与规则确定性风险；全量并行不适合当前架构 |
| 资源 | 同步加载、全异步或第三方资源系统 | **依赖图 + 后台 CPU 解码 + 主线程小步 GPU upload** | 控制首帧速度与内存峰值，不引入新资源系统；支持失败回退与优先级 |

### 9.2 红线

- 新路径在固定场景 p95 比旧方案慢超过 5%、p99 慢超过 10%，默认不启用（除非换来可接受的确定性改善）。
- 内存峰值增加超过 10%、加载时间增加超过 10% 的方案需要额外评审与阶段性基准。
- 3D golden（glTF 的 primitive/材质/skin/animation、深度/阴影/视锥/实例化）任一回归，阻塞该工作包合并。
- 新增字符串解析量不小于被替换量时，优先选实现更简单、文档更强、可维护性更高的一侧。
- 绝对指标（例如"10k Sprite <4ms"）只作为可选目标；正式门槛以固定硬件、分辨率、插桩方式下的 30 次
  重复测量与历史基线变化为准。


因此，本计划的"折中方案"优先保证不把 Unity、Godot 或 Bevy 的整套方案直接照搬：本仓的选择是

每一项都必须由实测 benchmark 证明收益，而不是因为成熟引擎那样做就采用。

## 10. 最优方案选择原则

成熟引擎方案仅作为候选基线。每个工作包必须比较现状、成熟方案和针对 RustLua 的候选改进方案，并按吞吐、延迟、内存、确定性、维护成本、迁移成本和 3D 回归风险评分。最终选择综合收益最高且满足 3D 不回退门的方案；证据不足时先做 prototype 和 benchmark。

当前优先组合：混合 ECS（热点组件 dense/sparse，低频组件保留类型擦除）、源格式加 typed compile、Local/Global Transform、2D 专用仿射快捷路径、Camera/Projection/RenderView、Atlas 加材质键排序和实例缓冲、Tilemap chunk dirty rebuild、CPU SoA 粒子基线加可选 GPU 后端、保留 Rapier2D/3D 并统一 authority、CPU 可见性先行且 indirect 后置、确定性主线程加纯数据白名单并行。选择理由是兼顾性能、兼容、wgpu 多后端和 3D 零回退，而不是照搬 Unity/Godot/Bevy。

决策门：关键路径 p95 回退不得超过 5%，p99 不得超过 10%；内存/包体/加载回退超过 10% 必须解释；3D golden、glTF、深度、阴影、相机、物理任一回归立即回退；绝对 FPS/倍数目标必须由固定硬件和至少 30 次重复基线确认。
