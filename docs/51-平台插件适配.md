# 平台插件适配

平台适配统一放在 `plugins/`：发布脚本只负责**复制 + 改名 + 校验**平台文件，平台差异不写进
引擎代码，也不在脚本里各写一份运行时。

| 平台 | 插件目录 | 产物入口 | 验证 |
|---|---|---|---|
| PC | —（引擎运行器 `game.exe`） | `game.exe` + `pack/` + `fonts/` | `package.ps1` 内置 `--check` + `-SelfTest` |
| WebGL | `plugins/webgl/` | `index.html` + `web-runtime.js` + `pkg/` | `scripts/verify-webgl-bundle.ps1` |
| 微信小游戏 | `plugins/wechat-minigame/` | `game.js` + `wechat-adapter.js` + `game.json` + `project.config.json` + `web-runtime.js` + `pkg/` + `pack/`/`mainpack/` | `scripts/verify-wechat-minigame.ps1` |

## 发布

```powershell
powershell -NoProfile -File scripts\package.ps1 -Platform pc
powershell -NoProfile -File scripts\package.ps1 -Platform webgl

# 小游戏：默认就是主包 + 单分包（-AssetPack subpackage），零服务器、零备案、零域名白名单。
powershell -NoProfile -File scripts\package.ps1 -Platform wechat-minigame -SelfTest

# 可选：瘦首包 + 资源包导出到 CDN（需要公网 HTTPS + 备案 + downloadFile 域名白名单）
powershell -NoProfile -File scripts\package.ps1 -Platform wechat-minigame -SelfTest `
  -AssetPack remote -RemotePackBaseUrl https://cdn.example.com/games/jianghu

# 本地联调（仅 remote 形态需要）：先起只读静态服务托管**资源包目录**（<发布根>\assets），
# 开发者工具里勾「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。
# 也可以直接双击 scripts\serve-wechat-pack.bat（自动定位资源包、端口取 remote-assets.json），
# 或 scripts\test-wechat-minigame.bat（先跑完整验收再起同一个服务）。
```

三者都走同一套原子发布流程（`builds/<platform>/<publish_name>/`：staging → 原子替换 → 失败回滚），
发布目录不会是半更新状态。小游戏的发布根下固定是 `launcher/`（代码包，上传微信的就是它）；
只有 `remote` 形态才多一个 `assets/`（CDN 资源包）兄弟目录。两者都在同一个 staging 里生成、
由同一次原子交换落地。

## 平台文件职责

- `plugins/webgl/web-runtime.js`：**两个 web 平台共用**的 Lua 运行时（Fengari 执行 + canvas 绘制 +
  输入 + 启动自检标记）。共用一份是刻意的：避免 webgl 与微信小游戏的游戏逻辑各自漂移。
- `plugins/webgl/index.html`：浏览器页面模板，`package.ps1` 替换 `__PUBLISH_NAME__` /
  `__PUBLISH_NAME_JSON__` / `__FONT_PATH__` 占位符。
- `plugins/wechat-minigame/wechat-adapter.js`：把 `wx` API 映射为运行时所需的宿主 API
  （`fetch`/`document`/`window`/`Image`/`FontFace`/`requestAnimationFrame`/`localStorage`/键鼠事件）。
  详见 [plugins/wechat-minigame/README.md](../plugins/wechat-minigame/README.md)。
- `plugins/wechat-minigame/game.js`：小游戏入口，负责按序加载适配层 → Lua VM → 运行时 → 启动。

## 微信小游戏特有约束

- **资源形态三选一**（`-AssetPack`，微信平台默认 `subpackage`），细节见
  [微信小游戏分包发布](52-微信小游戏分包发布.md)：
  - `subpackage`（默认）：**主包 + 单分包**。首屏资源在兄弟目录 `mainpack/`（属主包，随包上传），
    其余资源在 `pack/` 并由 `game.json` 的 `subpackages` 声明成分包，运行时按需
    `wx.loadSubpackage` 挂载。零服务器、零备案、零域名白名单，微信自带 CDN 分发。
    `pack/` 的 root 下必须有入口 `game.js`（微信硬要求，缺了开发者工具拒绝打开工程）。
  - `remote`：瘦首包。包内 `pack/` 只留骨架，重资源上传 CDN，适配层优先包内、读不到才远端下载。
    需要公网 HTTPS、备案与 `downloadFile` 域名白名单。
  - `full`：`pack/` 整个随主包分发。`jianghu_youtian` 全量 4.4 MB 必然超过 4 MB 主包上限，
    因此这一形态对本工程实际不可用（发布脚本会在超限时明确报错并给出另两条出路）。
  三种形态互斥（`subpackage` 与 `-RemotePackBaseUrl` / `-CdnPackDir` 相互拒绝）：
  两套资源来源同时存在只会让"包内读到了"掩盖"分包根本没挂载上"。
- **脚本必须是 CommonJS**：小游戏运行时不支持 ES Module，包里任何顶层 `export`/`import`
  都会让启动直接失败（实测：`WAGame.js:1 SyntaxError: MiniProgramError Unexpected token 'export'`，
  来源是 `wasm-bindgen --target web` 的浏览器胶水）。因此微信分支**不构建也不发行**
  `pkg/game_web.js` / `pkg/game_web_bg.wasm`（`pkg/` 内只有 `fengari-web.js`），
  并且发布脚本、验证脚本、无头 harness 三处都会按脚本模式逐个解析包内 `.js`。
  检测不能用 `node --check`：Node 会按内容自动识别 ESM，对顶层 `export` 反而"通过"，
  必须用 `vm.Script`（始终按 script 解析）。
- **字体**：只随包分发 assetc 子集化后的字体（实测 226 KB），
  不复制 17 MB 的完整字体。它在包内的位置随形态变（分包形态下属首屏资源，在 `mainpack/assets/fonts/`）。
- **平台入口隔离**：小游戏包里不允许出现 `game.exe` / `index.html`，
  发布脚本会把"平台分支选错"变成发布期失败，而不是线上白屏。
- **无头验证**：`scripts/wechat-minigame-harness.js` 用 Node 伪造 `wx` API，真实执行
  `game.js → wechat-adapter.js → web-runtime.js`，断言资源读取、逐帧 Lua 绘制、二进制字节一致、
  贴图真的被宿主加载（假 `Image` 只走宿主的受限读取路径，不再直接从磁盘偷读）、触摸/键盘桥接，
  并按形态断言分包行为（分包形态：声明有且仅有 1 个 `root=pack`、入口可执行、挂载门生效、
  进度条消费了进度；其余形态：`subpackage_loads=0` 且不得有分包声明）；
  `scripts/verify-wechat-minigame.ps1` 在其上再做布局与体积校验，并跑 4 种宿主路径方言 +
  形态专属用例（分包：`ok/off/delay/never/fail-once`；远端：`auto/thin/corrupt/down/png-fail`）。
  这些检查都在实测教训之后加上：
  ① "本机全绿但开发者工具拒绝启动"（分包入口缺失）→ 分包形态现在生成**真的**入口 `pack/game.js`
  并在挂载时真的 `require` 一次，非分包形态则断言不得有分包声明且 `subpackage_loads=0`；
  ② "无头测试里贴图全对、真机上贴图全丢"（假 `Image` 直接读磁盘掩盖了问题）→ 假 `Image` 只接受
  宿主能读到的路径，且启动 Promise 不 settle 时带诊断失败而不是无限等待；
  ③ "开发者工具里全黑、0 帧、0 错误、日志全绿"（基础库把 `Image.src` 定义在**原型**上，
  只读 own 描述符的实现静默退化成写 `image._src`，宿主永不开始加载）→ 按原型链探明
  own/原型访问器与 `setSrc` 三种接管方式并自报 `image_src_takeover`（`--image-src-prototype`），
  同时补上**启动看门狗**：卡死超时后既 `console.error` 又把"启动超时"画到画布上
  （`--image-src-silent --expect-boot-stall`）；
  ④ 同源的另一半：基础库 2.32.3 的 `k$` 包装类把 `onload`/`onerror` 也做成原型访问器、
  回调存进私有字段 `__onload`，真实 image 的回调桥在**构造时**接好 → 适配层用自己的
  accessor 盖住 `onload` 等于拆桥，贴图加载成功也传不回运行时（症状同 ③）→ 现在回调
  **转发给宿主的 setter** 并自报 `image_callback_takeover`（`--image-callback-bridge` 1:1 复现）；
  ⑤ "标题界面 600 帧全绿、一按开始新游戏就崩"（`attempt to call a nil value (field 'current')`）：
  引擎的 `scene.load` 是**排队的场景切换**，真正换数据在下一帧；web 运行时若不跟着换场景数据，
  `update()` 会立刻按"已在玩法地图"分支执行。只跑标题界面的用例永远走不到这条路径 →
  现在 `--drive-new-game` 走玩家真实路径（标题按确认 → `on_click('BtnStart')` →
  `scene.load("manor")`），并逐项断言**世界状态**（地图真换了、存活实体不少于场景声明数、
  主角落在落点）；
  ⑥ "全绿但世界是空的"：缺失的宿主 API 曾静默降级成空表，`entity.find_id` 返回真值会让
  `activate()` 永远走"已存在"分支（NPC 根本不生成）→ 现在缺失 API **逐条点名**
  （`[lua missing-host-api]`）并配白名单断言（只允许游戏自己探测过、会降级的那批），
  其余按引擎源码补齐（`physics.set_position` / `transform.set` / `entity.spawn|find_id|persist_id|destroy` /
  `sprite.set` / `animation.*` / `tilemap.set_cell|set_texture|find_path` / `save.clear` / `audio.*`）；
  ⑦ "世界在动"不等于"画面在动"：Lua 世界与渲染器各存一份实体数据、靠回写通道同步，
  只在 Lua 侧取样看不见"世界里主角在走、画面上钉死在出生点" → 运行时每帧自报
  `data-p2-world`（含渲染侧坐标 `drawn=`），质量门新增玩法路径用例：按住**运动驱动键**（键盘桥接注入）——可见虚拟控件（`ui/virtual_pad.lua`）走鼠标事件 + Lua 侧注入，不再有"触摸摇杆派发键盘键"。按住**运行时自己从触摸
  摇杆派发出来的键**若干帧，断言主角坐标真的变了、且渲染侧与 Lua 侧一致（不硬编码游戏键位）。
- **分包形态下的路径路由**：`plugins/wechat-minigame/wechat-adapter.js` 是唯一知道"某个逻辑路径该
  从主包还是从分包读"的地方，依据是构建期生成的 `mainpack.json`（`scripts/first-screen-pack.js`，
  构建/运行时/harness 三方共用的唯一事实来源）。实现上是**主体 × 方言**两层正交组合——
  主体（`mainpack/` 还是 `pack/`）是包内布局属性，方言（根相对 / 前导斜杠 / 分包根相对…）是宿主
  属性，把主体塞进策略表当别名会在 `slash` / `sub-root` 这类宿主上拼出读不到的路径。
  首屏清单随形态体积**此消彼长**：清单越大主包越大、分包越小，而被 4 MB 卡住的是分包那一侧，
  所以清单「宁可多列、不可漏列」与体积上限方向一致。
- **远端资源回落（`-AssetPack remote` 形态）**：`remote-assets.json` 存在时语义为**包内优先 + 远端兜底**
  （下载 → 按 `pack/manifest.txt` 的体积 + FNV-1a 校验 → 落地 `USER_DATA_PATH` 缓存 → 下次命中缓存）。
  `-AssetPack remote -RemotePackBaseUrl <CDN>` 写入该文件并导出资源包，不传 `-RemotePackBaseUrl`
  则删除陈旧配置；本地联调用 `scripts/serve-pack.ps1`（底层 `scripts/pack-server.js`，只读、防目录穿越、
  带请求日志）托管**资源包目录**。宿主自己加载的 `Image.src` 会被适配层改写成本地缓存路径；
  宿主怎么写 `src`（以及 `onload`/`onerror` 的回调桥怎么接）由适配层启动时探明并各打一行自检
  `Image.src 接管方式 = own-accessor|prototype-accessor|setSrc-method`、
  `Image.onload/onerror 接管方式 = host-setter|own-accessor`；
  若某基础库不允许改写，适配层会**响亮失败**而不是静默丢图（`--image-src-frozen` 用例覆盖两种模式；`full`
  形态不需要改写 src，因此那一档下必须照常启动——三种形态对"能不能改写 src"的依赖不同，
  断言也按形态分支）。
  这条路径只在**开发者工具**侧可自测（需勾「不校验合法域名…」）：真机要求公网 HTTPS +
  公众平台 `downloadFile` 白名单，且手机访问不到 `127.0.0.1`，本地服务也无法验证 CDN/证书行为。
  harness 的 `--remote corrupt`（只翻转 1 字节、长度不变）与 `--remote down` 是这条路径的反向用例。
- **未完成项**：`pkg/game_web_bg.wasm` 的 wasm-bindgen 胶水是浏览器 ESM/web-sys 形态，
  小游戏既不能加载也不能解析，因此**不随包分发**；接入 `WXWebAssembly` 需要去 DOM 化的
  CommonJS 胶水，在此之前小游戏侧游戏逻辑由 Fengari + `pack/` 承载。

## Web 平台不提供的宿主 API

共享运行时（`plugins/webgl/web-runtime.js`）按引擎源码逐条实现宿主 API，但有一批**平台不提供**、
且游戏自己探测过会降级的能力。它们不进"缺失即失败"，而是记在白名单里（`wechat-minigame-harness.js`
的 `MISSING_HOST_API_ALLOWED`）；**不在这张表里的缺失一律算质量门失败**，因为那意味着某条游戏
行为被静默跳过了：

| 缺失的宿主 API | Web 平台的处理 | 游戏侧的降级 |
|---|---|---|
| `ui.focus_open/select/index/move/close`、`ui.scroll_close` | 不提供（web 端没有手柄焦点系统） | `ui/panel_nav.lua` 用 `api()` 取函数，取到 nil 就当"没有焦点导航"直接跳过 |
| `input.nav_settings`、`input.set_nav_settings`、`input.last_device`、`input.action_repeat` | 不提供（导航设置只在 PC 运行器的 `settings.toml` 体系里） | `ui/input.lua` 同样用 `type(x)=="function"` 探测后沿用默认阈值 |

运行时会把这些缺口逐条打成 `[lua missing-host-api] <名字>`，所以"游戏静默少了一个功能"
在日志里是可见的，而不是要靠猜。

## 平台能力矩阵

| 能力 | PC | WebGL | 微信小游戏 |
|---|---|---|---|
| Lua 游戏逻辑 | 引擎内嵌 Lua | Fengari + `pack/` | Fengari + `pack/` |
| 资源包加密/压缩（`-Encrypt`/`-Compress`） | 支持 | 不支持（脚本拒绝） | 不支持（脚本拒绝） |
| 存档 | 用户数据目录 | 浏览器存储 | `wx` 存储 + `USER_DATA_PATH` |
| 输入 | 键鼠 + 手柄 | 键鼠 | 触摸 → 指针事件（游戏侧可见虚拟摇杆/按钮接管）+ 微信 PC 键盘 |
| 完整字体随包 | 是 | 是 | 否（只用 pack 子集字体） |
| 资源分发形态 | 无（随包） | 无（随包） | `subpackage`（默认）/ `remote` / `full` |
| 需要服务器/备案/域名白名单 | 否 | 否 | 仅 `remote` 形态需要 |
| 自动化验收 | `--check` + `-SelfTest` | `verify-webgl-bundle.ps1` | `verify-wechat-minigame.ps1` |
