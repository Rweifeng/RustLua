# 平台插件适配

平台适配统一放在 `plugins/`：发布脚本只负责**复制 + 改名 + 校验**平台文件，平台差异不写进
引擎代码，也不在脚本里各写一份运行时。

| 平台 | 插件目录 | 产物入口 | 验证 |
|---|---|---|---|
| PC | —（引擎运行器 `game.exe`） | `game.exe` + `pack/` + `fonts/` | `package.ps1` 内置 `--check` + `-SelfTest` |
| WebGL | `plugins/webgl/` | `index.html` + `web-runtime.js` + `pkg/` | `scripts/verify-webgl-bundle.ps1` |
| 微信小游戏 | `plugins/wechat-minigame/` | `game.js` + `wechat-adapter.js` + `game.json` + `project.config.json` + `web-runtime.js` + `pkg/` + `pack/`/`mainpack/` | `scripts/verify-wechat-minigame.ps1` |

## 发布

```powershell
powershell -NoProfile -File scripts\package.ps1 -Platform pc
powershell -NoProfile -File scripts\package.ps1 -Platform webgl

# 小游戏：默认就是主包 + 单分包（-AssetPack subpackage），零服务器、零备案、零域名白名单。
powershell -NoProfile -File scripts\package.ps1 -Platform wechat-minigame -SelfTest

# 可选：瘦首包 + 资源包导出到 CDN（需要公网 HTTPS + 备案 + downloadFile 域名白名单）
powershell -NoProfile -File scripts\package.ps1 -Platform wechat-minigame -SelfTest `
  -AssetPack remote -RemotePackBaseUrl https://cdn.example.com/games/jianghu

# 本地联调（仅 remote 形态需要）：先起只读静态服务托管**资源包目录**（<发布根>\assets），
# 开发者工具里勾「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。
# 也可以直接双击 scripts\serve-wechat-pack.bat（自动定位资源包、端口取 remote-assets.json），
# 或 scripts\test-wechat-minigame.bat（先跑完整验收再起同一个服务）。
```

三者都走同一套原子发布流程（`builds/<platform>/`：staging → 原子替换 → 失败回滚），
发布目录不会是半更新状态。小游戏的发布根下固定是 `launcher/`（代码包，上传微信的就是它）；
只有 `remote` 形态才多一个 `assets/`（CDN 资源包）兄弟目录。两者都在同一个 staging 里生成、
由同一次原子交换落地。

## 平台文件职责

- `plugins/webgl/web-runtime.js`：**两个 web 平台共用**的 Lua 运行时（Fengari 执行 + canvas 绘制 +
  输入 + 启动自检标记）。共用一份是刻意的：避免 webgl 与微信小游戏的游戏逻辑各自漂移。
- `plugins/webgl/index.html`：浏览器页面模板，`package.ps1` 替换 `__PUBLISH_NAME__` /
  `__PUBLISH_NAME_JSON__` / `__FONT_PATH__` 占位符。
- `plugins/wechat-minigame/wechat-adapter.js`：把 `wx` API 映射为运行时所需的宿主 API
  （`fetch`/`document`/`window`/`Image`/`FontFace`/`requestAnimationFrame`/`localStorage`/键鼠事件）。
  详见 [plugins/wechat-minigame/README.md](../plugins/wechat-minigame/README.md)。
- `plugins/wechat-minigame/game.js`：小游戏入口，负责按序加载适配层 → Lua VM → 运行时 → 启动。

## 微信小游戏特有约束

- **资源形态三选一**（`-AssetPack`，微信平台默认 `subpackage`），细节见
  [微信小游戏分包发布](52-微信小游戏分包发布.md)：
  - `subpackage`（默认）：**主包 + 单分包**。首屏资源在兄弟目录 `mainpack/`（属主包，随包上传），
    其余资源在 `pack/` 并由 `game.json` 的 `subpackages` 声明成分包，运行时按需
    `wx.loadSubpackage` 挂载。零服务器、零备案、零域名白名单，微信自带 CDN 分发。
    `pack/` 的 root 下必须有入口 `game.js`（微信硬要求，缺了开发者工具拒绝打开工程）。
  - `remote`：瘦首包。包内 `pack/` 只留骨架，重资源上传 CDN，适配层优先包内、读不到才远端下载。
    需要公网 HTTPS、备案与 `downloadFile` 域名白名单。
  - `full`：`pack/` 整个随主包分发。`jianghu_youtian` 全量 4.4 MB 必然超过 4 MB 主包上限，
    因此这一形态对本工程实际不可用（发布脚本会在超限时明确报错并给出另两条出路）。
  三种形态互斥（`subpackage` 与 `-RemotePackBaseUrl` / `-CdnPackDir` 相互拒绝）：
  两套资源来源同时存在只会让"包内读到了"掩盖"分包根本没挂载上"。
- **脚本必须是 CommonJS**：小游戏运行时不支持 ES Module，包里任何顶层 `export`/`import`
  都会让启动直接失败（实测：`WAGame.js:1 SyntaxError: MiniProgramError Unexpected token 'export'`，
  来源是 `wasm-bindgen --target web` 的浏览器胶水）。因此微信分支**不构建也不发行**
  `pkg/game_web.js` / `pkg/game_web_bg.wasm`（`pkg/` 内只有 `fengari-web.js`），
  并且发布脚本、验证脚本、无头 harness 三处都会按脚本模式逐个解析包内 `.js`。
  检测不能用 `node --check`：Node 会按内容自动识别 ESM，对顶层 `export` 反而"通过"，
  必须用 `vm.Script`（始终按 script 解析）。
- **字体**：只随包分发 assetc 子集化后的字体（实测 226 KB），
  不复制 17 MB 的完整字体。它在包内的位置随形态变（分包形态下属首屏资源，在 `mainpack/assets/fonts/`）。
- **平台入口隔离**：小游戏包里不允许出现 `game.exe` / `index.html`，
  发布脚本会把"平台分支选错"变成发布期失败，而不是线上白屏。
- **无头验证**：`scripts/wechat-minigame-harness.js` 用 Node 伪造 `wx` API，真实执行
  `game.js → wechat-adapter.js → web-runtime.js`，断言资源读取、逐帧 Lua 绘制、二进制字节一致、
  贴图真的被宿主加载（假 `Image` 只走宿主的受限读取路径，不再直接从磁盘偷读）、触摸/键盘桥接，
  并按形态断言分包行为（分包形态：声明有且仅有 1 个 `root=pack`、入口可执行、挂载门生效、
  进度条消费了进度；其余形态：`subpackage_loads=0` 且不得有分包声明）；
  `scripts/verify-wechat-minigame.ps1` 在其上再做布局与体积校验，并跑 4 种宿主路径方言 +
  形态专属用例（分包：`ok/off/delay/never/fail-once`；远端：`auto/thin/corrupt/down/png-fail`）。
  这些检查都在实测教训之后加上：
  ① "本机全绿但开发者工具拒绝启动"（分包入口缺失）→ 分包形态现在生成**真的**入口 `pack/game.js`
  并在挂载时真的 `require` 一次，非分包形态则断言不得有分包声明且 `subpackage_loads=0`；
  ② "无头测试里贴图全对、真机上贴图全丢"（假 `Image` 直接读磁盘掩盖了问题）→ 假 `Image` 只接受
  宿主能读到的路径，且启动 Promise 不 settle 时带诊断失败而不是无限等待；
  ③ "开发者工具里全黑、0 帧、0 错误、日志全绿"（基础库把 `Image.src` 定义在**原型**上，
  只读 own 描述符的实现静默退化成写 `image._src`，宿主永不开始加载）→ 按原型链探明
  own/原型访问器与 `setSrc` 三种接管方式并自报 `image_src_takeover`（`--image-src-prototype`），
  同时补上**启动看门狗**：卡死超时后既 `console.error` 又把"启动超时"画到画布上
  （`--image-src-silent --expect-boot-stall`）；
  ④ 同源的另一半：基础库 2.32.3 的 `k$` 包装类把 `onload`/`onerror` 也做成原型访问器、
  回调存进私有字段 `__onload`，真实 image 的回调桥在**构造时**接好 → 适配层用自己的
  accessor 盖住 `onload` 等于拆桥，贴图加载成功也传不回运行时（症状同 ③）→ 现在回调
  **转发给宿主的 setter** 并自报 `image_callback_takeover`（`--image-callback-bridge` 1:1 复现）；
  ⑤ "标题界面 600 帧全绿、一按开始新游戏就崩"（`attempt to call a nil value (field 'current')`）：
  引擎的 `scene.load` 是**排队的场景切换**，真正换数据在下一帧；web 运行时若不跟着换场景数据，
  `update()` 会立刻按"已在玩法地图"分支执行。只跑标题界面的用例永远走不到这条路径 →
  现在 `--drive-new-game` 走玩家真实路径（标题按确认 → `on_click('BtnStart')` →
  `scene.load("manor")`），并逐项断言**世界状态**（地图真换了、存活实体不少于场景声明数、
  主角落在落点）；
  ⑥ "全绿但世界是空的"：缺失的宿主 API 曾静默降级成空表，`entity.find_id` 返回真值会让
  `activate()` 永远走"已存在"分支（NPC 根本不生成）→ 现在缺失 API **逐条点名**
  （`[lua missing-host-api]`）并配白名单断言（只允许游戏自己探测过、会降级的那批），
  其余按引擎源码补齐（`physics.set_position` / `transform.set` / `entity.spawn|find_id|persist_id|destroy` /
  `sprite.set` / `animation.*` / `tilemap.set_cell|set_texture|find_path` / `save.clear` / `audio.*`）；
  ⑦ "世界在动"不等于"画面在动"：Lua 世界与渲染器各存一份实体数据、靠回写通道同步，
  只在 Lua 侧取样看不见"世界里主角在走、画面上钉死在出生点" → 运行时每帧自报
  `data-rustlua-world`（含渲染侧坐标 `drawn=`），质量门新增玩法路径用例：按住**运动驱动键**（键盘桥接注入）——可见虚拟控件（`ui/virtual_pad.lua`）走鼠标事件 + Lua 侧注入，不再有"触摸摇杆派发键盘键"。按住**运行时自己从触摸
  摇杆派发出来的键**若干帧，断言主角坐标真的变了、且渲染侧与 Lua 侧一致（不硬编码游戏键位）。
- **分包形态下的路径路由**：`plugins/wechat-minigame/wechat-adapter.js` 是唯一知道"某个逻辑路径该
  从主包还是从分包读"的地方，依据是构建期生成的 `mainpack.json`（`scripts/first-screen-pack.js`，
  构建/运行时/harness 三方共用的唯一事实来源）。实现上是**主体 × 方言**两层正交组合——
  主体（`mainpack/` 还是 `pack/`）是包内布局属性，方言（根相对 / 前导斜杠 / 分包根相对…）是宿主
  属性，把主体塞进策略表当别名会在 `slash` / `sub-root` 这类宿主上拼出读不到的路径。
  首屏清单随形态体积**此消彼长**：清单越大主包越大、分包越小，而被 4 MB 卡住的是分包那一侧，
  所以清单「宁可多列、不可漏列」与体积上限方向一致。
- **远端资源回落（`-AssetPack remote` 形态）**：`remote-assets.json` 存在时语义为**包内优先 + 远端兜底**
  （下载 → 按 `pack/manifest.txt` 的体积 + FNV-1a 校验 → 落地 `USER_DATA_PATH` 缓存 → 下次命中缓存）。
  `-AssetPack remote -RemotePackBaseUrl <CDN>` 写入该文件并导出资源包，不传 `-RemotePackBaseUrl`
  则删除陈旧配置；本地联调用 `scripts/serve-pack.ps1`（底层 `scripts/pack-server.js`，只读、防目录穿越、
  带请求日志）托管**资源包目录**。宿主自己加载的 `Image.src` 会被适配层改写成本地缓存路径；
  宿主怎么写 `src`（以及 `onload`/`onerror` 的回调桥怎么接）由适配层启动时探明并各打一行自检
  `Image.src 接管方式 = own-accessor|prototype-accessor|setSrc-method`、
  `Image.onload/onerror 接管方式 = host-setter|own-accessor`；
  若某基础库不允许改写，适配层会**响亮失败**而不是静默丢图（`--image-src-frozen` 用例覆盖两种模式；`full`
  形态不需要改写 src，因此那一档下必须照常启动——三种形态对"能不能改写 src"的依赖不同，
  断言也按形态分支）。
  这条路径只在**开发者工具**侧可自测（需勾「不校验合法域名…」）：真机要求公网 HTTPS +
  公众平台 `downloadFile` 白名单，且手机访问不到 `127.0.0.1`，本地服务也无法验证 CDN/证书行为。
  harness 的 `--remote corrupt`（只翻转 1 字节、长度不变）与 `--remote down` 是这条路径的反向用例。
- **未完成项**：`pkg/game_web_bg.wasm` 的 wasm-bindgen 胶水是浏览器 ESM/web-sys 形态，
  小游戏既不能加载也不能解析，因此**不随包分发**；接入 `WXWebAssembly` 需要去 DOM 化的
  CommonJS 胶水，在此之前小游戏侧游戏逻辑由 Fengari + `pack/` 承载。

## Web↔PC API 一致性：三层门（2026-10-03 起）

本节替换掉原来那张"Web 平台不提供的宿主 API"表。那张表（以及 `wechat-minigame-harness.js` 里
配套的 `MISSING_HOST_API_ALLOWED`）描述的是 Fengari 时代**按引擎源码逐条手工实现宿主 API**的
状态，逐条核对下来已经整体失真：表里当作"平台不提供"的 `ui.focus_open`/`focus_select`/
`focus_index`/`focus_move`/`focus_close`、`ui.scroll_close`、`input.action_repeat` 七条今天
**在补丁层里都已实现**（L3 的 `ui.focus.shape` 用例就在跑它们），而 `input.nav_settings`/
`set_nav_settings`/`last_device` 三条**确实还没有**（活体探测实测 `absent`，见下面"豁免表"一节）。
Web 侧确实曾是第二套独立实现，但 WP10 把 mlua
编进 wasm 之后，**注册层已与桌面同源**——"逐条实现"这件事只剩在 `web-runtime.js` 的补丁层里。
现在它不再靠人记，由三层门分别检查（判据各不相同，因为抓的是三种不同的漂移）：

| 层 | 判据 | 跑法 | 实测结论（2026-10-03） |
|---|---|---|---|
| **L1 注册层锁** | wasm VM 的 `_G`「模块表→函数名」逐项 == 桌面基线 `lua_api_surface.json` | `scripts/verify-wasm-lua.ps1`（内含 `wasm-lua/verify-no-modules-bridge.mjs` 的 L1 段） | **41 张表 / 275 个函数，0 增 0 删**。所以"比名字"的门在注册层是空转的，它只保证 wasm 里没少注册 |
| **L2 覆盖清单** | 两类账都要与代码逐项一致：① 补丁层重定义的每个引擎名字（`function a.b(` / `a.b = function`）都要在清单里且无幽灵条目；② 补丁层把整张引擎表换掉的每个站点（`^<注册表名> = {`）都要有 dropped/invented/referenced 三份账加理由 | `node scripts/check-web-api-overrides.mjs`（`--write` 重生成） | **56 个覆盖点 / 11 个模块**（纯覆盖、0 新增）**+ 23 处整表替换 / 77 个函数在 web 上是 nil / 3 个名字是 web 独有 / 其中 9 个发包工程正在引用**，明细见下面"整表替换"一节 |
| **L3 行为契约** | **同一份 Lua** 在桌面与"打完补丁的活体运行时"各跑一遍，输出逐行对拍 | PC：`cargo run -q -p engine --example run_lua_contract -- --write` + `cargo test -p rustlua-scripting lua_api_contract`；Web：`scripts/verify-webgl-bundle.ps1 -ApiContract`；微信：`node scripts/wechat-minigame-harness.js <launcher> --check-api-contract` | 31 条用例，**28 绿 3 红**（红的是下面那张表，尚未修完所以 `-ApiContract` 还没并进 `verify.ps1` 默认序列）。微信侧 `wechat_api_contract_failed mismatches=3`，红的正是同三条（L16/L28/L30）——两个平台共用同一份 `web-runtime.js`，所以分叉一模一样，这条门是**第二次独立复现**而不是重复计数 |

L3 用的契约文件与基线 transcript 都和源码一起提交：
`engine/crates/rustlua-scripting/src/api_surface_snapshot/lua_api_contract{.lua,_transcript.txt}`。
契约文本**不进发布包**（10 KB 的验证资产要占微信 4 MB 主包配额，且一帧都不参与游戏），
由 `scripts/web-api-contract.js` 的同一个 `pageExpression` 现读现注入：浏览器侧经 CDP
`Runtime.evaluate`，微信侧经 harness 的 `vm.runInThisContext`（宿主 `window` 上挂着同一个
`__RUSTLUA_LUA_BRIDGE`）。两侧跑的是逐字节的同一段 JS，所以两边测的都是**真产物**，不是模拟环境。

写用例的规则（否则门会变成噪声源）：只断言"两侧理应相同"的部分；表的键集要排序、错误文本
剥位置前缀；**平台确实不同的行为（设备拓扑、Canvas 度量）不写进契约**，而不是写进来再豁免；
某条两侧不一致 = 真 bug，修实现或删覆盖，不改期望。

### L3 已经抓到的东西

- **`clock` 兜底覆盖是死代码，已删**（原 `web-runtime.js` 的 `genericCompat` 开头）。它写于
  "微信侧 wasm 桥未接线、`clock` 是 nil"的年代，WP10 之后 wasm 里 clock 就是引擎那份 Rust 实现，
  于是这段变成**有损重复**：契约实测出 6 条分叉——`clock.now()` 少 `hour/paused/rate` 三个字段
  （Lua 读到 nil 且不报错）、`clock.set(0,0)` 桌面拒绝而补丁接受、`clock.add(-9999)` 桌面钳到
  `day=2/minute=0` 而补丁留着 `minute=30`、`sleep_to_morning()` 桌面 `day=6/minute=360` 而补丁
  `day=183/minute=1000`。删掉之后这 6 条全绿，web 侧一行代码都没多。**保留它挡不住任何东西**：
  两边都不会自动推进时间（见下面的"web 时间基"）。
- **曾红着的 3 条，2026-10-03 已按"只改实现"修完**（契约与 PC transcript 一行都没动，
  `cargo test -p rustlua-scripting lua_api_contract` 仍 1 passed；两侧现在都 `cases=31` 全绿）。
  处置顺序固定：能删的死覆盖先删（`clock` 就是），要留的覆盖**把缺的引擎语义补上**，只有
  "平台确实不同"的行为才允许从契约里**不写**（并同时进 L2 清单说明理由）。这一轮的共同前提是
  **不能靠"少覆盖"解决**：`web-runtime.js` 里 `input`、`ui` 这些表是**整表替换**（见下面那节实测
  19 处），引擎版函数在 web 上根本不在这张表里，删掉补丁的覆盖只会让它们变成 nil，
  而不是"回落到引擎实现"。

  | 用例 | PC | 修前的 web | 改法 |
  |---|---|---|---|

### 豁免表：过期必须红（活体探测，2026-10-03）

`wechat-minigame-harness.js` 里那张 `MISSING_HOST_API_ALLOWED` 只能回答"这个缺口允不允许出现"，
回答不了"这条豁免还成不成立"。上面那七条就是这么烂在表里的：实测
`node scripts/wechat-minigame-harness.js <launcher> --frames 120 --drive-new-game --expect-runtime-spawns`

`type(x)=="function"` 命中就不再碰代理，代理才会打那条日志）。所以"这局没撞上"永远不等于"这条还缺"。

判据因此换成直接问活体 Lua 状态：按 `全局.字段` 用 `rawget` 逐级下钻。用 `rawget` 而不是普通取值，
是因为缺失的全局与缺失的字段都是**带 `__index` 的空代理表**——普通取值会顺带打一条缺口日志并返回
可调用代理（看着像成功），`rawget` 只看表里到底躺着值没有。探测只在 Lua 活着时做，做不成就在
结论行写 `exemption_probe=skipped:<原因>`：不放行，也不假装验过。

### 顺手修掉的：门自身的两处读数缺陷

- **PS 函数返回值被 node 的 stdout 污染**。`verify-webgl-bundle.ps1` 的 `Invoke-HeadlessDom`
  里那句 `& node webgl-cdp-wait.js …` 没有接输出，而 PS 会把函数内**未捕获**的输出并进返回值，
  于是它返回的是「`[cdp]` 那几行 + 报告正文」的**数组**。`-match` 作用在数组上返回的是
  "匹配到的元素数组"、**不填 `$Matches`**（判空却照样为真），所以
  `$contractOutput -match 'mismatches=(\d+)'` 之后取到的 `$Matches[1]` 还是上一条无关
  `-match` 的捕获组。实测红字：`verdict=failed(scene=main entities=17) cases=0`——
  红绿方向侥幸没错，**两个数全是假的**。接进 `$cdpEcho` 之后同一条门报
  `api_contract: failed(3) cases=31`。教训：结论是"解析出来的"门，格式要写死到解析式里，
  对不上就判红，而不是降级成"少一个字段也算读到"。
- **失败行不带 cases**。报告首行原本只有 `web_api_contract_failed mismatches=N`，PS 的失败分支
  没人填 `$contractCases`，于是日志里那句 `cases=0` 读起来像"只跑了 0 条用例"。现在 ok/failed
  两种首行都带 `cases=N`，正则也要求它存在；微信侧同一口径（`用例数 31`）。

### 整表替换会静默删掉引擎函数（2026-10-03 已进门）

`_G` 名字对拍（L1）与老的"覆盖点清单"都抓不到 `input = { ... }` 这种**赋值整张表**的写法——
它不是"覆盖某个函数"，而是"把这张表里没重写的函数全删了"，而 Lua 读到 `nil` **不报错**
（只在调用那一刻炸，或者静静走 falsy 分支）。规模实测：**23 处站点**。

```
grep -cnE '^[a-z][a-z0-9_]* *= *\{' plugins/webgl/web-runtime.js   # 23
# log time input scene grid inv map entity transform transform3d tilemap health physics
# physics3d sprite animation animation3d audio ui save particles camera mesh
```

（首字母限死为字母，是为了排除 `__rustlua_*` 那些补丁自己的状态表——它们不是引擎注册名。
门里用的是同一个锚：列 0 起始，否则 JS 侧的 `audio = {` 赋值会被误判成 Lua 站点。）

现在这一类由 `node scripts/check-web-api-overrides.mjs` 直接判，读到的账（2026-10-03 实测）：


|---|---|---|

| `dropped=77` | 引擎注册了、补丁没换回来的函数名 → **在 web 上是 nil** | 逐表清单见 `plugins/webgl/lua_api_overrides.json` 的 `replacements[].dropped` |

`input` 那一行里的"2 个由补洞循环给出"是这一类的**第三种隐身写法**：

```lua
for _, api in ipairs({audio, input}) do
  if not api.load_settings then api.load_settings = function() return false, '…unavailable; defaults retained' end end
  if not api.save_settings then api.save_settings = function() return false, '…persistence unavailable' end end
end
```

循环里的 `api.X = function` 既不是 `function a.b(` 也不是 `a.b = function`，所以门现在把
`ipairs({表名…})` 的表清单与循环变量一起解析，把 `load_settings`/`save_settings` 记到 audio 与
input 两张表头上。于是 `main.lua:291` 那句**没有 pcall 的** `input.load_settings()` 在 web 上
不会炸（拿到 `false` + 一句诊断，与桌面"缺文件时保留默认"同形）。
活体探测逐条实测（`--probe-host-api input.load_settings,input.save_settings,input.last_device,input.nav_settings,input.action_map_text,input.rumble`）：
`present present absent absent absent absent`——上表那 14 条就是按这个口径判的，不是纸面推断。

同一条实测还钉出一个真实的功能性静默：`hints.lua:221` 的
`if type(input.last_device) == "function"` 守卫在 web 上**恒假**（`last_device` 确实 absent），
所以"按最近输入的设备切提示文案"那支从来不执行，走的是缺省分支。控制台对此一个字都不会打——
代理只在你**碰**缺失全局时才记名字，而 `input` 是补丁自己的真表，缺字段就是 `nil`。
这正是豁免表那节说的"控制台证据对已实现/对 nil 字段两头隐身"的另一半。

**门自身的两处计数坑（都是本轮踩过才修对的）**：

- Lua 块层级必须记账。函数体在参数列表那对括号闭合后会**回到深度 1**，不跟踪
  `function`/`if`/`do` ↔ `end` 就把 `local value = {}` 里的 `value` 当成表键——
  第一轮实测 `input` 报出 37 个键、`tilemap` 报 36 个（引擎侧只有 10 个）。而关键字匹配
  必须**锚在当前位置**：`/function/.exec(text.slice(i))` 不带 `^` 会在串里任意位置命中，
  `i` 随后跳到无关偏移，把中间的代码整段吃掉（症状反过来：所有键都扫不出来，`dropped` 变成全表）。
- `referenced` 要先**剥掉 Lua 注释与字符串字面量**，再限定在 `examples/*/scripts`（跳过

  三口径实测：含 `game_api` 时 `referenced=76`（等于全表，毫无信号）；排除后 9。

`health.invented 新增 [poke]`（补丁多一个桌面没有的名字）、`health.dropped 新增 [get]`

**它买不到的部分**：这仍是**清单层**的门，判据是名字集合，所以它只说"这条在 web 上是 nil"，

### web 时间基缺口（L3 顺带查出，未修）

游戏内时间由 `LuaRuntime::step`（`rustlua-scripting/src/script/step.rs:120` 的
`state.game_clock.step(delta_seconds)`）推进，而 `game_web` 只暴露 `start` / `lua_call_global` /
`lua_do_string` 这一类**按需调用**的桥，web 帧循环（`web-runtime.js`）从不调它。
后果：`clock.set_rate(2)` 之类的倍率在 web 上永远是空的，游戏天数只会在脚本自己
`clock.set/add` 时变。修法是把 step 经桥暴露出来并在 JS 帧循环里按 delta 调；
这属于**补功能**，不在本轮"把一致性自动化"的范围内，先记在这儿。
