# 引擎统一支持 2D/3D：核心复核与实施计划

状态：待评审。本轮为静态代码复核与规划，未修改引擎实现，未执行编译、测试或 GPU 验收。

## 1. 结论与完成定义

建议采用 **统一 Transform + 统一 Camera + 独立的渲染和物理专业系统**。最终 ECS 只保留一份权威空间状态；旧场景和 Lua 接口通过边界适配迁移。

核心收益是统一空间、脚本、编辑器和相机语义，并支持世界空间精灵与模型混合。不是性能优化项目：Vec3/Quat 和世界矩阵缓存可能增加纯 2D 内存开销。

首版完成定义：

- 同一场景和实体模型表达 Sprite、Mesh、正交/透视相机。
- Sprite 与 Mesh 可在同一相机下投影并参与深度遮挡；屏幕 UI 不受世界相机影响。
- 旧 2D 相机缩放、旋转、边界、输入、排序和 UI 行为保持；旧 3D 相机视图及选择保持。
- 新场景支持明确的父子空间变换，兼容旧场景组织树。
- 编辑器 Scene/Game 预览与桌面运行时使用一致的空间求解和投影。Web 按现有能力回归，新增后端能力不默认包含。

不顺带合并 Rapier2D/Rapier3D、精灵/骨骼动画、UI 布局/世界变换；首版不要求完整 RenderGraph、分屏或世界空间 UI。

## 3. 目标架构

### 3.1 一个局部 Transform，一份派生世界矩阵

设计示意，非当前已有 API：

```rust
struct Transform {
    position: Vec3,
    rotation: Quat,
    scale: Vec3,
}
struct GlobalTransform { matrix: Mat4 }
struct SpatialParent(EntityId);
```

- Transform 表达局部 TRS；GlobalTransform 为派生缓存，不序列化。
- 2D 默认 XY 平面、z=0、绕 Z 旋转、scale.z=1。2D setter 修改 XY 时保留 Z；不隐式压平已有 3D 姿态。
- 不用 TransformMode 作为全引擎分支开关。平面约束由物理、控制器或编辑工具表达。
- parent/children 独立于 Transform，关系只有一个权威来源。Vec2 保留给 UI、输入、2D 物理；可通过 re-export 保持模块兼容。
- 世界矩阵保留剪切：非均匀父缩放与子旋转组合不能保证无损分解回 TRS。
- 初期沿用正缩放限制；负缩放另立任务。解析器、Lua、setter、矩阵入口统一 finite/单位四元数校验；零四元数拒绝，近单位误差归一化阈值明确。

**旧层级兼容：** v2 的 parent 是既有组织关系，不能自动推断旧 Transform 为局部坐标。默认迁移保持组织树和原有世界位置，不启用空间继承。新场景显式建立 SpatialParent；可提供“保持世界位置并建立空间继承”转换。遇逆矩阵或剪切导致无法表达局部 TRS 时报告实体并拒绝有损转换。UI 与骨骼层级独立。

### 3.2 相机姿态、投影、控制器分开

```text
Camera = Projection + Viewport + ClearPolicy + VisibilityMask + Order + Enabled
Projection = Orthographic(ScalingPolicy, near, far)
           | Perspective(fov_y, AspectPolicy, near, far)
CameraController2D = zoom/bounds/follow 等操作语义
RenderView = 有效 viewport、view/projection/inverse、可见层与 pass 策略
```

- 相机姿态来自同实体 Transform/GlobalTransform。look_at 是改姿态的方法，不能再保留独立可写 camera.position/target。
- 正交相机可看模型，透视相机可看精灵；投影类型不等于渲染维度。
- 旧 zoom 对应可视世界高度 `viewport_pixel_height / zoom`。P0 核实旧路径的逻辑/物理像素含义，覆盖 DPI 与离屏预览。
- bounds 在控制器中解析有效中心；保留原始中心与钳制结果的区别。
- 正交裁剪范围独立校验，不能照搬透视 near>0；保持现有 wgpu 深度约定并测试 near/far 投影。
- 初期拒绝相机带缩放/剪切的空间父链，避免视图意外变形。
- 保留默认 2D 中心、默认 3D 相机、选择与回退。相机选择归属视图槽，3D 切换不影响 ScreenUI。
- viewport/aspect 从实际目标解析。分屏和 RenderTexture 为后续增强。

### 3.3 统一视图，保留专用管线

| 用途 | 行为 |
| --- | --- |
| World | Sprite/Mesh 共用投影，材质决定深度/混合 |
| Legacy2DOverlay | 过渡期保留旧精灵、瓦片与 UI 无深度叠加行为 |
| ScreenUI | UiLayout/Canvas 解算，与世界相机分离 |

先引入 RenderView 和显式 pass 列表，保持旧顺序，再新增 world-sprite quad 路径。已经变成屏幕坐标的旧 2D 顶点不能直接用于透视世界渲染。

不透明/裁切精灵深度测试并写入；透明精灵深度测试、通常不写深度、按视图后向前稳定排序。旧 layer/order 不直接映射为世界 Z。mesh、sprite、UI 保留自己的 shader、材质和批处理。billboard 是显式可选行为。

输入统一提供 screen→ray；2D screen_to_world 是射线与指定平面相交的便利操作；屏幕 UI 保留布局命中测试。

### 3.4 物理与更新权威

保留两套物理后端与专用速度类型。动态刚体由物理回写；静态/运动学由游戏变换同步。禁止同实体被普通积分、2D 和 3D 动态物理重复驱动。

结合现有 scheduler 实施：脚本/控制器→必要空间传播→静态/运动学同步→固定物理步→动态回写→最终空间传播→渲染快照。显示插值如需新增，不反写模拟状态。

初期动态刚体限根空间或明确支持的无缩放刚性父链；不能把世界位置直接写到有父节点的局部位置。UI 动画和骨骼 palette 不并入实体空间传播。

## 4. 分阶段实施

### P0：契约与基线（2–3 人日，粗估）

- 补全生产调用、场景、Prefab、Lua、Inspector、assetc、game_web 入口清单。
- 固定纯2D、纯3D、UI场景的截图、输入命中、相机参数、帧时间与内存测量条件。
- 建立 Camera2D 新旧对照和 Camera3D look-at/射线/视锥 fixture。
- 冻结角度、像素、缩放、旧层级、相机父链规则。
- 验收：基线可复现，迁移 fixture 完整；不在基线未知时批量改类型。

### P1：统一空间求解（3–5 人日）

- 新增统一 TRS、GlobalTransform、SpatialParent 与 parent-first 求解。
- 定义 2D 转换和便利方法，规划 integrate_velocity 平面更新语义。
- 先完整求解保证正确，再按基准引入 dirty/version；所有 get_mut 写入必须覆盖失效机制。
- 测试循环、失效实体、换父/删除、无空间父、非均匀缩放、剪切、非法四元数。
- 验收：Gchild=Gparent*Lchild；旧路径不变，core 无 host 依赖。

### P2：版本迁移与单一运行时 Transform（5–8 人日）

- 新场景建议 v3，在严格校验前加显式 v2→v3 边界；未知未来版本仍拒绝。
- 五字段旧 Transform 提升为 Vec3/Quat；Transform3D 转为统一格式。边界双读，新写只写规范格式。
- 同实体有两种旧 Transform 时诊断冲突，默认拒绝自动转换，不按遍历顺序覆盖。
- 迁移 script 装载、scene_extract、component_schema、Prefab/override、Sprite/Tilemap/Particle、物理、glTF 实例化及编辑器预览。
- 旧 Lua facade 转发到同一组件。Rust alias 共享 TypeId，不能用于维持两个 ECS 槽；禁止永久双写真源。
- 迁移工具提供 dry-run、实体错误报告、备份、原子写入；Prefab override 的组件键和字段路径一并处理，保留未知自定义数据。
- 验收：运行时只查询统一 Transform；旧世界位置保持；迁移幂等、v3 roundtrip。

### P3：统一 Camera/RenderView（4–6 人日）

- 新增 core Camera/Projection/RenderView，host 保留 GPU 资源。
- Camera3D position/target/up 转为相机姿态。与同实体已有 Transform 不一致时报告冲突，明确迁移选择，不能静默覆盖。
- Camera2D 兼容控制器生成正交视图，保留 zoom、bounds、默认中心和 resize。
- 统一 active/fallback/编辑器 override，迁移 Lua 与 Inspector。
- 先通过旧渲染适配消费 RenderView，此阶段不同时重写透明排序。
- 验收：旧 2D 坐标等价；正交看模型；旧射线等价；切换/销毁/缺失相机、无效 viewport 行为确定。

### P4：世界空间混合（5–8 人日）

- frame.rs 改显式视图/队列快照；运行时与静态预览共享空间/相机解析。
- renderer.rs 按视图组织 clear、depth、opaque、transparent、overlay，保留专业 pipeline。
- 新增 world Sprite quad；Tilemap、Particle、世界文字逐项列能力表，未支持组合明确诊断。
- 正确配置视图深度附件、viewport、排序；保留旧 overlay 模式。
- 验收：Sprite 在 Mesh 前后正确遮挡、透明边缘不错误写深度、HUD 不随相机移动、窗口和离屏一致。

### P5：编辑器和发布收口（4–7 人日）

- 一个 Transform 面板，2D/3D 仅为编辑方式；一个 Camera 面板按投影显示字段。
- 合并撤销数据源，回归 2D 对齐/分布、3D Gizmo、批量编辑、复制粘贴、Prefab override、撤销/重做、Play 停止恢复。
- XY 操作保留 Z；非平面旋转的 2D 编辑行为明确，不暗中清除倾斜。
- 更新 Lua 文档、兼容期告警、模板、示例、assetc 和迁移手册。
- 跑桌面、编辑器、headless、Web 现有质量门；声明各平台能力限制。
- 验收：新内容不再写 Transform3D/Camera3D；删除旧运行时存储和重复编码；回归和性能结论可复现。

依赖：P0→P1→P2→P3→P4→P5。相机投影设计和 schema 设计可并行，但避免同时改 script.rs/runtime_scene.rs 的多个状态来源。


## 6. 风险、估算与回滚

优先解决状态权威、旧数据迁移和相机投影等价，再做共享深度。最大的兼容风险是旧 parent 被误解释为局部空间、相机自身姿态与 Transform 冲突、旧 2D layer 被当深度、物理重复回写、UI 被世界矩阵驱动。

粗估一名熟悉代码的工程师约 23–37 人日，P0 后重估；静态复核不能确认平台隐藏成本。这是完整目标估算，不是组件更名工作量。

每阶段保留可编译提交和 fixture。渲染可切换旧路径；格式升级以备份恢复，不能承诺新增三维/父链内容无损降回旧2D格式。降级无法表达的数据必须拒绝。

后续增强另立任务：负缩放、完整 RenderGraph、分屏、RenderTexture、世界空间 UI、跨物理世界交互。

**建议首先实施 P0+P1：建立契约和统一空间基础，再迁移消费者。**
