# WP0 第二批：统一报告与渲染指标

## 1. 批次目标

第二批在第一批可重复 benchmark 的基础上统一统计口径和 JSON 输出，并为 Renderer 增加公开的逐帧提交指标。该批只建立可信观测，不改变 2D/3D 的渲染顺序、深度或材质语义。

## 2. 实现内容

### 2.1 统一 benchmark 报告

ECS、Sprite、Tilemap 报告统一为 `wp0-v2`，时间统计统一包含：

- `min_us`
- `average_us`
- `p50_us`
- `p95_us`
- `p99_us`
- `max_us`

三个入口均支持 `--output PATH`。`scripts/verify.ps1 -Benchmarks` 批量生成：

- `baselines/ecs-stairs.json`
- `baselines/sprite-10000.json`
- `baselines/tilemap-100x100.json`

ECS 固定阶梯为 1,000 / 10,000 / 50,000 / 100,000 entities，每档默认运行 1 秒。Sprite 与 Tilemap 默认采集 30 个样本。

### 2.2 公开 Renderer 帧指标

新增并从 `engine::host` 重新导出 `RenderFrameMetrics`：

```rust
pub struct RenderFrameMetrics {
    pub cpu_frame_us: u64,
    pub gpu_frame_us: Option<u64>,
    pub draw_calls: u64,
    pub instances: u64,
    pub triangles: u64,
}
```

`Renderer::last_frame_metrics()` 返回最近一次成功提交的帧指标。

### 2.3 统计语义修正

- 2D 仅统计实际成功编码的 draw；资源绑定失败或缺失时不虚增 draw call；
- 3D shadow pass 与 main mesh pass 分别计入 draw call；
- 3D instance 与 triangle 按逻辑场景几何统计一次，不因 shadow pass 重复计算；
- Vector Text 计入 draw call 和 triangle，但不误算为 Sprite instance；
- GPU timestamp 未接入，`gpu_frame_us` 保持 `None`，不以 CPU frame time 代替。

## 3. 自动测试

Renderer 纯统计测试覆盖：

- 纯 2D draw 与几何数量；
- Vector Text 不增加 Sprite instance；
- 纯 3D 的 shadow/main pass 与逻辑几何计数；
- 2D + 3D 混合场景计数。

本轮复验 `host::renderer::tests`：11 passed，其中包含上述 4 项统计测试及离屏渲染/readback 回归。

## 4. 当前 `wp0-v2` 基线

### 4.1 ECS 阶梯

下表来自 `baselines/ecs-stairs.json`，单位为微秒：

| Entities | Query p50 / p95 / p99 | Update p50 / p95 / p99 | Command p50 / p95 / p99 |
|---:|---:|---:|---:|
| 1,000 | 24 / 29 / 41 | 76 / 91 / 132 | 57 / 73 / 101 |
| 10,000 | 253 / 377 / 420 | 818 / 1,069 / 1,330 | 292 / 492 / 535 |
| 50,000 | 1,536 / 2,480 / 2,749 | 4,827 / 5,965 / 10,090 | 2,052 / 2,562 / 2,856 |
| 100,000 | 3,350 / 4,642 / 5,520 | 10,752 / 12,267 / 14,183 | 10,365 / 10,957 / 11,815 |

所有阶梯均满足 `final_entities == min_entities == max_entities`，没有实体数量漂移。

### 4.2 Sprite 10,000

来自 `baselines/sprite-10000.json`，30 个样本：

| 阶段 | p50 | p95 | p99 |
|---|---:|---:|---:|
| push | 236 µs | 282 µs | 282 µs |
| build | 1,437 µs | 2,425 µs | 2,518 µs |

渲染数据：80 draw calls、10,000 instances、20,000 triangles。

### 4.3 Tilemap 100×100

来自 `baselines/tilemap-100x100.json`，30 个样本：

- p50：1,388 µs
- p95：1,863 µs
- p99：1,994 µs
- 1 draw call
- 10,000 instances
- 20,000 triangles
- 60,000 vertices

旧的 `artifacts/baselines/sprite.json` 与 `tilemap.json` 是 10-cycle 探测结果，正式第二批对照应使用带规模后缀的 30-cycle 文件。

## 5. 验收结论

第二批完成了 WP0 的统一 CPU 统计和渲染提交可观测性：三类 benchmark 可由一个脚本生成统一版本报告，Renderer 计数边界有纯测试保护，2D、3D、混合和 Vector Text 的统计语义已明确。

尚未完成：

- GPU timestamp query/resolve/readback；
- 纯 3D 100 / 1,000 / 10,000 阶梯；
- CPU allocation 与 peak live bytes；
- 纹理/mesh buffer 的完整已知字节统计；
- 跨后端容差型 3D golden；
- 同机重复运行误差 ≤5% 的自动比较门。

这些缺口由第三批 3D 基准先补纯 3D 阶梯和 CPU allocation；GPU timestamp 与完整 golden 仍需后续批次。
