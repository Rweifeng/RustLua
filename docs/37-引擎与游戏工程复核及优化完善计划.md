## 1. 执行摘要

工程**功能完成度很高**：M0–M20 全部里程碑任务已归档（`tasks/done/` 当时共 132 份；现已 **133 份**，多出的是 M22 输入层专题），14 个 headless 验收示例实测全绿（62.8s），765 个单元测试全通过，`cargo fmt`/`cargo clippy -- -D warnings` 零告警。这在同类自研引擎里属于难得的基线质量。

但复核发现**四类系统性问题**，且都不在"缺功能"这一层：

| 类别 | 性质 | 代表证据 |
|---|---|---|
| **A. 质量门等于没有** | CI 因路径硬编码指向已删除目录而**必然红**，且从不执行任何验收套件 | `.github/workflows/quality.yml:65,69` 指向不存在的 `game_jianghu_youtian` |
| **B. 失败被伪装成成功** | 运行器把 Lua 崩溃、无 GPU、渲染致命错误一律以 **exit code 0** 退出 | `game_app.rs:123-133` → `request_exit` → `main.rs:81 Ok(())` |
| **C. 数据完整性缺陷** | 存档可被一次多行文本**整档损坏**（已复现）；编辑器存在 3 处用户可达 panic；**"开始新游戏"会继承上一局农田/采集进度** | `save.rs:38` 不转义 + `script.rs:5133` 不校验；`inspector.rs:1381`、`recovery.rs:315`；`main.lua:154-176` 缺 `farm`/`gather` 复位 |
| **D. 文档与版本状态失真** | 章程/README/CHANGELOG/游戏文档的"待办"清单与实际相反；8 个测试样例、5 份文档未纳入版本控制 | `tasks/plan/` 已清空但 3 份文档仍称有遗留任务 |

**结论**：当前最高优先级**不是继续加功能**，而是把"验收信号"修好（A+B），再修数据完整性（C），然后做工程卫生（D）。在 A、B 未修好之前，`verify.ps1` 的绿灯**不具备说服力**——它现在会对缺失的测试样例静默跳过并返回成功。

## 4. 值得保留的部分（避免优化时回退）

复核确认以下设计是**做对了**的，改进时不得破坏：

- **Lua 边界**：core 不泄漏 mlua/wgpu/egui/rapier 类型，Lua 只持 `i64` 句柄与表、无 userdata；16 处 Lua 回调调用点均未在持 `borrow_mut` 时回调 Lua → **无 `already borrowed` panic 路径**（章程 §6-4/5 达成）。
- **实体句柄**：全量 generation + `ensure_alive` 前置校验，陈旧句柄被拒且不误伤复用实体。
- **调度器语义**：`(stage.rank, registration_order, index)` 堆键保证确定性排序，拒绝跨阶段反向依赖与环，panic 归类为带 system+stage 的错误。
- **固定时间步**：有界追赶 + 丢弃 + 计数，单测覆盖 60Hz 与丢弃上界。
- **格式层**：`resource_db` 的 temp+rename 原子写 + 表头版本拒收 + TSV 转义；`scene`/`prefab` 解析后强制 `validate()` + BTreeMap 确定性输出 + 错误带行号/字段/路径；`settings.rs` 宽松解析 + 保序 upsert 保留注释与未知段。
- **编辑器落盘**：`document.rs:223-270` 三段式原子写（temp → 重新 `Scene::load` 校验 → rename → backup 回滚）。
- **Play/Stop 状态机**：`PlayState` + "任一初始化失败绝不进 Playing"，错误可读且有回归测试。
- **预览回读管线**：非阻塞双槽轮询 + `map_result` 三态 + 失败清槽可重试，提交顺序有注释与单测。
- **手柄层**：死区仅后端应用一次、边沿只在变化帧、断连清空按钮与轴，11 项测试充分。
- **游戏工程分层**：`scripts/` 已清晰分为 `core/ data/ player/ systems/ ui/ world/`（data 3031 行 / systems 3412 / ui 2831 / world 1992 行）；Lua 侧 **无 `_G`/`_ENV`/`rawset` 使用者**（grep 0 命中），无仅为副作用而 require 的模块（唯一"按 import 顺序注册"是 `main.lua:38-41` 的 combat→enemy，`scripts/README.md:101-103` 已明确列为不可调整契约），无真正的孤立模块；89 处 `pcall` 绝大多数是 `local ok, err =` 显式处理。
- **Lua 存档降级链**：`core/save_manager.lua` 的 provider 注册中心（幂等注册、按注册顺序确定性恢复、单个 provider 用 `pcall` 包裹）设计干净，读档失败降级链完整（`peek_map` → 降级 manor → `load()` 失败 → 走新档），**无 panic 面**。
- **Lua 校验器架构**：`validate_data.lua` 是单一事实来源，启动/`game --check`/`editor --check`/编辑器面板**共用同一份清单与诊断文本**，且 1133 行手工校验的**诊断质量极高**（每条带文件 + 对象路径 + 字段，如 `data/recipes.lua:recipes.pill_refine.inputs[1].item: unknown item`）。**不得为减行数改成泛型 schema 而丢失字段路径**；只建议把 25 处"required non-empty string"这类纯样板抽成 `check_string(path, v, issues)` 小助手（约省 200 行，诊断文本不变）。
- **Lua 玩法底座**：`systems/combat.lua` 的固定步判定窗（`ready_at`/`expires_at` + `atk.hits[]` 去重 + 攻击者死亡即作废）确定性强、与 60Hz 对齐、有只读 `M.log()` 供 headless 断言——**数值改动只需改 `data/skills.lua`/`data/enemies.lua`，不要碰底座**；`systems/interaction.lua:106-136` 的两段式候选排序有明确行内理由且只在按 E 时调用（**不要改成每帧排序**）；`core/state.lua` 的类型安全（`var_value_ok` 白名单、`VALID_MODES`、`var_events` 有界 32 条带来源追溯）与 `capture/restore/reset` 三处字段对称；`ui/panel_nav.lua` 的引擎能力探测（`api(name)` 为 nil 时静默降级 + `pcall`/`tonumber` 兜底）是全项目旧引擎兼容最规范的一处。

## 7. 验收与回归要求

每个任务按[章程 §9.1/§10](00-project-charter.md) 五阶段推进，并满足：

1. **任务级门**：`cargo fmt --all -- --check` + `cargo clippy --workspace --all-targets --all-features -- -D warnings`（当前是零告警基线，**不得引入新告警**）+ `cargo test --workspace --all-features`（765 个测试基线全绿）；
2. **新增缺陷必须带复现测试**：上述 P0/P1 每项都要有"修复前失败、修复后通过"的用例；
3. **性能类任务必须带基准**：以阶段 0-6 建立的 `criterion` 底座为准，给出前后对比数字，禁止只做代码审查就宣称优化；
4. **格式/API 变更**：按章程 §6-10 与 §12，必须记录 ADR 到 `docs/02-technical-decisions.md` 并给出迁移策略；
5. **阶段出口**：跑通 `scripts/verify.ps1 -Mvp`（阶段 0 后 CI 自动执行），且无未解决 P0/P1；
6. **不得回退**：第 4 节列出的"值得保留"部分必须在代码审查中显式确认未被破坏。

## 8. 不做的事（范围边界）

依[章程 §4.2](00-project-charter.md) 与本次复核结论，明确**不在**本计划内：

- 不更换核心技术选型（wgpu/winit/mlua/rapier/egui 保持）；

- 不引入 ECS 重写（`World`/`Scheduler` 只做定点修复与缓存，不做数据布局改造）；
- 不做多线程渲染器改造（只消除每帧分配与逐 draw 创建）；
- 不承诺 WebGL/微信小游戏平台能力（`game_web` 仅补契约或降级标注）；
