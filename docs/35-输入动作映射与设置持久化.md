# 输入动作映射与设置持久化（M20-07 → M22）

本文记录命名动作输入层的接线：物理输入 → `ActionMap` → Lua `input.action*`，以及
`<project>/settings.toml` 的 `[input]` 段读写与版本回退策略。

设计决策见 [ADR-0021](02-technical-decisions.md)。M22/W3 的增量（轴边沿、时间制连发、
径向死区、设备判定下沉）见 §7。

## 1. 三层模型

```
物理输入                     命名动作映射                        动作消费
键盘/鼠标（InputKey/MouseButton）   ActionMap（ScriptState 内单实例）   Lua input.action* / pad*
手柄设备帧（host::gamepad，M20-06）  Binding::{Key,Mouse,GamepadButton,GamepadAxis}
```

- **单一事实来源**：`ActionMap` 随 `ScriptState` 走，Lua 侧 `input.rebind(...)` 与宿主
  `LuaRuntime::set_action_map/action_map` 操作同一份实例，不会出现「脚本改了、宿主没改」。
- **设备帧合并**：`RuntimeScene::run_script_steps` 每帧调用 `gamepad.poll_into(&mut input)`
  （M20-06），把真实手柄按钮/轴写进本帧 `InputSnapshot`；无设备时与传入快照等价，headless 行为不变。
- **旧物理键 API 不变**：`input.is_down/just_pressed/just_released/axis/mouse*/cursor/scroll`
  语义与行为完全保留，老脚本与既有 headless 用例（直接喂物理键）继续通过。
- **动作查询也不变**：`input.action/action_pressed/action_released/action_axis` 的签名与
  返回类型不变；M22/W3 只是让**手柄轴也参与边沿**（见 §7），因此 `action_pressed("ui_up")`
  对键盘方向键、DPad 与左摇杆同义。

## 2. 默认绑定（`ActionMap::with_defaults`）

| 动作 | 默认绑定 | 说明 |
|---|---|---|
| move_up / move_down / move_left / move_right | W / S / A / D | 世界移动（方向轴由 `input.axis` 或动作合成） |
| interact | E | 交互（农田/建筑/商店/NPC/出口/采集） |
| attack / skill / gift / sleep / practice | J / K / G / T / Q | 战斗与日常 |
| inventory / pause | I / P | 面板 |
| confirm | Space + 手柄按钮 0（A） | 确认 |
| cancel | Escape + 手柄按钮 1（B） | 取消/关闭 |
| **ui_up** | ↑ + 左摇杆 Y 正向 + DPad 上（12） | 菜单/焦点上移 |
| **ui_down** | ↓ + 左摇杆 Y 负向 + DPad 下（13） | 菜单/焦点下移 |
| **ui_left** | ← + 左摇杆 X 负向 + DPad 左（14） | 菜单/焦点左移 |
| **ui_right** | → + 左摇杆 X 正向 + DPad 右（15） | 菜单/焦点右移 |

约定与要点：

- 摇杆 **上为正**（与 WASD `vertical` 一致）；轴判定阈值默认 `0.5`（可用 `[input] nav_threshold`
  调整，见 §7），与设备死区（摇杆 0.15、扳机 0.05）是两个概念。
- 菜单方向按**方向拆成四个动作**，因此 `input.action_axis("ui_down", "ui_up")` 能得到带符号的
  模拟量（向上的推杆为正）。若把两个方向塞进同一动作，正负会在合成时相互抵消。
- `action_axis(negative, positive)` 的**首参是负向动作**：垂直写作 `("ui_down", "ui_up")`，
  水平写作 `("ui_left", "ui_right")`。
- 手柄按钮索引契约见 [手柄设备接入与输入契约](33-手柄设备接入与输入契约.md)。
- **摇杆菜单导航依赖 `ui_*` 的轴绑定**（M22/W3 起）：把 `ui_up/ui_down` 的 `padaxis:*` 解绑，
  摇杆就不再驱动菜单（解绑即禁用，这是预期行为）。若同时把玩法移动改绑到同一根摇杆，会与
  `ui_*` 冲突——编辑器按跨动作冲突提示，二选一。

## 3. Lua API

| API | 返回 | 说明 |
|---|---|---|
| `input.action(name)` | `bool` | 任一绑定按下（手柄轴：数字态过阈值） |
| `input.action_pressed(name)` / `input.action_released(name)` | `bool` | 本逻辑帧边沿（保留到本帧被消费）；**手柄轴越阈值也有边沿**（M22/W3） |
| `input.action_repeat(name)` | `bool` | 菜单导航专用：按下边沿一步 + 模拟量按住后按 `delay_ms`/`repeat_ms` 连发（M22/W3，见 §7） |
| `input.action_axis(negative, positive)` | `number` | 手柄摇杆取模拟量、键位取 0/1，结果钳制到 -1..1 |
| `input.pad_button(index)` / `input.pad_axis(index)` | `bool` / `number` | 原始手柄查询（调试与特殊玩法） |
| `input.last_device()` | `"keyboard"` / `"gamepad"` | 最近一次产生**真实边沿**的设备（M22/W3）；UI 提示据此选文案 |
| `input.actions()` | `{ name... }` | 全部动作（字典序） |
| `input.bindings(action)` | `{ "key:e", "pad:0" }` | 绑定文本（`Binding::to_text` 稳定形式） |
| `input.rebind(action, binding)` | `ok, err` | 覆盖该动作的全部旧绑定（单一主绑定语义）；非法绑定返回 `false, reason` |
| `input.unbind(action, binding)` | `bool` | 解绑一个绑定 |
| `input.reset_bindings()` | — | 恢复默认（唯一重置入口） |
| `input.action_map_text()` | `string` | 序列化（含版本头 `rustlua-actions-v1`） |
| `input.set_action_map(text)` | `ok, err` | 版本头不符 → `false, reason` 且**不改动**当前映射 |
| `input.settings_path()` | `string\|nil` | 默认 `<project_root>/settings.toml` |
| `input.load_settings(path?)` / `input.save_settings(path?)` | `ok, err` | 读写 `[input]` 段；无工程根且未给路径 → `false, "no_project_root"`。`load_settings` 现在**同时应用导航手感**（阈值 + 连发节奏），游戏不必再单独调 `apply_nav_settings()` |
| `input.nav_settings(path?)` | `{threshold, delay_ms, repeat_ms}` | 读 `[input]` 段的菜单导航手感；无工程根返回 `nil`，缺键/脏值回落并钳制。旧的 `nav_delay_frames`/`nav_repeat_frames` 仍可读（按 60Hz 换算成毫秒，M22/W3） |
| `input.set_nav_settings(threshold, delay_ms, repeat_ms)` | 生效值三元组 | 把导航手感推给引擎：阈值 → 设备层轴判定阈值；两个时长 → `action_repeat` 连发（M22/W3） |
| `input.diagnostics()` | `{ message... }` | 设置读取/回退的可定位诊断 |

绑定文本（`Binding::to_text`）：`key:e`、`key:space`、`key:escape`、`key:up`/`key:down`/`key:left`/`key:right`、
`key:other:113`、`mouse:left`、`pad:0`、`padaxis:1+`、`padaxis:1-`。

- 方向键（`InputKey::ARROW_*`）用**可读名字** `key:up`/`key:down`/`key:left`/`key:right`
  （与 Lua 侧 `input.is_down("up")` 同名）序列化，便于设置文件阅读与编辑器的重绑定面板展示；
  旧文件里的内部码位写法 `key:other:1048577`…`1048580` 仍可解析（向后兼容），
  重新保存后归一化为可读名字。
- `key:other:<码位>` 用于其它非 ASCII 可打印键；可打印 ASCII 字符键直接写字符本身（`key:q`）。

## 4. 设置文件 `[input]` 段

```toml
# 玩家设置
[audio]
master = 0.5
bgm = 0.25

[input]
map = "rustlua-actions-v1\ninteract=key:f\nconfirm=key:space,pad:0"
# 手柄死区（M20-08；仅编辑器「项目设置 → 输入」写入）
stick_deadzone = 0.15
trigger_deadzone = 0.05
# 菜单导航手感（M22/W3 起用毫秒；阈值 0..1、时长 ≤5000ms、间隔 ≥16ms，越界钳制、非有限值回落默认）
nav_threshold = 0.5
nav_delay_ms = 350
nav_repeat_ms = 90
```

导航手感三行的语义（`parse_nav_section` / `NavSettings::new`）：

| 键 | 默认 | 语义 | 钳制 |
|---|---|---|---|
| `nav_threshold` | `0.5` | 摇杆推杆达到多少才算一次菜单导航（同时是设备层轴判定阈值） | `0..=1`，非有限值回落默认 |
| `nav_delay_ms` | `350` | 按住后多久开始连发（毫秒） | `0..=5000` |
| `nav_repeat_ms` | `90` | 连发间隔（毫秒） | `16..=5000` |
| ~~`nav_delay_frames`~~ | — | 旧「帧」键，**兼容读取**：按 60Hz 换算成毫秒；毫秒键优先 | 同旧语义（换算后钳制） |
| ~~`nav_repeat_frames`~~ | — | 同上 | 同上 |

**为什么改成毫秒**（M22/W3）：帧数制手感随刷新率漂移（8 帧 @144Hz 的连发速度是 60Hz 的
2.4 倍）。写入统一用毫秒键，旧文件里的帧键不删也不生效（毫秒键优先），最后一次保存即归一化。

读取路径有两条且**同源**：`input.nav_settings()`（Lua，游戏启动时 `apply_nav_settings()` 应用
并推给引擎）与 `load_nav_section`（Rust 宿主/测试）。游戏内 `input.save_settings()` 只写 `map`，
死区与导航三行原样保留（不会被游戏内保存抹掉）。

- `map` 是一行**转义字符串**（`\n` 为分隔符），由 `ActionMap::to_text` 生成。
- `stick_deadzone` / `trigger_deadzone` 是 M20-08 引入的手柄死区偏好（默认 `0.15` / `0.05`，
  非有限值/越界值回落默认并钳制）。**游戏内的 `input.save_settings()` 只写 `map`**，
  死区两行原样保留；只有编辑器路径（`upsert_input_settings(..., Some(deadzone))`）会写入它们，
  以免玩家改键时被面板默认值回冲。详见 `docs/33` §2。
- **保序读改写**：写入只替换/插入 `[input]` 段的 `map` 键，`[audio]` 段、注释与未知键原样保留。
- **版本与回退**（章程 §12）：
  - 版本头不符或绑定文本非法 → `load_settings` 返回 `false, reason`、**回退默认映射**、写入
    `<path>: <reason>; reverting to defaults` 诊断；
  - 缺 `[input]` 段或文件缺失 → 返回 `false`、**保留当前绑定**（`... keeping current bindings` /
    `missing`），绝不静默清空用户改键；
  - 文件中缺失的动作由 `merge_missing` 用默认补齐（新增动作在旧设置文件上仍可玩），
    用户已重绑的动作**不被覆盖**。
- 设置属于**工程/玩家偏好**，不进存档、不随场景切换或读档回滚（`reset_bindings()` 是唯一重置入口）。

## 5. 面板导航接线（与 M20-02 的焦点 API 协同）

M20-02 已把 `ui_navigation::{FocusRing,ScrollState}` 暴露为 `ui.focus_*` / `ui.scroll_*`。
面板侧只需把动作接到焦点 API（示例见 `input_actions_drive_ui_focus_navigation` 测试）：

```lua
-- M22/W3 推荐写法：边沿 + 时间制连发都由引擎给（键盘/DPad/摇杆同源，与帧率无关）
local step = nil
if input.action_repeat("ui_up") then step = "up"
elseif input.action_repeat("ui_down") then step = "down" end
if step then ui.focus_move(panel_id, step) end
if input.action_pressed("confirm") then ui.focus_select(panel_id, ui.focus_index(panel_id)) end
if input.action_pressed("cancel") then ui.focus_close(panel_id) end
```

键盘（方向键）、DPad 与手柄（左摇杆）走**同一套动作**，因此面板代码不需要区分设备，
也不需要自己数帧做按住重复。

## 6. 测试与限制

自动测试（`cargo test -p engine`）：

- `input_action_map_defaults_are_available_to_lua`：默认动作可枚举、映射文本含版本头与默认绑定；
- `input_action_api_matches_keyboard_and_gamepad_bindings`：键盘与手柄触发同一动作、原始 `pad_*` 查询一致、
  自定义摇杆对给出模拟量；
- `input_action_map_rebind_unbind_and_text_round_trip`：重绑定生效、旧绑定失效、非法/重复绑定返回原因、
  文本往返、版本头不符被拒且不改动映射、宿主注入对脚本立即可见；
- `input_action_settings_round_trip_and_version_fallback`：`[input]` 段写盘/读盘与内存一致、`[audio]` 段与注释保留、
  版本头不符回退默认并产生可定位诊断、非法绑定回退、缺段保留当前绑定、文件缺失返回 `missing`、
  场景切换不回滚绑定；
- `input_actions_drive_ui_focus_navigation`：动作层驱动 `ui.focus_*`（摇杆与方向键同源）；
- M22/W3 追加：`axis_digital_state_and_edges_drive_actions`（轴边沿）、
  `axis_without_device_state_falls_back_to_analog_threshold`（无设备态时回落阈值且无边沿）、
  `radial_deadzone_scales_by_magnitude_and_keeps_direction`（径向死区）、
  `last_device_follows_real_input_edges_only`（设备判定）、
  `action_repeat_is_time_based_for_analog_holds` / `action_repeat_does_not_double_step_without_edge` /
  `action_repeat_does_not_repeat_digital_holds`（时间制连发）与设备层
  `poller_synthesizes_axis_press_edges_with_hysteresis` 等（见 `docs/33` §5）。

限制：

- 不做触屏输入、输入录制/回放、多语言原生按键图标；
- 手柄设备轮询为 Windows XInput（M20-06）；gilrs（跨平台、更多型号映射）因离线依赖不可解析未落地，
  抽象层已保留以便替换。
- **发布包内的设置路径（已知限制，P2）**：设置文件按**工程根**解析。开发工程根是
  `examples/game_jhyt`，路径没问题；但用 `game.exe --pack pack` 启动发布包时，工程根被解析为
  **`<release>/pack`**（`cli::find_project_root` 先找 `pack/project.toml`），因此
  `input.save_settings()`/`audio.save_settings()` 会写 `<release>/pack/settings.toml`：
  ① 若安装目录只读（如 `Program Files`）保存失败（Lua 侧返回 `false, 原因`，不崩溃但改键丢失）；
  ② 重新发布时 `package.ps1` 会整体替换发布目录内容（M20-03），玩家的改键会被新包覆盖。
  当前按「设置属于工程偏好、开发期可用」处理，未做「写到 exe 同级或用户配置目录」的迁移；
  后续任务若要让玩家在发布版里持久改键，需要把设置根从工程根改为**用户可写目录**
  （`%APPDATA%/<game>/settings.toml`）并给出版本迁移。
  `settings.toml` **不会**被 `assetc package` 打包（打包只复制 `project.toml`、`scenes/`、
  `scripts/`、`assets/`，见 `assetc/src/lib.rs::package_project`）；但 `package.ps1` 在打包后会把
  **工程根已有的** `settings.toml` 复制到 `<pack>/settings.toml`（存在才复制，`build-info.txt` 的
  `settings_check` 行记录该行为），这样工程里绑定好的手柄/死区能直接进入发布包，不再是「打包版
  回落键盘默认绑定」。注意：游戏内保存仍写回同一路径，所以**重发布仍会覆盖玩家在发布版里的改键**
  （上述 P2 未解决）；本次仅补齐「工程 → 发布包」这一方向。

## 7. M22/W3 增量：轴边沿、时间制连发、径向死区、设备判定

| 项 | 语义 | 落地位置 |
|---|---|---|
| 轴数字态与滞回 | 设备层每帧写 `(轴, 方向) → 是否过阈值`；进入用 `AXIS_DIGITAL_ON`（默认 0.5，可配）、退出用 `进入 − AXIS_HYSTERESIS(0.1)`，避免阈值附近抖动反复产生边沿 | `host/gamepad.rs::GamepadPoller` |
| 轴按下/松开边沿 | 只在**变化帧**写 `gamepad_axis_event`；`action_pressed/action_released` 因此对摇杆成立。边沿保留到本逻辑帧被消费（与按钮同一套约定） | `core/input.rs`、`host/gamepad.rs` |
| 时间制连发 | `input.action_repeat(name)`：**按下边沿**立即一步；模拟量绑定按住超过 `nav_delay_ms` 后每 `nav_repeat_ms` 一步；数字键/DPad 按住**不连发**（保持 M20-08「一次按下 = 一步」）；「已按住但无边沿」不补步（避免同摇杆同时驱动 `move_*`/`ui_*` 时双步）。逻辑时间按固定步累加（`ScriptState::logical_ms`），与渲染帧率无关 | `core/script.rs` |
| 径向死区 | 摇杆按 `(x, y)` **模长**判死区并保持方向，消除「斜向比正向灵敏」；单轴函数保留 | `core/input.rs::apply_stick_deadzone_radial` |
| 设备判定 | `InputSnapshot::last_device` 只在**真实按下边沿**切换（键盘/鼠标→`keyboard`，手柄按钮/轴→`gamepad`），空闲帧不写；`ui/hints.lua` 因此删掉了每帧 36 动作 × `bindings()` 的全量扫描 | `core/input.rs`、`examples/game_jhyt/scripts/ui/hints.lua` |
| 分层 | 死区值类型/常量/纯函数从 `host::gamepad` 下沉到 `core::input`（`host::gamepad` 保留重导出）；`core_does_not_depend_on_host` 架构回归测试防复发 | `core/input.rs`、`core/mod.rs` |

| API | 返回 | 说明 |
|---|---|---|
| `input.action(name)` | `bool` | 任一绑定按下（手柄轴过阈值） |
| `input.action_pressed(name)` / `input.action_released(name)` | `bool` | 本逻辑帧边沿（保留到本帧被消费） |
| `input.action_axis(negative, positive)` | `number` | 手柄摇杆取模拟量、键位取 0/1，结果钳制到 -1..1 |
| `input.pad_button(index)` / `input.pad_axis(index)` | `bool` / `number` | 原始手柄查询（调试与特殊玩法） |
| `input.actions()` | `{ name... }` | 全部动作（字典序） |
| `input.bindings(action)` | `{ "key:e", "pad:0" }` | 绑定文本（`Binding::to_text` 稳定形式） |
| `input.rebind(action, binding)` | `ok, err` | 覆盖该动作的全部旧绑定（单一主绑定语义）；非法绑定返回 `false, reason` |
| `input.unbind(action, binding)` | `bool` | 解绑一个绑定 |
| `input.reset_bindings()` | — | 恢复默认（唯一重置入口） |
| `input.action_map_text()` | `string` | 序列化（含版本头 `rustlua-actions-v1`） |
| `input.set_action_map(text)` | `ok, err` | 版本头不符 → `false, reason` 且**不改动**当前映射 |
| `input.settings_path()` | `string\|nil` | 默认 `<project_root>/settings.toml` |
| `input.load_settings(path?)` / `input.save_settings(path?)` | `ok, err` | 读写 `[input]` 段；无工程根且未给路径 → `false, "no_project_root"` |
| `input.nav_settings(path?)` | `{threshold, delay_frames, repeat_frames}` | 读 `[input]` 段的菜单导航手感（M20-09）；无工程根返回 `nil`，缺键/脏值回落并钳制 |
| `input.diagnostics()` | `{ message... }` | 设置读取/回退的可定位诊断 |

绑定文本（`Binding::to_text`）：`key:e`、`key:space`、`key:escape`、`key:up`/`key:down`/`key:left`/`key:right`、
`key:other:113`、`mouse:left`、`pad:0`、`padaxis:1+`、`padaxis:1-`。

- 方向键（`InputKey::ARROW_*`）用**可读名字** `key:up`/`key:down`/`key:left`/`key:right`
  （与 Lua 侧 `input.is_down("up")` 同名）序列化，便于设置文件阅读与编辑器的重绑定面板展示；
  旧文件里的内部码位写法 `key:other:1048577`…`1048580` 仍可解析（向后兼容），
  重新保存后归一化为可读名字。
- `key:other:<码位>` 用于其它非 ASCII 可打印键；可打印 ASCII 字符键直接写字符本身（`key:q`）。

## 4. 设置文件 `[input]` 段

```toml
# 玩家设置
[audio]
master = 0.5
bgm = 0.25

[input]
map = "rustlua-actions-v1\ninteract=key:f\nconfirm=key:space,pad:0"
# 手柄死区（M20-08；仅编辑器「项目设置 → 输入」写入）
stick_deadzone = 0.15
trigger_deadzone = 0.05
# 菜单导航手感（M20-09；手改或由游戏启动读取，默认 0.5 / 16 帧 / 8 帧）
# 阈值 0..1、间隔 ≥1、帧数 ≤120，越界钳制、非有限值回落默认。
nav_threshold = 0.5
nav_delay_frames = 16
nav_repeat_frames = 8
```

导航手感三行的语义（`parse_nav_section` / `NavSettings::new`）：

| 键 | 默认 | 语义 | 钳制 |
|---|---|---|---|
| `nav_threshold` | `0.5` | 摇杆推杆达到多少才算一次菜单导航 | `0..=1`，非有限值回落默认 |
| `nav_delay_frames` | `16` | 按住后多久开始连发 | `0..=120` |
| `nav_repeat_frames` | `8` | 连发间隔帧数 | `1..=120`（0 会退化成每帧连发，故下限 1） |

读取路径有两条且**同源**：`input.nav_settings()`（Lua，游戏启动时 `apply_nav_settings()` 应用）
与 `load_nav_section`（Rust 宿主/测试）。游戏内 `input.save_settings()` 只写 `map`，
死区与导航三行原样保留（不会被游戏内保存抹掉）。

- `map` 是一行**转义字符串**（`\n` 为分隔符），由 `ActionMap::to_text` 生成。
- `stick_deadzone` / `trigger_deadzone` 是 M20-08 引入的手柄死区偏好（默认 `0.15` / `0.05`，
  非有限值/越界值回落默认并钳制）。**游戏内的 `input.save_settings()` 只写 `map`**，
  死区两行原样保留；只有编辑器路径（`upsert_input_settings(..., Some(deadzone))`）会写入它们，
  以免玩家改键时被面板默认值回冲。详见 `docs/33` §2。
- **保序读改写**：写入只替换/插入 `[input]` 段的 `map` 键，`[audio]` 段、注释与未知键原样保留。
- **版本与回退**（章程 §12）：
  - 版本头不符或绑定文本非法 → `load_settings` 返回 `false, reason`、**回退默认映射**、写入
    `<path>: <reason>; reverting to defaults` 诊断；
  - 缺 `[input]` 段或文件缺失 → 返回 `false`、**保留当前绑定**（`... keeping current bindings` /
    `missing`），绝不静默清空用户改键；
  - 文件中缺失的动作由 `merge_missing` 用默认补齐（新增动作在旧设置文件上仍可玩），
    用户已重绑的动作**不被覆盖**。
- 设置属于**工程/玩家偏好**，不进存档、不随场景切换或读档回滚（`reset_bindings()` 是唯一重置入口）。

## 5. 面板导航接线（与 M20-02 的焦点 API 协同）

M20-02 已把 `ui_navigation::{FocusRing,ScrollState}` 暴露为 `ui.focus_*` / `ui.scroll_*`。
面板侧只需把动作接到焦点 API（示例见 `input_actions_drive_ui_focus_navigation` 测试）：

```lua
local axis = input.action_axis("ui_down", "ui_up")   -- 上为正
if math.abs(axis) >= 0.5 then
  ui.focus_move(panel_id, axis > 0 and "up" or "down")
end
if input.action_pressed("confirm") then ui.focus_select(panel_id, ui.focus_index(panel_id)) end
if input.action_pressed("cancel") then ui.focus_close(panel_id) end
```

键盘（方向键）与手柄（左摇杆/A/B）走**同一套动作**，因此面板代码不需要区分设备。

## 6. 测试与限制

自动测试（`cargo test -p engine`）：

- `input_action_map_defaults_are_available_to_lua`：默认动作可枚举、映射文本含版本头与默认绑定；
- `input_action_api_matches_keyboard_and_gamepad_bindings`：键盘与手柄触发同一动作、原始 `pad_*` 查询一致、
  自定义摇杆对给出模拟量；
- `input_action_map_rebind_unbind_and_text_round_trip`：重绑定生效、旧绑定失效、非法/重复绑定返回原因、
  文本往返、版本头不符被拒且不改动映射、宿主注入对脚本立即可见；
- `input_action_settings_round_trip_and_version_fallback`：`[input]` 段写盘/读盘与内存一致、`[audio]` 段与注释保留、
  版本头不符回退默认并产生可定位诊断、非法绑定回退、缺段保留当前绑定、文件缺失返回 `missing`、
  场景切换不回滚绑定；
- `input_actions_drive_ui_focus_navigation`：动作层驱动 `ui.focus_*`（摇杆与方向键同源）。

限制：

- 不提供编辑器可视化重绑定面板（M20-08）；
- 不做触屏输入、输入录制/回放、多语言原生按键图标；
- 手柄设备轮询为 Windows XInput（M20-06）；gilrs（跨平台、更多型号映射）因离线依赖不可解析未落地，
  抽象层已保留以便替换。
- **发布包内的设置路径（已知限制，P2）**：设置文件按**工程根**解析。开发工程根是
  `examples/game_jhyt`，路径没问题；但用 `game.exe --pack pack` 启动发布包时，工程根被解析为
  **`<release>/pack`**（`cli::find_project_root` 先找 `pack/project.toml`），因此
  `input.save_settings()`/`audio.save_settings()` 会写 `<release>/pack/settings.toml`：
  ① 若安装目录只读（如 `Program Files`）保存失败（Lua 侧返回 `false, 原因`，不崩溃但改键丢失）；
  ② 重新发布时 `package.ps1` 会整体替换发布目录内容（M20-03），玩家的改键会被新包覆盖。
  当前按「设置属于工程偏好、开发期可用」处理，未做「写到 exe 同级或用户配置目录」的迁移；
  后续任务若要让玩家在发布版里持久改键，需要把设置根从工程根改为**用户可写目录**
  （`%APPDATA%/<game>/settings.toml`）并给出版本迁移。
  `settings.toml` **不会**被 `assetc package` 打包（打包只复制 `project.toml`、`scenes/`、
  `scripts/`、`assets/`，见 `assetc/src/lib.rs::package_project`）；但 `package.ps1` 在打包后会把
  **工程根已有的** `settings.toml` 复制到 `<pack>/settings.toml`（存在才复制，`build-info.txt` 的
  `settings_check` 行记录该行为），这样工程里绑定好的手柄/死区能直接进入发布包，不再是「打包版
  回落键盘默认绑定」。注意：游戏内保存仍写回同一路径，所以**重发布仍会覆盖玩家在发布版里的改键**
  （上述 P2 未解决）；本次仅补齐「工程 → 发布包」这一方向。
