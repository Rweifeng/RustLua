# P2 RustLua 游戏引擎工程目录功能说明

- 项目根目录：`E:\Codex\p2`
- 当前版本：`v0.4-scripting`
- 适用平台：Windows 优先
- 引擎核心：Rust stable
- 游戏脚本：Lua 5.4
- 图形与窗口：`wgpu` + `winit`

本文说明工程每个主要目录和文件的职责，方便独立开发、AI 会话恢复、代码定位和后续维护。

## 1. 工程总览

```text
E:\Codex\p2
├── .github       持续集成配置
├── assets        原始游戏资源
├── docs          设计、规范、使用手册和验收文档
├── editor        编辑器 MVP 预留目录
├── engine        Rust Cargo workspace 和引擎源码
├── game          具体游戏项目和 Lua 脚本
├── scripts       Windows 自动化构建、测试和运行脚本
├── tasks         AI 任务管理和完成记录
├── tools         工具链预留目录
└── artifacts     构建、日志、性能和截图产物
```

## 6. Rust 引擎目录

### `engine`

Rust Cargo workspace 根目录，也是引擎主要源码目录。

```text
engine/
├── .cargo
├── crates
├── examples
├── tests
├── Cargo.toml
├── Cargo.lock
├── README.md
└── rust-toolchain.toml
```

### `engine/Cargo.toml`

Workspace 配置，负责成员 Crate、统一 Rust 版本、依赖版本和构建配置。

### `engine/Cargo.lock`

依赖锁定文件，确保本地、CI 和不同开发会话使用一致的依赖版本。

### `engine/README.md`

Rust workspace、质量门、构建、测试和 CI 的基础说明。

### `engine/rust-toolchain.toml`

固定 Rust stable 工具链，并声明 `rustfmt` 和 `clippy` 组件。

### `engine/.cargo/config.toml`

Cargo 局部配置，统一构建参数和 workspace 构建行为。

### `engine/crates`

Cargo workspace 的成员 Crate 目录，当前包含 `engine_core` 和 `game_runner`。

### `engine/examples`

workspace 级示例预留目录。

### `engine/tests`

workspace 级集成测试预留目录。

## 7. `engine/crates/engine_core`

引擎核心库，不直接依赖桌面窗口生命周期。负责 ECS、实体、组件、系统、输入、时间、2D 数据、资源、场景、Lua 和诊断等可复用能力。

### `engine/crates/engine_core/Cargo.toml`

核心库包配置和依赖，包括 `mlua`、`image`、`tracing` 等。

### `engine/crates/engine_core/src/lib.rs`

核心库模块入口，注册并公开各个引擎模块。

### `engine/crates/engine_core/src/entity.rs`

Entity ID 和 generation 句柄。防止实体销毁后旧句柄访问新实体。

### `engine/crates/engine_core/src/world.rs`

World 和最小组件存储，负责实体创建、销毁、组件读写、移除和组合查询。

### `engine/crates/engine_core/src/commands.rs`

延迟 Command 队列，负责安全执行 Spawn、Despawn、添加组件、移除组件等 World 修改。

### `engine/crates/engine_core/src/events.rs`

帧边界事件队列，负责事件发布、交换、消费和防止重复消费。

### `engine/crates/engine_core/src/scheduler.rs`

系统调度器，负责阶段、依赖、执行顺序、循环依赖检测、耗时和系统错误处理。

### `engine/crates/engine_core/src/transform.rs`

Transform、Velocity 组件和最小积分系统，负责位置、旋转、缩放、线速度和角速度。

### `engine/crates/engine_core/src/time_step.rs`

固定时间步，负责 60 Hz 逻辑更新、Delta Time、追赶步数限制、丢步和暂停恢复。

### `engine/crates/engine_core/src/input.rs`

输入快照，负责键盘、鼠标、光标、输入边沿、输入轴和帧边界状态。

### `engine/crates/engine_core/src/window.rs`

平台无关的窗口生命周期状态，包括初始化、运行、暂停、恢复、退出和可渲染状态。

### `engine/crates/engine_core/src/logging.rs`

日志模块和错误上下文，负责操作描述、错误原因、修复建议和 tracing 初始化。

### `engine/crates/engine_core/src/performance.rs`

性能采样，记录 FPS、帧耗时、固定更新耗时、Lua 耗时和性能快照。

### `engine/crates/engine_core/src/math2d.rs`

2D 向量、变换、摄像机、坐标转换、颜色和 sRGB 转换。

### `engine/crates/engine_core/src/texture.rs`

PNG 解码、RGBA8 数据、尺寸检查、颜色空间记录和纹理资源数据验证。

### `engine/crates/engine_core/src/sprite.rs`

单个 Sprite 的四边形顶点、位置、旋转、缩放、Pivot、UV 和 Tint。

### `engine/crates/engine_core/src/sprite_batch.rs`

Sprite 排序、按纹理和层级分组、批次生成及 GPU 顶点数据准备。

### `engine/crates/engine_core/src/atlas.rs`

图集区域、命名区域、子纹理引用和 UV 计算。

### `engine/crates/engine_core/src/text.rs`

文本布局、多行文本、字符图集、字符 UV 和文本顶点数据。

### `engine/crates/engine_core/src/resource_db.rs`

资源 ID、资源路径、资源类型、资源状态、依赖关系、资源移动、删除检查和数据库保存。

### `engine/crates/engine_core/src/import_cache.rs`

源文件指纹、内容哈希、导入器版本、缓存复用、失效和失败保护。

### `engine/crates/engine_core/src/scene.rs`

版本化场景文本格式，负责实体树、组件、资源引用、元数据、保存、加载和校验。

### `engine/crates/engine_core/src/prefab.rs`

预制体提取、保存、加载、实例化、实例映射、覆盖值和重建策略。

### `engine/crates/engine_core/src/script.rs`

Lua VM 和脚本桥接，负责脚本加载、生命周期、Lua API、热重载、运行时错误和脚本诊断。

### `engine/crates/engine_core/examples/ecs_stress.rs`

ECS 压力测试，验证批量实体、组件、系统、销毁和长时间运行基线。

## 8. `engine/crates/game_runner`

桌面运行器 Crate，把 `engine_core` 连接到真实 Windows 窗口和 GPU 环境。

### `engine/crates/game_runner/Cargo.toml`

运行器配置和依赖，包括 `wgpu`、`winit`、`pollster`、`bytemuck` 和 `engine_core`。

### `engine/crates/game_runner/src/main.rs`

桌面运行器入口，负责：

- 创建窗口和 winit 事件循环；
- 初始化 wgpu Instance、Adapter、Device、Queue 和 Surface；
- 配置清屏和性能 Overlay；
- 处理窗口输入、暂停和退出；
- 加载项目 Lua；
- 运行固定时间步；
- 输出日志和性能数据。

## 10. 自动化脚本目录

### `scripts`

Windows PowerShell 自动化脚本目录。

### `scripts/verify.ps1`

完整质量门：Cargo metadata、格式、Clippy、workspace 测试和 Debug/Release 构建，并生成日志。

```powershell
.\scripts\verify.ps1 -KeepLog
.\scripts\verify.ps1 -Release -KeepLog
```

### `scripts/test.ps1`

测试快捷脚本，支持 `-NoClippy` 跳过 Clippy。

```powershell
.\scripts\test.ps1
.\scripts\test.ps1 -NoClippy
```

### `scripts/build-release.ps1`

构建 Release 运行器，并复制到：

```text
artifacts/builds/release/game_runner.exe
```

### `scripts/run-demo.ps1`

运行基础桌面 Demo，支持普通和 Release 模式。

```powershell
.\scripts\run-demo.ps1
.\scripts\run-demo.ps1 -Release
```

- `--check` 无窗口验收入口；

## 独立工程结构

游戏工程至少包含 `project.toml` 和 `scripts/`；`scenes/`、`assets/` 为可选目录。引擎与游戏工程可分别复制、构建和发布，运行关联通过 `--project` 显式完成。
