# RustLua 游戏引擎工程目录功能说明

- 项目根目录：`E:\Codex\RustLua`
- 当前阶段：M6 2D 游戏能力与样板游戏（M0–M6 已完成）；最近标签 `v0.5-editor-mvp`
- 适用平台：Windows 优先
- 引擎核心：Rust stable
- 游戏脚本：Lua 5.4
- 图形与窗口：`wgpu` + `winit`

本文说明工程每个主要目录和文件的职责，方便独立开发、AI 会话恢复、代码定位和后续维护。

## 1. 工程总览

```text
E:\Codex\RustLua
├── .github          持续集成（GitHub Actions）配置
├── docs             设计、规范、使用手册、验收文档、第三方许可与验收证据
├── engine           Rust Cargo workspace（引擎、桌面/Web 运行器、编辑器与可复用能力库）

├── git-hooks        版本库内的 git 钩子（pre-commit：提交前跑 CI 的 fmt/clippy 门）
├── scripts          Windows 自动化构建、测试、运行和资源生成脚本
└── tasks            AI 任务管理与完成记录
```

根目录不含可再生的构建/日志/资源产物（`artifacts/` 已移除；`assets/` 已归入 `game/assets/`）。

根目录另有 `.gitattributes`：只钉住 `git-hooks/* text eol=lf`（sh 钩子遇到 CRLF 的 `#!` 行会报
`bad interpreter: /bin/sh^M`），刻意不加 `* text=auto`——那会把 `scripts/*.ps1` 既有的 UTF-8 BOM + CRLF
口径一次性改成满屏脏 diff。

## 4. Rust 引擎目录

### `engine`

Cargo workspace 根目录，成员分为三层：可复用能力库（`rustlua-*`）、宿主/运行器（`engine`、`game`、`game_web`）与工具（`assetc`、编辑器）。完整成员列表以 `engine/Cargo.toml` 的 `members` 为准。主要目录：

```text
engine/
├── .cargo/config.toml   # 统一构建参数（target-dir = "target"）
├── crates/
│   ├── assetc/          # 资源构建 CLI（扫描/导入/清理/打包，M7-01）
│   ├── engine/          # 引擎 crate（core/ 纯逻辑 + host/ GPU 渲染）
│   ├── game/            # 桌面运行器（wgpu + winit）
│   ├── editor/          # egui/eframe 编辑器（GUI 外壳 + 门面）
│   ├── rustlua-editor-core/       # 编辑器无头领域层（无 egui/wgpu）
│   ├── rustlua-editor-ui-studio/  # UI Studio 与 .ui.json 文档宿主
│   └── game_web/        # WebGL 运行器（wasm32 + wasm-bindgen）
├── Cargo.toml           # workspace 成员、统一依赖版本
├── Cargo.lock           # 依赖锁定
├── README.md            # workspace 质量门/构建/测试说明
└── rust-toolchain.toml  # 固定 Rust stable + rustfmt/clippy
```

`engine/target/` 为 Cargo 构建缓存（`engine/target/release/game.exe`、`editor.exe` 等），不入库。

## 5. `engine/crates/engine`

`engine` 是宿主与引擎装配 crate。纯逻辑能力由独立的 `rustlua-*` crate 提供，调用方直接依赖其实际使用的 crate；`engine::host` 提供 GPU 渲染与运行时场景入口。

```text
src/
├── lib.rs            # crate 入口：host、lua_api；version 与 PROJECT_WORK_DIR 便捷导出
├── host/             # GPU 渲染与运行时宿主（wgpu + winit）
│   ├── renderer/     # 2D/3D 渲染器、render passes、纹理/网格缓存与 readback
│   └── runtime_scene/ # 场景实例化、脚本驱动、每帧渲染数据与运行期系统
└── lua_api.rs        # Lua API 文档入口（API 文档由脚本生成）
```

核心 crate 按职责拆分：`rustlua-ecs`（实体/组件/World/调度）、`rustlua-scene`（场景/prefab/导入）、`rustlua-render`（渲染数据/字体/纹理）、`rustlua-scripting`（Lua VM 与绑定）、`rustlua-infra`（路径/日志/配置等）；数学、相机、动画、UI、物理、资源、音频、输入和玩法能力也各有独立 crate。`engine` 的宿主内部按需依赖这些 crate，编辑器、运行器与工具直接声明各自使用的子 crate 依赖。

`examples/ecs_stress.rs`：ECS 压力测试；`examples/sprite_stress.rs`：精灵批处理 CPU 基准（M7-04）。

## 6. `engine/crates/game`

桌面运行器，把 `engine` 的 core 逻辑连接到真实 Windows 窗口与 GPU（经 `engine::host`）。

- `src/main.rs`：窗口、wgpu 渲染、固定时间步、Lua 驱动、场景实例化与渲染、粒子/UI/文本渲染、存档路径、`--project`/`--pack`/`--check`/`--log-filter` 参数；`windows_subsystem = "windows"`（双击不弹终端）、无 `--project` 时自动探测游戏项目、日志按 exe 目录解析；启动期资源完整性校验（`--pack` 缺失即拒绝启动），panic 写 `crash.log`。
- `examples/`：15 个可重复 Demo（`texture_upload`、`sprite_demo`、`sprite_batch_demo`、`camera_demo`、`atlas_demo`、`text_demo`、`demo_2d`、`resource_db_demo`、`import_cache_demo`、`scene_format_demo`、`prefab_demo`、`lua_api_demo`、`lua_hot_reload_demo`、`lua_script_debug_demo`、`scene_script_demo`）。

## 7. `engine/crates/editor`

egui/eframe 编辑器（M5 完成，M10 面板拆分，M77 起按耦合分层）。编辑器拆成三个 crate，
依赖方向固定为 `editor` → `rustlua-editor-ui-studio`、`editor` → `rustlua-editor-core`：

| crate | 定位 | 不含 |
|---|---|---|
| `editor` | GUI 外壳：`EditorApp` 状态、`panels/`、`actions/`、引擎桥（`runtime_sync`/`profiler`/`schema_fields`）、发布与 Play 生命周期 | — |
| `rustlua-editor-ui-studio` | UI Studio 与 `.ui.json` 文档宿主：读写/revision/校验/预览/提案、UiSpec→`.scene` 导出、发布前审查报告 | egui、`EditorApp` |
| `rustlua-editor-core` | 无头领域层：文档/历史/补丁/恢复、选择与场景树/Inspector/资源浏览状态、布局、Play 控制、文件监听与资源刷新、schema 审计、图模型操作 | egui、wgpu、`engine` 宿主 |

`editor` 的 `lib.rs` 现在是**门面**：`pub use rustlua_editor_core::*;` 与
`pub use rustlua_editor_ui_studio::*;` 让 `editor::document::…`、`editor::layout_path`、
`editor::SceneDocument` 这类既有路径保持不变，自身只留 `profiler`/`runtime_sync`/`schema_fields`
三个依赖 `engine::host` 的模块。`graph_ops`/`scene_interaction`/`scene_tools` 下沉到 core 后，
bin 根用 `use editor::{graph_ops, scene_interaction, scene_tools};` 再导出一次，`crate::scene_interaction::…`
一类路径也不改写。

`editor/src/`：

- `main.rs`：入口 + `EditorApp` 状态定义 + `update()` 组合调用各面板（不再含面板 UI 逻辑）
- `lib.rs`：门面（两条 glob re-export）+ `profiler`/`runtime_sync`/`schema_fields`
- `panels/`：每个面板一个文件（`impl EditorApp` 块）
  - `header.rs`：标题栏 + 菜单栏（项目/帮助）+ 恢复提示 + 版本说明
  - `hierarchy.rs`：层级面板（场景切换/新建 + 实体树）
  - `resource_browser.rs`：资源面板（扫描/筛选/缩略图/拖放）
  - `console.rs`：控制台（实时日志 + Lua 输出 + 诊断）
  - `inspector.rs`：属性面板（组件管理/Transform/Camera/Light/Collider）
  - `scene_view/`：Scene 视图（2D/3D 渲染/Gizmo/框选/拖放生成；按主绘制、指针、拾取、瓦片、渲染、投影拆成 10 个模块）
  - `game_view.rs`：Game 视图（未 Play 编辑预览 + Play/Stop 运行生命周期）
  - `toolbar.rs`：中央工具栏（Play/Stop、工具、吸附、对齐、Undo/Redo）
- `actions/`：跨面板共享编辑命令（撤销/重做/保存/实体/对齐/同步；按事务、文档读写、布局、实体、组件、预设拆成 9 个模块）
- `progress.rs`：**通用进度面板 ProgressPanel**（导入/发布均后台线程执行 + 非阻塞进度窗口，发布不弹终端窗）
- `publish.rs`：发布/导入后台任务
- `geometry.rs`：几何/变换工具
- `util.rs`：通用工具（路径清理/CJK 字体/目录选择）

`rustlua-editor-core/src/`（无 egui / 无 wgpu / 无 `engine` 宿主）：

- `project.rs`：工程打开与检查（`--check`）、必需目录、基线版本、schema 审计汇总
- `document.rs`：场景文档与 PlaySession 隔离
- `document_space.rs`：编辑态空间语义（世界变换、目标世界→新局部、换父 keep-world）
- `history.rs` / `patch_history.rs`：Undo/Redo 命令系统与字段级补丁原型
- `recovery.rs`：自动保存/闪退恢复（写入 `game/.temp/`）
- `selection.rs` / `scene_tree_state.rs` / `inspector_state.rs` / `resource_browser_state.rs`：选择模型与三面板的状态模型
- `layout.rs`：Dock 布局持久化；`user_config.rs`：用户级设置与 DPAPI 加密的 API Key
- `play_control.rs`：固定步进 Play 控制器；`scene_tools.rs` / `scene_interaction.rs` / `graph_ops.rs`：场景工具、交互与可视化脚本图操作
- `file_watcher.rs` / `resource_refresh.rs` / `resource_ops.rs`：文件指纹监听、后台刷新、引用改写
- `schema_audit.rs` / `prefab_graph.rs` / `anim_ops.rs` / `material_ops.rs` / `services.rs`：schema 漂移审计、prefab 嵌套扫描、动画/材质编辑操作、命令与诊断服务
- `perf_fixture.rs` / `diagnostics.rs`：性能夹具与诊断解析

`rustlua-editor-ui-studio/src/`：

- `ui_spec_host.rs`：`.ui.json` 宿主（读写、revision、校验、预览、提案）
- `ui_studio.rs`：UI Studio 无头状态层（层级/检查器/预览/提案箱），egui 面板只做绘制
- `ui_scene_export.rs`：UiSpec → `.scene` 的确定性导出（宿主证据的生产真源）
- `review.rs`：发布前审查报告（诊断/资产/许可/体积/宿主证据/未收口项）
