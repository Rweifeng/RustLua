> 状态：**批 A–E 全部落地**（2026-10-02）。运行时侧的事实源已并入 `docs/11`，依赖边见 `docs/14`，
> 导入校验见 `docs/15`，Lua 侧写法见 `docs/18`。下面的批次标题后附了实际实现与原计划的偏差。

## 背景

`docs/62` 把 Sprite Atlas 打包列为 P0（2D 项目刚需，预估 1-2 周）。当前现状：

- **运行时消费端已就绪**：`rustlua-render/src/atlas.rs` 提供 `AtlasRegion`/`SpriteAtlas`
  （命名区域、像素→UV 转换、`apply` 到 `Sprite`），`atlas_demo` 通过单批次单纹理绑定验收
  （见 `docs/11-texture-atlas.md`）；
- **管线其余环节全部是占位**：`.atlas` 源格式未定义、`AtlasImporter::validate` 仅校验非空
  （阶段 1 无解析器）、无运行时加载路径、Lua API 零暴露、无打包器。

## 格式约定

`.atlas` 源文件采用**行式文本**（与 scene/prefab 的手写格式同一族约定：`#` 注释、空行跳过、
`key=value` 头部、tab 分隔记录；工作区无 `ron` 依赖，离线不可新增 crates）：

```text
atlas_version=1
texture=sprites/hero_sheet.png
region	idle_0	0	0	64	64
```

- 坐标单位是**像素**（对美术工具友好，归一化 UV 由 `AtlasRegion::from_pixels` 换算）；
- 原点为纹理左上角，区域为半开区间 `[x, x+width) × [y, y+height)`，与 `docs/11` 一致；
- `texture` 是纹理源文件相对工程的路径，导入时记依赖边（批 E）；
- **导入 `validate` 拦截**：空文件/BOM/非 UTF-8、语法损坏（定位到行）、缺 `atlas_version`、
  缺 `texture`、无 region、零尺寸、空名；非法输入不落缓存；
- **越界在构造时拒绝**：`SpriteAtlas::from_definition` 拿到纹理实际尺寸后由
  `AtlasRegion::from_pixels` 报 `AtlasError::InvalidDimensions`；
- 同名 region 后写覆盖先写（对齐 `SpriteAtlas::insert` 语义）。

## 批次切分

每批独立可提交；每批全量门（verify.ps1）绿后带走。

### 批 A — 格式定义 + 真实解析器 ✅（2026-10-02 完成）

- `rustlua-assets/src/atlas_format.rs`：`AtlasDefinition`/`AtlasRect` + `from_text`/`to_text`/`load`
  （放 assets 层是因为 render→assets 的既有依赖方向，反过来会成环）；
- `rustlua-render/atlas.rs`：`SpriteAtlas::from_definition(def, width, height)` +
  `AtlasBuildError`，越界在这里拒；
- `rustlua-assets/importer.rs`：`AtlasImporter::validate` 换真实解析，占位注释删除；
- 导入版本 `atlas-1` → `atlas-2`（语义变化，避免与占位期缓存串味）；
- 单测：格式往返/覆盖语义/坏语法定位到行（atlas_format.rs）、导入器门
  （importer.rs `atlas_importer_validates_text_format`）、越界构造拒绝
  （atlas.rs `builds_atlas_from_definition_and_rejects_out_of_bounds`）；
- schema 对拍门不涉及（未新增 ECS 组件）。
- **验收**：`cargo test --workspace --all-features` + `import_cache_demo` 展示 `.atlas`
  首次导入/复用/重建。

### 批 B — 运行时加载路径 + 最小消费闭环 ✅（2026-10-02 完成）

- `rustlua-render/atlas.rs`：`load_atlas(root, atlas_path)`（`AtlasDefinition::load` + 只读图片头取纹理尺寸
  → `SpriteAtlas::from_definition`）、`resolve_atlas_reference(root, raw)`
  解析 `图集路径#区域名`，非图集引用返回 `None` 原样透传；`root` 是工程根，落盘规则与渲染器读纹理
  一致（有根则 `root.join(path)`，无根则用原始路径），返回的纹理路径保持 `.atlas` 里写的工程根相对写法；
- Sprite 消费落在**装配期**：Scene/Prefab 的 Sprite `texture=`（`script/scene_spawn.rs`）与 Lua
  `sprite.set` 各自解析一次，把 `texture_path` 写进 `SpriteAsset`、把区域 UV `apply` 到 `Sprite`；
  运行期抠图/合批代码（`runtime_scene.rs`）零改动——这是选择"装配期解析"而不是"运行期查表"的原因；
- `atlas_demo` 改为写真实 `sheet.png` + `hero.atlas` 到临时目录再 `load_atlas` 读回（文件级回归）；
- **验收**：demo 输出契约不变（`regions=4 sprites=4 vertices=24 draw_calls=1 texture=4x4`，
  Intel Iris Xe 实测通过）；`crates/engine/tests/atlas_sprite_reference.rs` 四条门：区域引用解析成
  合批 UV、普通贴图仍透传、断链（区域/图集不存在）响亮报错而非静默回落、未设工程根时相对图集引用报错。
- **批 E 修的偏差**：批 B 的门只用了绝对路径（等价于"无根"分支），真实项目的工程根相对写法从未跑过，
  照当时的实现会解析不到文件。批 E 把 `root` 补进两个签名、把上述门改成工程根相对形状并加了那条
  "无根必须报错"的门。
- **批 E 修的第二个偏差**：尺寸读取原来是 `image::image_dimensions(path)`，直接吃磁盘原始字节；发布包里
  assetc 会把 `assets/` 下的 png 压成 `RustLua` 容器（`is_compressible_asset` 清单），那样连图片头都读不出来。
  现在纹理字节先过 `pack::decode` 再用 `ImageReader` 只猜格式取尺寸。`.atlas` 不在这份清单里、打包后仍是
  明文，所以 `AtlasDefinition::load` 保持明文读取（不做用不上的解码分支），门
  `load_atlas_reads_packed_texture_with_plain_definition` 钉住"压缩纹理 + 明文描述"这个真实组合。

### 批 C — Lua 消费与文档门 ✅（2026-10-02 完成）

- **不新增 Lua 函数名**：图集引用是 Sprite 组件串 `texture=` 字段的一种写法，走已有的
  `sprite.set` / 场景装配路径。原计划的 `set_sprite_atlas_region(entity, atlas, region)` 被这个设计
  取代——理由：新名字要同步 `api_surface_snapshot` 基线、`docs/59` 覆盖率门与 `docs/61` API 文档桩，
  而它买不到任何新能力（`sprite.set` 已能表达同一条组件串），反而多一个会被拆掉后又长回来的表面；
- `docs/18-lua-api.md` 的 `sprite.set` 行补上 `图集路径#区域名` 语义；
- **验收**：`rustlua-scripting` 门 `lua_sprite_set_resolves_atlas_region_reference`（Lua 侧写区域引用，
  读回 `sprite.get(id).texture` 是合批纹理、Sprite UV 为区域 UV、未知区域报错）。API 快照门未受影响。

### 批 D — 打包器 ✅（2026-10-02 完成）

- `rustlua-assets/src/atlas_pack.rs`：shelf 装箱（高度降序 → 宽度降序 → 名字字典序，完全确定性）、

### 批 E — 依赖边 + 编辑器 + 文档收口 ✅（2026-10-02 完成）

- `rustlua-assets/src/dependency.rs`：`ResourceKind::Atlas` 成为容器——`.atlas` 的 `texture=` 行建
  `atlas → texture` 边；场景/预制体/Lua 里的 `图集路径#区域名` 在建边前剥掉 `#区域名`，得到
  `scene → atlas` 边（区域只在使用点解析）。`recompute_edges` 的容器集合纳入 Atlas；
  源图变更沿两级边把图集与场景标 `Stale`，重新进入待导入队列触发重导入；图集文件删除则场景按
  图集路径断链标 `Invalid`；
- 编辑器：`.atlas` 的登记、校验文案、待导入队列全部走既有的通用扫描路径（`ResourceKind::Atlas`
  早已有扩展名/label/token 映射，`dnd` 落点 `assets/atlases`），批 A 的真实 `validate` 生效后
  错误行号直接显示在资源浏览器条目上；新增门
  `atlas_rows_display_and_chain_texture_to_scene` 把这条链钉住；
- 文档：`docs/11`（从运行时 API 参考扩成"格式 + 加载 + 打包 + 依赖 + 验收"全链）、`docs/14`（依赖边章节）、
  `docs/15`（Atlas 导入器行不再是"占位非空"，顺手修了同表里过期的 LuaScript 行）、`docs/18`、`docs/62`
