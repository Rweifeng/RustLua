# 游戏级回归与性能基线（M19-04）

本文定义 `game_jhyt` 的**退出级回归套件**：核心剧本 headless 回归、帧率确定性、长跑稳定性、
读档循环、发布目录隔离启动与性能/稳定性基线。它是 M20-05 质量门（Alpha/Beta/RC）的**证据来源**，
阶段门槛与命令矩阵见 `docs/34-质量门与发布清单.md`。

## 1. 判定原则

- 所有用例**固定随机种子与输入序列**，逐章断言，失败即以非零退出码终止（不"记录后继续"）。
- 结果是**规则状态**（库存/任务/农田/建筑/时间/存档摘要）的比对，不是像素或帧时间的比对，
  因此不依赖显卡、音频设备或浏览器。
- 环境缺失导致无法执行的项（WASM 构建、真实手柄）**必须标注为「环境受限未执行」并给出复现命令**，
  不得记为通过（`docs/34` §1）。

```powershell

cargo test --workspace

```

## 4. 性能与稳定性基线

`jhyt_m19_soak` 每次运行都覆写 `baselines/m19-soak.json`（供文档与回归对比引用），字段：

| 字段 | 含义 |
|---|---|
| `per_step_ms` | 单个固定步的平均耗时（含 Lua 玩法脚本），本机横向对比用 |
| `steps` / `total_ms` | 长跑推进的固定步数与总耗时 |
| `soak_days` | 长跑跨越的游戏天数 |
| `harvested_total` | 长跑累计收获次数（规则可见的状态量，用于验证长跑"真的在跑"） |
| `real_load_cycles` | 真实 runtime 读档次数（每次新建 runtime，走 BtnContinue 路径） |
| `disk_save_load_cycles` | 同一 runtime 上的磁盘存档/读档往返次数（默认 100） |
| `snapshot_restores` | 纯快照恢复次数（`validate_long_run(30, 100)` → 3000） |
| `line` | 单行汇总，便于回归脚本 grep |

该文件与 `artifacts/logs/**` 一样属于**生成的本地证据**（`.gitignore` 忽略 `artifacts/`），
不进版本库；复现方式就是重跑 `cargo run -p game --example jhyt_m19_soak`（会顺带覆写基线）。

最近一次运行（收尾轮统一复跑，机器与负载会带来波动，仅作同机对比基线）：

```json
{
  "per_step_ms": 0.4098,
  "soak_days": 31,
  "harvested_total": 465,
  "real_load_cycles": 20,
  "disk_save_load_cycles": 100,
  "snapshot_restores": 3000,
  "line": "jhyt_m19_soak_baseline steps=1800 total_ms=737.661 per_step_ms=0.4098 npc_registry=10 buildings=0 planted=0 inventory_items=55 days=31 harvested=465 real_loads=20 disk_cycles=100 save_summary=31|manor|manor|plots=1"
}
```

该示例本轮实测退出码 0，逐章输出：`30/60/120fps` 规则状态完全一致；30 天长跑 `day=31 harvested_total=465`；
`real load cycles: 20`；`disk save/load cycles: 100`；基线行如上。
（`per_step_ms` 是同机同负载对比值，随机器负载与并行构建波动，实测区间约 `0.15–0.41 ms/步`。）

发布体积基线：`package.ps1` 打印 `Package size: <KB> KB, <N> files`（PC 平台当前约 32.8 MB / 714 files，
资源包内 707 个文件）。

## 5. 已知限制

- **WASM / 浏览器内玩法未执行**：本机离线无法安装 `wasm32-unknown-unknown` 目标，`game_web` 无法构建，
  因此浏览器只验证到平台契约层（`scripts/verify/verify-webgl.ps1`，见 `docs/32`）。属环境受限，非回归失败。
- **真实手柄未实机验证**：无物理设备，`jhyt_m20_gamepad` 用 `FakeBackend` 注入设备帧；
  「设备 ↔ 动作层」的插入/拔出步骤标注为未执行（见 `docs/33`、`tasks/done/M20-06-*.md`）。
- **发布包内的设置路径**：`game.exe --pack pack` 时工程根是 `<release>/pack`，
  `settings.toml` 会写到 pack 内，重新发布会被覆盖（P2，见 `docs/35` §6）。
- 浏览器自动化与跨平台（macOS/Linux）矩阵不在本轮范围（属 Beta 之后的平台任务）。
