## 逐条

### G01 运行期替换 Spine 骨骼资源
- **要做什么**：按出战名单给槽位换不同角色的骨骼（而不是全部共用一个占位骨骼）。
- **为什么做不到**：`SpinePlayer` 在场景实例化期由 applier 一次性构建；Lua `spine` 表没有改写
  `data=` 或替换 player 的入口；`entity.spawn` 也不能挂组件。
- **生产代价**：战斗槽位外观与出战角色无关，辨识度只能靠名字/配色；为绕开它按阵容预生成场景。
- **建议补法**：`spine.set_data(id, "<manifest path>")`——用装配期同一个 `load_spine_player`
  重建，保留 `animation/skin/speed/scale/z/order/enabled`；资源缺失**报错**而不是静默保留旧骨骼。
- **验收**：game_api 加演示；实体不存在/无组件/资源缺失三类错误均为 `api_error`；API 面基线同步。

### G02 场景内按需增删带组件的实体
- **要做什么**：按实际参战人数 spawn N 个带 `SpineSkeleton` 的单位，而不是永远预置固定槽位。
- **为什么做不到**：`component_applier` 只在装配期被组合根调用；无运行期写/删组件入口。
- **建议补法**：`entity.set_component(id, name, value)` + `entity.remove_component(id, name)`，
  内部走同一批 applier，**失败回滚**（不能留半装配实体）；`entity.spawn` 增加可选
  `components = { {name=, value=}, … }`。
- **验收**：成功/失败回滚/无组件报错三类集成测试；与场景 `.scene` 装配走同一条代码路径。

### G03 骨骼姿态烘焙成贴图（已实现）
- 引擎侧已补 `spine.snapshot` / `spine.snapshot_frames`（见 [docs/18](18-lua-api.md) §spine、
  [snapshot.rs](../engine/crates/rustlua-spine/src/snapshot.rs)）。这是"角色进 UI"的出口：
  烤成贴图后即可放进任意 UI 层。边界：clipping 导入期拒绝、图集页需可读盘、不适合 60fps 实时。

### G04 响应式 UI 布局
- **要做什么**：720×1280 竖屏基准，同一套界面在别的分辨率下不错位。
- **为什么做不到**：动态 UI（`ui.panel/image/...`）只吃屏幕设计像素绝对值；场景 `UiLayout`
  的 anchors/offsets 与动态 UI 不是同一条通道。
- **建议补法**：**优先**加 `ui.anchor(id, ax, ay, dx, dy)`（不改现有签名、向后兼容）；
  或让 x/y/w/h 接受 `"50%"`/`"right-16"` 这类字符串。
- **验收**：同一界面在两档分辨率下顶点/像素 golden 一致；不破坏 `RenderPlan::is_canonical`。

### G05 动态 UI 文本对齐
- **要做什么**：数值右对齐、标题居中，且随文本长度变化仍贴合。
- **为什么做不到**：`ui.text_at` 只有左上角定位；脚本只能先 `ui.measure_text` 再手算 x
  （每帧每文本多一次度量，中文长句可能有 1px 级偏差）。
- **建议补法**：`ui.text_at` 增加可选第 7 参 `align = "left"|"center"|"right"`（默认 left），
  Rust 侧用同一份 `measure` 对齐。
- **验收**：三种 align 的像素/顶点断言；`measure_text` 与渲染同口径（已有门）。

### G06 动态 UI 显式层级
- **要做什么**：卡面按"底框 → 立绘 → 描边 → 图标 → 文字"的顺序叠放。
- **为什么做不到**：五层顺序写死（[frame_data.rs:1259](../engine/crates/engine/src/host/runtime_scene/frame_data.rs#L1259)），
  面板永远在图下面、图片之间按 id 字典序——生产里只能用 `z0:/z1:` id 前缀硬凑，跨界面 id 一改顺序就变。
- **建议补法**：在 `RenderLayer::ScreenUI` 桶内加显式子序（`layer`/`order`），**不新增 pass**、
  不改 `RenderPlan` 的规范顺序；`ui.image/panel/text_at` 增加可选 `layer` 参数。
- **验收**：叠放顺序 golden（同一组元素按 layer 重排，像素结果可断言）；`is_canonical` 仍绿。

### G07 贴图透明区 RGB 清理
- **要做什么**：图集透明/半透明像素的 RGB 不应带底色（线性过滤缩放时会渗出可见色框）。
- **为什么做不到**：导入期原样保留 PNG 像素；渲染按 `src*a + dst*(1-a)` 直通混合，不清理透明区。
- **建议补法**：**导入期清理**（`rustlua-assets-import` 对 PNG 做"alpha < 阈值则 RGB=0"）——
  不增加每帧成本，所有工程受益；渲染期方案（预乘图集 + ONE/ONE_MINUS_SRC_ALPHA）作为备选。
- **验收**：构造"透明区带底色"的 PNG，导入后透明像素 RGB=0；像素 golden 无橙色框。

### G08 Spine PMA / Multiply / Screen
- **要做什么**：`pma: true` 的图集（很多 DCC 导出的默认形态）必须能正常显示。
- **为什么做不到**：Spine 管线只实现直通 alpha；PMA/Multiply/Screen 在绘制时跳过并计入
  `dropped_draws`（[world_sprite.rs:330](../engine/crates/rustlua-gpu/src/renderer/world_sprite.rs#L330)）——
  表现是"实体存在、动画在跑、`spine.bounds` 有值、画面什么都没有"。
- **建议补法**：按 `SpineDraw.premultiplied_alpha`/`blend` 选 BlendState 与管线变体
  （PMA 用 `One / OneMinusSrcAlpha`）；spike 里的 `raptor-pma`/`spineboy-pma` 正好当 golden。
- **验收**：离屏 golden 像素 + `dropped_draws=0`；wasm32 仍编译；同步 [docs/18](18-lua-api.md) 支持范围表。
- **备注**：烘焙路径（G03）已支持反预乘；渲染路径仍未做（M85-00 P1-01，S 成本）。

### G09 动态 UI 压在世界 Sprite 之上（设计不变式）
- `RenderPlan` 规范顺序里 `ScreenUI`/`VectorText` 全在 `WorldSprite` 之后 ⇒ 任何 `ui.*` 都会盖住
  场景里的 Spine 角色。生产绕法是"UI 分区 + 中间留白"。
- 若将来要突破：给 UI 通道增加 `RenderLayer::WorldUI`（世界 Sprite 之后、ScreenUI 之前），
  或允许 `ui.image` 指定 `render_layer`——这是渲染计划层改动，牵动 `is_canonical` 断言，**不宜临时改**。

### G10 运行期换骨骼 / 隐藏实体
- 同 G01/G02：没有 `spine.set_data`，也没有 `entity.set_active`/`set_visible`。
- **最低成本补法**：`entity.set_active(id, bool)`——立即解决"多余槽位露出"，且不牵动其它系统。
- **生产绕法**：用 `scene.load` 换整场景（有一次性装配开销，且场景文件名必须可枚举）。
