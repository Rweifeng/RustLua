# 发布包与用户数据目录（M31 / 阶段五 P3）

本文定义**发布出去的那份包把玩家数据写到哪里**，以及怎么用命令验收这件事。
它是 `docs/34`（质量门与发布清单）里"产物布局/干净目录"两节的展开。

## 1. 为什么必须区分"程序目录"与"用户数据目录"

发布包被装到 `C:\Program Files\...` 时，程序目录对普通用户**不可写**。玩家设置与存档若
写在 `<安装目录>/pack/`：

* **不可写** → 存档静默失败（画面上什么也不报，退出即丢进度）；
* **可写** → 卸载/重装/覆盖升级连带丢档；
* 还违反 Windows 应用数据约定：程序文件属于安装目录，玩家数据属于用户配置目录。

M31 之前正是第一种形态（`<release>/pack/.cache/save.sav` 与 `<release>/pack/settings.toml`，
见 `docs/34` §5 已知限制 4）。

## 2. 一条规则

| 工程形态 | 判定条件 | 存档 | 玩家设置 | 运行期日志 |
|---|---|---|---|---|
| **发布包** | 项目根是 `<exe>/pack` **且**同级存在 `release.toml`；或命令行给了 `--pack` | `<用户数据目录>/save.sav` | `<用户数据目录>/settings.toml` | `<用户数据目录>/logs/game.log`、`crash.log` |
| **开发工程** | 其余情况 | `<project>/.cache/save.sav` | `<project>/settings.toml` | 工作区 `artifacts/logs/game.log`（既有行为） |

开发工程保留工程内路径**是有意的**：编辑器「项目设置 → 输入/音频」面板直接编辑
`<project>/settings.toml`，`jhyt_m20_*` / `jhyt_m23_*` 等验收样例也直接检查这些文件。
发布包则一律走用户数据目录，两者由同一函数 `core::user_dir::data_roots` 决定，不存在
"这里按 A 判、那里按 B 判"。

运行期日志同理（`DataRoots::log_dir`）：发布包的 `game.log`/`crash.log` 写进用户目录，
**安装目录在运行期完全不被写入**——装到 `Program Files` 也能留下日志，且发布目录里不会
出现运行期残留（`jhyt_m31_pc_release` ① 节把"发布目录不得有 `.log`/`.sav`/`.cache`"
写成断言，所以这条不是洁癖）。

用户数据目录：

* Windows：`%APPDATA%\<app>`（缺失时退 `%LOCALAPPDATA%`，再退 `%USERPROFILE%\AppData\Roaming`）；
* 其他平台：`$XDG_DATA_HOME/<app>`，否则 `$HOME/.local/share/<app>`；
* `RUSTLUA_USER_DIR=<dir>` 覆盖整个用户数据根（便携版分发、CI、验收隔离都用它）。

`<app>` 取 `release.toml` 的 `publish_name` → `project.toml` 的 `name` → 兜底名
（`rustlua-game`），并做文件名安全化：只保留 ASCII 字母数字与 `-`/`_`，其余换成 `-`，
两端 `-` 去掉。发布名含空格/中文也不会生成有问题的路径。

## 3. 首次运行播种，升级不覆盖玩家设置

发布包自带一份 `pack/settings.toml`（由 `package.ps1` 从工程根复制）作为**默认值**：

1. 首次运行：用户目录没有 `settings.toml` → 原样复制过去（`user_dir::seed_settings`）；
2. 之后：用户目录那份是唯一真相。换新发布包（默认值可能变了）**不会**覆盖玩家改键、
   音量、手柄死区；
3. 发布包内 `settings.toml` 本身只允许是默认值——玩家的任何改动都不会写回包内字节。

包内没有 `settings.toml`（`package.ps1` 未打包设置）时不播种，引擎默认值生效（死区
`0.15/0.05`），文件在玩家第一次保存设置时建立。

## 4. 一处根，两处读者

同一份 `settings.toml` 有两个读者，必须同源：

| 读者 | 位置 | 读的东西 |
|---|---|---|
| Rust 设备后端 | `game_app.rs` 启动时 `settings::load_deadzone_section(settings_root)` | `[input]` 的 `stick_deadzone`/`trigger_deadzone` |
| Lua 面板/存档 | `input.settings_path/load_settings/save_settings`、`audio.*`（经 `LuaRuntime::set_settings_root`） | 改键映射 `map`、`[audio]` 音量 |

`settings_root` 未显式设置时退回 `project_root`（开发工程），发布包由宿主在
`RuntimeScene::init` 里指向用户目录。相对路径参数也相对**设置根**解析
（`input.save_settings("player/custom.toml")` → 用户目录下 `player/custom.toml`，
不会在安装目录里建目录）。

# 2) 端到端验收（真实发布目录 + 真实 LuaRuntime + 真机环境证据）

#    → jhyt_m31_pc_release_ok

# 3) 真实二进制在发布布局下的解析结果

#    → game_check_ok … / player_data_roots packaged=true save_dir=… settings_dir=…

# 4) 干净发布 + 隔离自测（含空格路径、无源码/target/.cache）

`jhyt_m31_pc_release` 六节断言：

1. **发布目录形态与卫生**：13 项必需条目（`game.exe`/`release.toml`/`run.txt`/`build-info.txt`/
   `deps.txt`/`fonts/*`/`pack/{project.toml,manifest.txt,chars.txt,settings.toml,scripts/main.lua,
   scripts/ui/ui_text.lua,scripts/ui/text_fit.lua}`）；`pack/` 内不得出现 `.cache`/`.data`；
   发布目录不得有 `.sav`/`.log`/`.tmp` 与 `.staging-*` 残留（本轮据此清掉了 P2 遗留的一处）。
2. **判定与两套根**：发布包 → 用户目录（且不等于程序目录），显式 `--pack` 同一结果，
   开发工程 → 工程根 `settings.toml` + `<project>/.cache/save.sav`。
3. **播种/升级 + 真实脚本落盘**：种子默认值；玩家改死区后换包不覆盖；真实 LuaRuntime
   （项目根 = 发布包、设置根/存档 = 用户目录）跑 `scripts/main.lua`，改键/音量/存档全部落在
   用户目录，包内 `settings.toml` 一个字节都不变，且新 runtime 能读回。
4. **设备后端与面板同源**：用户目录 `0.33/0.11`、包内默认 `0.15/0.05`、缺失回落默认。
5. **真机/浏览器证据**：XInput 槽位采样（无硬件时 `connected=false slots=[]`，逻辑链路由
   `jhyt_m20_gamepad` 的 Fake 后端覆盖）；`artifacts/logs/webgl/summary-*.json` 断言
   `status=ok` 且 `wasmTarget=true`（本机 Edge 153 无头 + WebGL2 真实通过，见 `docs/32`）。
6. **中文文本管线随包发布**：`manifest.txt` 含 `ui_text.lua`/`text_fit.lua`/`hud.lua`/
   `save_manager.lua`；`chars.txt` CJK ≥ 500（缩水即红灯）；包内 `settings.toml` 必须带
   `[input]` 与 `stick_deadzone`（否则玩家改键落在不存在的段上）。

## 6. 常见问题

* **存档"不见了"**：先看日志 `[save] release layout: user data directory in use` 给出的
  `save=`/`settings=` 路径；`RUSTLUA_USER_DIR` 未设置时就是 `%APPDATA%\<publish_name>`。
* **想做成便携版**：启动前设 `RUSTLUA_USER_DIR=<U 盘目录>`，存档与设置随之落盘到该处。
* **改键在编辑器里改了、游戏里没生效**：编辑器编辑的是 `<project>/settings.toml`（开发
  工程形态），发布包读的是用户目录那份——改发布包默认值要改工程根文件后重新发布；
  玩家自己的改键在用户目录里，重新发布不会丢。
* **包名/应用名带空格或中文**：用户目录名会被安全化（空格/中文 → `-`），这是有意的，
  避免路径在不同代码页/工具链下出问题。

## 7. 发布脚本侧（`scripts/package.ps1`）

| 位置 | 内容 |
|---|---|
| `run.txt` 第 6~8 行 | 玩家数据目录的确切路径（Windows `%APPDATA%\<publish_name>`）+ "`pack/` 只读、永不接收玩家数据" + `RUSTLUA_USER_DIR` 覆盖说明 |
| `build-info.txt` 的 `player_data:` 行 | 同上，机器可读（WebGL 平台写 `browser storage; no filesystem player data`） |
| `-SelfTest` 隔离自测 | 把隔离副本里真实 `game.exe --pack <隔离>/pack --check` 的输出解析出 `player_data_roots`，断言 `packaged=true` **且** `save_dir` 落在临时 `RUSTLUA_USER_DIR` 下，并扫描隔离发布目录**不得**出现 `.cache`/`.data`/`*.sav`/`*.log` |

自测通过时打印：

```
Directory-isolation self test passed (spaces path + no-source check + user data dir OK)
```

这条自测覆盖三个此前只能靠人工确认的失败形态：路径含空格、目标机无源码/工具链、
**发布包把玩家数据写进安装目录**（含只读安装目录与重装丢档）。

> **踩坑记录（M31 修正的一个空跑自检）**：发布版 `game.exe` 是 **Windows GUI 子系统**程序
> （`crates/game/src/main.rs` 的 `windows_subsystem = "windows"`，双击不弹控制台）。这类程序
> 用 `& game.exe --check` 调用时 PowerShell **既不等待也不捕获 stdout**，而 `$LASTEXITCODE`
> 会保留上一条命令的值（通常是 `0`）——于是"发布包自检"过去一直是**静默空跑成通过**。
> 现在统一走 `Invoke-PackagedCheck`（`Start-Process -Wait -PassThru` + 重定向文件），
> 真实取回退出码与 stdout，并断言 `player_data_roots` 行存在、`packaged=true`、
> `save_dir` 落在 `RUSTLUA_USER_DIR` 下。人工手动验证同理：
> `game.exe --pack pack --check > out.txt 2>&1`（重定向到文件），而不是直接看控制台。

## 8. 引擎编辑器绿色版（`scripts/package-engine.ps1`）

上面第 7 节讲的是**游戏**发布包（`game.exe` + 只读 `pack/`）。与之并列的还有一类产物：
**给别人试用/验收的引擎编辑器绿色包**——免安装、整目录拷走即用，用来核对体积、
在别的 Windows 主机上跑起来、以及演示编辑器本身。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-engine.ps1 -Zip
# 产物：artifacts\packages\RustLua-Engine-<版本>-win64\  与同名 .zip（artifacts/ 已被 .gitignore 忽略）
```

| 位置 | 内容 |
|---|---|
| `editor.exe` / `game.exe` / `assetc.exe` | release 构建（LTO fat + `codegen-units=1` + strip） |
| `fonts/NotoSansSC-VF.ttf` | **中文界面的前提**：编辑器按「exe 同目录 `/fonts/`」查找（见下） |
| `samples/game_api`、`samples/game_jhyt` | 样例工程（已剔除 `builds/`、`.cache/`、`.temp/`） |
| `启动编辑器.bat` / `便携模式启动.bat` / `运行样板游戏.bat` | 双击即用；便携那个把 `RUSTLUA_USER_DIR` 指到包内 `userdata\`，不写 `%APPDATA%` |
| `运行说明.txt` / `build-info.txt` | 怎么跑、按什么顺序验收、已知限制；构建信息（版本/commit/工具链/体积） |
| `文件清单.manifest.txt` | 每个文件的相对路径 + 字节数 + SHA256，用于核对"拷过去的是不是同一份" |

### 8.1 编辑器找中文字体的规则（绿色版的关键）

原先编辑器只认**编译期绝对路径**（`env!("CARGO_MANIFEST_DIR")/fonts/…`，也就是构建机上的
`…\engine\crates\editor\fonts\…`）。绿色版把目录拷到另一台机器后那条路径不存在，
中文会全部变成"豆腐块"——一个与包本身无关、却会让跨机验收直接失败的坑。

现在按下面的顺序找（`crates/editor/src/util.rs::cjk_font_candidates`）：

1. 环境变量 `RUSTLUA_FONT`（显式指定）；
2. **`<exe 同目录>/fonts/NotoSansSC-VF.ttf`**（绿色版形态）；
3. `<exe 同目录>/NotoSansSC-VF.ttf`（允许直接摆在 exe 旁）；
4. 编译期源码树路径（开发形态）。

命中或失败都会打印一行，跨机验收时这行日志就是结论：

```
editor: CJK fallback font = <实际使用的路径>        # 命中
editor: no CJK fallback font found; tried 4 path(s). …   # 全都没找到（中文会是豆腐块）
```

### 8.2 跨机自测（本仓库每次发绿色包都应做）

把包**拷到带空格与中文的目录**（模拟 U 盘/共享目录）再跑，四条都要过：

```powershell
editor.exe --gui-smoke                              # cases=29 failed=0 result=ok
editor.exe --perf-baseline                          # scenarios=31 failed=0 result=ok
editor.exe --project samples\game_api  --check      # schema_errors=0 unknown_components=0
editor.exe --project samples\game_jhyt --check      # schema_errors=0 unknown_components=0
editor.exe --project samples\game_api               # 真实窗口；stderr 必须打印命中的字体路径
```

前三条不需要 GPU，用来把"包坏了"和"这台机器的图形栈不行"分开——这是跨机验收里最容易混淆的两种失败。

### 8.3 踩坑记录

* **`.bat` 必须是 CRLF 行尾，内容保持纯 ASCII**（用户实测踩到）：
  打包脚本自身是 LF 换行，here-string 会原样带出 LF；而 cmd.exe 按 CR 找行尾，
  **LF-only 的 bat 遇到多字节（GBK）注释行会把注释行切碎**——实际报错是
  `'_api: 2D' 不是内部或外部命令，也不是可运行的程序或批处理文件`，
  即注释里 `game_api：2D` 的残片被当成命令执行了。
  现在的做法：写文件前一律过 `ConvertTo-Crlf`，且 **bat 内容只用 ASCII**
  （注释英文，中文说明放 `运行说明.txt`）。这样控制台代码页是 GBK 还是 UTF-8 都不会出问题。
* **`.bat` 不能带 UTF-8 BOM**：cmd.exe 会把 BOM 当命令执行。三条合起来就是：
  bat = **CRLF + ASCII + 无 BOM**。
* **`.txt` 也转成 CRLF**：`运行说明.txt`/`build-info.txt` 用 UTF-8 **with BOM**（记事本直接可读），
  行尾统一 CRLF，老工具显示才一致。
* **调用参数必须自己加引号**：`Start-Process -ArgumentList @("--project", $path)` 会把数组元素
  用空格拼起来**且不加引号**，路径里的空格于是把参数切开，游戏报
  `argument error: unknown argument: <路径片段>`。自测脚本里要传完整的一串并自带引号。
* **自测时别给启动脚本重定向 stdout 再 `-Wait`**：`start ""` 拉起的编辑器会继承重定向句柄，
  管道不关闭，`Start-Process -Wait` 会永久挂住。测"bat 有没有报错"看 `cmd` 自身的退出码与
  stderr，测"程序有没有起来"看进程和它自己的 `editor.log`。
