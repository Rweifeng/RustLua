# 编辑器强化实施计划（对标 Unity / Godot / UE5）

- 项目：P2 Rust + Lua 游戏引擎
- 制定日期：2026-08-22
- 当前基线：`v0.9-3d-game`（M0–M9 路线图已完成）
- 状态：READY

## 1. 现状盘点

当前编辑器（`engine/crates/editor`，约 5456 行，egui/eframe）：

**已有能力**：
- 场景树（层级）/ 添加 / 重命名 / 父子 / 隐藏 / 锁定；
- Inspector：Transform、Sprite、LuaScript、Transform3D、Camera3D、Light、MeshRenderer、Collider3d 数值编辑；
- 资源浏览器（搜索 / 筛选 / 刷新 / 导入状态）；
- 2D 场景视图（网格 / pan / zoom / 旋转框选）；
- 3D 场景模式：XZ 俯视平面 + 平移 Gizmo（M9-03）；
- Undo/Redo（history）、自动保存 / 崩溃恢复、Lua 控制台、发布面板、进度面板。

**关键缺口**（与成熟引擎的差距）：
1. **Game 视图是占位符，Play 不运行游戏**。`PlaySession` 只是克隆场景文档，`draw_game_view` 画 "Press Play" 文本。Unity/Godot/UE5 的 Play 都在视口里实时运行游戏 —— 这是最大缺口。
2. **3D 场景视图不是透视视口**。当前是 XZ 俯视平面，无轨道/平移/缩放导航，无法像 Unity Scene 视图那样从任意角度观察和编辑。
3. **Gizmo 仅平移**（无旋转/缩放，无多轴手柄，无吸附/对齐）。
4. **无组件增删/重排**（只能编辑已有组件）。
5. **资源浏览器无缩略图 / 拖放 / 双击预览**。
6. **无多选 / 对齐 / 快照工具**。
7. **Prefab 只有数据层，无编辑器 UI**。

## 3. 总体目标与架构方向

目标：让编辑器能 **在视口里实时运行和编辑游戏**（Unity/Godot 的核心体验），并补齐常用编辑工具。不做 UE5 级重型编辑器（蓝图/材质编辑器/地形编辑器），遵循「轻量、可落地」原则。

**架构核心决策 —— 引擎内嵌渲染**（P0 的地基）：
当前 `game_runner` 是独立二进制，编辑器无法运行它。要嵌入游戏预览，需把运行时抽成可复用库并支持 offscreen 渲染。

| 方案 | 说明 | 评价 |
|---|---|---|
| **A（推荐）单一 wgpu 设备** | 编辑器从 eframe 的 wgpu render_state 取 Device/Queue，改造 `Renderer` 接受外部设备并渲染到 offscreen 纹理，直接注册为 egui 纹理 | 性能最好、无跨设备拷贝；`Renderer` 改造较大但一次到位 |
| B 独立设备 + GPU 拷贝 | 游戏用自己设备渲染到纹理，再跨设备 copy 到 egui 纹理 | 需要跨设备拷贝特性，复杂且兼容性风险 |
| C CPU readback | 渲染→map-read→CPU→上传 egui | 每帧同步慢，仅适合低分辨率预览 |

推荐 **方案 A**：改造 `Renderer` 支持「窗口 surface」与「offscreen 纹理目标」两种模式；编辑器持有单一 wgpu 设备，游戏预览与 3D 场景视口共用它。

## 4. 分阶段任务与验收

### 阶段一（P0，核心）：引擎内嵌 + 透视视口

**M10-00 编辑器强化基线与技术决策**
确认 `v0.9` 基线；新增 ADR（单一 wgpu 设备 / offscreen 渲染 / 编辑器相机约定）；建立 `tasks/active/M10-*`。
验收：基线质量门通过；ADR 齐全。

**M10-01 运行时抽取为可复用 crate**
把 `game_runner` 的 `RuntimeScene`（场景→帧数据桥）与 `Renderer`（GPU 渲染）抽到独立 crate（如 `engine_host`），暴露「创建运行时 / 步进 / 渲染到目标」接口；`game_runner` 改用它，行为不变。
验收：抽取后 game_runner 运行行为与基线一致；质量门通过；`main.rs` 进一步瘦身。

**M10-02 Renderer offscreen 渲染目标**
`Renderer` 支持渲染到 offscreen 纹理（而非仅窗口 surface）：创建渲染目标纹理 + 视图，把 3D/2D pass 输出到它。
验收：Renderer 能以纹理为目标的单元/集成路径存在；窗口模式行为不回归。

**M10-03 编辑器内嵌游戏预览（Play 真正运行）**
编辑器从 eframe wgpu 取设备，创建引擎运行时；Game 视图用 egui 纹理显示游戏实时画面；Play 真正跑 Lua + physics + 渲染，Stop 恢复编辑场景。
验收：编辑器内 Play 后 Game 视图显示实时游戏画面（2D 与 3D 场景均可）；Stop 恢复编辑状态；可发布。

**M10-04 3D 透视视口 + 导航**
编辑器 3D 场景视图升级为透视视口：编辑器相机轨道导航（中键轨道 / 右键平移 / 滚轮缩放），复用内嵌渲染器渲染 3D 场景到 egui 纹理；Gizmo 在透视视口内工作。
验收：可从任意角度观察/编辑 3D 场景；导航与 M9 俯视模式共存（可切换）；性能可接受。

### 阶段二（P1，编辑体验）

**M10-05 组件增删 / 重排**
Inspector 支持添加/移除组件、调整组件顺序（经 history 可撤销）。
验收：添加/移除/重排组件后保存重开一致；撤销正确。

**M10-06 Gizmo 完善**
平移 Gizmo 增加多轴平面手柄；新增旋转、缩放 Gizmo；支持对齐/吸附（网格吸附 + 旋转角吸附）。
验收：三种 Gizmo 可操作；吸附结果可验证；保存重开一致。

**M10-07 资源浏览器增强**
资源缩略图（纹理/模型预览）、从浏览器拖放到场景创建实体、双击打开/预览。
验收：纹理缩略图显示；拖放精灵/模型到场景生成实体；预览可用。

**M10-08 多选 / 对齐 / 快照**
场景视图多选实体；对齐工具（对齐网格/对齐到选择）；快捷键与工具栏入口。
验收：多选可批量变换；对齐结果正确。

### 阶段三（P2，高级）

**M10-09 Prefab 编辑器集成**
从场景对象创建/实例化 Prefab；Prefab 覆盖值编辑；Prefab 编辑 UI。
验收：创建/实例化/覆盖/更新策略可用。

**M10-10 编辑器验收与性能**
编辑器启动/交互性能基线；长会话稳定性；发布包编辑器可用；验收矩阵更新；标签 `v0.10-editor`。
验收：无 P0/P1；性能基线可对比；发布可用。

## 5. 质量门与停止条件

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
cargo build --workspace
cargo build --workspace --release
git diff --check
cargo run -p game_runner -- --project C:\GitHub\p2\game --check
cargo run -p editor -- --project C:\GitHub\p2\game --check
```

出现以下任一情况时暂停并先修复：game_runner 行为回归、渲染行为不一致、编辑器嵌入导致卡顿不可用、场景格式不兼容。

## 6. 主要风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 运行时抽取/offscreen 改造量大 | P1 | 分步：先抽 crate 行为不变，再加 offscreen 目标 |
| 编辑器与游戏双 wgpu 设备冲突 | P1 | 方案 A 单一设备，避免跨设备拷贝 |
| 内嵌预览性能 | P2 | offscreen 纹理复用、分辨率可调、按需重绘 |
| egui 与游戏渲染时序冲突 | P1 | 渲染到纹理再贴图，不直接复用 egui surface |
| 范围膨胀（变成重型编辑器） | P1 | 严守能力矩阵，不做蓝图/材质/地形编辑器 |

## 7. 通过条件

阶段一（M10-00..04）落地：编辑器能内嵌运行游戏预览 + 3D 透视视口导航，Play 真正运行。阶段二/三按优先级推进。全程不回归 game_runner 与既有游戏。
