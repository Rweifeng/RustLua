# 83 包体逐依赖体积归因（wasm，2026-11-26）

- 目的：给 `verify.ps1 -Metrics` 的包体判红（`game_web.wasm +28% raw`、`assetc.exe gzip +33%`、
  包体 `+10~68%`）一个**可复核的归因**，再决定是否按 docs/70 §4 重签基线。
- 结论先行：**增长主要是能力增量（M84 Spine 2D、矢量字体栈、序列化单态化、工作区功能），不是回归**；
  同时发现两个**口径/工程问题**：①原始 cargo wasm 里约 1/4 增量是 `name` 调试段（发布前会被剥掉）；
  ②当前打包 recipe 锁 rustc **1.88**，而 M84 的 `spine2d@0.5` 要求 **≥1.95** ⇒ **WebGL/微信发布打包链
  当前编不出来**（见 [M86-01](../tasks/done/M86-01-Web打包工具链与spine2d-MSRV.md)）。

## 1. 方法（可复现）

同一工具链、同一 profile 环境，只换 commit，排除编译器差异：

```powershell
# 基线：M85-04 记的二进制基线 commit（metrics/baselines/binaries.json 的 baseline_commit）
git worktree add --detach artifacts/attr/baseline-src 0c0c6ced
# 两者都用 rustc 1.97.1 + wasm32-unknown-unknown，profile 覆盖与打包脚本一致：
$env:CARGO_PROFILE_RELEASE_STRIP="none"
$env:CARGO_PROFILE_RELEASE_OPT_LEVEL="z"
$env:CARGO_PROFILE_RELEASE_LTO="fat"
$env:CARGO_PROFILE_RELEASE_CODEGEN_UNITS="1"
$env:ZIG="engine/.tools/zig/zig-x86_64-windows-0.16.0/zig.exe"
cargo build -p game_web --release --target wasm32-unknown-unknown   # 两个 worktree 各跑一次
```

- 对比对：`0c0c6ced`（基线）vs `334559c5`（M85 最终 HEAD）；
- 原始产物：`artifacts/attr/wasm/{baseline,current}.wasm`；
- 发布口径代理：`wasm-bindgen --target web --no-typescript --remove-name-section` +
  `wasm-opt -Oz`（与 `scripts/build/package/50-runner.ps1`、`10-helpers.ps1` 同参数）；
- 逐 crate 归因：解析 wasm `name` 段（rustc v0 mangling 的 `Cs<hash>_<len><crate>`）+ `code` 段
  每个函数体字节数，按 crate 聚合（脚本：`artifacts/attr/attribute4.cjs`，派生数据
  `artifacts/attr/attribution.json`，均 gitignored）。

## 4. 与 `-Metrics` 判红的关系（口径问题，需先修口径再重签）

`metrics/baselines/binaries.json` 的 `game_web.wasm = 9,074,177` 来自 **2026-10-21 的打包 recipe**
（rustc 1.88 + strip=none/z/fat-LTO/CGU=1）。而 `measure-artifacts.mjs` 直接量 `engine/target` 里
**当前最后一次构建**的 raw wasm：本地实测出现过 11.6 MB（默认 release profile）与 21.1 MB
（另一种构建）两个值——**同一指标在不同 recipe 之间差 1.2~2.3×**。

因此 `-Metrics` 的"wasm +28%"里混了三样东西：①真实代码增长（本节归因 +2.75 MB 发布口径）；
②recipe 变化；③`name`/debug 元数据是否被剥。**直接拿 raw target 文件重签基线会把口径噪声写成基线。**

## 5. 建议（按顺序）

1. **先修度量口径**（S）：`measure-artifacts.mjs` 对 wasm 增记 build recipe 指纹（rustc 版本、
   `CARGO_PROFILE_RELEASE_*`、strip 状态）与**发布产物**（`game_web_bg.wasm`，来自打包目录）体积，
   raw target 只作诊断字段；
2. **同时修发布链工具链冲突**（P0，见 [M86-01](../tasks/done/M86-01-Web打包工具链与spine2d-MSRV.md)）：
   这是"能不能发 WebGL/微信包"的问题，比基线数字更硬；
3. 修完口径后，用**发布产物**的当期读数 + 本节归因理由按 docs/70 §4 `accept-baseline` 重签；
4. 若微信 4 MiB/20 MiB 配额吃紧，按上图优先砍体积：矢量字体栈（按需 subset）、serde 单态化
   （`spine2d` 的 JSON 解析可否只在编辑器侧启用、运行时用 `.skel`）、mlua 绑定注册面（按 dimension 裁剪）。
