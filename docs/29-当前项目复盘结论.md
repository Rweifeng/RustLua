## 2. 总体判断

项目已经从“引擎基础设施”进入“编辑器强化与运行时整合”阶段，核心代码链路基本成型：

- `engine_core`：ECS、场景、资源、Lua、2D/3D 数学与组件、物理、动画、文本与字体；
- `engine_host`：从 `game_runner` 抽出的运行时场景实例化和 GPU 渲染；
- `editor`：场景树、Inspector、资源浏览器、Game 预览、2D/3D Scene 视图、Gizmo 和 Prefab；
- `game_runner`：正式游戏运行入口；
- `assetc`：资源扫描、导入缓存和发布打包。

代码实现已经具备轻量游戏引擎的主要骨架，但当前最大的风险不是功能完全缺失，而是：

> 近期功能实现、文档状态、验收证据、CI 范围和发布路径没有同步闭环。

因此不建议继续使用“ M10 全部正式验收完成、`v0.10-editor` 已发布”的表述。更准确的状态是：

> 代码实现已进入可用阶段；自动化测试通过；真实 GUI/GPU 交互、发布包路径和近期 M10-11/M10-12 变更仍缺少完整可追溯验收，并存在若干应优先修复的回归风险。

## 3. 当前架构状态

### 3.1 `engine_core` 已具备较完整的引擎基础

[engine_core/src/lib.rs](../engine/crates/engine_core/src/lib.rs) 已经包含：

- ECS：`EntityId`、`World`、commands、events、scheduler；
- 2D：`Transform`、`Sprite`、`SpriteBatch`、`Camera2D`、`Tilemap`；
- 3D：`Transform3D`、`Camera3D`、`Mesh3D`、`Light`、`Physics3D`、骨骼动画；
- 资源：纹理、图集、glTF、资源数据库、导入缓存、Prefab、发布包；
- 脚本：Lua VM、热重载、调试、场景 API、UI API；
- 游戏能力：音频、粒子、存档、输入、固定时间步；
- 文本：动态字体、SDF 字形生成、TMP 风格布局和 bitmap fallback。

项目已经完成从 M0 到 M9 的大部分基础能力建设，3D 和 Lua 游戏运行时也已不再是单纯 Demo 级别。

### 3.2 `engine_host` 抽取方向正确，但边界尚未完全闭合

[engine_host/src/lib.rs](../engine/crates/engine_host/src/lib.rs) 已承担：

- `RuntimeScene`；
- `Renderer`；
- 2D `SceneMesh`；
- 3D `Scene3d`；
- offscreen 渲染；
- CPU readback；
- SDF shader 和字体绘制。

这解决了编辑器和正式运行时不能复用同一套运行时的问题，是 M10 最重要的架构变化之一。

但编辑器的 3D Scene 视图仍存在一套独立的场景解释逻辑，没有完全复用运行时的 3D 场景提取路径。后续可能在以下方面出现分叉：

- 活动相机和光源选择；
- 动画关节；
- 材质；
- 脚本修改后的实体状态；
- 后续新增组件。

建议后续将“场景解析”和“编辑器相机覆盖”分离，底层 drawable、材质和资源解析尽量复用，编辑器只覆盖视角和编辑态行为。

### 3.3 编辑器模块化重构已完成，但近期变更量较大

提交 `0b781a6` 将编辑器从单体 `main.rs` 拆分为多个模块，涉及约 4163 行新增/删除。当前结构包括：

- `panels/scene_view.rs`
- `panels/game_view.rs`
- `panels/hierarchy.rs`

- `panels/resource_browser.rs`
- `panels/console.rs`
- `actions`、`geometry`、`history`、`document` 等状态与编辑逻辑模块。

这是合理的重构方向，但大规模拆分后，现有测试主要覆盖状态、文档和纯逻辑，不能替代真实 GUI 回归。

## 8. 当前高优先级实现风险

### 8.1 3D Scene 视图可能永久停留在半分辨率

位置：[scene_view.rs:837-860](../engine/crates/editor/src/panels/scene_view.rs#L837-L860)

拖拽期间使用半分辨率渲染，但缓存仍记录完整视口尺寸。拖拽结束后缓存可能继续命中，导致不会自动重新渲染完整分辨率。

建议在 `preview_active` 从 `true` 变为 `false` 时强制使缓存失效，或将实际渲染尺寸纳入缓存命中条件。

### 8.2 readback 失败后缓存状态没有失效

位置：

- [scene_view.rs:856-887](../engine/crates/editor/src/panels/scene_view.rs#L856-L887)
- [scene_view.rs:946-989](../engine/crates/editor/src/panels/scene_view.rs#L946-L989)

当前在渲染/readback 成功前就写入缓存。如果 readback 失败，只记录 warning，下一帧仍可能命中缓存，不再重新渲染。

建议只有在 readback 成功后提交缓存；失败时清除对应 cache，并保留用户可见错误状态。

### 8.3 内嵌 Game 预览的输入边沿可能每个 tick 重复触发

位置：

- [game_view.rs:164-180](../engine/crates/editor/src/panels/game_view.rs#L164-L180)
- [game_view.rs:264-299](../engine/crates/editor/src/panels/game_view.rs#L264-L299)
- [input.rs:59-76](../engine/crates/engine_core/src/input.rs#L59-L76)

预览每次 tick 都从空的 `InputSnapshot` 创建输入。如果鼠标或键盘持续按住，每帧都可能被识别为新的 `just_pressed`。

可能导致：

- 按住鼠标时重复触发 UI `on_click`；
- 按住键盘时重复触发一次性动作；
- Game 预览与正式窗口运行时不一致。

建议让 Play Session 或 Game View 持有跨 tick 的输入快照，并在模拟帧边界清理 transient 状态。

### 8.4 SDF 字体加载存在持续内存泄漏

位置：

- [font.rs:46-53](../engine/crates/engine_core/src/font.rs#L46-L53)
- [runtime_scene.rs:90-107](../engine/crates/engine_host/src/runtime_scene.rs#L90-L107)
- [scene_view.rs:900-920](../engine/crates/editor/src/panels/scene_view.rs#L900-L920)

`FontAtlas::load` 使用 `Box::leak` 将字体字节转为 `'static`。编辑器在场景 revision 变化时重建 `RuntimeScene`，反复编辑可能反复泄漏字体数据。

建议使用 `Arc<[u8]>`、字体缓存或可管理的 owned buffer。

### 8.5 Play 初始化失败后仍然进入 Play 状态

位置：[game_view.rs:19-42](../engine/crates/editor/src/panels/game_view.rs#L19-L42)

`create_preview()` 失败时只更新错误文本，但后续仍设置 `play_session`。这会导致 Game 视图为空、状态显示错误，且用户必须 Stop 后才能重试。

应只有在预览创建成功后才建立 `PlaySession`。

## 9. 其他实现风险

### 9.1 编辑器和运行时存在两套 3D 场景解释逻辑

可能导致 Game View 和 Scene View 在相机、光源、动画、材质或新增组件上出现不一致。

### 9.2 Renderer 对非法纹理索引可能 panic

[renderer.rs:1782-1787](../engine/crates/engine_host/src/renderer.rs#L1782-L1787) 直接通过索引访问纹理路径。对 malformed `SceneMesh` 应返回结构化错误，而不是 panic。

### 9.3 非阻塞 readback 忽略 `map_async` 失败

[renderer.rs:1616-1622](../engine/crates/engine_host/src/renderer.rs#L1616-L1622) 无论映射成功与否都设置 ready，后续可能无条件读取映射范围。应保存并传递 map 错误。

### 9.4 UI 颜色解析未验证范围

[ui.rs:71-91](../engine/crates/engine_core/src/ui.rs#L71-L91) 只检查有限数值，没有拒绝或 clamp 负数及大于 1 的值。

### 9.5 SDF glyph 容量固定为 256

当前图集为 `16 × 16`，超过 256 个动态 glyph 后可能返回空 metrics，导致中文或复杂 UI 文本静默消失。需要扩容、分批或明确溢出错误。

### 9.6 `git diff --check` 尚未覆盖近期历史

近期历史检查发现编辑器文件存在 EOF 空行问题：

- `engine/crates/editor/src/main.rs:570`

建议将 `git diff --check` 纳入提交前和 CI 门禁。

> 项目代码已具备继续开发和内部试用条件，但仍处于“实现已落地、验收和稳定性闭环进行中”的阶段。
