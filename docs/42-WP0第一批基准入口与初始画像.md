# WP0 第一批：基准入口与初始性能画像

## 1. 批次定位

本报告整理 WP0 第一批已经落地的性能证据基础。第一批目标是先建立可重复的 CPU 基准入口和固定工作负载，暂不把 GPU 帧时间、完整 3D 阶梯或跨设备性能结论写成已完成项。

本批沿用了仓库已有的性能基线工作，并将入口收敛到 engine workspace：

- ECS 压力：`engine/crates/engine/examples/ecs_stress.rs`
- Sprite 批处理：`engine/crates/engine/examples/sprite_stress.rs`
- Tilemap 顶点生成：`engine/crates/engine/examples/tilemap_stress.rs`
- 既有窗口/发布/编辑器采样：`scripts/m15-00-baseline.ps1`、`scripts/m15-00-real-window.ps1`

历史依据：`tasks/done/M7-04-性能基线.md` 与 `tasks/done/M15-00-性能基线.md`。

## 2. 固定工作负载

| 工作负载 | 第一批覆盖 | 观测内容 |
|---|---|---|
| ECS | 10,000 entity，固定步循环，创建/查询/更新/销毁/命令批处理 | cycles、实体数量稳定性、CPU 操作耗时 |
| Sprite | 1,000 Sprite，CPU push/build | push、build、顶点数量、draw batch 数 |
| Tilemap | 100×100 Tilemap | 顶点生成耗时、顶点数量、draw 数 |
| 编辑器/发布 | 既有 M15 窗口采样脚本 | 启动时间、工作集、private bytes、句柄数 |

第一批的核心验收是：基准能重复运行、实体数量不漂移、批处理输出可解释、异常以非零退出，而不是追求跨机器绝对耗时。

## 3. 原始证据摘要

历史 Release 采样记录过以下结果，数字只作为当机参考：

- ECS 10,000 entity / 10 秒：`query avg_us=441`、`update avg_us=1029`、`command avg_us=33`、`cycles=5960`；
- Sprite 1,000：`push_ms=0.020`、`build_ms=0.091`；
- Sprite 10,000：`push_ms=0.201`、`build_ms=0.862`；
- Tilemap 100×100 / 3 cycles：`avg_ms=1.454`、`vertices=60000`；
- Tilemap 500×500 / 1 cycle：`avg_ms=42.977`、`vertices=1500000`。

这些历史结果来自 `tasks/done/M15-00-性能基线.md`，不能与后续 `wp0-v2` 的统计口径直接横向比较；后续比较必须使用同一版本的报告 schema、采样次数和构建模式。

## 4. 第一批交付边界

已完成：

- 有独立、可参数化的 ECS/Sprite/Tilemap benchmark；
- 可重复生成固定场景输出；
- 既有窗口内存和发布启动采样保留为补充证据；
- 为后续 p50/p95/p99、RenderFrameMetrics 和 3D 不回退证据提供入口。

未完成：

- 没有统一 JSON schema；
- 没有统一 p50/p95/p99；
- 没有 draw/instance/triangle 的统一渲染指标；
- 没有纯 3D 阶梯和 3D golden；
- 没有 GPU timestamp；
- 没有可移植的分配次数、GPU heap 或完整显存统计。

## 5. 结论

第一批完成了 WP0 的“可测量入口”建设，证明 ECS、Sprite、Tilemap 可以在固定工作负载下重复采样。它是后续统一报告格式和渲染指标的基础，不单独构成 WP0 完成门。

下一批重点转为统一证据格式、补齐 RenderFrameMetrics，并修正资源失败、阴影 pass、实例/三角形和 Vector Text 的统计边界。
