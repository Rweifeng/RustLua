# RustLua 游戏引擎使用手册

- 项目：P2 RustLua Game Engine
- 当前版本：`v0.4-scripting`
- 适用平台：Windows 优先
- 引擎核心：Rust stable
- 游戏脚本：Lua 5.4（通过 `mlua` 接入）
- 图形与窗口：`wgpu` + `winit`

本文面向独立开发者和后续 AI 开发会话，目标是让使用者能够完成环境检查、构建、运行 Demo、编写 Lua 脚本、验证场景和排查问题。

## 5. 编写 Lua 游戏脚本

当前 Lua 运行时脚本通常包含三个生命周期函数：

```lua
function on_create()
    -- 脚本加载后执行一次
end

function update()
    -- 每个固定逻辑步执行
    return "running"
end

function on_destroy()
    -- 脚本卸载或热重载前执行一次
end
```

### 5.1 时间、日志和退出

```lua
function update()
    local dt = time.delta()
    log.info("delta=" .. dt)
    if input.pressed("escape") then
        app.quit()
    end
    return "running"
end
```

### 5.2 实体和 Transform

```lua
player = entity.spawn("player")
transform.set(player, 0, 0)

function update()
    local speed = 4
    transform.move(player, speed * time.delta(), 0)
    local position = transform.get(player)
    return position.x
end
```

实体 ID 是带 generation 的句柄。实体销毁后旧 ID 不能继续访问新实体：

```lua
entity.destroy(player)
-- 后续继续使用 player 会得到明确的 Lua 错误
```

### 5.3 输入

支持键盘状态、边沿和轴查询：

```lua
if input.is_down("d") then
    transform.move(player, 1, 0)
end

if input.just_pressed("space") then
    log.info("jump")
end

local horizontal = input.axis("horizontal")
local vertical = input.axis("vertical")
```

也可以使用兼容 API：

```lua
input.action("d")
input.pressed("space")
input.released("space")
```

### 5.4 生命值和物理查询

```lua
health.set(player, 100)
local current = health.damage(player, 10)
local nearby = physics.overlap(0, 0, 2)
local target = physics.raycast(0, 0, 1, 0, 20)
```

### 5.5 UI、资源和存档

```lua
ui.text("status", "HP=" .. health.get(player))
ui.hide("status")
ui.show("status")
local status = ui.get("status")

local texture = asset.load("textures/player.png")
asset.release(texture)

save.write("last_scene", "arena")
local last_scene = save.read("last_scene")
scene.load("arena")
local active_scene = scene.reload()
```

当前 `scene`、`asset`、`ui`、`save` 是内存适配层，真实编辑器和持久化工作流将在后续阶段继续完善。

## 6. 场景脚本开发流程

推荐按以下方式组织一个场景：

1. 使用 `Scene` 创建实体和组件数据；
2. 将对象角色写入场景组件或元数据；
3. 在 Lua `on_create()` 中创建或绑定运行时实体；
4. 在 `update()` 中实现玩法规则；
5. 在 `on_destroy()` 中释放脚本创建的实体；
6. 使用 `reload_if_changed()` 验证脚本热更新；
7. 使用 `lua_script_debug_demo` 验证错误诊断。

完整示例参见：

```text
E:\Codex\p2\docs\21-scene-script-demo.md
E:\Codex\p2\engine\crates\game_runner\examples\scene_script_demo.rs
```

场景脚本 Demo 的规则包括玩家、敌人、拾取物、门和触发器。Rust 只准备场景，胜利和失败条件全部由 Lua 实现。

## 7. 脚本热重载

宿主代码使用：

```rust
runtime.reload_if_changed()?;
```

返回值：

- `ReloadStatus::Unchanged`：脚本没有变化；
- `ReloadStatus::Reloaded`：候选 VM 加载成功并替换旧 VM。

热重载建议：

- 初始化放入 `on_create()`；
- 清理放入 `on_destroy()`；
- 不依赖旧 VM 中的闭包、协程和全局状态；
- 语法错误时保留旧 VM；
- 修改脚本后先运行 Demo，再接入窗口运行器。

## 8. 脚本错误排查

使用调试调用捕获运行时错误：

```rust
if let Err(error) = runtime.call_update_debug() {
    eprintln!("{error}");
}
```

读取诊断记录：

```rust
runtime.set_debug_filter(Some("player.lua".to_string()));
for diagnostic in runtime.diagnostics() {
    println!(
        "{}:{} [{}] {} x{}",
        diagnostic.path.display(),
        diagnostic.line.unwrap_or(0),
        diagnostic.phase,
        diagnostic.message,
        diagnostic.occurrences
    );
}
```

诊断系统支持：

- 脚本路径；
- 错误阶段；
- 行号；
- Lua 错误文本和调用栈；
- 重复错误聚合；
- 过滤和清空。

## 9. 常见问题

### Cargo 或 target 目录访问被拒绝

关闭正在运行的 Cargo、IDE 构建任务或旧的 Demo 进程，再重试：

```powershell
.\scripts\verify.ps1 -KeepLog
```

不要删除整个 `target` 目录作为第一选择；先确认没有进程占用文件。

### 窗口没有启动

确认：

- Windows 图形会话可用；
- GPU 驱动正常；
- 没有通过远程桌面禁用硬件图形；
- `artifacts/logs/quality` 和运行日志中的 GPU 错误信息。

### Lua 脚本找不到

运行器默认查找：

```text
game/scripts/main.lua
../game/scripts/main.lua
```

请从项目根目录或 `engine` 目录启动，并确认脚本路径存在。

### Lua 运行时错误

先执行：

```powershell
cargo run -p game_runner --example lua_script_debug_demo --release
```

再检查脚本的函数名、Entity ID 生命周期、Transform 是否存在，以及参数是否为有限非负数。

### 场景文件加载失败

场景格式是版本化文本格式。错误信息包含行号和字段。优先检查：

- `scene_version` 是否为当前版本 `1`；
- 实体 ID 是否重复；
- parent 是否已经存在；
- 记录字段数量和转义字符是否正确。

## 18. M5-01 编辑器启动与项目打开

编辑器当前提供最小项目检查和只读项目状态窗口。建议在项目根目录执行：

```powershell
Set-Location E:\Codex\p2
cargo run --manifest-path engine/Cargo.toml -p editor -- --project E:\Codex\p2 --check
cargo run --manifest-path engine/Cargo.toml -p editor -- --project E:\Codex\p2
```

第一条命令用于无窗口自动检查，成功时会输出项目基线和 `engine/`、`game/`、`assets/`、`docs/` 状态。第二条命令启动编辑器窗口。按窗口关闭按钮退出。

若项目路径不存在，命令会返回非零退出码，并显示具体路径和原因：

```powershell
cargo run --manifest-path engine/Cargo.toml -p editor -- --project E:\Codex\p2\not-found --check
```

当前 M5-01 编辑器只读显示项目状态，不会修改场景、资源或资源数据库。场景树、Inspector、资源浏览器、Play/Stop 和 Undo/Redo 将在后续 M5 任务实现。
