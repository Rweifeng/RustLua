## 1. 背景与目标

RustLua 是单人/小团队、全 Rust、强门文化（`scripts/verify/verify.ps1` + MVP 回归 + 黄金对账）的
2D/3D 引擎，脚本层是 Lua（vendored 补丁版 mlua）。编辑器是 egui/eframe，已具备商业引擎对标的
类型化命令总线、事务/撤销、schema 驱动 Inspector、插件注册表与 GUI 证据 harness（见
[docs/55 编辑器商业引擎对标重构计划](55-编辑器商业引擎对标重构计划.md)、
[docs/58 阶段 0-3 收口](58-编辑器重构阶段0-3收口与验收.md)）。

**目标**：把 AI（大模型）接入编辑器**授权侧**工作流——让 AI 能读场景/组件/控制台/Lua API、
能经确认与撤销安全地改场景与写 Lua 脚本、能跑无头自测，且全程可审计、可回放、可进门。

**非目标（本期）**：游戏内运行时推理（智能 NPC 等）、生成式美术资产管线、绑定单一云厂商。

## 2. 市场方案对标与取舍

2025–2026 年主流引擎的 AI 融合已收敛：**授权侧统一到 MCP（Model Context Protocol）**，
运行时侧各家自造推理引擎。

| 引擎 | 授权侧（AI 驱动编辑器） | 运行时侧（游戏内推理） | 对 RustLua 的启示 |
|---|---|---|---|
| Unity AI（原 Muse） | Assistant（代理式动作：解控制台错误、批量重命名、造 NPC 变体、摆物件）+ Generators（Sprite/Texture/Animation/Sound）+ 官方 MCP Server | Inference Engine（原 Sentis，端侧推理） | 代理式动作 + MCP 是主形态；生成式资产后置 |
| Unreal | Epic 官方实验性 Unreal MCP 插件（进程内起 server） | 第三方为主 | 进程内 MCP server 的范式 |
| Godot | 社区 Godot-MCP（C# addon 暴露编辑器操作为 tools） | 弱 | 小引擎靠 MCP 也能补齐 |
| Unity-MCP（CoplayDev，MIT，47 tool） | 建场景/GameObject、改脚本、管资源、跑测试、构建 | — | **tool 粒度与清单的最佳参照** |
| BlenderMCP | 提示词驱动建模 | — | 生成式资产管线参照 |

**统一架构范式（三层，边界必须分离）**：

```
AI 客户端(Claude/Qoder/Cursor)  ──MCP(JSON-RPC over stdio/TCP)──►  MCP Server
      ──本地Socket──►  引擎桥接层(进程内)  ──Editor API──►  编辑器
```

**取舍结论**：
1. **主轴选授权侧**，运行时推理（Track B）暂缓——它对 wasm/微信体积极不友好，重投入低紧迫。
2. **走 MCP，不自造协议、不绑厂商**——模型无关，Qoder/Claude Code/Cursor/本地 LLM 皆可直连。
3. **RustLua 的结构性优势：单语言单进程**。Unity/Unreal 之所以要"MCP Server(Python) + 引擎桥接(C#/C++)"
   两进程，是因为跨语言；RustLua 全 Rust，可把 MCP server 直接嵌进编辑器进程，省掉进程跳与序列化桥，
   延迟更低、崩溃域可控（已有 `PluginRegistry` 的 panic 隔离，见
   `engine/crates/rustlua-infra/src/editor_plugins.rs:7`，`PLUGIN_API_VERSION=1`）。

## 4. 关键裁定：MCP 先行，能力层建一次双客户端复用

"用 MCP，还是把 AI 直接集成进编辑器？"——**这不是二选一，两者不在同一层。**

- **MCP 模式** = 编辑器只当"工具提供方"，LLM 活在外面（Qoder/Claude Code）。编辑器不含大模型。
- **直接集成** = 编辑器内做 Assistant 面板，自己调 LLM API、自己驱动动作（像 Unity 内置 Assistant）。

**核心认知**：只要把"能力面（typed command → tool）"这一层建一次，两种交付方式都复用它。
MCP 只是传输层，内置面板不过是同一套 tool 的另一个客户端。

| 维度 | MCP 模式 | 直接集成 |
|---|---|---|
| 模型绑定 | 无关，任意客户端 | 需自建 Provider 抽象（易锁厂商） |
| 开发量 | 小（协议面窄） | 大（LLM 客户端+流式 UI+上下文+密钥/成本） |
| 可测/进门 | **可确定性回放**，LLM 在环外 | LLM 在环内 → CI flaky、吃 token，难进门 |
| UX | 有摩擦（外部客户端、切窗口） | 丝滑（编辑器内聊天、拖实体入 prompt） |
| 维护成本 | 低 | 高（模型/UI 长期自养） |

**裁定：MCP 先行（P1/P2 建能力层），内置面板（P3）作为同层薄客户端后加，返工近零。**
只有当目标用户是不会跑 Claude Code 的非技术策划、或要做带品牌的成品特性时，才把内置面板提到首要交付——
但即便如此，它仍坐落在这同一套 tool 层之上，不另起炉灶。

## 6. 总体架构（分层，单一能力层 + 双客户端）

```
┌── 交付层（clients，只说自然语言/调 tool，绝不含引擎逻辑）────────────────┐
│  外部 MCP 客户端                        内置 Assistant 面板 (P3)         │
│  Qoder / Claude Code / Cursor           egui dock tab                    │
│  （已有，当天可连）                      ← 本身就是"进程内 MCP 客户端"     │
└───────────▲───────────────────────────────────────▲─────────────────────┘
    MCP stdio/本地TCP                        进程内直连(同一 registry)
┌───────────┴───────────────────────────────────────┴─────────────────────┐
│  传输层  MCP Server (rmcp / JSON-RPC 2.0)  —— 仅翻译意图，不含业务         │
├──────────────────────────────────────────────────────────────────────────┤
│  ★能力层（地基，只建一次，两种交付共用）  crate: rustlua-editor-ai          │
│    • Tool Registry:  读tool / 写tool / 运行时探针tool                     │
│    • Resource Provider: lua_api_surface + doc桩 / scene schema / project  │
│    • 确认·事务网关:  写动作一律 confirm → transaction（对两客户端同等生效） │
│    • AiBridgePlugin : EditorPlugin  (挂进 PluginRegistry, panic 隔离)      │
├───────────────────────────────┬──────────────────────────────────────────┤
│  引擎执行层（已存在，直接接线）                                             │
│   command_router               │  LuaRuntime                              │
│   typed EditorCommand          │  eval_json (受 ScriptGuard 预算/沙箱)     │
│   + transaction/undo           │  + api_surface 探针                       │
│   + patch_history (逐字段审计)  │  + gui_evidence (让 AI "看见")            │
└───────────────────────────────┴──────────────────────────────────────────┘
   门: ai_tool_surface.json 快照门(先红后刷)  +  确定性回放门(LLM 剥离到环外)
   feature gate: 仅 editor 原生构建启用，永不进 wasm/game/微信包
```

**三条设计红线**：
1. **协议归协议、引擎归引擎、AI 归 AI**：MCP server 只翻译意图，不塞业务；引擎侧不理解自然语言。
2. **写动作一律经 `EditorCommand` + 事务 + 撤销**：AI 绝不直接改 `ProjectDocument`，受既有架构棘轮测试保护。
3. **人在回路**：所有写 tool 默认需编辑器内确认（可配置自动批处理白名单）。

### 7.4 扫描结论

- **33 命令 → 23 写 tool + 8 读 tool ≈ 31 个**，量级与 Unity-MCP（47）相当（对方多覆盖 assets/build/test）。
- **AI 友好度已很高**：多数命令显式携带 `entity`/`name`（`RenameSelection`、`AddComponent`、`SetComponentField`），
  不偷读面板缓冲——接线成本低。
- **4 个必须处理的坑**：① `NewScene` 清 Undo 栈；② `OpenDocument` 脏文档挂起（无头会 pend）；
  ③ 4 个**选区相对**命令（Duplicate/Delete/Reparent/OnSelection）对 AI 脆弱，建议显式 `entities[]` 化；
  ④ `AddCollider3d` 依赖 Inspector 缓冲、`PasteComponents` 依赖剪贴板——**无头不可用**，不暴露或改走通用命令。
- **2 个跨文件副作用**（`SavePrefabToSource`、`UnpackPrefab`）定 T2，永远确认。

## 8. 安全、可审计与确定性（门集成）

这是让方案"能进门"而非"能跑就行"的关键，贴合既有门纪律：

1. **tool 面快照门**：新增 `ai_tool_surface.json`，仿 `lua_api_surface` 的探针+diff 机制。tool 契约漂移
   （新增/删除/改签名）必须先红后刷，防止 LLM 依赖的接口静默变更。
2. **确定性回放门**：把 AI 一次 tool 调用序列录成 fixture（命令 + 期望 patch），CI 里**无 LLM 重放**，
   只验引擎侧执行确定性。AI 功能因此能进 `verify.ps1` 且不吃 token、不 flaky。
3. **`eval_lua` 护栏**：复用现有 `ScriptGuard`（回调预算、错误策略，见
   [docs/64 Lua 脚本错误处置策略](64-Lua脚本错误处置策略.md)）；默认只读；写需确认；超时/死循环熔断。
4. **撤销即安全网**：所有写动作进 `edit_transaction`，一键 `undo`；`patch_history` 提供逐字段审计。
5. **隐私/成本**：LLM Provider 抽象支持本地（Ollama）优先；上下文注入前脱敏；不上传 `.env`/密钥。
6. **feature gate 隔离**：`rustlua-editor-ai` 依赖（如 `rmcp`）仅 editor 原生构建启用，
   **绝不进 wasm/game/微信包**（体积与真机兼容零关联）。

## 10. 关键技术选型与风险

- **MCP SDK**：优先官方 Rust SDK（`rmcp`）而非手搓 JSON-RPC；若其依赖树与 vendored/patched 生态冲突，
  退化为自实现最小 JSON-RPC 2.0（stdio），协议面很小可控。**P1 开工前先做 1–2 天依赖探针**收窄此选型。
- **不做的事**：不自造 AI 协议、不绑单一 LLM 厂商、P1–P4 不碰运行时推理、不让 AI 绕过 typed command 直改文档。
- **主要风险与压制**：
  1. LLM 生成 Lua 幻觉 API → resources 注入真签名 + api_surface 探针 + `eval_json` 校验，三重压制。
  2. wasm/微信体积污染 → feature gate 硬隔离，AI crate 永不进发布包。
  3. tool 契约漂移 → `ai_tool_surface.json` 快照门。
  4. 非确定性难进 CI → 回放 fixture 把"LLM 环节"从门里剥离。
  5. `rmcp` 依赖膨胀拖累 editor 编译时间 → 探针阶段量一次增量编译时间，超预算则自实现最小协议。

## 11. 与现有工程纪律的契合

- **架构棘轮测试**（`src/panels/architecture_tests.rs`，"面板只发类型化动作"）天然覆盖 AI：AI 只发
  `EditorCommand`，与面板同源，不需要为 AI 开特例。
- **插件隔离**：`AiBridgePlugin` 经 `PluginRegistry` 挂载，panic 被 `catch_unwind` 隔离，AI 桥崩溃不拖垮编辑器。
- **门文化**：`ai_tool_surface.json` 快照门与确定性回放门按 `lua_api_surface` / 黄金对账的"先红后刷"范式接入
  `verify.ps1`（见 [docs/34](34-质量门与发布清单.md)、[docs/70](70-性能与测试度量.md)）。
- **文档门**：本文与新计划文件受 `scripts/verify/check-docs.ps1` 约束（编号唯一、单 H1、索引可达、链接可解析）。
