# RustLua 编辑器商业引擎对标重构计划

> 文档性质：基于当前代码与既有编辑器计划的现状复核、目标架构和执行路线。
> 对标对象：Unity 6 Editor、Unreal Engine 5 Editor，并参考 Godot 的节点与 UI 布局工作流。
> 核心原则：借鉴成熟工作流，不复制商业引擎的体量；保留 RustLua 轻量、可读格式、Lua 热更新、2D/3D 同源和快速启动优势。

## 1. 结论

RustLua 编辑器已经具备项目/场景管理、Hierarchy、Inspector、资源浏览、2D/3D Scene View、Gizmo、Prefab、Widget、Play/Stop、Undo/Redo、自动恢复、Console 和发布链路，不应推倒重写。

当前主要矛盾不是“没有编辑器”，而是：

1. `EditorApp`、`scene_view.rs`、`inspector.rs` 和 `actions.rs` 聚合过多职责，扩展成本持续上升；
2. 面板直接读写共享状态，文档、选择、历史、预览和缓存边界主要靠约定；
3. 组件仍大量以字符串读写，Inspector、校验、迁移和运行时 schema 容易漂移；
4. Undo 主要保存完整文档快照，大场景和长编辑会话的内存成本不可控；
5. 资源刷新和部分校验会阻塞 UI，缺少完整的文件监听、增量任务和取消模型；
6. 当前视觉与布局可用，但缺少成熟商业工具的密度、层级、停靠布局和一致反馈；
7. GPU、DPI、resize、面板拖拽和长会话仍缺真实 GUI 自动化证据。

重构目标是把现有编辑器升级为“快速、稳定、可扩展的中型项目生产工具”，而不是追求 Unity/Unreal 的全部功能。

## 2. 扬长避短

### 2.1 应借鉴的商业引擎能力

| 来源 | 借鉴内容 | RustLua 落点 |
|---|---|---|
| Unity | Hierarchy + Scene + Inspector 的对象工作流 | 统一 Selection、Command、PropertyPath，三面板同帧一致 |
| Unity | Prefab Mode、逐字段 Override、Apply/Revert | 独立 Prefab 文档、override diff、选择性应用和回退 |
| Unity | Asset Database、Importer、Profiler | 稳定 AssetId、增量导入、依赖图、Editor Profiler |
| Unity | UI Toolkit / UI Builder | Schema 驱动 Inspector、Widget Designer、样式 token |
| Unreal | 可停靠多窗口、Details、Content Browser | 可保存 Workspace Layout、统一命令与面板框架 |
| Unreal | 异步任务、构建报告、取消与诊断 | Job System、通知中心、结构化 Build/Import Report |
| Unreal | World Partition / One File Per Actor 思路 | 大场景后续采用分块/实体外置，不在首轮强推 |
| Godot | Node 场景、Control Anchor/Container | 保持轻量树模型，完善 Canvas、Anchor、Container |

### 2.2 不应照搬的部分

- 不引入 Unity 式大规模域重载和反射体系；Rust 类型注册与 Lua 热重载更轻。
- 不在近期复制 Unreal 的 World Partition、Blueprint、完整材质图和大型多人协作系统。
- 不用自研 Docking、文本编辑器或图表控件替代成熟库；优先扩展现有 egui/eframe 生态。
- 不把所有编辑器功能做成插件；稳定核心能力先保持内建，扩展 SDK 后置。
- 不把 Scene v2 一次性切为全新格式；采用 typed schema 兼容层、迁移报告和逐组件升级。

### 2.3 必须保留的 RustLua 优势

- Debug 构建和编辑器启动快、内存占用可控；
- 场景与 Prefab 文本确定性、可 diff、原子保存；
- Lua 玩法脚本热重载与 Console 调试；
- 编辑器预览与桌面运行时共享 RuntimeScene；
- 2D/3D 同一实体模型、统一 Transform/Camera 的既定方向；
- Windows 优先、离线、自包含发布链路和严格质量门。

## 3. 产品目标

### 3.1 目标体验

- 第一次打开即可理解：左侧 Project/Hierarchy，中间 Scene/Game，右侧 Inspector，底部 Console/Profiler。
- 高频操作不超过两步：创建、选择、改属性、拖资源、进入 Play、定位错误。
- 所有长任务均异步、可取消、有进度、有最终报告。
- 所有编辑操作可撤销；所有保存可恢复；所有错误可定位。
- 同一对象在 Hierarchy、Scene View、Inspector、Console 中具有一致的身份和选择状态。

### 3.2 性能预算

| 场景 | 目标 |
|---|---|
| 普通点击、选择、属性提交 | P95 < 50 ms |
| 搜索 10k 实体或资源 | P95 < 100 ms |
| Hierarchy 10k 实体滚动 | 60 FPS 目标，最低 30 FPS |
| Scene View 常规项目 | 60 FPS 目标，最低 30 FPS |
| Inspector 1000 对象批改 | UI 不冻结，操作可取消或分帧 |
| 外部文件变化反映到 Project | 2 秒内最终一致 |
| Console 100k 条记录 | 搜索/滚动不冻结主线程 |
| 进入 Play | 建立小/中/大项目 P50/P95 基线，阶段间不得回退 > 10% |
| 长会话 | 8 小时无持续内存增长、无 GPU 资源泄漏 |

绝对值必须在固定硬件和固定 fixture 上复测；正式门槛以历史基线变化为主。

## 4. 目标架构

```text
EditorShell
  -> CommandRouter / Shortcut / Layout / Notification
  -> WorkspaceController
       -> DocumentService
       -> SelectionService
       -> CommandService / History
       -> AssetService / ImportJobs
       -> SceneViewController
       -> InspectorRegistry
       -> PlayController / PreviewService
       -> DiagnosticsService / Profiler
       -> BuildService
  -> Infrastructure
       -> Scene/Prefab Serializer
       -> ResourceDatabase / FileWatcher
       -> RuntimeScene / Renderer
       -> Lua Runtime
       -> assetc / platform adapters
```

### 4.1 边界规则

1. View 只发出 typed action，禁止直接写 `SceneDocument`。
2. 所有持久数据修改必须经过 `CommandService` 和 `Serializer`。
3. `SelectionService` 是选择的唯一事实源；面板不得保留第二套业务选择。
4. `PreviewService` 单独拥有运行时、GPU 纹理、readback 和字体资源。
5. 后台任务只返回不可变结果；主线程在明确提交点合并结果。
6. 引用使用稳定 `AssetId`/实体 ID，路径只作为展示和导入边界。
7. 每个服务定义取消、失败、恢复和 telemetry 契约。

### 4.2 现有文件迁移

| 目标模块 | 当前主要文件 | 做法 |
|---|---|---|
| Workspace/Document | `document.rs`、`recovery.rs`、`actions.rs` | 先加 facade，保持现有方法名，再逐步迁移调用 |
| Selection | `selection.rs`、Hierarchy/Scene/Inspector | 保留已成形模型，清除重复字段和越权写入 |
| Command/History | `history.rs`、`actions.rs` | 快照保底，新增 patch command 与 checkpoint |
| Asset | `resource_browser_state.rs`、`import.rs` | 拆扫描、导入任务、缩略图、DB 提交四层 |
| Scene View | `scene_view.rs`、`scene_interaction.rs` | 先接状态机，再拆 interaction/render/cache/tool |
| Inspector | `inspector_state.rs`、`inspector.rs` | 按组件族拆面板，统一 Schema/PropertyPath |
| Play | `preview_session.rs`、`game_view.rs` | PreviewSession 保持 GPU 所有权，增加 PlayController |
| Diagnostics | `console.rs`、`runtime_debug.rs` | 统一 Diagnostic DTO、环形缓冲和过滤索引 |
| Shell | `main.rs`、`header.rs`、`toolbar.rs` | 最后收缩，避免同时改初始化和所有借用关系 |

禁止一次性重写 `main.rs`、`actions.rs`、`scene_view.rs` 或 `inspector.rs`。

## 5. 功能完善优先级

### P0：生产可靠性与响应速度

- 统一 Workspace、DocumentChange、Selection、Command 提交入口；
- 未保存切换、关闭、Prefab/Widget 跳转全部走同一确认流程；
- 资源扫描、依赖重算、领域校验全部后台化，可取消；
- Hierarchy 使用扁平可见列表和虚拟滚动，消除逐行文档 clone；
- Inspector 改为 dirty 驱动，禁止每帧读 Prefab 或编码所有组件；
- Console 使用有界环形缓冲、增量过滤和虚拟列表；
- Preview panic/致命错误隔离，错误不拖垮编辑器；
- 建立 Editor Profiler：UI frame、面板耗时、命令耗时、扫描队列、导入队列、GPU readback、缓存命中率。

### P1：日常工作流达到商业编辑器水准

- 可保存的停靠布局、默认布局、布局重置和损坏恢复；
- Hierarchy 补齐 Shift 范围选、多选拖拽、F2、Ctrl+D、键盘导航、类型过滤；
- Inspector 完成多选 Mixed Value、搜索、组件菜单、引用选择器、字段校验和自定义 Drawer；
- Gizmo 完成 Local/World/Pivot/Center、角度/网格/顶点吸附和统一事务；
- Prefab 完成嵌套、逐字段 override、Apply/Revert、变体最小闭环；
- Project Browser 完成文件监听、增量导入、移动/重命名引用保持、收藏和依赖视图；
- Play 增加 Pause、Step、Restart、运行态对象只读检查与“选择性保留修改”；
- Console 统一脚本、导入、构建、渲染错误，并支持文件/行/实体定位。

### P2：UI Designer 与专业工具

- 完成独立 Widget 文档、Palette、Hierarchy、Canvas、Inspector 五区工作流；
- Anchor/Offset、VBox/HBox/Grid/Margin/Scroll、Safe Area、多分辨率预览与运行时同源；
- UI 事件、Binding、Button State、Animation 使用结构化 schema；
- Tile Palette、Sprite 切片/九宫格、Collider 编辑、Animation Timeline；
- 资源和场景批量验证、修复建议、语义 diff；
- 基础 CPU/内存/渲染/资源 Profiler 时间线与报告导出。

### P3：扩展与规模化

- 版本化 Editor SDK：Panel、Menu、Command、Inspector、Importer、Gizmo、Build Step；
- 插件 manifest、依赖、禁用、崩溃隔离和兼容测试；
- 大场景分块加载、实体外置或分区资产仅在基准证明需要时启动；
- Git/Perforce 状态、只读/锁定、结构化合并辅助；
- 远程设备预览、构建缓存或协同能力按实际项目需求立项。

## 6. UI/UX 设计规范

### 6.1 视觉方向

采用中性深灰工作台，不使用大面积蓝紫渐变、装饰卡片或营销式布局。颜色只表达状态：蓝色为选择/主操作，绿色为成功，琥珀为警告，红色为错误；2D/3D 轴保持 X 红、Y 绿、Z 蓝。

- 密度：默认紧凑，支持 Compact/Comfortable 两档；
- 圆角：2-6 px，避免大圆角；
- 间距：4/8/12/16 px token；
- 字体：正文 13-14 px，面板标题 14-16 px，不随窗口宽度缩放；
- 图标：统一单色图标库，工具按钮优先图标并提供 tooltip；
- 状态：hover、active、selected、disabled、error 必须可区分；
- 空状态：只给下一步动作，不展示冗长说明；
- 面板内不嵌套装饰卡片，以分组标题、分隔线和折叠区建立层级。

### 6.2 布局与交互

- 顶部只保留菜单、Play/Pause/Step、工作区和全局状态；视图工具放入 Scene View 本地工具栏；
- Project 与 Hierarchy 支持标签停靠，不固定为永久左右栏；
- Inspector 支持锁定对象和多实例；
- Console/Profiler/Build Report 共用底部文档区；
- 命令搜索提供“功能名 + 快捷键 + 当前可用状态”；
- 长任务显示全局进度，但不弹阻塞模态框；失败进入通知中心和 Console；
- 危险操作使用可撤销优先，只有不可恢复操作才确认。

### 6.3 可访问性

- 100%/150%/200% DPI 不重叠、不裁字；
- 键盘可完成选择、创建、重命名、复制、删除、保存、Play 和面板切换；
- 状态不能只依赖颜色，必须配合图标或文本；
- 所有图标按钮具有 tooltip 和可读名称；
- 中文、英文和长路径均做省略与完整悬停显示。

## 7. 分阶段执行计划

### 阶段 0：基线与契约，3-5 人日

交付：编辑器性能 fixture、GUI smoke 清单、服务依赖图、状态不变量、当前内存/GPU/启动/Play 基线。

验收：固定小/中/大工程可重复测量；Windows 100/150/200% DPI 截图；30 分钟 Play/Stop 循环和 8 小时 soak 有报告。

### 阶段 1：状态内核与性能止血，8-12 人日

交付：WorkspaceService、CommandService facade、选择单一事实源；后台资源刷新/校验；Hierarchy/Console 虚拟化；Inspector dirty 驱动；历史内存预算。

验收：文档切换、Undo/Redo、Prefab、Play/Stop 状态一致；主线程不执行递归资源扫描；10k 实体/100k 日志仍可交互；现有场景格式不变。

### 阶段 2：Scene View 与 Inspector 解耦，10-15 人日

交付：`scene_interaction` 接入生产路径；拆分 2D/3D/Widget 工具控制器；Component Schema/PropertyPath；组件族 Inspector；Gizmo 完整事务。

验收：绘制与交互可独立测试；一次拖拽一条 Undo；2D/3D picking 与运行时投影一致；新增组件不再修改巨型 match；3D golden 不回退。

### 阶段 3：资源、Prefab 与工作区体验，10-15 人日

交付：FileWatcher、增量 AssetGraph、稳定 AssetId；可保存停靠布局；Prefab override diff、选择性 Apply/Revert；Pause/Step/Restart；统一诊断跳转。

> 其中"可保存停靠布局"与资产拖放已由 **M27-00/01** 交付（2026-10-02，见
> `tasks/done/M27-00-dock化基线与多标签面板布局.md`、`tasks/done/M27-01-资产拖放.md`）；
> "是否为此更换更富表现力的 UI 框架"已由 **M27-03** 书面裁定为**不迁移**（[docs/02](02-technical-decisions.md)）。

验收：资源移动后引用不丢；外部变化 2 秒内可见；布局 100 次保存/恢复；Prefab 往返 hash 一致；导入失败可重试且不阻塞 UI。

### 阶段 4：Widget Designer 与专业工具，12-20 人日

交付：独立 Widget 文档、完整 Canvas/Anchor/Container、UI 动画时间线；Tile/Sprite/Collider 专业面板；基础 Profiler。

验收：编辑器与运行时布局像素级对拍；多分辨率和 Safe Area golden；UI 资源可作为 Prefab/Widget 复用；Profiler 开销不超过主线程 2%。

### 阶段 5：扩展 SDK 与规模化，按需立项

交付：版本化插件 SDK、外部示例插件、VCS/大型场景原型。

启动条件：核心模块边界稳定，且至少两个真实项目提出相同扩展需求；不得为了“像商业引擎”提前建设。

## 8. 质量门

每个阶段必须同时交付：

1. 单元测试：Command、Selection、Schema、序列化、资源依赖、迁移；
2. 集成测试：创建项目 -> 导入 -> 建场景 -> 编辑 -> Undo/Redo -> 保存 -> 重开 -> Play -> Build；
3. GUI smoke：DPI、resize、拖放、停靠、输入焦点、多选、弹窗；
4. GPU 实机：2D/3D/Widget View、readback、设备丢失或初始化失败；
5. 性能前后报告：P50/P95/P99、内存峰值、GPU 资源数、任务队列长度；
6. 兼容报告：旧场景、Prefab、Lua、发布流程和 3D golden；
7. 回滚说明：feature flag、旧路径保留范围、迁移失败恢复方式。

硬门槛：

- 编辑交互 P95 回退 > 5% 不合并；
- 内存峰值或进入 Play 时间回退 > 10% 必须专项评审；
- 数据损坏、Undo 不等价、引用丢失、3D golden 回归直接阻断；
- 后台任务无取消/失败反馈不得进入默认路径；
- 新 UI 在 100/150/200% DPI 存在重叠或裁字不得封板。

## 10. 最终完成定义

重构完成不是代码文件变小，而是以下事实同时成立：

- 用户能快速完成创建、导入、搭场景、调属性、调试、Play 和发布；
- UI 具备一致层级、响应状态、停靠布局和 DPI 适配；
- 面板不直接修改领域数据，所有操作可追踪、可撤销、可恢复；
- 大场景、大资源库和长日志不会冻结主线程；
- Inspector、Prefab、Widget 和资源管线由 typed schema/稳定 ID 驱动；
- Preview、Game 和 Build 使用一致的运行契约和诊断；
- 旧项目可无损打开，迁移失败不覆盖源文件；
- GUI、GPU、性能和长会话进入持续质量门。
