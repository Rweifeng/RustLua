  13583 字节逐位相同）。流程账：一条"工作树绿"证明不了提交树。

## Unreleased — 用户级编辑器设置 `~/.rustlua`：服务商与 API Key 不再每次重设（2026-10-25）

- **服务商设置搬到用户级**：地址/模型/max_tokens 从工程 `.cache/editor/layout.json` 迁到
  `<用户主目录>/.rustlua/editor.json`。此前它跟着工程走，不带 `--project` 启动或换工程就会看起来
  “全丢了”；现在跨工程、跨启动都是同一份。`RUSTLUA_HOME` 可覆盖目录（便携版/测试）。
- **API Key 首次可持久化**：单独存 `~/.rustlua/assistant.key`，Windows 用 DPAPI
  （`CryptProtectData`）绑定当前用户账户，拷到别的账户/机器解不开；解密失败会在控制台说明原因
  而不是静默当没填。非 Windows 平台退回 0600 权限的明文文件。`editor.json` 与工程布局都不含 Key。
- **旧工程值只读迁移**：布局加载器仍读 `assistant` 段，作为旧工程的迁移来源；用户级文件一旦
  提供设置（或本进程保存过一次），工程布局不再覆盖它，新版本也不再往工程里写助手段。
- **保存时机**：文本输入稳定 500ms 后合并写一次；关窗时补最后一笔。写盘失败进控制台提示，
  下次改动再重试（不每帧重试打满磁盘）。
- **证据**：`editor` lib 4 条 `user_config` 测试（往返/未知键保留/损坏回落/密文不含明文）；
  `assistant_settings_autosave_waits_for_typing_to_settle` 改为断言用户级文件与 `assistant.key`。
- **边界**：本次只迁移助手服务商；面板密度等其余偏好仍按工程布局保存，`editor.json` 已预留
  顶层扩展位（未知键原样保留）。Key 仍不进模型上下文与命令行参数。

  所以 tool 回 `{"result":"queued","target_root":…}`，并要求用 `get_project_config` 的 `root`
  轮询确认——在主线程阻塞等会冻住事件循环，进度反而永不落地。四条前置在排队前就判掉：目标不是
  工程、目标就是当前工程、后台任务在跑（`start_import` 对它静默 return）、已挂着一条待确认的文档
  操作；脏文档沿用同一个确认网关挂起等人裁决，无头策略按 T3 直接拒绝。
- **买不到的部分**：切换是会话级全局的，两个工程不能同时在线；落地时 `apply_progress_result`
  会 `history.clear()`，旧工程的 Undo 栈随之清空（脏文档已被前一条挡住，但已保存未 Undo 的栈救不回来）。
- **活体双向读数**（Qoder 连接器拉起 `editor --project examples/game_jhyt --mcp-stdio`）：无人批准时
  `open_project` 在 30.0s 回 `isError=true` 的「已排队」，前后两次 `get_project_config` 的 `root` 逐字节
  相同——确认门没有放水；在编辑器「AI 动作确认」里点批准后，同一条 tool 当帧执行、约 12s 后台导入落地，
  `root` 换成 `examples/game_api`，即一个 stdio 会话确实服务了两个工程。
- 复现：`cargo test -p editor --bins open_project`（4 条前置/排队/挂起判据）；快照门
  `AI_TOOL_SURFACE_BLESS=1 cargo test -p rustlua-editor-ai tool_surface`；活体负对照
  `node target/m78-negative.mjs`（本机探针脚本，在 gitignored 的 `target/` 下、不入库；需 30s，且不要点弹窗）。
