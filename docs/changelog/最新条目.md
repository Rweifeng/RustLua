## Unreleased — P1：ScrollView 接入导出链、门输出区分环境缺失（2026-10-28）

- **一句话**：UI Studio 的 `list` 一直导出 `ScrollView`，但运行时 typed scene 侧没有它——
  opaque 映射认不出、UI codec 表没装、示例工程也没覆盖。本批把它接进 `ComponentId::ALL`
  与 UI codec 表（渲染层 6 + UI 层 15 = 21），`api_ui.scene` 补一个可滚动的三行列表，
  并重算布局 golden（仅 `api_ui` 三行，2 → 16 节点）。
- **为什么不静默**：`ScrollView` 是**已知名字**，装表缺失时 typed scene 会硬错而不是退回原始层；
  codec 校验拒绝 `horizontal=sometimes` 这类非法值。示例场景同时被"每个运行时组件都要在场景里
  出现"与 typed-scene 逐组件对账两道门锁住，导出链断裂会直接红。
- **门输出**：`verify-webgl-bundle.ps1` 与 `verify-webgl-eh.ps1` 的 no_bundle 分支分别补
  `webgl_bundle_blocked` / `webgl_eh_blocked reason=no_bundle`——直跑也能看出是"本机没有合格
  产物"而非代码红；exit 0/1/3 契约不变。

## Unreleased — M79-04：PC 宿主的输入法事件接到脚本（2026-10-26）

- **一句话**：打字和按键是**两条通道**，此前引擎只有后一条。`WindowEvent::KeyboardInput` 给的是
  "哪个物理键被按下"，输入法给的才是"用户想输入什么字"——Windows 上它根本不发
  `CharacterReceived`，中文只以 `Ime::Preedit`（组合串）+ `Ime::Commit`（上屏词）下发。
  本批把后一条通道接通：宿主的 IME 事件写进 `InputSnapshot` 的两个文本槽，脚本用**一个新名字**
  `input.text_events(command)` 既能读（`composition` / `committed[]` / `capturing`）也能注入
  （`capture` / `composition` / `commit`），并让"要不要收字"由脚本声明、宿主据此向操作系统开机。
  API 面 42 张表不变、函数 **308 → 309**。
- **从 winit 0.30.13 源码核到的事实**（判据都写进了 `game_app.rs` 的函数文档，不是猜的）：
  ① 变体是 `Enabled / Preedit(String, Option<(usize,usize)>) / Commit(String) / Disabled`，
  **没有** `Ime::Composition`；② `Window::ime_allowed` **默认 false**，不显式 `set_ime_allowed(true)`
  就一个 IME 事件都收不到，而本批只在**读数变化时**下发一次（不每帧调）；
  ③ Windows 下操作系统自绘的组合框被抑制，所以"组合串看得见"只能由**引擎自己绘制**——本批没做；
  ④ 拼音的到达形状是 `Preedit("a") → Preedit("a b") → Preedit("",None) → Commit("啊不")`，
  **提交前会先空一次组合串**，且 `push_text_commit` 刻意同时清空 `text_preedit`（两条规则叠起来，
  脚本侧看到的就是"committed 到手时 composition 已经是 nil"）；`Disabled` 要清残留，否则切走窗口
  时那截拼音会挂在 HUD 上不走；⑤ `KeyEvent` 的六个字段里**没有 `modifiers`**，修饰键只在独立的
  `WindowEvent::ModifiersChanged` 里下发 ⇒ 宿主自己留一份，Ctrl+A 才判得出"全选命令"而不是塞一个 `a`；
  ⑥ `KeyEvent` 还有**私有字段** `platform_specific`，结构体字面量在 winit 之外写不出来（E0063）
  ⇒ 收字规则抽成 `KeyPress { logical_key, pressed, synthetic, modifiers }` 这个小结构体，
  单测因此能不起窗口就覆盖五条排除规则；⑦ `is_synthetic` 是切回窗口时补发的旧按键，不是新输入 ⇒ 跳过。

  **脚本侧的意图**，跨帧——`HostInput::set_input` 里让新快照显式继承旧值（与虚拟键同构），

- **文档级四项必须显式记住**（`DocumentAnchor`：`path`/`dirty`/`revision`/`disk_signature`）。它们里有两个
  被 `SceneDocument` 的 `PartialEq` 刻意排除，而 `dirty` 决定 E06 换文档闸门、`revision` 决定外部改动检测——
  撤销时把它们改了就不是"只省内存"，是改语义。合并同理：只并**同目标同字段**（`same_slot`），只按实体配对
  会把同一实体上的 `Quad` 与 `Transform` 并成一条、先前终点被后一次覆盖——那是丢编辑，不是合并。

  重做后逐字段比，含被 `PartialEq` 排除的那两项；并断言两条栈深、`undo_signature()` 与 Undo 菜单标签序列一致，

  提交与 native 同步回读；无 compute 时所有入口返回 `ComputeError::Unsupported`，不 panic、
  不静默空转。第一个真实消费者是 GPU 粒子：状态在 storage buffer 里积分，compute 直接写
  `WorldSpriteVertex` 到 `STORAGE | VERTEX` 缓冲，渲染侧零回读，新增 `RenderPass::Particle`
  （`ALL` 9→10）。默认仍是 CPU 粒子，GPU 档由 `Renderer::configure_gpu_particles` 显式打开，
  `set_compute_enabled(false)` / WebGL2 / 微信上回到 CPU 且画面逐字节不变。10k 粒子 × 120 步
  CPU/GPU 最终位置差 `9.155e-5 < 1e-4`；验收命令
  `cargo run -p game --example jhyt_m95_gpu_particles`（同门另报 50k × 60 步的 CPU 迭代与
  GPU command 提交读数，独立 GPU 时间因本机 `timestamp=false` 不可得）。连续发射（`rate > 0`）在 v1 明确拒绝，
  场景/Lua 的 `mode=cpu|gpu` 接线与 50k 基准留给 P3-R07。
