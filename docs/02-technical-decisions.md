# 技术决策记录

## 使用说明

所有会影响架构、公共 API、资源格式、依赖或发布平台的决策都写入本文件。旧决策不删除，通过状态标记为 Accepted、Superseded 或 Rejected。

## ADR-0001：采用 Rust 作为引擎核心

- 状态：Accepted
- 日期：2026-08-20
- 原因：需要接近 C++ 的性能、无垃圾回收运行时、较强的内存和并发安全性。
- 代价：游戏行业生态和主机平台支持不如 C++，需要更多自行建设。
- 回滚：保留 C ABI/插件边界，避免未来接入主机或特定 C++ SDK 时重写全部引擎。

## ADR-0002：采用 Lua 作为游戏脚本

- 状态：Accepted
- 日期：2026-08-20
- 原因：运行时轻量、嵌入简单、适合玩法热重载和快速迭代。
- 代价：静态类型和 IDE 能力弱于 C#，需要 API 封装和类型提示。
- 回滚：脚本边界以稳定句柄和命令 API 为中心，未来可增加另一种脚本语言。

## ADR-0003：Windows 优先，2D 优先

- 状态：Accepted
- 日期：2026-08-20
- 原因：降低独立开发者的首发复杂度，先用垂直切片验证引擎价值。
- 代价：早期不覆盖主机、移动和完整跨平台需求。

## ADR-0004：先使用成熟第三方库

- 状态：Accepted
- 日期：2026-08-20
- 范围：wgpu、Rapier、mlua、egui、Serde、tracing 等。
- 原因：独立开发者不应重复实现图形后端、物理、音频和序列化基础设施。
- 约束：通过适配层接入，锁定版本并记录许可证。

## ADR-0005：编辑器采用独立 crate，egui/eframe 起步

- 状态：Accepted
- 日期：2026-08-20
- 范围：M5 编辑器 MVP
- 决定：编辑器作为独立 `editor` crate，第一版采用 `egui` + `eframe`；编辑器通过 `engine_core` 公共 API 访问场景、资源和脚本。
- 原因：独立 crate 可以隔离编辑器依赖和运行时发布包；egui/eframe 适合独立开发者快速完成 Windows 优先的工具界面，并可复用现有 Rust 代码。
- 代价：需要处理 eframe 与现有 wgpu/winit 版本兼容；GUI 自动化能力弱于无窗口测试。
- 约束：先实现无窗口项目检查和状态模型，再接入复杂 GUI；依赖版本锁定在 Cargo.lock；若依赖冲突，回滚为独立 winit + engine_core 状态模型，不修改 M4 场景格式。
- 重新评估条件：M5-01 最小窗口无法构建、启动稳定性不达标，或编辑器与运行时依赖无法共存。

## ADR-0006：M8 采用 glTF 2.0 作为 3D 交换格式

- 状态：Accepted
- 日期：2026-08-22
- 范围：M8 轻量 3D 的 Mesh、材质、纹理、节点和动画导入。
- 决定：首版支持 `.gltf` 和 `.glb`，使用成熟的 glTF 解析库；导入结果先转换为 `engine_core` 自有的 CPU 资源模型，再由渲染层上传 GPU 资源。
- 原因：glTF 2.0 适合运行时分发，`.glb` 可将测试资产和二进制数据封装为单文件，成熟解析库能降低 accessor、buffer、材质和动画边界错误。
- 支持范围：静态 Mesh 的 POSITION/NORMAL/TEXCOORD_0、索引、基础材质纹理、节点层级；后续增加一个 skin 和动画状态。
- 非目标：首版不支持任意 glTF 扩展、 morph target、复杂材质扩展、压缩 Mesh 和自研解析器。
- 兼容：assetc 以导入器版本控制缓存；场景格式通过版本号和迁移保持 `v0.7` 旧 2D 场景可加载；不支持的扩展必须报告文件、节点或 primitive 上下文并返回失败。
- 重新评估条件：目标资产无法由标准 glTF 2.0 表达，或解析库无法在当前许可证和 Windows 发布约束下使用。

## ADR-0007：M8 3D 坐标、单位和深度约定

- 状态：Accepted
- 日期：2026-08-22
- 范围：Math3D、Transform3D、Camera3D、Mesh 和光照。
- 决定：世界坐标使用右手系，+Y 向上、+Z 指向观察者；长度单位为米；矩阵按列向量语义组合，渲染使用 `clip = projection * view * model * position`；透视相机使用弧度 FOV 和正的 near/far 平面。
- 决定：深度纹理使用 `Depth32Float`，清除值为 1.0，比较函数为 `LessEqual`；3D pass 使用深度测试和写入，2D pass 保持现有无深度行为。
- 决定：颜色纹理按 sRGB 采样，法线/金属度/粗糙度和深度数据按线性数据处理；near 必须大于 0，far 必须大于 near。
- 原因：约定简单、适合 wgpu 默认坐标转换和常见 glTF 资产，且可用纯 CPU 数学测试验证，不依赖 GPU 截图才能发现基本错误。
- 代价：glTF 的节点坐标需在导入边界明确转换；阴影和后续反向深度不在首版范围。
- 重新评估条件：实测资产坐标转换普遍需要特殊例外，或 wgpu 后端验证显示深度范围与该约定不兼容。
