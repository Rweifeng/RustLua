# 技术决策记录

## 使用说明

所有会影响架构、公共 API、资源格式、依赖或发布平台的决策都写入本文件。旧决策不删除，通过状态标记为 Accepted、Superseded 或 Rejected。

## ADR-0001：采用 Rust 作为引擎核心

- 状态：Accepted
- 日期：2026-08-20
- 原因：需要接近 C++ 的性能、无垃圾回收运行时、较强的内存和并发安全性。
- 代价：游戏行业生态和主机平台支持不如 C++，需要更多自行建设。
- 回滚：保留 C ABI/插件边界，避免未来接入主机或特定 C++ SDK 时重写全部引擎。

## ADR-0002：采用 Lua 作为游戏脚本

- 状态：Accepted
- 日期：2026-08-20
- 原因：运行时轻量、嵌入简单、适合玩法热重载和快速迭代。
- 代价：静态类型和 IDE 能力弱于 C#，需要 API 封装和类型提示。
- 回滚：脚本边界以稳定句柄和命令 API 为中心，未来可增加另一种脚本语言。

## ADR-0003：Windows 优先，2D 优先

- 状态：Accepted
- 日期：2026-08-20
- 原因：降低独立开发者的首发复杂度，先用垂直切片验证引擎价值。
- 代价：早期不覆盖主机、移动和完整跨平台需求。

## ADR-0004：先使用成熟第三方库

- 状态：Accepted
- 日期：2026-08-20
- 范围：wgpu、Rapier、mlua、egui、Serde、tracing 等。
- 原因：独立开发者不应重复实现图形后端、物理、音频和序列化基础设施。
- 约束：通过适配层接入，锁定版本并记录许可证。
