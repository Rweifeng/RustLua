# 手柄设备接入与输入契约（M20-06）

本文记录引擎的手柄设备层：抽象接口、按钮/轴契约、死区与判定阈值语义、Windows 后端、
测试方式，以及与原计划的 gilrs 依赖差异。

## 1. 分层

```
设备层（本任务）          抽象层（已存在）                      玩法/脚本层
host::gamepad::poll  ---> InputSnapshot::gamepad_button_event  ---> Lua input.* / ActionMap
                          InputSnapshot::set_gamepad_axis            Binding::GamepadButton/Axis
```

- `host/gamepad.rs`：`GamepadBackend`（`poll() -> GamepadFrame`）、`GamepadFrame`、
  `XInputBackend`（Windows）、`UnsupportedBackend`（其他平台）、`FakeBackend`（脚本化）、
  `GamepadPoller`（把帧写进 `InputSnapshot`）。
- 宿主接入点：`RuntimeScene::run_script_steps` 在每帧克隆宿主输入后调用
  `gamepad.poll_into(&mut step_input)`，因此**正式 game、编辑器 Play 预览与 headless
  共用同一路径**；无设备时返回未连接帧，快照与传入值等价，headless 行为不变。
- 测试/验收注入：`RuntimeScene::set_gamepad_backend(Box<dyn GamepadBackend>)`、
  `gamepad_connected()`、`gamepad_backend_name()`。

## 2. 按钮与轴契约（写入后只增不改）

| 按钮索引 | 语义 | | 轴索引 | 语义 |
|---|---|---|---|---|
| 0 | A / Cross | | 0 | 左摇杆 X（右为正） |
| 1 | B / Circle | | 1 | 左摇杆 Y（**上为正**，与 WASD `vertical` 一致） |
| 2 | X / Square | | 2 | 右摇杆 X |
| 3 | Y / Triangle | | 3 | 右摇杆 Y（上为正） |
| 4 | LB | | 4 | LT（0..1） |
| 5 | RB | | 5 | RT（0..1） |
| 6 | LT（数字，≥0.5 置位） | | | |
| 7 | RT（数字，≥0.5 置位） | | | |
| 8 | Back / Share | | | |
| 9 | Start / Options | | | |
| 10 | L3 | | | |
| 11 | R3 | | | |
| 12..15 | DPad 上 / 下 / 左 / 右 | | | |

与 `ActionMap::with_defaults()` 一致：`GamepadButton(0)`=确认（confirm）、`GamepadButton(1)`=取消（cancel）、
轴 1 双向绑定 `ui_up`（正向）/`ui_down`（负向），轴 0 双向绑定 `ui_right`/`ui_left`，
DPad 按钮 12..15 绑定同名的 `ui_up/down/left/right`。

**死区 ≠ 判定阈值**：死区（摇杆默认 `0.15`、扳机默认 `0.05`）消除回中漂移并在死区外按比例重映射；
动作判定阈值是轴数字态的**进入阈值** `AXIS_DIGITAL_ON`（默认 `0.5`，M22/W3 起可由
`[input] nav_threshold` 配置），退出阈值 = 进入 − `AXIS_HYSTERESIS`（`0.1`）形成滞回，
避免杆位在阈值附近抖动时反复产生按下/松开边沿。

死区自 **M20-08** 起可配置：`GamepadDeadzone { stick, trigger }`（非有限值/越界值回落默认并钳制到
`0.0..MAX_DEADZONE`），运行期经 `RuntimeScene::set_gamepad_deadzone` 注入，持久化在
`settings.toml` 的 `[input] stick_deadzone` / `trigger_deadzone`；引擎默认值保持不变，
编辑器「项目设置 → 输入」面板可调。注意 `input.save_settings()`（游戏内改键保存）**不会**覆盖
这两个键——只在编辑器路径写入，避免玩家改键时被面板默认值回冲。

**摇杆死区是径向的（M22/W3）**：`apply_stick_deadzone_radial(x, y, dz)` 按 `(x, y)` 的**模长**
判定并保持方向（死区内归零，死区外按 `(mag - dz) / (1 - dz)` 缩放），消除逐轴死区造成的
「斜向比正向灵敏」。单轴函数 `apply_stick_deadzone` 仍保留（单轴绑定与测试用）。

## 2.1 轴的数字边沿与菜单连发（M22/W3）

`GamepadPoller` 除模拟量外还维护**每个轴方向的数字态**：

- 越过进入阈值的那一帧写一次按下边沿（`InputSnapshot::gamepad_axis_event`），回到退出阈值
  以下的那一帧写松开边沿；其余帧只写数字态（与按钮的「按住每帧写全量、边沿只在变化帧」同一套约定）。
  因此 `input.action_pressed("ui_up")` 对键盘方向键、DPad 与左摇杆**同义**。
- 轴值仍是模拟量，`input.action_axis(...)`/`input.pad_axis(...)` 不受影响；
- 没有设备数字态的路径（测试/宿主直接 `set_gamepad_axis`）回落到 `|value| >= 0.5` 判定且
  **不产生边沿**，M20 的既有语义不变；
- 断连时释放仍在数字按下的轴方向并清零轴（不粘杆）；
- 菜单连发由引擎按**毫秒**执行（`input.action_repeat`：边沿一步 + 模拟量按住超过
  `nav_delay_ms` 后每 `nav_repeat_ms` 一步；数字键/DPad 按住不连发），细节见
  [输入动作映射与设置持久化](35-输入动作映射与设置持久化.md) §7。

`InputSnapshot::last_device()`（Lua `input.last_device()`）在**真实按下边沿**时更新为
`keyboard`/`gamepad`，供 UI 提示选文案；空闲帧不上报，因此插着手柄用键盘玩仍显示键鼠说明。

## 3. Windows 后端（XInput）

`XInputBackend` 经 `windows-sys`（`Win32_UI_Input_XboxController`）调用 `XInputGetState`：

- **逐槽位采样**（M22/W2）：`poll_all()` 采样 0..3 号用户，各槽位独立返回
  `Option<GamepadFrame>`（未连接为 `None`）；`poll()` 仍返回**第一个已连接**设备（保持
  M20-06 语义，供 `GamepadPoller::poll_frame` 与默认 `poll_all` 使用）；
- `wButtons` → 契约按钮索引（纯函数 `buttons_from_flags`，无需设备即可测试）；
- 摇杆 `-32768..32767` → `-1..1`，扳机 `0..255` → `0..1`，再各自过死区（摇杆**径向**）；
- 扳机模拟量 ≥0.5 时同步置位数字按钮 6/7；
- **震动**（M22/W2）：`set_rumble(slot, low, high)` 调用 `XInputSetState`，强度 0..1 → 0..65535；
- 无设备/驱动缺失时静默降级（不报错、不影响键鼠路径）。

### 3.1 槽位与热插拔（M22/W2）

`GamepadPoller` 逐槽位跟踪设备状态，并维护一个**粘性**活动槽位：

- 选择顺序：`set_active_slot` 显式指定 → 粘住当前活动槽位（若仍连接）→ 第一个已连接槽位。
  粘性避免了「后来接入的低编号设备抢走正在用的手柄」以及随之而来的假释放/假按下；
- 切换或拔线时，**释放旧槽位仍按住的按钮与轴方向**（不粘键），并逐槽位打印
  `[gamepad] connected` / `disconnected; buttons and axes cleared`；
- 默认行为与 M20-06 逐帧等价（单设备场景下活动槽位就是那台设备）；
- **未接线到玩法层的部分**：`InputSnapshot` 仍只有一份按钮/轴状态（活动槽位），因此
  **本地双人（各玩家独立输入）尚未支持**——需要把快照扩展为「每槽位一份」并让动作层按玩家
  取用。这是**已裁定的不做项**（M22 §9 第 4 条：只做热插拔不串扰 + 震动 + 槽位跟踪），
  不是遗漏；将来要做时的入口见 [`tasks/done/M22-输入层收口.md`](../tasks/done/M22-输入层收口.md)
  §11「仍未完成」（该专题 W1–W5 已全部落地，总纲已归档到 `tasks/done/`）。

### 3.2 震动（M22/W2）

- Lua `input.rumble(low, high, ms)` 只**登记请求**（`ScriptState::rumble_request`），
  `RuntimeScene::run_script_steps` 在帧末取走并交给设备层（主机不与 Lua 共享 poller），
  编辑器 Play 预览与独立 game 同一条路径；
- `GamepadPoller::rumble(low, high, duration_ms)` 设置强度并记下到期时间（上限
  `MAX_RUMBLE_MS = 5000`）；`duration_ms = 0` 表示立即停止；
- XInput 的震动是「设置即持续」，因此**到期归零由 `poll_into` 每帧检查**（不依赖调用方
  记得清除）；无设备时静默忽略；
- headless 验收用 `SlotBackend`（多槽位脚本后端 + `RumbleLog` 共享记录）覆盖，见 §5。

## 4. 与原计划的 gilrs 依赖差异（重要）

原任务计划「落地 `gilrs` 依赖并把设备轮询封装成平台无关层」。实施时发现**本机离线环境无法解析该依赖**：

```
$ cargo metadata --offline --format-version 1
error: no matching package named `gilrs` found
```

尽管 `~/.cargo/registry/cache/.../gilrs-0.11.2.crate` 与 `gilrs-core-0.6.8.crate` 已缓存，
且 `~/.cargo/config.toml` 已把 crates.io 替换为 USTC 镜像，但**索引缓存不完整**
（`index/mirrors.ustc.edu.cn-*/` 下只有 gilrs 的部分 `.cache` 条目，缺少可解析的索引），
离线解析仍失败（用一次性探针工程验证过 sparse 与 git 两种镜像配置均失败）。
联网后可执行 `cargo add gilrs@0.11` 完成落地。

因此本任务改为**零新增依赖**的 Windows 原生 XInput 实现：既满足「真实拿到手柄设备状态」，
又保持 `GamepadBackend` 抽象——后续要跨平台（Linux/macOS）或统一到 gilrs 时，新增一个
`GilrsBackend` 实现即可，无需改动上层（`GamepadPoller`/`RuntimeScene`/`ActionMap`/Lua）。

## 5. 测试与验收

自动（headless，`cargo test -p engine --lib host::gamepad`，13 项）：

- 死区边界（死区内=0、死区外按比例、极值 ±1、扳机阈值）；
- 按钮位 → 契约索引映射；轴方向（左摇杆上推为正）与扳机数字按钮；
- **快速按下/松开在逻辑帧边界前不丢**（`poller_preserves_edges_and_held_state`，
  并断言 `confirm` 动作的 press/release 边沿被保留到 `finish_frame`）；
- 轴驱动动作绑定（默认 `ui_up`/`ui_down` 与一对自定义 `stick_up/stick_down` 的合成轴）；
- 断连与失焦清空按钮与轴（不粘键）；
- 无设备不产生输入、不 panic；平台默认后端名称（Windows=`xinput`）；
- M22/W3 追加：`poller_synthesizes_axis_press_edges_with_hysteresis`（轴边沿 + 滞回）、
  `poller_axis_hold_does_not_repeat_edges_across_frames`（按住不重复边沿）、
  `poller_releases_axis_directions_on_disconnect`（拔线释放轴方向）、
  `axes_use_radial_stick_deadzone`（径向死区按模长、不越界）；
- M22/W2/W4 追加：`slot_switch_releases_old_slot_state_and_adopts_new_device`（槽位切换释放旧状态）、
  `active_slot_is_sticky_and_explicit_selection_wins`（粘性 + 显式指定）、
  `rumble_sets_levels_then_expires`（震动强度与到期归零）、
  `last_frame_shares_sampled_frame_without_consuming`（共享帧不消费）、
  以及运行时层 `zero_step_frame_does_not_drop_gamepad_edges`（0 步帧不吞边沿）、
  `lua_rumble_reaches_device_layer`（Lua 震动请求到达设备层）。

动作层侧（`cargo test -p engine --lib core::input`）另有轴边沿驱动动作、径向死区、
`last_device` 与时间制连发的单测，清单见 `docs/35` §6。

手工（需要实机手柄，本环境无设备**未执行**）：

```powershell
cargo run -p game -- --project ../examples/game_jhyt
```

插拔手柄各一次：日志出现 `[input] [gamepad] connected` / `disconnected; buttons and axes cleared`，
不 panic、不粘键；`--log-filter input=debug` 可看到逐按钮变化（M22/W3 起还打印逐轴方向的
`[gamepad] axis` 变化帧）。

## 6. 已知限制

- 未接入浏览器 Gamepad API（WebGL/WASM 目标手柄不可用）。
- **本地双人未接线**：设备层已逐槽位跟踪并可显式选择活动槽位（见 §3.1），但
  `InputSnapshot` 只有一份按钮/轴状态，玩法层还拿不到「每玩家一份」的输入。
- 手柄按键编号依赖 XInput 固定映射；gilrs 的 SDL 映射数据库（更多设备型号）待联网后落地。
- 死区常量 `STICK_DEADZONE`/`TRIGGER_DEADZONE` 仍是**默认值来源**；玩家可配置版本（`GamepadDeadzone`
  + `settings.toml` 的 `[input]` 两个键 + 编辑器「项目设置 → 输入」滑块）已在 M20-08 落地。
- 轴判定阈值默认 `0.5`（可被 `[input] nav_threshold` 覆盖）；摇杆菜单导航依赖 `ui_*` 的
  `padaxis:*` 绑定——解绑即禁用摇杆导航（M22/W3 语义）。
- 震动只有左右马达强度与时长（M22/W2），没有扳机震动/触觉曲线；`input.rumble` 在无手柄时静默无效。
- 真实手柄的插入/拔出/震动实机步骤未执行（本机无物理设备）；`FakeBackend`/`SlotBackend`
  覆盖了设备帧到动作层的等价位。
