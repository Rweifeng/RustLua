# M9 3D 可玩垂直切片实施计划

- 项目：P2 Rust + Lua 游戏引擎
- 制定日期：2026-08-22
- 当前基线：`v0.8-3d-foundation`
- 状态：READY

## 1. 当前判断

M8 轻量 3D 已全部实施并验收（`v0.8-3d-foundation`，2026-08-22）：glTF/GLB 导入、Math3D/Transform3D/Camera3D、Mesh/Material GPU 上传、Depth pass、方向光 + 阴影 + 基础 PBR、骨骼动画、视锥剔除与实例化、3D Demo 与发布包。2D 样板游戏（俯视角 Roguelite）保持可玩且可发布。

但当前 3D 只是**技术演示，不是游戏**：

- `demo3d.lua` 是自动走场 + 实例网格基线演示，无碰撞、无玩法、无胜负；
- `engine_core` 物理只有 `rapier2d`，没有 3D 刚体/碰撞体/射线；
- 编辑器只有 3D Inspector 查看/编辑（M8 明说「不做 3D Gizmo」），3D 关卡只能手写坐标摆放；
- `game_runner/src/main.rs` 已 2995 行，M8 风险登记挂着的 P1「3D 改造堆积在 game_runner 单文件」仍未偿还；
- 路线图 M0–M8 已全部走完，`docs/README.md` 与项目章程仍停留在「下一阶段 M8」，需要同步。

因此 M9 的目标是把 3D 从演示推进到**可玩通一局的最小游戏**，同时偿还阻塞性的技术债。遵循「双轨交付」：任何 3D 引擎能力都必须绑定到这款 3D 游戏的具体需求上。

## 2. 范围与非目标

### 目标

1. 拆分 `game_runner` 单文件，抽出明确的 Renderer / GPU 资源 / RenderPass 边界（偿还 M8 P1 风险）；
2. 增加 3D 物理：`rapier3d` 刚体、碰撞体（球/盒/胶囊）、触发器、射线/重叠查询，碰撞事件进入 Lua，固定时间步推进，与 Transform3D 同步；
3. 编辑器支持 3D 实体平移 Gizmo 与 Inspector 组件编辑，可摆放 Mesh 和碰撞体来搭建关卡；
4. 用一款小 3D 样板游戏垂直切片验证整条链路：移动（碰撞）、攻击、至少一种敌人、拾取物、HUD、胜负与重开；
5. 复用现有 2D UI 文本（`ui.text`）、音频（rodio）、场景切换与存档路径，不重造；
6. 发布包可独立运行并玩通 3D 游戏，性能基线可对比 M8。

### 非目标

- 不做后处理、反射探针、完整生产级 PBR、地形编辑器或复杂 DCC 工作流；
- 不做 3D 音效空间化（复用 2D 音频）；
- 不扩展骨骼动画状态机（复用 M8 动画能力，游戏只消费剪辑）；
- 3D Gizmo 首版只做**平移**，旋转/缩放后置；
- 不重写 2D 场景格式，不破坏 `v0.7`/`v0.8` 场景与发布路径；
- 不在有性能数据支持前引入多线程渲染、GPU-driven indirect 或自研物理。

## 3. 实施顺序

```text
M9-00 基线与技术决策
  → M9-01 渲染边界重构（拆分 main.rs）
  → M9-02 3D 物理（rapier3d + Lua API）
  → M9-03 编辑器 3D Gizmo 与组件编辑
  → M9-04 3D 样板游戏垂直切片
  → M9-05 3D 性能、发布与验收
```

M9-01 与 M9-02 无强依赖（一个在渲染层、一个在 engine_core），可串行或并行推进；M9-03 依赖 M9-01 后的编辑器边界；M9-04 依赖 M9-02/M9-03 全部完成；M9-05 依赖全部能力。

## 4. 任务与验收

### M9-00 基线与技术决策

复验 `v0.8` 质量门与旧 2D/3D demo 不回归；同步文档索引（`docs/README.md` 将 M8 标记为历史、M9 设为下一阶段，更新项目章程里程碑表）；新增 ADR，明确 3D 物理选型（`rapier3d` 与 `rapier2d` 的 workspace 版本统一）、`main.rs` 拆分后的模块边界、3D Gizmo 交互方案、M9 游戏玩法锁定清单；建立 `tasks/active/`，先创建 `M9-00` 与 `M9-01` 任务文件。

**验收**：质量门通过；旧 2D 样板游戏与 M8 3D demo 不回归；ADR、计划文档、任务文件齐全；玩法清单已锁定（可拒绝范围外需求）。

### M9-01 渲染边界重构

把 `game_runner/src/main.rs` 中渲染相关职责抽到独立模块，建立明确边界：GPU 资源（buffer/texture/pipeline 创建与生命周期）、RenderPass（2D pass / 3D pass / depth 管理）、实例化与剔除数据缓冲、Camera/Depth 生命周期。重构只移动与组织代码，**不改变渲染行为**。

**验收**：重构前后 2D 游戏与 3D demo 画面一致、性能基线不劣化；Debug/Release 质量门通过；`main.rs` 行数与模块划分有量化记录（目标：主入口显著瘦身，渲染职责不再堆积在单文件）；每个重构提交独立可编译、可运行。

### M9-02 3D 物理

在 `engine_core` 增加 3D 物理，复用现有 2D 物理的 API 形态（`ColliderDesc`、layer/mask、sensor、碰撞事件）。支持：刚体与碰撞体（球/盒/胶囊）、触发器、射线/重叠查询、碰撞事件进 Lua、固定时间步推进、与 Transform3D 双向同步。2D 物理路径保持不回归。

**验收**：3D 球/盒/胶囊碰撞、层掩码与传感器行为有单测；射线/重叠 Lua API 有测试；Demo 中角色落地、被阻挡、触发事件可复现；旧 2D 物理测试与游戏不回归；`rapier2d`/`rapier3d` 版本在 workspace 统一锁定。

### M9-03 编辑器 3D Gizmo 与组件编辑

编辑器支持选中 3D 实体并拖动**平移** Gizmo，Inspector 可查看/编辑 Transform3D、MeshRenderer、Camera3D、Light、碰撞体组件；可摆放 Mesh 与碰撞体来搭建 3D 关卡。保存/加载 roundtrip 与 2D 编辑流程不回归。

**验收**：编辑器可选中 3D 实体、拖动平移、Inspector 数值同步；保存后重新打开位置一致；播放/停止不污染编辑场景；2D 编辑与保存不回归；场景格式版本迁移测试通过。

### M9-04 3D 样板游戏垂直切片

用 Lua 实现一款小 3D 游戏，范围锁定（参照 2D 样板游戏验收标准）：

- 玩家角色（复用 M8 战士资产或简单 Mesh + 胶囊碰撞体），碰撞移动；
- 至少一种敌人（AI 追击）与攻击判定；
- 拾取物、血条 HUD（复用 `ui.text`）、音效（复用现有音频）；
- 胜负条件、死亡/胜利重开一局；
- 玩法逻辑全部由 Lua 驱动（参照 `player/enemies/coins/hud/state` 的模块化结构）；
- 支持 `main.scene` 或独立 3D 场景进入。

**验收**：新会话按 README 可从零进入并完整玩通一局；连续运行 30 分钟无 P0/P1；碰撞/攻击/拾取/胜负/重开全部由 Lua 实现；Rust 不包含具体游戏规则。

### M9-05 3D 性能、发布与验收

记录 3D 场景实例化/剔除基线与 M8 对比（实例数、Draw Call、CPU/GPU 帧耗时、场景加载）；接入 `package.ps1`（加密 + 含空格路径 + 目录隔离）并独立运行 Release 包玩通；更新 M9 验收矩阵与证据目录；无 P0/P1；创建 `v0.9-3d-game` 标签。

**验收**：Release 发布包可独立玩通 3D 游戏；性能基线可对比 M8 并可解释变化；`--check` 类命令与质量门全部通过；证据归档 `docs/acceptance-evidence/m9/`；标签 `v0.9-3d-game` 创建。

## 6. 质量门与停止条件

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
cargo build --workspace
cargo build --workspace --release
git diff --check
cargo run -p assetc -- --project C:\GitHub\p2\game --check
cargo run -p game_runner -- --project C:\GitHub\p2\game --check
```

出现以下任一情况时暂停扩展功能并先修复：旧 2D 游戏或 M8 3D demo 回归、场景格式无法向后兼容、GPU 资源错误只能 panic、3D 物理与 Lua 事件不一致、或性能出现无法解释的劣化。

## 7. 主要风险

| 风险 | 等级 | 应对 |
|---|---|---|
| `rapier3d` 与 `rapier2d` 依赖/API 冲突 | P1 | workspace 统一版本，先做最小 3D 刚体冒烟再扩展 |
| main.rs 重构引入回归 | P1 | 只抽边界不改行为；每步独立编译并跑质量门 |
| 3D 玩法与 2D UI/音频对接不稳 | P2 | 复用 `ui.text`/音频 API，先做 HUD 冒烟再上玩法 |
| 3D Gizmo 复杂度过高吞噬时间 | P1 | 首版只做平移 Gizmo，旋转/缩放明确后置 |
| 样板游戏范围膨胀 | P1 | 玩法清单在 M9-00 锁定，范围外需求进 backlog |
| 3D 性能无法解释 | P2 | 与 M8 基线同机对比，记录硬件与驱动信息 |

## 8. 通过条件

M9-00 至 M9-05 全部 PASS；旧 2D 项目和 `v0.8` 发布路径兼容；Debug/Release 质量门通过；3D 游戏可在 Release 发布包中独立玩通；3D 物理、Gizmo、玩法均有自动化或可复现证据；完成 `v0.9-3d-game` 标签。
