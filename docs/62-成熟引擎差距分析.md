## 2. 核心差距矩阵

### 2.1 渲染管线 — 差距最大

| 能力 | RustLua（2026-10-29） | Unity / Unreal | Godot 4 |
|---|---|---|---|
| 光照模型 | **PBR 五槽贴图**（base color / metallic-roughness / emissive / normal / occlusion）+ **IBL**（SH9 漫反射 + 预过滤 cubemap 镜面；Tier C 回退只剩 SH9）+ **1 盏方向光**（阴影）+ **最多 8 盏点光源**（无阴影，`Light` 组件 `type=point`；PBR 与默认着色路径都参与） | 全 PBR + IBL + 光照探针 + 光照贴图 | Full PBR + IBL + SDFGI + VoxelGI |
| 后处理 | exposure / tint / vignette + **HDR tonemap**（ACES Narkowicz 拟合，或 Reinhard）；无 Bloom / SSAO / SSR / DOF / Motion Blur | 完整后处理栈（ACES/Filmic、Bloom、SSAO、SSR、DOF、MB） | 完整后处理栈 |
| HDR | `Rgba16Float` 场景目标 + tonemap；`RenderSettings::hdr` 默认 **off**（2D/旧场景像素不变） | 标配 | 标配 |
| 阴影 | 单张方向光 shadow map + PCF；点光源不投影；无 CSM、无点光阴影 | CSM + VSM + 级联 + GPU-driven | 多光源阴影 |
| Compute Shader | 原生支持（能力探针 = 后端声明 + 限制值双证据）；**WebGL2 判 false**；GPU 粒子消费者（10k 对拍） | 全面支持 | GDExtension + Vulkan compute |
| 粒子系统 | CPU 默认；GPU compute **仅 burst**（`rate > 0` 的连续发射显式拒绝，不静默降级） | VFX Graph / Niagara | GPUParticles3D/2D |
| Shader 系统 | 8 个 WGSL 文件 + **变体缓存** + **热重载**（`shader_variants` / `shader_hot_reload`） | Shader Graph / HLSL + 热重载 | VisualShader + GLSL + 热重载 |
| GPU Instancing | 静态 mesh 分组 | 全场景自动 | 自动 |
| 可见性 / 几何 | CPU 视口预筛（`spatial_index`）+ 3D `LodGroup` 距离切模 | 层级 BVH + 遮挡剔除 + LOD/HLOD | 遮挡剔除 + LOD |

**核心差距**：已经从"没有 PBR/HDR/IBL"变成"**有 PBR/IBL，光照数量只到 1 盏方向光 + 8 盏不投影点光**"——缺 CSM、点光源阴影、Bloom/SSAO/SSR，以及 WebGL 上的 compute；GPU 粒子只支持 burst。视觉表现力的天花板下一步在**阴影质量与后处理栈**（点光已能参与着色，但不投影）。2D 侧（精灵批/图集/瓦片/文字）已经是生产级，差距集中在 3D。

### 2.2 ECS 架构 — 差距较小

| 能力 | RustLua | Unity DOTS | Godot 4 |
|---|---|---|---|
| 存储模型 | `DenseStorage`（WP3 已把组件存储**整体**换掉）+ 懒排序实体序，`TypeId` 类型擦除 | Archetype-based | 传统 OOP（无原生 ECS） |
| 系统调度 | 10 级固定 stage（Input→Script→Sync→Physics→Writeback→Simulation→Animation→Spatial→Transform→Render），顺序执行 | 并行 job system | 信号/节点树 |
| 并行 | 无（2026-10-21 实测判"不做"：可并行 stage 占帧 ≤11.96%，跨系统收益上限 ≤1.18%） | 全面并行 | 有限 |
| 序列化 | 完整 schema 驱动（30 个 `ComponentId` 运行时组件） | 有 | 有 |

**亮点**：ECS 设计合理（generational index + dense storage + schema 驱动序列化），2D 游戏完全够用。差距主要在**系统并行调度**——但那一条已经有实测结论：瓶颈不在调度器，在单系统内部与提取阶段，所以"补并行"不是当前该做的事。

### 2.3 脚本系统 — 定位独特，差距中等

| 能力 | RustLua | Unity | Godot |
|---|---|---|---|
| 语言 | Lua 5.4 (mlua) | C# | GDScript / C# |
| API 规模 | 45 模块 / 338 函数 | 数千个类 | 数千个类 |
| 热重载 | 完整实现（指纹检测 → 新 VM 装载通过后才切换，失败保留旧脚本继续跑） | 不支持（需编辑器重编译） | 部分支持 |
| 调试 | 基础：脚本错误定位 + 诊断行跳编辑器内只读查看器 + 每回调错误预算（60）与指令预算（1e9）；断点/单步/局部变量/栈帧内核已通（无头测试），编辑器的暂停 UI 未接 | Visual Studio / Rider | 内置调试器 |
| IDE 支持 | 导出 LuaLS `---@meta`（补全与参数名；返回值一律 `any`、无 LSP 服务端） | 完整 LSP | 完整 LSP |

**亮点**：Lua 热重载是真正的竞争优势，Unity 做不到。API 覆盖面（338 函数 vs 数千个类）和缺少 LSP 服务端仍是明显短板；2026-10 的 LuaLS 类型提示导出把"补全/参数名"这一半补上了，返回值类型检查仍然买不到；2026-10-31 补上的是"断在哪、这一行有哪些局部变量"——**内核**已可无头断言，缺的是把它接到编辑器的 Play 暂停界面。

### 2.4 编辑器 — 差距中等偏大

| 能力 | RustLua | Unity | Godot |
|---|---|---|---|
| 技术栈 | egui (immediate mode) | 自研 IMGUI + UI Toolkit | 自研 Qt-like |
| 可视化脚本 | 有：18 个节点 + 校验 + 代码生成（`rustlua-visual-script`） | Visual Scripting (Bolt) | VisualShader |
| 动画编辑 | 有：`.anim` 时间线面板（播放头 / 轨道 / 关键帧增删拖拽 / 事件 / 帧吸附 / 撤销重做 / 原子写回） | Animation Window / Timeline | Animation Editor |
| 材质编辑 | 有：`.material` 段（PBR 五槽 + 贴图 + IBL；非法值即时标红且不提交） | Shader Graph / Material Inspector | VisualShader |
| 性能分析 | 有：编辑器内实时 Profiler（`panels/performance.rs` + `FrameProfile` 逐系统 p50/p95/p99 + 逐 GPU 通道计时） | Profiler + Frame Debugger | Built-in Profiler |
| UI 工具 | 有：UI Studio（spec 驱动设计 + 校验 + 预览 + 资产生成，`rustlua-ui-spec` / `editor-ui-studio`） | UI Builder | UI 编辑器 |
| AI 集成 | 有：内置 MCP 桥，**46 个工具**（场景/组件/Lua/UI spec 读写，另有只读求值） | 无内置 | 无内置 |
| 地形编辑 | 无 | Terrain System | 无原生（有插件） |

## 3. RustLua 的独特优势

差距不等于劣势。以下是成熟引擎反而做不到的点：

1. **极致轻量**：整个引擎 376.9K 行 Rust（含 `src/` 与示例/测试），Unity 编辑器本身千万行级别。启动快、打包小、嵌入容易。
2. **Lua 热重载**：改脚本即生效，不需要重编译或重启，Unity/Godot 都做不到原生支持。
3. **WebGPU-native + 微信小游戏**：直接面向 Web 和微信生态，Unity WebGL 打包体积大且性能差。
4. **Rust 内存安全**：没有 GC 暂停，没有 C++ 内存错误，引擎层面的可靠性天然更高。
5. **工程执行力**：ECS + 渲染 + 物理 + 脚本 + 编辑器 + 资产管线 + 两个完整示例游戏 + 质量门 + CI，约 10 周内由一人完成（706 commits、2,937 个测试）。

## 7. 总结

RustLua 是一个架构优秀、执行力惊人的引擎，在 **2D + Lua 热重载 + Web 小游戏**这个细分赛道上有真实竞争力。

1.4 版说"最大的短板是渲染表现力和编辑器工具链"——到了 1.5 版，这两项的性质变了：PBR/IBL/HDR、动画时间线、材质编辑、可视化脚本、插件基座、UI Studio、AI 集成都已落地，短板从**"有没有"**变成了**"有多深"**：3D 的光照数量与后处理栈、预制体工作流与三方合并、地形与导航烘焙、动态插件生态。这些都是成熟引擎用十几年团队积累换来的深度，靠单点功能补不齐。

建议策略：**不追求全面对标，聚焦细分赛道做到极致**。在 2D 游戏 + Web/微信小游戏这个定位上，RustLua 的轻量、热重载和 Rust 安全性是成熟引擎无法轻易复制的优势；3D 则应以"1 盏方向光阴影 + 8 盏点光 + PBR + IBL 足够用"的场景为边界，把 CSM/点光阴影/后处理栈当作按需项，而不是默认目标。
