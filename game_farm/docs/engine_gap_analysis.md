# game_farm 引擎能力缺口分析

## 1. 当前已有能力

`game_farm` 当前已经具备一套可支撑 2D 农场游戏原型的底层能力：

- 2D Sprite、SpriteBatch、Camera2D、纹理图集
- Tilemap 基础、视觉层和碰撞层
- 2D 动画状态机
- 2D 物理、碰撞体、触发器、射线和重叠查询
- Lua 脚本生命周期、实体、Transform、输入、场景切换
- UI 文本、图片、按钮基础
- 音效、音乐和粒子
- 基础存档读写
- 场景、Prefab、资源数据库、导入缓存
- 编辑器中的场景树、Inspector、资源浏览、Play/Stop、Undo/Redo
- 农场、城镇、室内、商店、钓鱼、采集、采矿等素材

目前工程仍主要是资源和场景预览，尚未形成完整的可玩循环。

## 2. P0：必须优先补齐

### 2.1 玩家控制与交互

需要支持：

- 四方向或八方向移动
- 面向方向和行走/待机动画
- 地图碰撞
- 工具使用方向与作用范围
- 与 NPC、箱子、门、作物、商店等对象交互
- 交互提示
- 进屋、进镇、下矿等触发器

建议形成可复用的高层概念：

```text
Interactable
ToolAction
UseItem
InteractionPrompt
TriggerZone
```

### 2.2 游戏时间、日历和每日结算

需要支持：

- 游戏内时间
- 时间流速和暂停
- 日期、季节、年份
- 每日开始/结束事件
- 睡觉和第二天切换
- 体力恢复
- 作物生长
- 动物产出
- 商店营业时间
- NPC 日程
- 天气和节日

建议提供 `GameClock`、`Calendar`、`DayLifecycle` 和 `Schedule` 等服务，并将游戏时间与真实帧时间分离。

### 2.3 结构化世界存档

基础键值存档还不足以保存农场状态，需要保存：

- 日期、时间、季节
- 玩家位置、背包、金钱、体力和工具
- 每块耕地的状态
- 每株作物的品种、生长阶段和浇水状态
- 箱子、机器、家具和动物
- NPC 好感度、任务和剧情状态
- 地图修改结果和世界开关

建议支持：

```text
SaveGame
SaveVersion
Migration
WorldSnapshot
PerMapState
EntityPersistentId
```

### 2.4 农田与作物模拟

这是第一条核心玩法闭环：

```text
移动 → 锄地 → 播种 → 浇水 → 睡觉 → 生长 → 收获 → 出售
```

需要支持网格化耕地、季节限制、生长阶段、枯萎、重复收获、作物品质、收获掉落和农场设施。

### 2.5 物品、背包、快捷栏和容器

需要支持：

- 物品定义和实例
- 类型、品质、堆叠数和容量
- 快捷栏与工具栏
- 拾取、丢弃、拆分、使用
- 箱子和仓库
- 拖拽交互
- 图标、名称、描述和价格

建议采用 `ItemDefinition`、`ItemInstance`、`Inventory`、`Container` 和 `Equipment` 数据模型。

## 3. P1：完整游戏循环能力

### 3.1 NPC、对话、好感度和日程

需要 NPC 实体、路点或寻路、日程、对话框、多分支对话、条件、送礼、好感度和特殊事件。

### 3.2 多地图与地图连接

需要地图注册、加载/卸载、出入口、传送点、地图持久化、室内外切换、屏幕过渡和地图音乐切换。

建议提供：

```text
MapManager
MapDefinition
MapTransition
SpawnPoint
PersistentMapState
```

### 3.3 商店和经济

需要商店营业时间、商品目录、买卖价格、季节商品、库存、玩家资金、出货箱、每日结算和交易确认。

### 3.4 钓鱼、采集和采矿

需要钓鱼点、出现条件、钓鱼小游戏、采集点刷新、季节性生成、矿洞楼层、矿石节点、随机地图和掉落表。

### 3.5 体力、伤害和工具数值

需要玩家体力、工具消耗、食物恢复、工具等级、蓄力工具、作用范围、升级材料和状态效果。

## 4. P2：中后期增强能力

### 4.1 数据驱动内容

农场游戏会包含大量作物、种子、鱼、矿物、食物、工具、NPC、礼物、配方、商店、任务、节日和天气数据。

建议支持 JSON/TOML 等数据资源、Schema 校验、本地化表、掉落表和配方表。

### 4.2 Sprite Sheet 和动画工作流

需要支持四方向帧、工具动作帧、动物动作、NPC 表情、作物阶段动画，以及动画事件。

### 4.3 Tilemap 编辑器

需要多层 Tilemap、地面/装饰/前景/碰撞/交互层、自动铺边、水面动画、阴影、遮挡、Tile 元数据和可种植属性。

### 4.4 NPC 寻路与调度

需要网格寻路、动态障碍、目标点、路点、卡住检测和移动动画联动。

### 4.5 完整 UI 交互

需要鼠标点击、键盘/手柄焦点、拖拽、Tooltip、背包网格、对话框、交易面板、日历、任务日志、选项菜单、存档菜单和滚动区域。

## 5. 暂不需要优先实现的能力

单机版小型农场游戏暂时不必优先投入：

- 联机和网络同步
- 3D 能力
- 复杂战斗系统
- 高级光照和 Shader
- 大型开放世界流式加载
- ECS 多线程优化
- 高级动画 Blend Tree

## 6. 推荐实施顺序

### 阶段 1：农场最小闭环

一个 20×20 农田地图、一个玩家、三种作物、背包、商店、游戏内一天和存档：

```text
移动 → 碰撞 → 锄地 → 播种 → 浇水 → 睡觉 → 生长 → 收获 → 出售
```

### 阶段 2：地图和生活系统

加入农场/室内/小镇切换、NPC、对话、商店、箱子、厨房、天气和每日事件。

### 阶段 3：扩展玩法

加入钓鱼、采矿、采集、动物、加工机器、任务、节日、好感度和技能成长。

### 阶段 4：编辑器增强

加入 Tilemap 编辑器、内容数据编辑器、对话编辑器、日程编辑器、动画切片工具、运行时调试器和存档查看器。

## 7. 结论

p2 已足够承载一个小型单机农场游戏原型。当前真正的瓶颈不是渲染或 3D，而是：

1. 游戏时间和每日生命周期
2. 网格化农田模拟
3. 物品/背包/容器
4. 玩家交互与工具系统
5. 多地图及持久化世界状态
6. 数据驱动内容
7. NPC、商店和对话
8. Tilemap 编辑工作流

下一步应优先完成农场垂直切片，而不是继续制作资源预览。
