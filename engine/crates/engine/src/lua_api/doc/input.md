## `input.text_events(command: Option<mlua::Table>)`

> 绑定：`engine/crates/rustlua-input/src/lua.rs:215`（直写）；签名由 `scripts/docgen/gen-lua-api-docs.js` 从绑定源码推断，需人工核对。

读取本帧宿主送来的**文本**（输入法组合串与上屏字符），同时可声明"这个字段在等字"。键位与文本是两条通道：`input.is_down("w")` 问的是键，`input.text_events()` 问的是打出来的字——中文由输入法转出来，键名通道永远拿不到"你"这个字。

- 参数：`command` 可省略；省略 = 纯读数。三个键都可选，给了就写、没给不动：
  - `capture = true|false`——收字声明。**跨帧保持**（这是脚本的意图，宿主每帧读它来决定要不要把系统输入法交给游戏窗口），换字段/关面板时必须显式 `capture = false`，否则按键会一直被当正文吃掉；
  - `composition = "字符串"`——本帧的组合串（预编辑，还没上屏）；空串 = 取消组合。宿主侧（winit）在 `Commit` 前一定先发一条空 `Preedit`，所以空串必须当成"清掉"而不是"没有"；
  - `commit = "字符串"`——本帧上屏的文本，追加进本帧提交队列。给 Lua 用是为了无头驱动同一条通道（与 `input.virtual_key` 的注入先例一致）。
- 返回：`{ composition = 字符串|nil, committed = {字符串, ...}, capturing = 布尔 }`。`composition`/`committed` 是**本帧数据**，帧边界（`finish_frame`/`clear_transitions`）清空，不跨帧；`capturing` 是上面那个声明。一帧内多次调用只重复读，不会消耗。
- 失败：`capture` 只接受布尔（`nil` 表示不改），`composition`/`commit` 只接受字符串，否则报 Lua 错误并带上字段名与原值——字符串写成 `"yes"` 不会静默变成 `true`。
- 示例：
  ```lua
  input.text_events({ capture = true })                 -- 进字段：把输入法交给我
  local t = input.text_events({ composition = "ni" })   -- 宿主写的组合串，画在光标处
  local t = input.text_events({ composition = "", commit = "你" })
  for _, s in ipairs(t.committed) do field.text = field.text .. s end
  input.text_events({ capture = false })                -- 出字段：还给玩法键位
  ```
  PC 宿主（`game/`）已把 winit 的 `WindowEvent::Ime` 与收字模式下的键盘 Unicode 字符喂进这条通道；web / 微信宿主还没有（见 `docs/75` §11.1 的宿主缺口）。引擎当前不绘制文本字段，组合串只是**状态**，要显示得自己用 `ui.text_at` 画。
