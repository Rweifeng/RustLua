# 《江湖有田》数值审计与调优

## 1. 范围与结论

本轮读取实际数据、恢复/耕作系统和 M24/M36/M53 数值样例；不修改价格、产量、任务奖励、场景或引擎。标记含义：**事实**是当前源码/实际断言结果，**推导**是写明假设的算式，**建议**尚未实施。

本轮修复两处同源错误：**消耗品恢复**和**打坐恢复**仍钳在基础100，导致经脉增加上限后恢复反而减资源。采用运行时延迟读取经脉聚合上限，保留背包基础上限接口100，避免经脉→背包→经脉递归。经济方面不贸然砍价，新增可复算报告，明确首茬门不等于全年经济平衡。

## 3. 首茬、再生收益和季内窗口

### 3.1 口径

**事实**：[M36经济样例](../../../engine/crates/game/examples/jhyt_m36_economy_sim.rs#L5-L16)检查24常规作物、各季数量、首茬利润范围、商店stock/buys关系和6种再生作物。它不是现金流/全年模拟，也不检验年1末里程碑。[M24](../../../engine/crates/game/examples/jhyt_m24_numeric_alignment.rs)另有文档表与数据、代表作物真实收获一致性测试。

**推导**：每格基础品质、无肥料、无专精、无温室加成；种子按买价，收获按基础sell价全部变现。设产量Y、售价P、种价C、首熟D、再熟R：

- 首茬净收益/有效成长日 = `(Y×P−C)/D`。
- 后续再生毛收益/有效成长日 = `Y×P/R`，已无重复种子成本；不能再次减C。
- 第1天种植、第28天截止共有27次跨天成长机会；再生茬数 `1+floor((27−D)/R)`，净收入 `茬数×Y×P−C`。
- 非再生比较值 `floor(27/D)×(Y×P−C)`，假定成熟当天立即重播并浇水。不是按“28次成长”算。

数据来自[作物表](../scripts/data/crops.lua)、[物品价格表](../scripts/data/items.lua)，全部24种的同口径CSV由[审计工具](../tools/audit_numeric.py)直接执行Lua数据后输出，避免维护另一套价格表。

**事实+推导**：桑葚和青瓜再生收益超过首茬门15，但不违反现有门的定义。相同27成长窗口，稻谷288、萝卜156、灵芝165、人参280；桑葚454是稻谷的1.576倍。只凭首茬门全绿无法证明跨季/全年现金曲线健康。品质会进一步提高收入：基础0级70%普通/25%良好/5%上品，售价派生取整；不能统一乘一个精确1.0925而忽略取整。例桑葚单个期望售价 `0.7×18+0.25×22+0.05×28=19.5`，再生期望19.5文/日，青瓜为21.767文/日。品质货可走[出货箱sell结算](../scripts/systems/shipping.lua#L89-L93)，不依赖商店buys。

**建议**：先新增季内窗口、品质分布、资金与劳动力约束验收，再决定再生收益允许区间；若产品目标确为基础再生≤15，可评估桑葚R从2→3（18→12）及青瓜R从3→4（20→15），但这会改作物定位及深耕收益，当前未实施。

### 3.3 模型边界

27次结算表是**每格理论值**，不是完整玩家仿真：不含买种限购/旅行时间/背包容量/场景日结算条件/首次资金不足/缺水/技能成长/节气/任务消耗/售卖时间。只在山庄执行农田日结算的入口见[主入口](../scripts/main.lua#L566-L568)。作物跨季未成熟死亡、售价季节加成等未在本模型假装已实现。最后一天收获的出货箱现金还需下次结算，不应把表中“可变现净值”当第28天已到账铜钱。

## 4. 体力与成长边界

**事实**：[耕作费用](../scripts/systems/farm.lua#L61-L68)基础工具翻土8、播种3、浇水4、收获2；再生收获后保留作物并重置浇水状态，[代码](../scripts/systems/farm.lua#L584-L595)。首茬新垦地体力 `13+4D`，后续再生 `2+4R`。非再生收获保留垦地，下一茬无需重付翻土8；不能每茬都算13+4D。工具升级、雨天、洒水器会改变体力，不改变本表基线定义。

**推导**：100体力全用于浇水时最多25格/日；首次翻土+播种+首日浇水每格15，最多6格（90），不是25格。四格稻谷首茬116体力分摊4成长日+收获操作；同四格灵芝164分摊7成长日+收获操作，所以总额超过100并不等于不能完成。再生桑葚每茬10体力换36文，青瓜14换60文，分别3.6和4.286文/体力（无种子边际成本）；不是年收益。

另一个**未修风险**：[产量专精](../scripts/systems/farm.lua#L560-L572)使用 `floor(基础产量×百分比)`；当前普通作物基础产量1或2，10%乃至15%都向下取整为0，玩家可能看见专精描述却没有多收。改为概率加产/跨茬余数累计会涉及随机与存档契约，故本轮只记录，不擅自扩大修复。

- 新增[共享Lua回归](../scripts/tools/numeric_audit.lua)，由既有[M53经脉样例](../../../engine/crates/game/examples/jhyt_m53_meridian.rs#L311-L325)调用，使用真实背包/经脉/打坐入口；保存并恢复原来的state、背包、经脉、stats及输入函数。
- 新增[轻量运行器](../tools/audit_numeric.py)：Python + `lupa.lua54`；缺依赖明确退出，不伪装通过。真实执行数据表、背包、stats、经脉与输入逻辑；用测试替身隔离引擎背包容器和渲染等，不证明引擎容量边界、UI绘制、真实设备输入及场景接线。
- 实跑 `python examples/game_jhyt/tools/audit_numeric.py`：退出0，`numeric_recovery_ok cases=13`，24作物首茬门通过。13案例为7个消耗品案例+2个日恢复案例+4个打坐案例。
- 内存mutation检验：分别把消耗品体力上限和打坐上限改回100，不写源文件；两次均被同一套断言拒绝，分别报 `heal_pill energy: 100 ~= 110`、`practice dynamic cap: 100 ~= 108`。
- 引擎集成命令（从engine目录）：`cargo run -j2 -p game --example jhyt_m53_meridian -- ../examples/game_jhyt`。主代理已实跑通过：`jhyt_m53_meridian_ok`，包含新增13案例、存档往返及strict数据门；M60真实购种/耕作/跨天/收获回归也通过。轻量结果与引擎结果分别记录，不代表全量发行回归。

## 6. 需要主代理同步数值设计案

本专项未改[设计案33](33-江湖有田-数值设计案.md)。建议同步：

1. §2.2“每日生命/体力/内力回满”改实际口径：体力动态回满、内力+30钳动态上限、当前睡眠无主动生命恢复；与§7.4一致。
2. §3打坐+5补“钳经脉聚合上限”；消耗品恢复同口径；不要声称基础100是所有角色永久上限。
3. §4.1.1及经济曲线段落：首茬利润门与再生边际收益分开，引用本报告六作物表。不要将M36门全绿称为年末里程碑模拟。
4. 版本3.2里“24作物利润/天[3,15]”明确为首茬基础值；年份里程碑/真实试玩耗时仍待对应证据。
5. 专精产量百分比向下取整无效、战败/HUD仍读基础上限，列作后续问题，不误写本轮已修。
