# 《江湖有田》项目执行总览

- 文档版本：0.3
- 本版同步：开发计划 0.3、引擎能力缺口 backlog 0.3

## 1. 项目结论

按 2026-09-07 对引擎 `E:\Codex\p2` 源码（HEAD `8f5bd5c`，含兼容层收口 `a7b43a1`）的实测，当前 RustLua 引擎已经具备承载《江湖有田》“武侠农庄”第一版垂直切片的基础底座：2D Tilemap（单格 solid/meta、A* 四/八向寻路 `find_path`、`map.schema/state` 分图版本化）、Lua 脚本、实体与稳定 PersistId（`entity.find_id`）、通用 Lua 事件总线、背包/商店/容器、时钟/日历/睡觉生命周期、动态 UI 与自动布局容器、固定时间步（60Hz）、音频/粒子、编辑器 Tilemap 碰撞层与 2D Animation 可视化编辑，以及键值存档（`save_version=1` 严格门 + `save.blob_*` JSON 兼容层）；农场 smoke 已覆盖耕地→播种→浇水→睡觉→成长→收获→交易→存档读档闭环。

但它还不是可直接制作完整商业版的成熟农场 RPG 引擎，仍待补齐的缺口（详见 [34-引擎能力缺口与执行backlog](34-引擎能力缺口与执行backlog.md)）：

- **引擎级统一存档入口 `world.save/load`**（引擎仅有键值/blob 兼容层；游戏侧已落地注册中心 `scripts/save_manager.lua` 走通 B-2，见开发计划阶段 B）；
- **战斗系统层 C-1**：固定时间步、health、overlap 等地基已就位，缺 hitbox/攻击事件/击退/硬直/无敌帧；
- **建筑 footprint D-0、NPC 日程 D-1、任务 D-3、关系声望 D-5** 缺失；对话 D-2 仅有通用 schema 校验、装备 D-4 仅有存储骨架（属性效果标注 M18-00）；
- **编辑器/体验**：Tilemap 批量操作 E-3、中文本地化排版检查 F-1、滚动容器与键鼠/手柄导航 F-2 部分具备；音频分组混音 F-3、发布原子替换 F-4、WebGL 浏览器集成测试 F-5、微信链路 F-6 未实现。

因此推荐产品路线是：

```text
武侠农庄 MVP
→ 第一章垂直切片
→ PC Alpha
→ PC Beta/首发
→ WebGL 验证
→ 微信小游戏可行性评估
```

不建议当前直接承诺“完整星露谷规模”或“多平台同步发行”。

## 5. 关键决策

- 游戏暂定名：《江湖有田》；
- 类型：生活模拟 + 轻动作 RPG；
- 首发：Windows PC；
- 视角：2D 俯视角；
- 视觉：32×32 逻辑网格的中国武侠像素风；
- 首发不做婚恋、联机、开放世界和微信小游戏；
- 游戏规则优先 Lua，稳定底座优先 Rust；
- 外部资源优先 CC0，其次明确允许商业使用的 CC-BY 或购买授权资源；
- 不能把未动态验证的 WebGL、微信小游戏和完整战斗描述为已支持。

## 6. 风险总表

| 风险 | 等级 | 应对 |
|---|---|---|
| 存档无法完整还原运行时状态 | P0 | 阶段 B 游戏侧注册中心已落地（`save_manager.lua`，读档恢复经 headless 验证）；引擎级 `world.save/load` 与 30 天长跑/100 次读档循环用例仍待补 |
| NPC/敌人无可靠寻路 | P0 | A* 已具备（B-4）；剩余为 NPC 日程执行器与敌人追击（D-1/C-1） |
| 战斗判定不稳定 | P0 | 固定时间步已接入（60Hz）；显式 hitbox/命中去重与事件日志属 C-1 待实现 |
| 建筑覆盖作物或入口 | P0 | footprint、占用层和放置预览 |
| 资源授权不清 | P0 | 禁止使用，建立许可证登记和 Credits |
| 美术风格混杂 | P1 | MVP 先灰盒，垂直切片统一采购/委托 |
| 编辑器制作效率不足 | P1 | Tilemap 碰撞层与 2D Animation 编辑已具备；批量操作 E-3 待补；先用数据和灰盒推进 |
| 中文文本溢出或缺字 | P1 | 字符收集与字体子集化已具备；文本排版检查工具待补 |
| 发布失败留下半成品 | P1 | 临时目录构建、校验、原子替换 |
| WebGL 运行差异 | P1 | Beta 真实浏览器测试，不以构建成功代替验收 |
| 微信小游戏适配成本失控 | P2 | 先隐藏平台选项，完成技术预研后决策 |

## 7. 验收原则

任何功能只有在以下条件同时满足时，才算完成：

- 有实现代码或数据；
- 有测试、Demo 或可复现手工步骤；
- Debug 和 Release 均可构建；
- 不引入新的 P0/P1 问题；
- 资源来源和许可证已记录；
- 存档和版本迁移影响已说明；
- 编辑器、运行器和发布包中的行为一致。

## 8. 文档同步规则

- 总策划案负责回答“做什么、给谁玩、做到什么范围”；开发计划负责回答“怎么做、依赖什么、如何验收”。
- 任何 MVP 范围、平台承诺、核心数值或公共数据字段变更，必须同时更新两份专项文档和本总览。
- 版本号只在内容发生实质变化并完成交叉检查后递增；资源方案的许可证变化需同步风险总表。
- 当前执行基线：Windows PC 首发、7 日 MVP 垂直切片、先补存档/寻路/战斗底座，再扩展内容。
