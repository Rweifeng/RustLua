## 1. 项目结论

按 2026-09-15 对引擎 `E:\Codex\RustLua` 源码的实测（历史文档里出现过改名前的旧检出路径，换算规则见 [项目章程 §0](../../../docs/00-project-charter.md)），当前 RustLua 引擎已经具备承载《江湖有田》"武侠农庄"垂直切片并在 **PC 上干净发布**的底座：2D Tilemap（单格 solid/meta、A* 四/八向寻路 `find_path`、`map.schema/state` 分图版本化）、Lua 脚本、实体与稳定 PersistId（`entity.find_id`）、通用 Lua 事件总线、背包/商店/容器、时钟/日历/睡觉生命周期、动态 UI 与自动布局容器、固定时间步（60Hz）、音频/粒子、编辑器 Tilemap 碰撞层与 2D Animation 可视化编辑，以及键值/blob 存档（`save_version=2` + provider 注册中心 + 新游戏隔离）。玩法侧三地图动线（山庄→云泽村→青云山道→寒泉洞，11 处传送）、种田/采集/制作/战斗/订单任务链/商店/7 日目标、季节与天气、中文排版契约均已落地并通过 headless 验收（`examples/game_jhyt` 的 24 项 MVP 套件 + PC 发布自检）。

仍待补齐的缺口（详见 [34-引擎能力缺口与执行backlog](34-引擎能力缺口与执行backlog.md)）：

- **浏览器内玩法**：WebGL 产物层已验证（wasm 39.6 KB + 662 项资源包 + 页面启动自检），但运行到 Lua 后缺 17 个宿主 API 全局（`app/asset/calendar/clock/container/data/day/event/grid/interact/inv/item/light/map/shop/sprite/tag`），**浏览器内可玩尚未实现**（backlog 4-24，定位实测见 [docs/32](../../../docs/32-webgl-浏览器平台验收.md) §4）；
- **引擎级统一存档入口**：引擎只提供 `save.*` 快照槽位，游戏侧用 provider 注册中心（`scripts/save_manager.lua`，带版本门与半恢复修正）承接——`world.save/load` 这一命名并不存在也未被需要；
- **仍有明确的 backlog**：NPC 每日送礼上限（4-18）、数值表与数值案对齐的剩余行（4-14）、固定名 `.tmp` 写入点收口（4-15/4-16/4-21）、性能基线与 bench 载体（5-3）；
- **编辑器/体验**：滚动容器与键鼠/手柄导航 F-2 已具备；音频分组混音 F-3 部分；微信链路 F-6 未启动（不在首发范围）。

因此推荐产品路线是：

```text
武侠农庄 MVP
→ 第一章垂直切片
→ PC Alpha
→ PC Beta/首发
→ WebGL 验证
→ 微信小游戏可行性评估
```

不建议当前直接承诺“完整星露谷规模”或“多平台同步发行”。

## 5. 关键决策

- 游戏暂定名：《江湖有田》；
- 类型：生活模拟 + 轻动作 RPG；
- 首发：Windows PC；
- 视角：2D 俯视角；
- 视觉：32×32 逻辑网格的中国武侠像素风；
- 首发不做婚恋、联机、开放世界和微信小游戏；
- 游戏规则优先 Lua，稳定底座优先 Rust；
- 外部资源优先 CC0，其次明确允许商业使用的 CC-BY 或购买授权资源；
- 不能把未动态验证的 WebGL、微信小游戏和完整战斗描述为已支持。

## 6. 风险总表

| 风险 | 等级 | 应对 |
|---|---|---|
| 存档无法完整还原运行时状态 | P0 | 阶段 B 游戏侧注册中心已落地（`save_manager.lua`，读档恢复经 headless 验证）；引擎级 `world.save/load` 与 30 天长跑/100 次读档循环用例仍待补 |

| 战斗判定不稳定 | P0 | 固定时间步已接入（60Hz）；显式 hitbox/命中去重与事件日志属 C-1 待实现 |
| 建筑覆盖作物或入口 | P0 | footprint、占用层和放置预览 |
| 资源授权不清 | P0 | 禁止使用，建立许可证登记和 Credits |
| 美术风格混杂 | P1 | MVP 先灰盒，垂直切片统一采购/委托 |
| 编辑器制作效率不足 | P1 | Tilemap 碰撞层与 2D Animation 编辑已具备；批量操作 E-3 待补；先用数据和灰盒推进 |

| WebGL 运行差异 | P1 | Beta 真实浏览器测试，不以构建成功代替验收 |
| 微信小游戏适配成本失控 | P2 | 先隐藏平台选项，完成技术预研后决策 |

## 7. 验收原则

任何功能只有在以下条件同时满足时，才算完成：

- 有实现代码或数据；
- 有测试、Demo 或可复现手工步骤；
- Debug 和 Release 均可构建；
- 不引入新的 P0/P1 问题；
- 资源来源和许可证已记录；
- 存档和版本迁移影响已说明；
- 编辑器、运行器和发布包中的行为一致。
