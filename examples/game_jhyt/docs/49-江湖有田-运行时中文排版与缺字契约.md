# 《江湖有田》运行时中文排版与缺字契约（M30 / 阶段五 P2）

- 文档版本：0.2（2026-10-08）
- 本版同步：`docs/42` §1（中文文字规范）、`docs/48`（资源接线与下架清单）、`docs/34`（引擎能力缺口）、`docs/58` §11（字体与授权登记，M72-03）
- 目标：把"文字画得对不对"从**肉眼抽查**变成**机器验收**——零溢出、零缺字、字号不低于可读下限

## 1. 为什么要有这份契约

中文排版不能按"字数 × 系数"估算。同一串字里：

| 字符 | 推进宽度（`size` px 字号下） |
|---|---|
| CJK（如「江」） | `size + 1`（满宽 + 1px 字距） |
| ASCII 字母（如 `A`） | 约 `0.5 × size + 1` |
| 宽拉丁（如 `W`/`M`） | 明显宽于普通字母 |
| 全角标点（如「，」） | 与 CJK 同宽 |

这张表**不是**按字体类型推出来的猜测：当前工程字体是像素点阵的
Fusion Pixel 12px Mono（`docs/58` §11），14px 下「江湖有田」= `60.0px`（4 × 15）
由 `jhyt_m30_cjk_text` ① 逐值钉住，换字体时这条断言会先红。

M30 之前 HUD 用的是「CJK 记 2 单位、其余记 1 单位」的启发式截断（`hud.clip`），
于是这些真实文案都会算错宽度：

* `金钱 99999 文`（长数字）；
* `WASD 移动 · E 交互 · J 攻击…`（宽拉丁字母 + 中文混排）；
* `限购剩余 999`、`容量 24/24 · 负重 999.9`。

对话正文此前**既没换行也没裁剪**，长台词直接画到面板外（面板外就是世界，字看不见）；
背包/任务/商店/暂停面板的行同样只按字符数截断。这些都属于「看起来在排版、其实会溢出」的坏行为。

## 2. 度量口径（唯一来源：引擎）

* 引擎 API：`ui.measure_text(text, size)` → `{width, height, lines, glyphs, missing, missing_count}`。
  * **与渲染同口径**：同一工程字体、同一 advance、同一字间距（`TextStyle::default().spacing = 1.0`，
    即每个字符后加 1px）；`size` 就是 `ui.text_at` 的 `font_size`（像素）。
  * 只度量、不光栅化：headless 可用，且很便宜。
  * 引擎单测 `core::text::measure_matches_layout_size` 钉住"度量 == 渲染布局"，`size` 覆盖 13/15/18/22。
  * 附带修复：`TextLayout::build` 的高度此前按 `ascent + descent`（= `0.8em`）算，正确答案是
    `ascent + |descent|`（= `1.2em`，即字身框）；否则行高/面板高度都会偏小。已修并由上述单测守住。
* 缺字：`missing` 直接给出字体**没有字形**的字符（如 emoji `🙂`）。
  点阵字体没有"找个相近字形顶上"这回事：缺一个码位屏上就是一个方框，所以缺字在本工程
  比矢量字体时代更硬（`project.toml` 的 `font_fallback = ""`，混排平滑字会立刻露馅）。
* **两种文字载体、两套读回 API**（M72-03 的关键口径）：
  * **动态层**（Lua 每帧画的）：`ui.text_get(id)` 读回 `{text, x, y, scale, size, visible}`；
  * **实体层**（字由 `prefab.set_text` 写进 `Text` 组件，面板搬进 `.prefab` 之后走这条）：
    `entity.find('<Name>')` 拿原始句柄 → `EntityId::from_raw` → `world.get::<UiText>(id)`
    读 `text` / `font_size`，再用 `runtime.prefab_ui_nodes()` 判断"这一帧真的被画了"。
  只认动态层的检查会在面板搬家之后**变成零条量宽**（搬家 = 检查变瞎）。M30 的门今天
  两套都读，暂停面板（含触屏帮助页 33 行）全部走实体层读数。

### 两条宽度路径必须一致

Lua 侧 `ui/text_fit.lua` 按**逐字符**求宽（拆到字符才能按宽度断行），引擎侧 `ui.measure_text`
按整串 f32 累加。两者在几百像素量级上的浮点差异约 `1e-5`（f32 在 592px 处精度约 `6e-5`），
因此比较容差统一取 `text_fit.EPSILON = 0.05px`（1/20 像素：远高于噪声、远低于可见）。
验收会拿 7 条真实文案 × 4 档字号逐条对比两条路径。

## 3. 排版层：唯一出口 `ui/ui_text.lua`

```lua
ui_text.begin(owner)                                   -- 每轮重绘先开一轮登记（按 owner 隔离）
ui_text.draw(owner, id, x, y, size, budget, text)      -- 单行：按真实字宽裁剪 + 登记
ui_text.draw_exact(owner, id, x, y, size, budget, t)   -- 固定短文案：不裁剪但同样登记
ui_text.draw_wrapped(owner, id, x, y, size, budget, max_lines, text)  -- 多行：按宽度换行
ui_text.record(owner, id, size, budget, text)          -- 实体层载体：字由 prefab.set_text 写，这里只登记宽度契约
ui_text.hide(owner, id) / hide_all(owner, ids) / reset([owner])
ui_text.audit()   -- 遍历登记表 → { checked, bad = {...}, worst }
```

要点：

1. **登记表是排版检查的唯一数据源**：每条记录带 `(文字, 字号, 可用宽度)`。
   验收不需要重抄一遍各面板几何（抄一遍就会漂），而是遍历登记表逐条量宽。
2. **`scripts/**` 不允许直接调 `ui.text_at`**（唯一出口是本模块）。否则"画了但没登记"的文字
   会从检查里漏掉——正是"零报错的坏行为"。这条由 `jhyt_m30_cjk_text` 静态扫描守住。
3. **两种载体共用同一张登记表、同一条下限**：`draw*` 是"画 + 登记"（字号是第 5 个实参），
   `record` 是"只登记"（字在 `Text` 组件里、位置由预设的 `UiLayout` 决定，字号是第 3 个实参）。
   面板从 Lua 搬进 `.prefab` 时**必须**把 `draw` 换成 `record`——不然 11px 下限和宽度契约
   会跟着搬家一起消失（M72-03 修的就是这个：门当时扫到 0 条面板行还照样绿）。
4. `owner` 隔离：HUD 每帧重绘只清自己那一轮，不会把"只在变化时重绘"的面板登记一起清空。
5. `audit()` 判定三条：① 缺字 ② 字号 `< 11px` ③ 实际宽度 > 预算（多行逐行量）。

`ui/text_fit.lua` 是纯数学层（无绘制、无状态）：

* `width(text, size)` / `char_width(char, size)`：带缓存的度量；
* `fit(text, size, max_width)`：**保证结果宽度 ≤ max_width**（省略号宽度计入预算）；
* `wrap(text, size, max_width [, max_lines])`：CJK 逐字可断、连续 ASCII 视作一个词（不拆单词）、
  **标点禁则**用"与前一字符成组"实现（标点不会落行首，也不会因此超宽）；
  给了 `max_lines` 而文本更长时，最后一行以省略号收尾（"还有下文"要在画面上看得出来）。

## 4. 缺字与首包字体子集

`assetc::package` 打包时用 `char_collect::collect_project_chars(project)` 收集字符
（场景/预制体的 `Text` 组件 + 全部 Lua 字符串字面量，注释先剥掉），写出 `chars.txt`，
并把 **`project.toml` 的 `font =` 指向的那款主字体**（M72-03 起是
`assets/fonts/FusionPixel-12px-Monospaced-zhHans.ttf`，不再是 Noto Sans SC）裁成子集。
仓库里那份工程字体本身也用同一条路径重裁：
`cargo run -q -p engine --example subset_project_font -- examples/game_jhyt --source <全量字体>`。

因此发布正确性契约是：

> **运行时画出来的每一个字符，都必须落在 `char_collect` 收集到的集合里。**

少一个字符，开发机上一切正常、正式包里就是豆腐块。验收按这条做双向核对：

* `scripts/tools/text_audit.lua` 从**运行时**收集语料（数据表 + 运行时行 + 全部对话节点/选项 +
  `last_action` 前缀族 + 最坏数字形态），返回字符集；
* `jhyt_m30_cjk_text` 用引擎 `char_collect` 算集合，逐个字符核对覆盖，并断言语料无缺字；
* `jhyt_m72_pixel_font` ④ 再往下一层：用到的每个字符不但要在集合里，还要**这款点阵字体真有点阵**
  （断言"字体覆盖它"且"栅格化后有亮 texel"，空字模 = 白框也算缺字）。

语料当前规模（`jhyt_m30_cjk_text` ② 实测）：**1,731 条文案 / 1,118 个字符**
（`char_collect` 侧 4,623 字符，覆盖 ok、缺字 0）。
语料规模设了下限（≥350 条 / ≥550 字符）：数据表缩水到把检查架空时会直接失败。
**上游全量字体也没有的字符一律改文案**（`›` `−` `✓` `鳜` 四例见 `docs/58` §11）。

### 点阵字体多了一档约束：字号与 12px 点阵格的关系

Fusion Pixel 的字模是 **12px 网格**画出来的（`unitsPerEm=1200`、有 `glyf`、无 EBDT/EBLC，
`jhyt_m72_pixel_font` ① 由二值覆盖率反推出 `raster_scale = 12`）。所以：

* 字号是 12 的**整数倍**时一个 texel 对一个屏幕像素（1:1），笔画最干净；
* 非整数倍（现在面板里的 13/14/15/18/22/24 全是）由 Nearest 采样 + `sdf=2` 阈值档出像素，
  **不会有灰边**（② 实测：85 个 UI 字形四边形里灰阶 texel = 0、alpha≠255 = 0），
  代价是横向笔画粗细会在"1 texel / 2 texel"之间跳；
* ② 的另一半读数：这 85 个四边形里 **1:1 档只有 5 个、非整数倍 80 个**——
  "整屏文字都落在整数倍档"是发行前的视觉打磨项，记在 `tasks/plan/M72-10`，
  不是这道门的判据（门只保证"没有亚像素糊边"，这本来就是点阵字体的目的）。

## 5. 容器预算表（谁有多少宽）

预算就是各面板自己的几何，写在**登记调用处**（`draw*` 的第 6 个实参 / `record` 的第 4 个）。
M66/B3（暂停菜单）与 M70（HUD）把面板搬进 `.prefab` 之后，同一个"预算"有两种载体：

### 5.1 动态层（`ui_text.draw*`，Lua 每帧画）

| 面板 | 元素 | 字号 | 可用宽度 |
|---|---|---|---|
| HUD 招式快捷栏 | `hud:skill_name1..7` | 12 | 48（单格 `SKILL_SLOT`） |
| 标题界面 | `title:label:*` | 24 | 360（`layout.PANEL.title_btn.w`） |
| 标题界面 | `title:arrow:*` | 24 | 48 |
| 标题界面 | `title:hint` | 13 | 1232（`layout.row_width()` = 1280 − 两侧 24） |
| 触屏动作盘 | `vp:close_x` / `vp:dlbl*` | `max(11, r×0.62)` / `max(11, r×0.42)` | 按键直径（`cg.size` / `radius*2`） |
| 触屏动作盘 | `vp:lbl1` / `vp:lbl2..5` | 24 / 14 | 按键尺寸（`b*.size`） |
| 触屏动作盘 | `vp:act_lbl*` / `vp:pactlbl*` / `vp:dbg` / `vp:more_lbl` | 14 / 14 / 14 / 12 | 槽位尺寸 / 400 / `MORE.size` |

桌面运行时**一行都不该有 `vp`**：`jhyt_m30_cjk_text` ③ 断言 `recorded().vp == nil`
（触屏控件在 `app.platform()='desktop'` 必须整个收掉）。触屏那套文案改由
`set_touch(true)` 旁路量（见 §6 ③）。

### 5.2 实体层（字由 `prefab.set_text` 写，`ui_text.record` 只登记契约）

| 面板（预设 `pause_menu.prefab`） | 元素 | 字号 | 可用宽度 |
|---|---|---|---|
| 暂停/设置/帮助 标题 | `pse:*:title` | 22 | 672（`w − title_dx×2` = 720 − 48） |
| 暂停菜单 / 设置页 行 | `pse:row*` / `pse:s:row*` | 18 | 672（`layout.list_width(PANEL)`） |
| 暂停菜单 / 设置页 消息 | `pse:msg` / `pse:s:msg` | 15 | 672 |
| 各页提示行 | `pse:hint` / `pse:s:hint` / `pse:h:hint` | 14 | 672 |
| 帮助页（触屏分叉） 标签列 | `pse:h:row*` | 18 | 672（section 行）/ 100（`HELP_VALUE_DX − 8`） |
| 帮助页 值列 | `pse:h:val*` | 18 | 556（`w − list_dx×2 − 108 − 8`） |

### 5.3 已知缺口：**这些面板今天量不到**

背包 / 任务日志 / 商店 / 对话 / HUD 状态行同样已经搬进预设，但**没有补 `record`**——
于是 ③ 里这几个面板的"量宽条数"仍是登记表里 HUD 那 7 条，
实测形状就是 `hud=7 bp=7 qst=7 pse=16 shp=7 dlg=7` 里那几个相同的 7。
字号下限这一路不受影响（预设里 `Text.font_size` 由 ⑤ 的"场景/预设 Text 168 个"直接量），
**受影响的是宽度契约**。补登记（把这些面板的行按预设几何 `record` 回去）、
并把 `MIN_REGISTERED_TEXT_SITES` 从 28 抬回迁移前的 30 以上，记在 `tasks/plan/M72-10`。

字号下限：**11px**（`docs/42` §1）。⑤ 的实测最小值：Lua 登记 11px（触屏按键标签的
`math.max(11, …)` 地板值）/ 场景与预设 `Text` 14px。

## 6. 验收

`scene_text=168@14px lua_text=28@11px`。

## 7. 改文案/改面板时怎么做

1. 文案随便改（`data/**`、脚本里的字面量都行）——**不许**手工维护字符清单，`char_collect` 会收。
   改完重裁工程字体：`cargo run -q -p engine --example subset_project_font -- examples/game_jhyt --source <全量字体>`，
   再跑 `jhyt_m72_pixel_font`；**全量字体也没有的字符就改文案**（不要加字体，见 `docs/58` §11）。
   三条踩过的细节：① 收的是**所有** Lua 字符串字面量，校验脚本里那句 `err("…")` 也算工程用字
   （M72-06 新增 `data/lighting.lua` 就因此红 6 个字：又/溢/特/秩/零/颜，全在 `err` 文案里）；
   ② 重裁的**目标**取自 `project.toml` 的 `font =`，跑之前核对它正是 `--source` 那份的子集——
   否则那次运行会把别的字体文件就地覆盖成本字体的子集（子集不可逆，只能 `git restore` 救）；
   ③ 裁完对拍新旧 `cmap`：新增集合必须恰好等于门点名的缺字、删除必须为 0。
2. 面板几何变了就改**那一处**登记的预算实参（`draw*` 第 6 个 / `record` 第 4 个）；登记表随之更新，验收自动跟上。
3. 新面板/新文本：动态层走 `ui_text.draw*`，**实体层（`.prefab` + `prefab.set_text`）走 `ui_text.record`**；
   两种都不许直接调 `ui.text_at`（静态扫描会失败）。把一个已有面板搬进预设时，
   原来的 `draw` 必须换成 `record` 带上同一份预算——只删不登记就等于把宽度契约删掉了（§5.3）。
4. 新增字号不要低于 11px。预设里 `Text.font_size` 与 Lua 里的登记字号由 ⑤ 两路各量一次。
5. 跑 `cargo run -p game --example jhyt_m30_cjk_text`；溢出会在 `bad` 里带着
   `owner/id:overflow=实际>预算(文本)` 直接报出来。
