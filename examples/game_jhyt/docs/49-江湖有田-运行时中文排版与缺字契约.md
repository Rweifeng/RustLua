# 《江湖有田》运行时中文排版与缺字契约（M30 / 阶段五 P2）

- 文档版本：0.1
- 本版同步：`docs/42` §1（中文文字规范）、`docs/48`（资源接线与下架清单）、`docs/34`（引擎能力缺口）
- 目标：把"文字画得对不对"从**肉眼抽查**变成**机器验收**——零溢出、零缺字、字号不低于可读下限

## 1. 为什么要有这份契约

中文排版不能按"字数 × 系数"估算。同一串字里：

| 字符 | 推进宽度（`size` px 字号下） |
|---|---|
| CJK（如「江」） | `size + 1`（满宽 + 1px 字距） |
| ASCII 字母（如 `A`） | 约 `0.5 × size + 1` |
| 宽拉丁（如 `W`/`M`） | 明显宽于普通字母 |
| 全角标点（如「，」） | 与 CJK 同宽 |

M30 之前 HUD 用的是「CJK 记 2 单位、其余记 1 单位」的启发式截断（`hud.clip`），
于是这些真实文案都会算错宽度：

* `金钱 99999 文`（长数字）；
* `WASD 移动 · E 交互 · J 攻击…`（宽拉丁字母 + 中文混排）；
* `限购剩余 999`、`容量 24/24 · 负重 999.9`。

对话正文此前**既没换行也没裁剪**，长台词直接画到面板外（面板外就是世界，字看不见）；
背包/任务/商店/暂停面板的行同样只按字符数截断。这些都属于「看起来在排版、其实会溢出」的坏行为。

## 2. 度量口径（唯一来源：引擎）

* 引擎 API：`ui.measure_text(text, size)` → `{width, height, lines, glyphs, missing, missing_count}`。
  * **与渲染同口径**：同一工程字体、同一 advance、同一字间距（`TextStyle::default().spacing = 1.0`，
    即每个字符后加 1px）；`size` 就是 `ui.text_at` 的 `font_size`（像素）。
  * 只度量、不光栅化：headless 可用，且很便宜。
  * 引擎单测 `core::text::measure_matches_layout_size` 钉住"度量 == 渲染布局"，`size` 覆盖 13/15/18/22。
  * 附带修复：`TextLayout::build` 的高度此前按 `ascent + descent`（= `0.8em`）算，正确答案是
    `ascent + |descent|`（= `1.2em`，即字身框）；否则行高/面板高度都会偏小。已修并由上述单测守住。
* 缺字：`missing` 直接给出字体**没有字形**的字符（如 emoji `🙂`）。
* `ui.text_get(id)` 读回 `{text, x, y, scale, size, visible}`，用于 headless 验收"真正画出来的那串字"。

### 两条宽度路径必须一致

Lua 侧 `ui/text_fit.lua` 按**逐字符**求宽（拆到字符才能按宽度断行），引擎侧 `ui.measure_text`
按整串 f32 累加。两者在几百像素量级上的浮点差异约 `1e-5`（f32 在 592px 处精度约 `6e-5`），
因此比较容差统一取 `text_fit.EPSILON = 0.05px`（1/20 像素：远高于噪声、远低于可见）。
验收会拿 7 条真实文案 × 4 档字号逐条对比两条路径。

## 3. 排版层：唯一出口 `ui/ui_text.lua`

```lua
ui_text.begin(owner)                                   -- 每轮重绘先开一轮登记（按 owner 隔离）
ui_text.draw(owner, id, x, y, size, budget, text)      -- 单行：按真实字宽裁剪 + 登记
ui_text.draw_exact(owner, id, x, y, size, budget, t)   -- 固定短文案：不裁剪但同样登记
ui_text.draw_wrapped(owner, id, x, y, size, budget, max_lines, text)  -- 多行：按宽度换行
ui_text.hide(owner, id) / hide_all(owner, ids) / reset([owner])
ui_text.audit()   -- 遍历登记表 → { checked, bad = {...}, worst }
```

要点：

1. **登记表是排版检查的唯一数据源**：每条记录带 `(文字, 字号, 可用宽度)`。
   验收不需要重抄一遍各面板几何（抄一遍就会漂），而是遍历登记表逐条量宽。
2. **`scripts/**` 不允许直接调 `ui.text_at`**（唯一出口是本模块）。否则"画了但没登记"的文字
   会从检查里漏掉——正是"零报错的坏行为"。这条由 `jhyt_m30_cjk_text` 静态扫描守住。
3. `owner` 隔离：HUD 每帧重绘只清自己那一轮，不会把"只在变化时重绘"的面板登记一起清空。
4. `audit()` 判定三条：① 缺字 ② 字号 `< 11px` ③ 实际宽度 > 预算（多行逐行量）。

`ui/text_fit.lua` 是纯数学层（无绘制、无状态）：

* `width(text, size)` / `char_width(char, size)`：带缓存的度量；
* `fit(text, size, max_width)`：**保证结果宽度 ≤ max_width**（省略号宽度计入预算）；
* `wrap(text, size, max_width [, max_lines])`：CJK 逐字可断、连续 ASCII 视作一个词（不拆单词）、
  **标点禁则**用"与前一字符成组"实现（标点不会落行首，也不会因此超宽）；
  给了 `max_lines` 而文本更长时，最后一行以省略号收尾（"还有下文"要在画面上看得出来）。

## 4. 缺字与首包字体子集

`assetc::package` 打包时用 `char_collect::collect_project_chars(project)` 收集字符
（场景/预制体的 `Text` 组件 + 全部 Lua 字符串字面量，注释先剥掉），写出 `chars.txt`
并把 `assets/fonts/NotoSansSC-VF.ttf` 裁成子集。

因此发布正确性契约是：

> **运行时画出来的每一个字符，都必须落在 `char_collect` 收集到的集合里。**

少一个字符，开发机上一切正常、正式包里就是豆腐块。验收按这条做双向核对：

* `scripts/tools/text_audit.lua` 从**运行时**收集语料（数据表 + 运行时行 + 全部对话节点/选项 +
  `last_action` 前缀族 + 最坏数字形态），返回字符集；
* `jhyt_m30_cjk_text` 用引擎 `char_collect` 算集合，逐个字符核对覆盖，并断言语料无缺字。

语料当前规模：**371 条文案 / 601 个字符**（`char_collect` 集合 2649 字符，覆盖 ok）。
语料规模设了下限（≥350 条 / ≥550 字符）：数据表缩水到把检查架空时会直接失败。

## 6. 验收

`engine/crates/game/examples/jhyt_m30_cjk_text.rs`（`scripts/verify.ps1 -MvpOnly` 的 MVP 清单成员）：

| 段 | 内容 |
|---|---|
| ① | 度量口径：CJK 满宽/ASCII 半宽、逐字符求和 == 整串度量、`missing` 报 emoji、`size<=0` 报错、`ui.text_get` 读回 |
| ② | 语料无缺字 + 运行时字符 ⊆ `char_collect` 首包子集（含规模下限） |
| ③ | 逐个打开 HUD / 背包 / 任务日志 / 暂停 / 设置 / 商店 / 对话，各自审计：零溢出、零缺字、字号达标 |
| ④ | 压力值：金钱 99999 / 999999、第 999 天、限购 999 —— 重绘后仍然零溢出；最坏行形态逐条按预算截断 |
| ⑤ | 字号下限：场景 `Text` 21 个（最小 14px）+ Lua 绘制 44 处（最小 13px，解析失败即自检失败）+ `scripts/**` 无直接 `ui.text_at` |
| ⑥ | 负例（审计必须有牙齿）：塞入超宽串 / emoji / 10px 字号必须各报一条；换行遵守标点禁则、行数上限、省略号收尾、空串/零预算边界 |

当前实测：`hud=12 bp=21 qst=26 pse=22 shp=23 dlg=18` 条量宽全部合规，
`scene_text=21@14px lua_draw=44@13px`，语料 `371/601`，缺字 0。

## 7. 改文案/改面板时怎么做

1. 文案随便改（`data/**`、脚本里的字面量都行）——**不许**手工维护字符清单，`char_collect` 会收。
2. 面板几何变了就改**那一处** `ui_text.draw(...)` 的预算参数；登记表随之更新，验收自动跟上。
3. 新面板/新文本一律走 `ui_text.draw*`，不要直接调 `ui.text_at`（静态扫描会失败）。
4. 新增字号不要低于 11px。
5. 跑 `cargo run -p game --example jhyt_m30_cjk_text`；溢出会在 `bad` 里带着
   `owner/id:overflow=实际>预算(文本)` 直接报出来。
