# 《江湖有田》美术资源规范（对标星露谷物语标准）
> 文档版本：v0.4（2026-10-10，M72-13 按实测回写；v0.3 = 2026-10-03 的 8 方向扩展）
> 依赖文档：31‑江湖有田‑美术资源方案.md v0.2、36‑江湖有田‑角色序列帧设计.md、37‑江湖有田‑山庄主场景美术.md
> 基准参考：星露谷物语（Stardew Valley）像素美术生产范式；保留原有三层资源策略、目录结构、许可证登记、引擎约束，对齐星露谷像素规格、动画逻辑、色彩管理、资源生产、验收标准。
> 星露谷核心美术特征：**32×32基础Tile网格、像素硬边无抗锯齿、有限调色板、角色8方向（本项目，2026-10-03 由 4 方向扩展）、序列帧Sprite Sheet、环境分层、作物多阶段生长、UI高可读性、统一光源、少半透明模糊特效**。

## 1 总体美术策略
依旧执行**原型层→垂直切片层→正式发行层三层资源策略**
1. **原型层**：CC0商用合规占位素材，只做玩法验证；不允许占位素材直接流入正式版本，参考星露谷早期原型，占位资源仅用于逻辑跑通，全部后期替换。
2. **垂直切片层**：统一国风武侠像素风格，禁止多画风拼接；全部内建美术为统一像素体系，外部素材仅允许用作次要装饰碎屑。
3. **正式发行层**：主角、关键NPC、Boss、主线场景、Logo、全套UI、宣传物料全部原创/专属委托；第三方素材仅限次要装饰物件，完整留存授权清单。

> 核心原则：全部游戏内像素美术禁用模糊抗锯齿，硬像素边缘；全局统一虚拟光源；统一调色板管控；Sprite Sheet批量管理动画资源；地图分前景、中景、背景层渲染。

## 2 基础像素规格（对标星露谷物语，适配本项目引擎约束）
> 注意本项目引擎`core/tilemap.rs`原有tileset列数硬编码为6，需要先完成引擎改造支持可配置tileset列数，否则单地图最多6种地表图块。
> **这条前置已闭合（M72-01/M72-04，2026-10-10 按 HEAD 复核）**：`Tilemap` 组件现在按 `tiles_format=1;atlas_cols=N;atlas_rows=M` 声明图集行列，引擎不再猜 6 列。实测读数：盘上 8 张场景里 7 张带 `Tilemap`，一共 **10 个 Tilemap 组件全部 `tiles_format=1`**（`main.scene` 是门面图、没有地面层）；其中 manor 的**地面层**与 `combat_arena` 那张已换成 **12×9**（108 槽，画出的非空格 920 = 逐格数出来的 920），manor 的作物层是 **8×29** 的 CropGrid、另有 2×1（农田）与 1×1（湿润叠层）两张小层，其余 5 张仍是 **6×1**（本身只用 6 格以内，换了编码没换图集尺寸，属正常而非漏迁移）。复现 `cd engine && cargo run --quiet -p game --example jhyt_m72_tileset_atlas -- ../examples/game_jhyt`（`probe_quads=18 manor_cells=920`，V 按 9 行分带）。**上限不是列数而是 u8**：`tiles: Vec<u8>` ⇒ 单图集 ≤255 槽，12×9=108 用掉 108，`CropGrid` 那张 8×29=232 已逼近上限（剩 23 槽）——"列数可配"不等于"图集无限大"，见 `57` §1 与 `docs/16`。

### 2.1 Tilemap 图块规范（环境/地面）
|项目|规范说明|星露谷对照|
| ---- | ---- | ---- |
|基础Tile尺寸|**固定32×32px**，所有地表、墙体、物件图块统一，不混用16×16与32×32同地图；若使用16px素材，导出阶段2倍最近邻放大至32×32，禁止双线性模糊放大|星露谷原生全部地图tile 32×32，无混合尺寸|
|图片格式|PNG‑24，透明通道，**关闭抗锯齿，硬像素边缘**，禁止JPG作为源素材|全部源资源PNG，无模糊软边|
|Tile分层|地图分为三层：<br>①背景层：地面、泥土、草地、石板（不可交互）<br>②中景层：作物、可拾取道具、建筑主体、NPC、敌人<br>③前景层：树冠、屋檐、栏杆，遮挡玩家角色|星露谷地图三层渲染逻辑，前景物件遮挡角色|
|图块拼接规则|地表图块必须支持无缝拼接；土地、田埂、石板边缘单独制作过渡tile；田地地块支持犁地、湿润、干涸3种状态|耕地拥有干湿状态变体，地块边角过渡tile齐全|
|装饰物Tile（灯笼、石碑、牌匾）|静态装饰物32×32；高于单tile的物件使用多tile拼接（例如大树占用2×2 tile），锚点对齐网格|大树、建筑采用多tile组合摆放|
|图集预算与寻址|每张 Tilemap 组件用 `tiles_format=1;atlas_cols=N;atlas_rows=M` 声明图集行列，**贴图尺寸必须正好等于 `N×M×32`**；未用到的槽位全透明。每地图 ≤4 张图集（ground/farm/moist/crop 各一张），单张 ≤1024×1024——口径与"为什么不再是一图一集"见 `57` §1 性能预算（M72-04 定）。**autotile 的变体上限是 16，不是"按需"**：邻接掩码是 4 bit（上下左右），`tilemap.rs` 的 `AUTOTILE_SLOTS = 16`，条目号 `entry = 1 + kinds*span + (kind-1)*16 + mask % 16` ⇒ 一种材质最多 16 个边角形态，**想超过 16 种外观只能换 tint 或换第二张图集，不能往 autotile 里加**。复现 `cargo run --quiet -p game --example jhyt_m72_autotile_mask -- ../examples/game_jhyt`（`cells=64 dirt_border=12 dirt_interior=4 mask_kinds=9`，含"全草图内部格必须是 0b1111 + 条目 18"的正向对照）；web 宿主的 Lua 垫片与引擎同解这张图是同一门的 §⑧，换根跑时必须把 `plugins/webgl/` 一起带上，否则那条报"找不到路径"|星露谷每图按 terrain/前层分多张图集，单张不超 2048|
|碰撞（`solid`）口径|**每一格实心都必须有可视依据**：那一格的地表本身就是墙/水，或有一个 sprite 的**不透明像素**压在上面——按 sprite 的 quad 矩形标是错的（建筑贴图四角全透明，多标一格就是"在屋外撞空气"）。建筑=本体∪同名拆层屋顶−门洞，树/道具=单格根碰撞，装饰不参与碰撞。读数由 `tools/building_kit.py --check` 现算、门 `jhyt_m72_building_footprint` 独立复算，缺格/悬空格都必须为 0（口径全文见 `57` §1.3 第 10 款，M72-07 定）|星露谷的建筑碰撞贴的是可见墙身，屋外空地不挡人|
|水体岸线|水池按**岸线形状**填水（不规则，实测 manor 池塘 27 格 / 外接框 40 格 ⇒ 填充率 0.675），不许整框灌满；水格外一圈 4 邻域刷石板做石砌岸，否则 autotile 在岸上读成"一摊蓝浮在绿布上"，且临水格该是能站得住的硬地（`places.lua:manor_dock`）|星露谷的池塘是自由岸线 + 石砌边，没有矩形水池|

山庄、村庄、山林、洞窟、室内全部遵循上述规格；MVP/首发资源数量沿用原31号文档。

### 2.2 角色序列帧规范（玩家/NPC/敌人/Boss）
> 本项目采用8方向（四正 s/n/e/w + 四斜 se/sw/ne/nw，2026-10-03 扩展）；斜向条带用"侧身布局 + 正脸头"的 3/4 视角绘制（像素游戏通用做法），动作帧数参考星露谷精简优化。
>
> 屏幕规格：相机 `zoom=2`（docs/52 §4 修订）——屏幕 tile = 32×2 = 64px、一屏 20×11.25 格、角色帧 64×64 在屏幕上 128px 高，与星露谷 16px tile 在 4× 缩放下完全同规格。

1. **画布尺寸**：角色Sprite Sheet单帧尺寸 **64×64px**；角色脚底锚点固定在帧底部`y=52`位置，脚底碰撞盒`12×8px`，保证站在32px tile地面上不浮空不下陷。
2. **线条与像素**：硬像素轮廓，禁止模糊抗锯齿；角色轮廓线1像素；全局统一主光源：**光源来自左上**，阴影落在角色右下方。
3. **动作帧数量标准**

|角色类型|必须动作（对标星露谷）|帧数要求|
| ---- | ---- | ---- |
|玩家主角|待机、8方向行走、锄地、播种、浇水、收割、普通攻击、受击、死亡|**行走每方向 6 帧**循环（v0.3 原写 4，2026-10-10 按盘上序列帧实测改判，见本节末"裁定"）；工具劳作动作6‑8帧；攻击4‑6帧；受击2帧闪白；总帧范围32‑48帧|
|普通NPC|待机、8方向行走、交互姿态；无攻击动作|**行走每方向 4 帧**循环（v0.3 原写 3，同上改判）；待机2帧轻微呼吸动画；单NPC总帧12‑20帧|
|普通敌人（山贼等）|待机、移动、攻击、受击、死亡|**移动每方向 6 帧**（v0.3 原写 3，同上改判）；攻击5‑7帧（实测 4，落在下界之下 1 帧，登记为可接受偏离）；死亡4帧倒地动画|
|Boss角色|待机、移动、多套技能攻击、受击、死亡；体型可大于64×64（例如96×96）|技能动画完整，攻击前摇帧明确，方便游戏做攻击提示。**实测缺口**：`mountain_ape_boss` 只有 idle/walk/attack/hurt 四条 96×96 条带，**没有 faint/死亡条带**，"多套技能"也只有一套 attack|

**裁定（M72-13，2026-10-10）：帧数与方向口径以实现为准，本表已按盘上真图刷新，不再留"开放偏离"。**
测量口径 = 直接读条带 PNG 的宽高（一帧正方形，宽 ÷ 高 = 帧数），逐条读数与可重跑命令在 `57` §3.2 末段，
更正记录在 `58` §15 第 3 条。实测事实：主角 `idle 4 / walk 6 / hoe 4 / water 4 / attack 4 / hurt 2 / faint 4`
（7 动作 × 8 方向 = 56 条，正是门 `jhyt_m21_appearance` 里 `clips != 56` 那句的出处——**它锁的就是 8×7，
不是"写死 4×7=28"**）；10 个 NPC 各 `idle 2 / walk 4 / talk 2`；敌人 `idle 4 / walk 6 / attack 4 / hurt 2 / faint 4`。
方向数实测 **8**（`s/n/e/w/se/sw/ne/nw` 齐全，12 个角色目录每个后缀各 56 个文件），
所以 `docs/54` §6.1 的"4 方向"是实现之前的旧口径，已就地标废（`54` 的经脉 6→12、结局 4→5 同一处更正；
复现 `grep -c '^\s*id = ' scripts/data/meridian.lua` → 12、`grep -o 'id = "ending_[a-z]*"' scripts/data/endings.lua | sort -u` → 5 条）。

4. **Sprite Sheet排版规则**
- Sheet按【行=动作类型，列=方向/帧】排布；文件命名小写英文下划线；
- 每个动作循环必须标记循环帧数、帧间隔；项目统一默认`200ms`，快动作刀光可下调至100ms；
- 对话头像（Portrait）：**64×64px**，每个角色至少4套表情（平静、开心、生气、忧伤），首发关键角色扩展至6套表情；头像同样左上光源，1px硬轮廓。
  **实测现状（2026-10-10，未达成）**：`assets/art/portraits/` 只有 **21 张 = 7 个角色 × 3 表情**（`calm / angry / surprised`）+ 1 张 `_preview.png`，
  既不到"≥4 套"，表情集也和规范不同（无"开心/忧伤"，多出"惊讶"）。复现（在 `examples/game_jhyt/` 下跑，ASCII 标签防 GBK 控制台乱码）：
  ```text
  python -c "import re,glob,os,collections;
  d=collections.defaultdict(set);
  [d[os.path.basename(p)[:-4].rsplit('_',1)[0]].add(os.path.basename(p)[:-4].rsplit('_',1)[1]) for p in glob.glob('assets/art/portraits/*.png') if not os.path.basename(p).startswith('_')];
  s=open('scripts/data/npcs.lua',encoding='utf-8').read();
  npcs=re.findall(r'persist_id = \"npc_([a-z_0-9]+)\"', s); chars=re.findall(r'character = \"([a-z_0-9]+)\"', s);
  print('portrait_chars=%d frames=%s npc_with_portrait=%d npc_without=%d' % (len(d), sorted(set(len(v) for v in d.values())), len(set(npcs)&set(d)), len(set(npcs)-set(d))));
  print('npcs=%d with_character=%d' % (len(npcs), len(chars)))"
  ```
  读数：`portrait_chars=7 frames=[3] npc_with_portrait=5 npc_without=11` / `npcs=16 with_character=10`。
  **立绘与序列帧是两份名单，但重合方向要说清**：有立绘的 5 条 NPC（`a_qi / gu_changfeng / shen_qingluo / situ_kui / zhao_tiesuanpan`）**全部**落在有序列帧的 10 条里，另 2 个立绘角色是两个主角；
  反过来有序列帧的 5 条（`han_tieshan / lin_xiaoman / lu_guizang / su_wanqing / xuanhe`）**没有立绘**，6 条（`a_yao / guimian / lu_qingfeng / niu_dazhuang / qianduobao / shi_gandang`）既无序列帧也无立绘。
  三条独立缺口 = 表情档数（3 而非 ≥4）、立绘覆盖（5/16）、序列帧覆盖（10/16），逐条见 `58` §2.2 与 §15 第 1 条。

> 产出状态（2026-10-10 按盘上目录实测，旧句"主角与7名NPC"作废）：`assets/art/characters/` 下 **12 个目录** =
> 主角 2（`player_female` / `player_male`）+ NPC **10** 条有序列帧；`scripts/data/npcs.lua` 的 16 条 NPC 里
> **另外 6 条没有角色目录**，走 `sprite = "texture=__white__;…"` 的 tint 色块兜底
> （`scripts/world/npc.lua:160` 优先读 `character`，所以这是"待委托"而不是"待修"）。
> 逐条点名与复现命令见 `58` §2.2、§15 第 1 条；立绘（portraits）与序列帧是两回事，别混为一谈。

### 2.3 作物、药材和可交互物件（对标星露谷农作物体系）
星露谷作物特点：多生长阶段、每个阶段独立sprite；成熟后可收获；支持枯萎状态；支持品质差异（普通/银星/金星）。

1. 单块田地Tile：32×32px；作物每个生长阶段占1个32×32 tile。
2. 每一种作物/药材必须产出资源：
`种子图标 → 芽期 → 幼苗期 → 成长期 → 成熟期 → 收获动画 → 枯萎状态 → 掉落物图标 →普通品质/优良品质/极品品质变体`
3. 动画规则：生长阶段切换为静态Sprite；**收获使用4‑6帧短动画（抖动+闪光）**；枯萎作物灰色降饱和调色，保留原有轮廓。
   **实测（M72-08 交付，2026-10-10 复核）**：`assets/art/crops/` **122 张阶段图**（13×4 + 11×5 + 5×3 按类分档）+ 一张 `8×29` 的 CropGrid（232 条目）；收成走 **4 帧 @100ms 抖动 + `harvest_sparkle`**（帧号 `[7, 13, 19, 25]`、瓦值 `[14, 15, 16, 0]`，落在"4‑6 帧"区间内）。复现 `cd engine && cargo run --quiet -p game --example jhyt_m72_crop_stages -- ../examples/game_jhyt`（`stage_files=122 atlas=8x29 entries=232 crops=29`）。**本条列出的两项里，"枯萎状态"与"品质变体"仍未接**（无 `stage_wither` 图、无普通/银/金角标），"每阶段独立 sprite"已达成——旧账那句"作物阶段 sprite 全部缺失"自 2026-10-09 起不成立。
4. 物品图标规范：
- 图标基础尺寸 **32×32px**，硬像素，左上统一光源；统一1px深色外描边，保证在不同UI背景上可读；透明PNG；
- 武器、丹药、材料、任务道具全部遵循；MVP 60个图标，首发扩充到100个图标。
  **实测（2026-10-10，`58` §6 有逐条复现命令）**：盘上 **92 张 32×32 图标**（另 1 张 `_preview.png` 预览页不计），引用侧 **90 条全部命中、缺 0**，且 **92 张里没有一张是纯色块**（最少的一张 4 档 RGBA，中位数 196.5 档）。
  "数量缺口 ≈16 张 / 64 张扩展图标是纯色块待替换"这两个旧口径作废（`58` §15 第 2 条）：**数量已到位，剩下的只是品质问题**（AI 生成的形态够不够发行级），那是外部委托判据，不是清单缺口。

### 2.4 特效规范（对标星露谷特效逻辑）
星露谷极少使用复杂粒子，大量采用Sprite Sheet序列帧特效；粒子仅用于雨雪等环境效果。
1. **优先使用Sprite Sheet序列帧动画，复杂粒子后置**；
2. 特效画布：基础特效帧32×32px；大型攻击特效64×64px；硬像素，尽量避免大面积半透明模糊。
3. MVP必做特效清单：锄地尘土、播种闪光、浇水水花、收获跳字、刀光、命中火花、受击闪白、轻功残影、治疗/中毒状态提示。
4. 环境天气：雨、雪使用分层粒子；天气叠加不遮挡UI；特效帧间隔统一配置。

> 禁止过度炫目的全屏特效，保持像素风格统一，特效优先服务玩法反馈。

### 2.5 UI美术规范（国风武侠像素，对标星露谷UI可用性标准）
星露谷UI特征：高可读性，面板分层，像素按钮，字体清晰，色彩克制，缩放适配窗口。
1. **基础色板**：深墨灰、朱砂红、竹青、米白、旧金色；像素化宣纸、木纹做面板纹理，纹理不能干扰文字阅读。
2. UI元件像素规格：
    - 面板、按钮全部为像素绘制，无矢量模糊；按钮具备普通/悬浮/按下三态；
    - 图标全部复用32×32物品图标资源；HUD状态图标32×32；
3. 字体规范：
    - 使用像素友好中文字体；打包执行字体子集化；

### 2.6 音频资源规范
1. BGM：优先短循环片段，支持无缝循环；MVP音频清单沿用原31号文档；
2. SFX音效：每个交互动作准备**2‑3个变体随机播放**，避免听觉疲劳；格式WAV/OGG，统一采样率44100Hz，控制峰值防止削波。
3. 严禁来源不明古风影视剧音乐，全部登记许可证。

**实测与裁定（M72-13，2026-10-10）**——本条是本文件唯一一处"规范与实现不一致、且两边都不改"的登记，因为差距在**链路**而不是格式：

- 盘上真实容器：`assets/audio/` 16 条 **MP3**，96 kbps / **22050 Hz** / 单声道，编码器 `TSSE = Lavf58.24.101`（ffmpeg 产物）。
  复现：`python -c "import struct,glob; ..."` 逐帧解帧头（口径与完整命令在 `58` §9：读 Xing/Info 的 `frames@+8 / audio_bytes@+12`，自检式 `audio_bytes + 45 == 文件大小`）。
  ⇒ **"WAV/OGG + 44100Hz" 这一档按实现改判为 MP3 + 22050**（微信/web 宿主对 ogg 的支持面窄，MP3 是两宿主都能播的那一档）；"2‑3 个变体随机播放"仍只是**目标档**——SFX 实测单变体，没达成。
- **两条 BGM 的时长与声明不符**：实测 30.07 s / 30.09 s，而 `gen_audio.py` 的表里声明 14 s / 16 s。⇒ 现在盘上的文件**不是当前生成器跑出来的**，"自研可复现"这句话不成立，授权表（`licenses/ASSET_REGISTER.tsv` 的 `audio_jhyt_16_tracks`）因此标 **链路未闭合**，发布门 #9 仍挂"待外部"。
  三处口径同时漂移也一并登记：`THIRD_PARTY.md` 说 16 WAV、`gen_audio.py` 的 docstring 说 15 条而 `build_jobs` 是 16 条、本规范原写 OGG。
- 旧的 `.ogg` 那一套是被 `1cd624b8` 删掉的，**不是没生成过**；不要拿它当"格式一直不对"的证据。
- 全文读数与逐条归因见 `58` §9 与 §15 第 6 条。

**授权表落点偏离（M72-13 裁定，已按实测改）**：`ASSET_REGISTER.tsv` 实际落在**工程根的 `licenses/`**（`examples/game_jhyt/licenses/`），
不在上面这棵 `assets/` 树下，`<asset-id>.txt` 那份许可证正文也仍在原处 `assets/fonts/LICENSE-FusionPixel.txt`。
理由不是手滑：`assets/` 下的每一个非引用文件都会被 `jhyt_m29_season_weather` ⑦ 的资产清点判成
**内容缺口孤儿**（`is_dev_artifact` 只放行 `manifest.json` / `*preview*.png` / `_` 前缀），把授权表塞进 `assets/`
就等于给那条门凭空加一条红；打包器也不复制 `licenses/`，所以 OFL 正文必须留在 `assets/fonts/` 里才随发布包走。
口径：**表在 `licenses/`（工程元数据，不发行），许可证正文在 `assets/fonts/`（发行必带）**。
校验（20 行 × 14 列，全部对齐 `docs/31` §5 的表头）：

```text
cd examples/game_jhyt
python -c "rows=open('licenses/ASSET_REGISTER.tsv',encoding='utf-8').read().rstrip('\n').split('\n'); print('rows=%d cols=%s' % (len(rows), sorted(set(len(r.split(chr(9))) for r in rows))))"
```

读数 `rows=20 cols=[14]`；条目内容（字体 **OFL-1.1**、16 条 MP3 链路未闭合、Noto 条目缺许可证正文 = 未闭合、
Kenney/KayKit CC0 只在引擎示例里、动物与宣媒 = 外部委托）逐条见 `58` §11 与 `59` 的门 #9。
