# 69-江湖有田-商店屏的迁移前黄金对账门（M65a）

68 号 §8 把路线改成"取消 M64b，直接搬三屏"之后，第一屏选 shop（形状最全：整块面板 +
半透明色块 + 9 行列表 + 移动高亮 + 双态页签 + 条件箭头）。本批只做**搬之前那份账**：
`engine/crates/game/examples/jhyt_m65_shop_prefab.rs` 这道门 + 一份 116 行的迁移前黄金表
（`support/jhyt_m65_shop_golden.tsv`，随门 `include_str!`）。搬家本身是 M65b。

里程碑取 M65a：M64a 之后引擎侧没有再补能力，这一批纯游戏侧。

---

## 1. 门量的四段账，与"读数与载体无关"这条地基

一块东西（29 个角色之一）的本帧读数，不管它是动态层 `ui.*` 画的还是将来 `.prefab` 画的，
必须印成**同一串字节**：

| 种类 | 动态层来源 | 实体层来源 | 读数串 |
| ---- | ---------- | ---------- | ------ |
| `panel` | `ui.panel_get` | `Image texture=__white__` + `ui_rects_by_name` | `x,y,w,h,r,g,b,a` |
| `image` | `ui.image_get` | 同上 + `UiImage.texture` | `x,y,w,h,texture,nine_slice` |
| `text`  | `ui.text_get` | 同上 + `UiText.{text,font_size}` | `x,y,size,文字` |

这条地基不是推断出来的，本批用"凭空在实体层造一块"实测过（§3 的对照 C3）：预设里
`ShopBox` 的矩形与颜色，和动态层 `shp:box` 的读数逐字节相等（`160.00,40.00,720.00,640.00,
0.100,0.110,0.150,0.940`），`ShopTitle` 的文字也一样（`184.00,56.00,22.00,云泽村·货摊`）。
所以 M65b 把某块换成预设来画，只要黄金表那行不动，画面就是没动。

两个读数的口径差别，写在门的注释里，这里只提两句：`ui.image_get` 的 `nine_slice` **本身就是一
个含逗号的串**（`16,16,16,16`），拿 `split(',')` 取前六段会把它截成 `16`（本批翻过一次车）；
`text_get` 没有颜色这一维 —— 动态层的 UI 文字**写死白色**（`mesh_ui.rs:416,422` 传
`[1.0,1,1.0]`），所以字色要单独一段账（④），不能塞进黄金表。

## 2. 基线：两个状态，不是一个

| 状态 | 怎么造 | 为什么必须有 |
| ---- | ------ | ------------ |
| `A` | `shop.open_ui('zhao_stall')` 后第 1 帧 | 刚打开：购买页、选中第 1 行 |
| `B` | 往 `data.shops.zhao_stall.stock` 追加 8 条（34 → **42** 行）、`select(42)`、`render()` | 窗口翻到末段：9 个槽是 34..42 号 |

`zhao_stall` 数据里**本来就有 34 条**库存（复现：`cd examples/game_jhyt && sed -n
'/zhao_stall/,/^  [a-z_]* = {/p' scripts/data/shops.lua | grep -c 'item = '` → 34），
9 个可视槽在 A 态就是满的、上下箭头在 A 态就出现 —— 想看到"没翻页"的形状得另找一个短列表
商店，A/B 这一对钉的是"翻页前后逐 id 都不许变"。门里另有一条 `B` 态形状自检：`txt/row*`
必须占满 9 格（`shown_rows != ROW_LIMIT` 直接红），否则这把钥匙只测了 A 态。

## 3. 反面对照：五道红，一次跑成

门登记进 `scripts/verify.ps1`（M63 之后、阶段 2 内容门之前）。按用户的口径，新门必须红一次：

| # | 怎么造的红 | 红在哪一句 |
| - | ---------- | ---------- |
| C1 | 黄金表第 14 行 `txt/title` 的 y 改 56.00 → 57.00 | `黄金对账第 14 行不一致：期望 …57.00… 实得 …56.00…` |
| C2 | 黄金表第 59 行 `A cover panel/box` 的覆盖者改成 `-` | `黄金对账第 59 行不一致`（同一句，说明 ③ 真的在表里） |
| C3 | 实体层凭空 spawn 一块与 `shp:box` 同位置的色块 | `panel/box 在实体层与动态层各画了一遍：实体 "…" / 动态 "…"` |
| C4 | 同上，但把 `shop.lua:697` 那个 `ui.panel` 的 id 临时改名 ⇒ 动态层少一块、实体层多一块 | `这一屏半搬了：既有实体层的块又有动态层的块（…）`（点名 58 格里实体层 2 块） |
| C5 | 只在动态层塞一块与本页面板相交的别人的块（`ui.panel('probe_foreign',200,200,…)`） | `这些动态块与商店面板矩形相交：probe_foreign` |

C3/C4 用的是同一份一次性预设 `.cache/m65_probe.prefab`（`.cache/` 已 gitignore），靠临时插在
`main()` 里的一段 `TEMP-CONTROL` 读环境变量来 spawn；跑完已删（现在文件里 grep `TEMP-CONTROL`
是 0 条）。**这段对照买不到什么**：环境变量驱动的注入点没了，下次要重跑 C3/C4/C5 得再插一次；
留个 prefab 在 `.cache` 也只是省重造，不构成任何自动重放。

**没跑成的对照，如实写**：④（字色）与 `entity_reading` 里那两条误用账（色块的贴图不是内置白图、
贴图块带半透明）**在迁移前造不出红** —— 今天实体层一块都没有，能凭空造出来的只有"两层各画一遍"，
而那先被 ①② 拦下（C4 就停在那儿）。它们的对照排在 M65b：整屏搬完之后把一条 `Text` 的 `color`
改成非白、把一个 `Image` 的 alpha 调低，各自必须红一次。

## 4. 覆盖账顺手量出两条既有画面缺陷

③ 把"谁整块盖住了谁"逐块写进黄金表（每块一行 `cover`，`-` = 没被盖住），于是这两条不是我推断
的，是表里的行：

1. **A 态有 8 块被 `shp:skin_bg` 整块盖住**：`panel/box`、`panel/rule`、`panel/sel`、
   `img/close`、`img/divider`、`img/seal`、`img/scroll_up`、`img/scroll_down`。
   机制是两维叠加：色块类别先提交（`push_ui_panels` 在 `push_ui_images` 之前），贴图块类别内
   按 id 字典序（`shp:c…` < `shp:skin_bg` < `shp:step…`），于是**选中行高亮今天根本看不见**
   —— 玩家看到的"当前行"只有行首那个 `>` 字符。
2. **B 态 `panel/sel` 落在画面外**：`shop.lua:701-711` 的 y 是
   `面板顶 + 100 + (绝对行号 - 1) × 行高`，翻页时不跟着窗口走 ⇒ 42 行时读数
   `184.00,1534.00,672.00,34.00`，而面板只到 y=680。它因此反而"看得见"了（没人盖它，
   因为整个都在面板外）。③ 在 B 态的"被盖住"计数从 8 掉到 7，掉的就是这一格。

这两条都是**搬运之前就有的**，不是搬出来的。本批的处理与 M63 一致：**搬家与改画面分两笔**，
黄金表照抄现状（bug-for-bug），否则门绿了也说不清绿的是哪一半。修不修、什么时候修，请裁定
（一条候选：`sel` 的 y 改按**窗口内序号**，顺带让它回到 `skin_bg` 之上 —— 后者要动绘制序，
等于动层序账，别和修 y 挤在同一笔里）。

## 5. 门没有的账

* **版面（`authored`）没有迁移前基线**：这一屏的版面今天住在 Lua 代码里，不在任何数据文件里，
  所以 M63 那种"预设里写的就是 `.scene` 里原来写的"的对账在这一屏没有对象。黄金表那 58 行
  `shown` 是唯一的一份账 —— 这也意味着 M65b 的 `shop.prefab` 写错了数字只能靠这道门红，
  没有第二道能兜。
* **跨屏层序**（shop 面板与 HUD / 引导行谁盖谁）：⑤ 只判"有没有相交"，今天实测**0 个**，
  所以整屏搬不会把谁推到预设底下；真相交时它红，但不负责给出新的层序账。
* `mesh.draws` 里没有文字分段，③ 的实测背书（`submission_order`）只能拿"白图段必须在
  `ui_panel_main_9s.png` 段之前"这一条对（本帧 49 个分段，白图 #14、九宫格 #37）。

## 6. 下一批（M65b）的形状

`assets/prefabs/shop.prefab`：root + 15 张图 + 16 条字 = 32 个实体，行序 = 绘制序，
必须复现今天这套类别/id 序（含 `ShopSkinBg` 排在那 8 块之后 —— 它们今天全被盖住，
所以它们在前在后画面一样，但 ③ 的 `cover` 行不一样，表会红）。`systems/shop.lua` 侧：

* **一个世界只 spawn 一次**（M63 实测：`spawn()` 拿回的是 LIFO 回收槽，同世界反复
  despawn/respawn 会换段序），开合面板改用 `prefab.set_visible`；
* 9 行列表：`set_text` 填窗口内那 9 条、`set_visible` 管占位空槽；`shipping.lua:494` 那种
  "少一个 else 隐藏"的漏子在本屏要逐行核对（68 号 §8 记的）；
* `ShopSel` 用 `set_rect`，y 按今天的绝对行号算（bug-for-bug）；
* 页签按下/未按下是同一矩形叠两张图 + `set_visible` 互斥（没有运行期换贴图这条 API）。

代价：这道门热缓存 4.1 s（复现：`cd engine && cargo run -q -p game --example
jhyt_m65_shop_prefab -- C:/GitHub/RustLua/examples/game_jhyt`），黄金表 116 行（两态 × 29 角色
的 `shown` + `cover` 各一半）、门本体 1040 行；后面四屏每屏都要再交一份这样的表，
`pause` / `shipping` 的状态数比两态多（页签数不同）。
