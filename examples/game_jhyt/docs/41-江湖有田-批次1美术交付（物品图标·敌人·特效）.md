## 3. 敌人（3 种骨架）

| id | 名称 | 骨架 | 动作（×朝向） | 帧数 |
|---|---|---|---|---:|
| `bandit_grunt` | 山贼喽啰 | **复用主角人形骨架** | idle4 / walk6 / attack4 / hurt2 / faint4 ×4 向 | 80 |
| `gray_wolf` | 灰狼 | 四足骨架（本工具实现） | idle4 / walk6 / attack4 / hurt2 ×4 向 | 64 |
| `training_dummy` | 训练木人 | 静态标靶 | idle2 / hurt2（只出 s） | 4 |

### 3.1 为什么山贼要复用主角骨架

`bandit_grunt` 直接调用 `gen_character_sprites.render_frame` + 同一套 POSE 表，
只换色板/发型/配件/武器（朱砂头巾 + 短打 + 单刀）。好处是**敌人的帧尺寸、朝向、
动作帧数与主角完全一致**，战斗接动画时不需要第二套约定；以后加"玄冥会徒""毒蝎"
之类人形敌人，只要在 `enemies` 列表里加一条调色板即可。

### 3.2 四足骨架的两次返工（值得记下来）

狼最初用矩形拼身体和头，描边之后并成一个**灰方块**（预览里像箱子）；
改成椭圆身体 + 独立头部/立耳/四条腿/尾，才读得出四足轮廓。像素画里
**轮廓靠"块之间的关系"而不是"块的形状"**，矩形拼贴在没有内部细节时会完全糊掉。

### 3.3 为什么敌人还是单帧

NPC/敌人由 `entity.spawn` 在运行期创建，而 Lua 侧**没有挂 `Animation` 组件的 API**
（`animation.set` 要求组件已存在，`entity.spawn` 只插 `Transform`，见 `docs/36` §8.3）。
所以：

- `data/enemies.lua` 现在指向 `<id>/static_s.png` 单帧（**立刻可见**，不再是白块）；
- 每个敌人目录里已经放好 **1×N 动画条带**，`manifest.json` 里也写好了完整
  `Animation` 组件串；引擎补 `animation.attach(id, str)` 之后，把
  `data/enemies.lua` 的 `sprite` 换成静态帧 + 在生成实体后 attach 一次即可播动画。

### 3.4 山贼喽啰暂未进 `data/enemies.lua`

`engine/crates/game/examples/jhyt_m18_combat.rs` 第 66 行断言
`#(require('data.enemies').list()) == 2`。加第三个敌人会让这条 M18 验收失败，
所以本次**只交付美术与 manifest**，没有动数据。要启用的话是两处改动：
`data/enemies.lua` 加一条记录（`map = "combat_arena"`）+ 把该断言从 2 改成 3。

### 3.5 数据接线交叉校验

`gen_enemy_art.py --check` 除了校验图片，还会扫 `data/enemies.lua` 里所有
`texture=...png` 路径并确认文件存在（跳过注释与 `__white__`）。
打错路径不会让游戏报错、只会画成白块，所以这道校验是必要的——
已用"故意写错 `gray_wolf/static_typo.png`"反向验证过：确实 exit 1 并指名该路径。
