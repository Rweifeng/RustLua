# 《江湖有田》竖版 720×1280 改造

- 文档版本：0.1（M32）
- 目标：把 `examples/game_jhyt` 从 **1280×720 横屏**整体改为 **720×1280 竖屏**——
  设计分辨率、8 个场景的 UI、7 个 Lua 面板、场景生成器、发布窗口尺寸、headless 验收，
  一处不漏地跟着翻过来，并用 `jhyt_*` MVP 套件 + `game --check` 验收
- 产出：
  - `scripts/ui/layout.lua`（**竖版设计分辨率与全部面板几何的唯一定义处**）
  - `scripts/ui/layout_check.lua`（版面契约校验器，登记进 `scripts/validate_data.lua`）
  - `tools/gen_*_scene.py` + `scenes/*.scene`（8 个场景重生）
  - `project.toml`（`window_width`/`window_height`）与宿主窗口读取（`core::project_config::window_size`）

## 1. 为什么不能只改一个数字

改造前"1280×720"这件事散在三类地方，彼此没有约束关系：

| 位置 | 表现 | 只改设计分辨率会怎样 |
|---|---|---|
| `scenes/*.scene` 的 `meta ui_reference_width/height` | 声明设计画布（编辑器设计框、scene UI 的 Canvas 缩放参考） | 场景 UI 与 Lua 面板**各按一套尺寸排**，画面上错位且零报错 |
| Lua UI 的硬编码几何（`hud.lua` 的 `PANEL={996,8,276,300}`、`shop.lua` 的 `{320,140,640,440}`…） | 6 个面板的矩形与行宽预算写在各自模块里 | 面板之间开始**互相重叠**，或整块画到屏幕外 |
| 宿主窗口尺寸（`game_app.rs` 写死 1280×720） | 发布窗口比例 | Lua 动态 UI 是**屏幕像素空间**，比例不对就整块错位 |

关键引擎事实（决定了改造方式，写在这里避免下次再查一遍）：

* **场景 UI**（scene 文件里的 `UiLayout`）在 Canvas 空间，按 `viewport / reference` 缩放
  （`core/ui.rs::authored_scale`）；参考分辨率由 `meta ui_reference_*` 声明。
* **Lua 动态 UI**（`ui.panel` / `ui.image` / `ui.text_at`）恒为 **Screen 空间**
  （`core/script.rs` 里 `space: UiLayoutSpace::Screen`），**不随参考分辨率缩放**。
* 因此"窗口尺寸 = 设计尺寸 = Lua 几何坐标"三者 1:1 对齐是唯一不需要运行期换算的方案。

## 2. 契约（四处必须一致）

| # | 位置 | 值 |
|---|---|---|
| ① | `scripts/ui/layout.lua` 的 `M.DESIGN_W` / `M.DESIGN_H` | `720` / `1280` |
| ② | `scenes/*.scene` 的 `meta ui_reference_width/height` | `720` / `1280` |
| ③ | `project.toml` 的 `window_width` / `window_height` | `720` / `1280` |
| ④ | `tools/gen_*_scene.py` 的 `REF_W` / `REF_H` | `720` / `1280` |

其中 ①②③ 由 `ui/layout_check.lua` 在**启动期、`game --check`、`editor --check`**
三条路径上守（登记在 `scripts/validate_data.lua` 的校验器清单里）：面板矩形必须落在设计
画布内、面板两两不重叠、三处尺寸必须一致。任一漂移都当场报错，而不是等画面上看出来。

## 3. 竖屏版面

```
        │                              │
        │ ▬▬▬▬▬▬▬▬  三条资源条（生命/体力/内力，画在面板正上方）
y=1020  │ 生命(气血) … · 体力 … · 内力 …     │  状态面板 672×124
        │ 时间 … · 天气 …                 │  5 行 × 20px
        │ 金钱 … 文 · 地图 …              │
        │ 快捷栏                          │
        │ 武器 … · 工具 … · 种子 … xN      │
        ├──────────────────────────────┤
        │ 目标 …（七日目标行）              │  y 1178

```

与横屏的差异（**信息一条都没少**，只是重新分组/换位）：

| 项 | 横屏 | 竖屏 |
|---|---|---|
| 状态面板 | 右上角 276×300，9 行 | **底部通栏** 672×124，5 行（合并同类项） |
| 资源条 | 面板正下方 | 面板**正上方**（竖屏没有"右列"） |
| 键位提示 | 顶部 y=8（与地图标题**叠字**） | 底部最后一行 y=1246 |
| 反馈 / 目标 / 引导 | 左下 660 / 634 / 686 | 1204 / 1178 / 面板上沿一行 |
| 天气图标 | 状态面板右上角 | 屏幕右上角 |

> 注：横屏版把键位提示画在 y=8，而 `manor.scene` 的 `HudTitle` 占 y 20..44、
> `HudHint` 占 y 50..72——Lua UI 画在 scene UI 之上，所以顶部本来是"提示压在标题上"。
> 竖版顺手修掉了这个重叠：顶部只留场景标题，键位提示挪到底部。

### 3.2 七个面板矩形（`layout.PANEL`）与同屏分组

| 面板 | 矩形 | 分组 | 版面要点 |
|---|---|---|---|
| `dialogue` | 24,800,672,200 | `gameplay` | 状态面板**正上方**；正文换行上限 2 行 → **3 行** |
| `hud_info` | 24,1020,672,124 | `gameplay` | 底部通栏 5 行 |
| `pause` | 64,330,592,620 | `modal` | 主菜单页与设置页共用；行底衬标出选中行 |
| `inventory` | 64,240,592,700 | `modal` | **单列 10 行**（横屏是 2 列 × 10 行） |
| `quest` | 64,240,592,720 | `modal` | 单列 7 行 + 发布者 + 目标列表 |
| `shop` | 64,240,592,720 | `modal` | 单列 9 行 + 页签 + 数量 |
| `title_btn` | 180,620,360,64 | `title` | 门面三块木牌按钮的**公共矩形**，`+24` 间距递进 |

**分组是这次改造里唯一"不能靠注释表达"的不变量**，所以它在代码里有两个明确口径：

* `M.CONTEXT`：声明**谁可能同屏**——同组面板必须互不重叠，`audit()` 逐个检查。
  * `gameplay` = `dialogue` + `hud_info`：对话面板在 800..1000、状态面板在 1020..1144，
    留 20px 缝。竖屏底部一块通栏放得下"对话框 + 状态行"，因此**说话时状态照样可见**
    （气血/铜钱/任务目标），比"对话时收起状态面板"更好——不必二选一。
  * `title` = `title_btn`：标题门面没有 HUD。
* `M.EXCLUSIVE_GROUPS`：声明**谁必然互斥**——组内面板同一时刻只会开一个，
  因此几何上叠在一起是有意的，`audit()` 豁免它们。
  * `modal` = `pause` / `inventory` / `quest` / `shop`：`state.mode` 是四者之一，
    四种面板共用中部版面。

`audit()` 还断言"每个面板都**恰好**登记在一个组里"：漏登记的面板从此不受重叠检查，
这件事本身会报错。此外 `hud_info` 与 `dialogue` 同组这条断言，正是"对话面板与状态面板
在竖屏底部互相遮挡"的机器防线——它在本轮改造里**真的抓到过一次**（见 §9）。

## 4. 不改的东西（以及为什么）

| 项 | 结论 |
|---|---|
| 世界坐标 / tile 尺寸 / 地图尺寸（40×22 = 1280×704） | **不动**。地图是玩法内容（`farm.lua` 的 FARM 矩形、`maps.lua` 的 spawn/exit 格、`places.lua` 的地点格、战斗验收锚点都按 cell 写死），改地图 = 改玩法与验收。代价：竖屏视口宽 720，40 列里同时可见约 22 列，相机跟随玩家左右平移（见 §4.1）。 |
| 精灵尺寸（32×32 角色、建筑道具贴图） | **不动**。竖屏只是可见范围变窄，不是缩放世界。 |
| BGM/音效/存档/任务/存档版本 | **不动**。 |

### 4.1 相机跟随与取景边界（M32 后续收口，2026-09-23）

竖版改造当时把相机留在了**默认相机**（中心 `(640,360)`、`zoom=1`、无 bounds），"跟随"只是
写在本文的取舍说明里、并没有接线。现在补齐为三处：

| 位置 | 内容 |
|---|---|
| 场景 | 每张玩法地图一个 `GameCamera` 实体：`Camera projection=orthographic;center=<地图中心>;zoom=1;bounds=0,0,W*32,H*32`（生成器 `tools/pixel_kit.camera_line` 单点产出） |
| 脚本 | `scripts/world/camera_view.lua` 每次进图后 `camera2d.follow(player)`，offset/死区/平滑全 0 ⇒ 玩家始终在视野正中 |
| 引擎 | 每帧渲染前 `Camera2D::constrained_center` 把相机中心夹到地图内；换图后新增的 `scene_camera_sync` 把 bounds 换成新场景声明的那份 |

竖屏下的边界事实（几何，不是 bug）：

* **x 轴**：视口 720 < 地图 1280 ⇒ 可夹取区间 `[360, 920]`，"跟随"与"不出图"同时成立；
* **y 轴**：视口 1280 > 地图 704 ⇒ 该轴上界(-288)低于下界(992)，引擎取边界中点，相机被
  **钉在地图纵向中心 352**。屏幕上下因此仍有留白：地图比屏幕矮时这在几何上不可避免，
  要彻底消掉只能放大视野 `zoom > 1.82`——那会缩放整个世界，与"竖屏只收窄可见列数"的
  既定口径冲突，故维持 `zoom=1`。

验收：`cargo run -p game --example jhyt_m32_camera`（进图居中、逐点跟随、贴墙夹取、
四角反投影可见矩形仍在地图内、换图重绑、室内图两轴退化、回门面取消跟随）；
数据门 `world/camera_view.validate_all` 在 `game --check` 上核对"场景 bounds == 真实地图矩形"。

## 5. 发布窗口（宿主侧的唯一改动）

窗口尺寸此前写死在 `game_app.rs`（`PhysicalSize::new(1280, 720)`），工程无法声明自己的
版面比例。现在由工程声明：

```toml
# project.toml
window_width = 720
window_height = 1280
```

* `core::project_config::window_size(root)` 解析：两个键都必须是 ≥1 的整数才生效，
  只写一个或写成非法值时**整对回退**到 1280×720 并给出诊断（不做"半截生效"——
  那会得到一个畸形窗口）；两个键都没写则静默用 1280×720（"没声明"不是错误）。
* 单一测试：`core::project_config` 的 `window_size_reads_declared_pair_and_falls_back_as_a_whole`。

## 7. 已知偏差（有意留下，不是漏改）

1. **夜景底图是纵向拉伸的**。`title_bg_pixel.png` 是 1280×720 的横构图夜景，
   竖版需要整屏覆盖，等比缩小贴顶部会在下方露出一整块空版面。夜景是"暗色天空 + 月 +
   远山"这类没有强水平结构的画面，纵向拉伸后仍然成立，因此选择铺满。
   将来补一张 720×1280 的竖构图底图即可替换（`gen_main_menu_scene.py` 的 `BgNight`）。
2. **墨色横幅等比缩到 2/3**（960×240 → 640×160）。墨晕没有直线结构，等比缩小不露证据；
   要 1:1 就得重画一张 720 宽的横幅（`gen_ui_art.py`）。
3. **木牌按钮底板被压扁**。9-slice 木牌原图 256×72，竖版按钮 360×64（更宽更矮），
   九宫格的四角 18px 不变、中间区域被拉伸。要"完全不变形"就得按 360×64 重出底板。
4. **同一屏可见地图列数从 40 降到约 22**。见 §4 的取舍说明。
5. **横屏裁剪**：`layout.lua` 的 `M.scale()` 是"窗口不等于设计尺寸"时的兜底系数，
   但引擎没有给 Lua 暴露"当前 UI 视口尺寸"的查询通路（`set_ui_viewport` 只有宿主侧），
   所以**运行期不做换算**：窗口尺寸由 §5 的契约保证等于设计尺寸。
6. **地图上下各留一条空白**（y 轴，约 288 世界单位 ×2）。地图 704 比视口 1280 矮，相机在
   该轴上无夹取区间可用，只能钉在地图纵向中心（§4.1）。这不是"相机没跟上"，也不是可以
   靠 bounds 消掉的东西：要么缩放世界（`zoom > 1.82`，已裁定不做），要么把地图加高
   （40×22 → 40×40，会动 spawn/exit/农田/战斗锚点等全部按 cell 写死的内容）。
   将来若要做"上下也跟随"，最小改动是加高地图高度 + 重跑生成器（相机 bounds 会自动跟上）。

## 9. 改造过程中被机器检查抓到的两处真问题

记在这里，因为它们是"版面自检到底值不值"的证据：

1. **`title_btn_gap = 24` 混在 `M.PANEL` 里**：它是标量不是矩形，`audit()` 的第一版
   把它当矩形检查，直接报「必须是 {x,y,w,h} 数值表」。修法是把版面常量拆到
   `M.METRIC`——**矩形表与常量表分开**，检查口径才不混。
2. **对话面板与状态面板在竖屏底部真的会互相遮挡**：`audit()` 的第一版按"全部面板两两
   不重叠"检查，报出 15 条重叠。逐条看下来，其中 14 条是"四种模态面板共用中部版面"的
   有意重叠，只有 `dialogue` × `hud_info` 是**真缺陷**——横屏时两者在右上/右下可以并存，
   照抄坐标搬到竖屏就叠在同一块底部通栏上了。最终修法是**把对话面板抬到状态面板上方**
   （800..1000 / 1020..1144），而不是让 HUD 在对话时收起状态面板：竖屏底部放得下两块，
   玩家说话时照样看得见气血与任务目标。同时把检查口径从"两两不重叠"改成
   「同屏组 + 互斥组」，让 14 条有意重叠变成**显式声明**而不是被静默忽略。
3. **生成器一直在写已被删除的 2D 旧 `Transform` 形态**（`x=..;y=..;scale_x=..`）。
   仓库早已把 `Transform` 收敛成统一形态（`position/rotation/scale`）并删掉了旧读法，
   盘上的场景是当时用一次性工具迁过的——**生成器与盘上场景早就漂了**：
   重跑任何 `gen_*_scene.py` 都会把旧形态写回去，然后启动即失败
   （`entity "BgNight" has an invalid Transform: malformed Transform3D field: x=...`）。
   修法是给 `tools/pixel_kit.py` 加一个 `transform_line()` 单点序列化器
   （2D 视图 → 统一形态：`z=0`、绕 Z 四轴数 `(0,0,sin(r/2),cos(r/2))`、`scale_z=1`，
   9 位小数与引擎 `to_component_str` 逐字节同口径），六个生成器全部改走它。
   现在重跑生成器是**幂等**的，且仓库级数据门
   `scene_migration::shipped_data_uses_only_unified_components` 保持绿灯。
   ——这条是本轮最有价值的意外收获：只改"竖版"不动生成器的话，这个坑会留给下一个
   重跑生成器的人。
