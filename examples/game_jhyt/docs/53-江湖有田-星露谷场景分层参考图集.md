## 2 实测色板（口径写死，别照抄成"官方色板"）
复现命令（PNG 专用，stdlib 实现，无 Pillow 依赖）：
```text
cd examples/game_jhyt
py tools/sample_pixel_palette.py references/stardew/Standard_Farm.png
```
**口径**：分箱宽度 16/通道，故 `#e0a020` 代表真实色落在 `e0-ef / a0-af / 20-2f` 区间；默认按像素总数自适应隔行采样（这三张是 step=10，即每 10 个像素取 1 个），百分比是**采样像素占比**，不是面积精确值。要看精确值传 `--step 1`。

| 色相族 | 实测分箱（占比） | 读法 |
| ---- | ---- | ---- |
| 土路/泥地 | `#e0a020` 13.9%、`#e0a010` 6.0%、`#f0b020` 5.5%（Standard Farm） | 单一条土路就吃掉 **约 25%** 画面，同族 3 档明度，不是一块平涂 |
| 草地 | `#40a010` 8.2%、`#107020` 5.5%、`#308030` 3.5%、`#70c020` 3.2%、`#30a010` 2.0%（Pelican Town） | 绿不是"一个绿"，是 **4-5 档**：亮顶、中调、暗部、偏青的阴影各一份 |
| 水体 | `#3080c0` 5.1%、`#3070a0` 5.0%、`#206080` 2.2%、`#3090c0` 2.2%（Cindersap Forest） | 水稳定 **3 档**：浅岸环带 → 主体 → 深部斑块，靠色阶而不是透明度 |
| 暗部/轮廓 | `#001010` 1.9%、`#002020` 1.8% | 描边与自阴影是**近黑但非纯黑**（B 通道常留 0x10-0x20） |
| 越界封边 | `#004030` 3.9%、`#005030` 2.5% | 地图四周的密林墙是一条固定的深青绿，用来当"不可达"的视觉语言 |

对 51 号规范的直接含义：
- §2.5 的基础色板目前只列了名字（深墨灰/朱砂红/竹青/米白/旧金色），**没有明度档数**。星露谷的实测是"每个色相族 3-5 档"，建议作物/草地/泥地各自补齐档数再投产。
- §2.1 要求"水体支持干湿/过渡 tile"，实测水体分档是**同族色阶**而非叠加半透明——与"禁用模糊/半透明"的总原则一致，可写进验收。

## 3 能直接落到 jhyt 的分层做法（看图所得，标注可信度）
1. **地表交界用"碎点压边"而不是描边**（高可信，已目验的 4 张整图一致：Forest_Farm / Hilltop_Farm / Meadowlands_Farm / pelican-town）：土路与草地之间没有 1px 分界线，是草叶碎点往路面上溢出 1-2px。51 号 §2.1 说的"边缘单独制作过渡 tile"，落地形态就是这个。山庄石板 ↔ 泥地、云泽村道路 ↔ 草地照此办。
2. **点缀层决定"空不空"**（高可信，Meadowlands vs Forest_Farm 对照）：同一套地表，Meadowlands 用草丛 + 小花 + 蓝莓丛（蓝绿色团块）铺满，读作"肥沃"；Forest_Farm 用树桩、倒木、散石，读作"未开垦"。**地表 tile 数量不变，换点缀层的种类和密度就能表达地块状态**——比给每种状态单独做一套 tile 省得多。田地的"犁过/湿润/干涸"三态（51 号 §2.1）建议照这条路走。
3. **崖壁三段式**（高可信，Hilltop_Farm 多处实测）：崖面是**圆石砌体**（不是裸岩）+ 顶部一条草帽沿 + 底部一条暗线；楼梯是**切进崖面的木板条**，台地之间只靠它连通；瀑布从崖顶切口直接落下、落水处有一圈浅色水花。演武场（docs/50）与山庄若做台地，直接用这套三段式，不要画整块大墙。
4. **建筑靠"出檐 + 自阴影"分层**（中可信，目测未逐格量）：屋顶 sprite 明显比墙体外扩，屋檐在墙顶压出一条暗带；左上光源下屋顶左亮右暗。这正好是 51 号 §2.2"光源来自左上"的建筑侧证据。
5. **树/大型物件：视觉占多格、碰撞只占根部一格**（高可信）：整图里树冠彼此重叠成林，但地表网格仍是干净的 32 格——多格视觉 + 单格锚点，是"前景遮挡角色"能成立的前提。
6. **越界用视觉墙，不用空气墙**（高可信）：四周是一条深色密林带（实测 `#004030` 族）。云泽村边界可借，比直接黑边或悬崖便宜。
7. **水陆交界先画 rim 再画水**（高可信，Beach_Farm）：岸线是一圈土色/碎石带，水色环带压在它内侧，所以水看起来"有厚度"而不是贴纸。
8. **前景叶簇比中景同种更暗更饱和，且允许越出画面边缘**（凭 §1.4 第一张）：棕榈叶压在沙地与海面上、并越过左缘和底缘——被遮的是地面与角色，不是反过来。jhyt 的"树冠/屋檐遮挡玩家"要照这个方向画：**前景 sprite 的锚点在地面格，但画面可以明显高出锚点若干格**。
9. **夜景与光晕用抖动，不用模糊**（凭 §1.4 第二张）：整场压成紫调，灯笼周围一圈径向暖色光池，光池边界是棋盘状 1px 抖动过渡。这把 51 号 §2.4 的"尽量避免大面积半透明模糊"从禁令变成了**有正面替代方案：抖动过渡**，建议直接写进验收判据。
10. **同屏多角色按屏幕 Y 排序互相遮挡**（凭 §1.4 第二张）：下方角色压住上方角色的脚部，家具同理。51 号 §2.1 只写了三层，没写**中景层内部的排序键**，这一条要补。

## 4 这批参考买不到的东西（缺口，别拿它当验收依据）
1. **遮挡样本太薄**：§1.1-§1.3 是整图平铺渲染，摊平了没有"谁压住谁"。真机图 7 张里，**户外遮挡只有 1 张**（`ingame-beach-foreground.png`）、室内 Y 排序 1 张（`ingame-newyear-night.jpg`），其余 3 张是 UI/公告特写、2 张未逐张目验。"遮挡时是否给被遮物加深阴影""Y 排序容差几像素""屋檐遮挡是否连带降饱和"这类**规则**，凭 1-2 张归纳不出来。要定规则得本机实机跑一次星露谷截屏。
2. **上一版这里写错过，更正如下（2026-10-03）**：原文写"wiki 体系里没有成建制的游戏内截图集"，那是**查询方式错导致的假阴性**——把 `ailimit=15` 拼在同一个 `--data-urlencode` 里，`&` 被当成值的一部分编码进去，于是每个前缀查询都返回空。重查后的事实：
   - EN wiki `Category:Screenshots` 成员数确实为 **0**（分参重查仍为 0，这条成立）；
   - 但真机/整图截图是**以版本号命名的散图**：`1.6 8p * close/separate`（16 张）、`1.5.6 * close/far`（16 张）、`1.6Teaser` 与 `1.6Teaser2-7`、`1.6Tweet`；

## 5 复现：怎么再抓一批
```bash
# ① 按前缀列文件（wiki 的 MediaWiki API，比爬页面稳）
curl -sG "https://stardewvalleywiki.com/mediawiki/api.php" \
  --data-urlencode "action=query" --data-urlencode "list=allimages" \
  --data-urlencode "aiprefix=Forest Farm" --data-urlencode "format=json"

# ② 拿原生尺寸与直链（titles 用 | 分隔多个 File:）
curl -sG "https://stardewvalleywiki.com/mediawiki/api.php" \
  --data-urlencode "action=query" --data-urlencode "prop=imageinfo" \
  --data-urlencode "iiprop=url|size" \
  --data-urlencode "titles=File:Standard Farm.png|File:Pelican Town.png" \
  --data-urlencode "format=json"

# ③ 下载后必须逐个验签名：curl -L 对 404 页也会写一个"看似成功"的文件。
#    本次就有一张因 hash 打错落成 17KB 的 HTML，靠 head -c 4 == \x89PNG 才抓出来。
```
取直链时注意：`iiprop=url` 返回的 `url` 才是原图，页面里的 `<img>` 常是缩略图；文件名带 `%28` 转义的，落盘后改名成括号，否则相对链接里带 `)` 会让 check-docs 的链接正则截断。
**参数必须一个一个 `--data-urlencode`**：把 `aiprefix=X&ailimit=15` 整串塞进一次 `--data-urlencode`，`&` 会被编码成值的一部分，查询条件变成前缀 `X&ailimit=15`，于是**永远返回空**——本次就是这样差点写下"wiki 没有游戏内截图"（见 §4.2）。空结果不等于没有，先怀疑查询。
