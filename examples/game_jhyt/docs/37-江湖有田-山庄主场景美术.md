# 《江湖有田》山庄主场景美术（地编 + 建筑）

- 文档版本：0.1
- 本版同步：美术资源方案 0.2、UI 资源设计 0.1、角色序列帧设计 0.1
- 目标：把美术资源方案 3.1 节的"Tilemap 与环境"在**主场景（山庄）**落地成
  可生成、可验收、可复现的地编与建筑规格，并说明接入 `scenes/manor.scene` 的方式
- 资源现状：地表 3 套 tileset（各 6 列 ×32px：GroundMap / FarmGrid / FarmMoist）+ 3 个建筑 + 8 类道具 + 场景装配，
  全部由 `tools/gen_manor_art.py`、`tools/gen_manor_scene.py` 生成

## 1. 引擎硬约束（先看这一节再改美术）

| 约束 | 事实 | 影响 |
|---|---|---|
| tileset 只能 6 列 | `core/tilemap.rs` 的 `TILE_PALETTE` 固定 6 项，`tile_uv` 用 `(n-1)/6..n/6` 切 U | 纹理**必须正好 192×32**；加第 7 列永远采不到 |
| V 方向整幅采样 | `tile_uv` 的 v 恒为 0..1 | 纹理高度必须 = tile 高（32），否则格子会被拉伸 |
| tile 值语义被玩法依赖 | `farm.lua` 用 `GroundMap tile == 2` 判定"可开垦" | **第 2 列必须是夯土**，草地/石板顺序不能重排 |
| 农田 overlay 列语义 | `farm.lua` 的 `tile_for()` 写 1..5 | 第 1..5 列必须是 已垦干土/已垦湿土/苗期/生长期/成熟 |
| Sprite 不能选 UV 区域 | `Sprite` 组件只有 texture/size/pivot/tint/sorting | **一个建筑/道具必须是一张独立 PNG**，不能共用图集 |
| 没有 Y 排序 | 精灵只有 `sorting_layer`（background/world/default/actor/foreground/ui）+ order | 上下遮挡靠 **solid 占位**解决，不靠深度排序 |
| pivot=(0,0) 是左下角 | `Sprite::quad()` 局部坐标 = `(-px*w, +(1-py)*h)` 起算，y 朝上 | 建筑用 `pivot=0,0` + transform=左下角世界坐标，最容易对齐格子 |
| 碰撞只看 tilemap | `tilemap.solid` 与 `tiles` 是两个独立数组 | 建筑/道具要"挡住人"就必须在 solid 串里标 1 |

## 2. 地表 tileset

`assets/art/tilesets/manor/manor_ground.png`（192×32，6 列，1 列 = 1 种 tile）：

| 列 | 名称 | 用途 | 画法要点 |
|---:|---|---|---|
| 1 | 草地 | 场景绝大部分 | 低对比噪点 + 草簇 + 零星小花；**不画大特征**，否则整片重复很扎眼 |
| 2 | 夯土 | 药田底、屋舍基底 | 土块 + 碎石点；**同时是 farm.lua 的可开垦判定位** |
| 3 | 石板路 | 屋前石院、田前石路、南门引道 | 每格 2×2 块 16px 石板 + 深色缝，可无缝平铺 |
| 4 | 院墙 | 地图四边包围 | 薄压顶瓦（4px）+ 错缝石砌墙身 + 墙脚阴影；**方向通用**，四个边都不"闪条纹" |
| 5 | 青瓦 | 保留列（与 village 语义一致） | 4px 瓦垄 + 两道瓦棱；主场景未使用，留给屋瓦/檐口类需求 |
| 6 | 水 | 池塘 | 深底 + 横向波纹 + 高光点 |

`assets/art/tilesets/manor/manor_farm.png`（192×32，6 列，FarmGrid overlay）：

| 列 | 语义 | 触发条件（farm.lua） |
|---:|---|---|
| 1 | 已垦干土 | 翻了土、没浇水 |
| 2 | 已垦湿土 | 当天浇过水 |
| 3 | 苗期 | 播种当天～生长第 1 阶段 |
| 4 | 生长期 | `watered_days >= 1` |
| 5 | 成熟 | `watered_days >= growth_days` |
| 6 | 稻茬（保留） | 未接入玩法，留给"收割后残茬" |

overlay 的 tile 值为 0 时透出 GroundMap（即夯土底），所以 overlay 图要自带土壤底，
不能画成透明背景的"植物贴纸"。

`assets/art/tilesets/manor/manor_farm_moist.png`（192×32，6 列，FarmMoist overlay，第三张 Tilemap）：

| 列 | 语义 | 触发条件（farm.lua） |
|---:|---|---|
| 1 | 当日已浇的湿痕（半透明） | `p.crop and p.watered_today` |
| 2..6 | 全透明占位 | 无 —— 列数仍必须是 6，见上表第一行约束 |

**为什么再开一层，而不是给 `manor_farm` 补一个"湿版"列**：`farm.lua` 的 `tile_for()`
在地块有作物时只看 `watered_days`（3 苗期 / 4 生长期 / 5 成熟），当天浇水不改 tile；
而 1..5 列早已被"干土/湿土/苗期/生长期/成熟"占满，第 6 列是留给"收割后残茬"的玩法列。
换句话说"今天浇过水"这件事在现有 6 列预算里**没有任何一格可以表达**，只能叠一层。
叠层不动引擎（引擎侧 6 值上限见 §1），PC / WebGL / 微信三端同时生效。

画法：只画四角湿痕、格边一圈和零星水滴，**中心留空**（湿痕压在作物之上，糊住作物就本末倒置），
alpha 74..230 之间；日结算（`settle_day`）把 `watered_today` 清零时这一格跟着归 0。

层序：FarmMoist 是 `manor.scene` 里**最后一张** Tilemap（id 30 > FarmGrid 的 2）。
原生按 ECS 插入顺序、web/微信按 entity id 升序排 tilemap 批次，两种排序都把它画在作物之上，
湿痕才不会压在下层。

预览：`assets/art/tilesets/manor/_preview.png`（12 格 4× 放大 + 标签）。

## 5. 场景布局与契约

`scenes/manor.scene`（40×22，1280×704 世界单位，正好一屏）：

| 分区 | 范围（cell） | 地表 | 可走 |
|---|---|---|---|
| 院墙 | row0 / row21 / col0 / col39 | 青瓦+石砌院墙 | ✖ |
| 正房 | x2..8, y5..11 | 夯土基底 | ✖ |
| 屋前石院 | x1..12, y1..4 | 石板 | ✔ |
| 柴房 | x4..8, y15..18 | 夯土基底 | ✖ |
| 药田 | x14..33, y4..13 | **夯土** | ✔ |
| 田前石路 | y=3, x13..33 | 石板 | ✔ |
| 南门引道 | x=16, y1..2 | 石板 | ✔ |
| 池塘 | x34..38, y4..9 | 水 | ✖ |
| 南门 | x15..17, y0..2 | （贴图压住院墙） | 门洞 (16,1)(16,2) ✔ |

**必须守住的契约**（`tools/gen_manor_scene.py` 每次生成都会自检，失败直接非零退出）：

1. `data/maps.lua` main.spawn = (16,3)、出口格 = (16,1)，两格必须可走且地表是石板；
2. `data/places.lua` 里 10 个山庄地点格必须可走，且从出生点 4 邻域**可达**（NPC A* 用）；
3. 药田矩形 x14..33 / y4..13 必须整块夯土（farm.lua 判定），且与 `farm.lua` 里写死的 FARM 常量一致；
4. 出生点/出口/地点格不能被建筑或道具的 solid 覆盖。

NPC 寻路只认 `GroundMap` 的 solid，所以建筑与道具的"实体感"完全来自第 5 节的 solid 列表 ——
**加了新道具一定要同时加 solid**，否则玩家和 NPC 会从建筑里穿过去。

## 6. 生成与验收

```powershell
cd examples/game_jhyt
python tools/gen_manor_art.py            # 地表 tileset + 建筑 + 道具 + 预览
python tools/gen_manor_scene.py          # 装配 manor.scene（含契约自检）
python tools/gen_manor_art.py --check     # 6 列 × 32px / 文件齐全校验
python tools/preview_scene.py scenes/manor.scene   # 合成 PNG 预览（不开窗口、不用 GPU）
```

`tools/preview_scene.py` 按引擎规则（6 列切 U、V 全幅、pivot 左下角、layer/order 排序）
把任意 `.scene` 合成为 PNG，并校验：tiles/solid 长度 = w×h、tile 值 ≤ 6、
tileset 宽度 = 6×32、所有贴图存在。**这是本项目的"地编验收"入口**，
不用起游戏就能发现"数据和美术对不上"。

| 验收项 | 标准 | 工具 |
|---|---|---|
| tileset 规格 | 正好 6 列 × 32px | `gen_manor_art.py --check` |
| 列语义 | 第 2 列是夯土、浅层 1..5 与 farm.lua 一致 | `gen_manor_scene.py` 自检 + `--check` |
| 场景结构 | tiles/solid 长度、tile 值、贴图存在 | `preview_scene.py` |
| 玩法契约 | spawn/exit/places/药田 | `gen_manor_scene.py` 自检 |
| 湿痕层 | FarmMoist 是场景里最后一张 Tilemap（id 30 > FarmGrid 的 2）、只有第 1 列有非透明像素 | `gen_manor_art.py --check` + `jhyt_m19_slice` §②（浇水 3 格→1、日结算后→0） |
| 资源链路 | `assetc scan` / `assetc import` / `assetc --check-deps` | 引擎 CLI |
| 装载 | `game --project <项目> --check` 退出码 0 | 引擎 CLI |
| 目视 | `_preview.png`（地表/建筑）与 `preview_scene.py` 输出 | 人工 |

## 7. 与美术资源方案的对应

- 对应 P0：**山庄地面、药田**（3.1 的"山庄地面 3 套"里先做 1 套：草地/夯土/石板）；
- 对应 P1：**药庐/铁匠铺**方向的建筑底座（正房 + 柴房已具备"瓦顶/茅草顶 + 木构"两种范式，
  加药庐只需换配色与门窗）；
- 装饰物（3.1 的 40 件 MVP）已交付 8 类；
- 未做：山林/洞窟/室内 tileset、季节变体、白天/夜晚光照 —— 属 P2 与后续章节。

## 8. 已知限制与后续

1. **没有 Y 排序**：建筑/道具靠 solid 占位保证不会"人被树挡住却站在树前"，
   但道具与玩家在同一格边缘仍可能重叠；彻底解决需要引擎加按世界 Y 排序的图层。
2. **单张草地重复**：只有 1 个草地 tile，整片平铺会有重复感。
   真要做"3 套地面"需要引擎把 `TILE_PALETTE` 从 6 扩到 9+，并让 tileset 列数可配。
3. **village / combat_arena 已不再用灰盒**：village 用自己的
   `tilesets/village/village_ground.png`（docs/39），combat_arena 直接复用本套
   `manor_ground.png`（列语义一致，由 `tools/gen_arena_scene.py` 装配，见 docs/41）；
   `art/greybox/` 已无场景引用，仅留作占位素材。
4. **道具朝向单一**：树/竹/篱只有一张图（无镜像变体），同一张贴图多处复用时会被看出来；
   可后续在生成器里加 `--flip-x` 变体。
5. **湿痕只有"当/不当"两档**：FarmMoist 只用第 1 列，表达的是 `watered_today` 这个布尔量，
   不是含水量深浅 —— 第二天没浇水湿痕就撤，看不到"昨天浇的、今天略干"的渐变。
   要多档就得再叠一层（每层仍是 6 值预算）或让引擎把 `TILE_PALETTE` 扩到 9+，
   后者会同时动 tileset 宽度契约（§1 第一条），三端渲染器都要跟着改。
