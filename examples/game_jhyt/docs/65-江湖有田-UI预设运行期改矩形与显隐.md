# 65-江湖有田-UI 预设的运行期写入面：改矩形与显隐（M62）

上一批（[64-江湖有田-UI 预设运行时桥 prefab 进活世界](64-江湖有田-UI预设运行时桥prefab进活世界.md)，M61）
交的是"版面进预设"：`prefab.spawn` 把 `.prefab` 实体树落进活世界，画得出、点得中，`set_text`
改得了文字。这一批补的是**把代码构建的 UI 迁过来之前必须存在的那两个写入面**：

- **位置由数据定**：背包 10 行、商店 9 行、任务 7 行——版面（图、九宫格、字号、行内偏移）在预设里，
  第 N 行摆在哪里由运行期的数据定。没有写矩形的口子，迁移动态层就等于"预设摆一份、`ui.panel` 盖一份"。
- **这一刻不该出现的节点要能收**：`title_menu` 现在的做法是 `ui.scene_text_visible(name,false)`
  逐名把场景文字隐藏、再由脚本用 `ui.*` 重画一遍（64 号 §1 第 3 行就是这个症状）。隐藏不是"改文字"
  能替代的，它必须同时关掉绘制与点击。

于是新增 `prefab.set_rect` 与 `prefab.set_visible`。这批的实质工作不在两个函数的签名，
而在**它们改的是哪一份真源**：改完必须"画得出/点得中"与"看不见/点不着"同时翻转，
而且只能动本实例。

里程碑号取 M62：M61 之后阶段内容门没有再占号。

---

## 1. 改造前卡住的三件事

| # | 症状 | 根因（改前） |
| - | ---- | ------------ |
| 1 | spawn 出来的预设节点位置**一个数都改不动**：`entity` 侧写 `UiLayout` 组件画面不动，`ui.*` 动态层又要重画一份 | 布局解算读的是 `ui_scene_nodes` 里那份 `UiRectLayout`，而这张表在 spawn 时**建完就定了**；写世界的组件只改了 `entity` 侧读得到的那一份 |
| 2 | 没有"藏一个节点"的口子：`entity.destroy` 会连带丢掉取值（重新显示要重建整棵子树），`Visibility { layers }` 组件只管**绘制** | 命中框走 `compute_click_targets`，它压根不看 `Visibility`——用那条路"藏"起来的按钮，看不见了还点得中 |
| 3 | 一份数据改一次，别的实例跟着掉 | 上一批的并表是"整表覆盖"，实例级的进出只在 spawn/despawn 发生；运行期要局部改，就得能说清"这次改动涉及**哪些键**" |

## 2. 新增的脚本 API：`prefab` 表多两个函数（5 → 7）

| 函数 | 返回 | 失败（都是 Lua 错误，不返回 nil、不静默 no-op） |
| ---- | ---- | -------------------------------- |
| `prefab.set_rect(handle, name, left, top, right, bottom)` | 无 | `没有 handle <n>` / `实例 <n> 里没有节点 "<name>"` / `节点 "<name>" 没有 UiLayout 组件（预设里它不会被画，也没有矩形可写）` |
| `prefab.set_visible(handle, name, visible)` | 无 | `没有 handle <n>` / `实例 <n> 里没有节点 "<name>"`（**没有** UiLayout 也能藏/显，显隐不依赖矩形） |

四边写的是 `UiLayout` 的 `offsets`，口径与预设文件里同一套：
**四边 = 父矩形 × anchors + offset**。默认锚点（`0,0,0,0`）下这四个数就是父坐标里的像素边；
stretch 锚点（`0,0,1,0`）下它们是"相对锚点的边距"，通栏宽度仍由父矩形撑出来。
`anchors` 一律沿用预设里 authored 的值——实现如果"顺手"把 anchors 重置成 0，stretch 节点的宽度会
当场塌成 0，门 ② 就是钉这条的。

## 3. 真源只有一份：`PrefabSpawn::sources`

```
prefab.set_rect / set_visible
  → PrefabSpawn.sources（本实例每个节点的 key/parent/components —— 事实源）
      · set_rect：解析那份 UiLayout 字符串，只换 offsets，写回 sources
                  并 .world.insert(id, layout)（entity 侧读到同一个数）
      · set_visible：只动 PrefabSpawn.hidden（隐藏**子树根**的集合）
  → refresh_prefab_instance(state, handle)
      · keys   = spawn.sources.keys()            ← 只摘本实例登记过的键
      · nodes  = build_ui_scene_nodes(本实例未被子树隐藏的 sources)
      · apply：prefab_ui_nodes 逐键 remove，再 extend nodes
  → 宿主每帧 sync_prefab_ui_nodes → ui_scene_nodes → resolve_scene_ui_layout → ui_layout_rects
      ├─ push_scene_ui 画 quad
      └─ compute_click_targets 算命中框
```

三条要紧的形状：

1. **"藏起来"的实现是"这个节点不建布局项"**，不是"建了再标隐藏"。上面那条链末端只有一张
   `ui_layout_rects`，绘制与命中都从它读，所以**少一个节点 = 画不出 + 点不着**，同一次生效。
   这是选它而不是选 `Visibility { layers }` 组件的全部理由（`rustlua-render/src/visibility.rs`
   那份只看绘制，`compute_click_targets` 不查它）。
2. **隐藏必须是子树闭包**。`resolve_node` 的兜底是"父不在表里 ⇒ 按画布解算"（附带一条
   `MissingParent` 诊断）。所以只把行根本身摘掉、行里的格与标签**不会**跟着消失，它们会被当成
   孤儿**跳到画布原点**（反面对照 RC-B 的实得读数就是 `M62Cell=(10,10,40,20)`）。因此
   `hidden` 存的只是"子树根"，判定走 `hidden_by_ancestor`（沿 parent 往上问，深度上限
   `sources.len()`，`.prefab` 的 parent 边在 `from_text` 末尾已 validate 成树）。
3. **`set_rect` 同时写两处**：`sources` 里那份组件串（重建节点表的事实源）与世界的 `UiRectLayout`
   （`entity` 侧读的那一份）。只写一处就成了"画面按 A 摆、脚本查到 B"，门 ① 两个都断言。

`PrefabSpawn` 因此多带 `sources`（`key → { parent, components }`）与 `hidden` 两个字段，
`instantiate_prefab_state` 建实例时顺手把 sources 抄下来（key = 落进世界的**槽位号**，与 64 号 §2 同一口径）。

## 4. 三条刻意的语义决定

| 决定 | 与谁一致 | 不这样会怎样 |
| ---- | -------- | ------------ |
| 显隐是**子树**语义 | Unity `GameObject.SetActive` | 藏一行要逐个藏行里的图与字，且漏一个就留下"看不见的碎片" |
| 显隐**相对父**：藏父之后单独显示子，子仍不可见 | 同上（activeInHierarchy） | 行的显隐要由行根一处决定；否则"列表滚动"每帧都要重算全体祖先 |
| 隐藏**不销毁**实体与组件 | 同上 | 显示回来要重建子树、重设文字与矩形——背包翻一页的成本 |

显隐的实现只增删一个 key 集合，所以"藏→显"之后运行期改过的矩形与文字**照旧在**（门 ⑤ 断言的正是这条）。
一个副作用要写下来：**没有 `UiLayout` 的节点本来就不参与解算**，藏/显它在读数上看不出差别（它本来就不在
表里），但它的**子节点**如果带布局，仍然会被这次隐藏带走——所以"对无 `UiLayout` 的容器调 `set_visible`"
是合法用法（门 ⑦ 有这条正向断言）。

## 5. 预设层与动态层的硬边界（作者规则）

M62 之后，"运行期要变的 UI" 里能进预设的是：**版面 + 由数据决定的位置/宽高 + 这一刻的出现与否**。
进不了的只有一类：**每帧变化的视觉属性**。

`UiImage` / `UiText` 的 `color` 是 `[f32; 3]`，**没有 alpha 通道**，引擎也没有逐实体淡入接口。于是这些
必须留在 `ui.*` 动态层：

- 按钮呼吸/淡入淡出（title_menu 的灯笼、`hud` 的呼吸高亮）；
- 跟随手指的 tooltip（位置每帧变，且要在任意 z 上）；
- 需要 per-frame 改字体颜色的动态文本。

这条边界不是风格偏好，是组件字段决定的，写在这里是因为迁移时每一屏都会撞上一次。
`set_rect` 能覆盖"数据决定的宽度"（进度条、经验条就是写四边），所以"要每帧动" ≠ "不能进预设"。

## 7. 反面对照：新门必跑，证明它会红

三条都是"看起来只是少写一行"的破坏，每条都在**它该红的那一段**红，且红话能直接指出坏在哪：

| # | 破坏 | 红在哪 | 实得红话（逐字） |
| - | ---- | ------ | ---------------- |
| RC-A | `set_rect` 末尾不刷新本实例的布局节点（只写 sources 与世界组件） | ① | `① set_rect 之后：M62Row 矩形第 0 项（0=x 1=y 2=w 3=h）= 60，期望 300；本帧读数 = … M62Row=(60,600,200,60) M62Cell=(70,610,40,20) …` |
| RC-B | 隐藏只看节点自己、不闭子树（`hidden.contains(key)`） | ④ | `藏了行根 M62Cell 之后它仍在绘制读数里：M62Root=(0,0,1280,720) M62Cell=(10,10,40,20) M62Label=(120,17,80,30) …` |
| RC-C | despawn 时清空整张 spawn 节点表（不按本实例的键摘） | ⑧ | `⑧ despawn 一份之后另一份照旧：M62OtherBtn 没有解析出矩形（spawn 的 UI 不会被画）；本帧读数 = <空>` |

RC-B 的 `(10,10,40,20)` 就是 §3 第 2 条说的"孤儿按画布解算"：偏移被当成画布坐标，节点从行里跳到了画面
左上角——画面上是"标签凭空挪了位置"，比"没藏住"更难查，所以这条必须有读数。
三条破坏跑完全部回退（`grep RC-` 零命中），回退后两道门复绿。
