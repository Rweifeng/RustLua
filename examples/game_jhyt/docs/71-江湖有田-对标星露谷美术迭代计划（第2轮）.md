## 1. 结论：现在像 demo 的六个原因

上一轮把"系统闭环"补齐了（29 系统全绿），但**画面信息量**没有跟上。按对观感的影响从大到小排：

| # | 病因 | 实测数字 | 星露谷同口径 |
|---|---|---|---|
| 1 | **场景几乎没有物体** | `manor.scene` 全图 40×23=920 格，只放了 **15 个非幽灵 sprite**，其中树/竹共 **7 株** | 同尺寸农场图数百株树 + 灌木 + 石头 + 杂草 |
| 2 | **地面只有 5 种瓦、没有边缘过渡** | 地表层 920 格里只用了 5 个取值：`{1:390, 2:269, 3:71, 4:160, 6:30}`；瓦片图集实测全是 `192x32`（6 列 × 1 行） | 每种地形一族瓦含 47 变体（含内外转角、碎点压边） |
| 3 | **中文是平滑矢量字，压在像素美术上** | `project.toml`：`text_render_mode = "vector"` + `NotoSansSC-VF.ttf`；引擎只有 `auto/vector/sdf` 三档，`ab_glyph`→MSDF 一律抗锯齿 | 点阵像素字，1 位硬边 |
| 4 | **HUD 是纯色块，弹窗才是真切图** | `assets/prefabs/hud.prefab` 里面板底 = `texture=__white__;color=0.08,0.09,0.12,0.62`；而 `ui_panel_main_9s.png`（96×96 木框+金角，质量合格）只出现在弹窗类 prefab | 全套统一质感 |
| 5 | **没有前景层、没有阴影、没有遮挡** | 8 张 `.scene` 的 `sorting_layer` 里无前景压人用法；sprite 无脚下投影，建筑无右下投影 | 树冠/屋檐必须压过玩家（`51` §2.1） |
| 6 | **作物是 3 个 32px 格子** | `assets/art/crops/` 目录**不存在**；29 种作物一律 `stages = 3`，画在 `manor_farm.png` 的 SPROUT/GROWING/RIPE 三列里 | 每种作物 4–6 阶段独立精灵 + 收成抖动 |

第 1、2、5 条同一个根因：**引擎的 tilemap 只能寻址 6 列**。这不是美术偷懒，是能力天花板——
`engine/crates/rustlua-ecs/src/tilemap.rs:91 tile_uv(column)` 把 U 切成 6 份、V 恒为 `0.0..1.0`，
`set_cell` 拒绝 >6（`:111`），`.scene` 里每格只存**一个 ASCII 数字**（`to_component_str` `:343`）。
所以本轮必须动引擎，否则重画多少瓦片图集都塞不进去。

第 3、4 条同一个根因：**没有点阵字模渲染路径**。真 1-bit 路径今天只服务 ASCII
（`rustlua-render/src/text.rs:15-79 TextAtlas::built_in`，5×7），CJK 走不到。

## 3. 为什么顺序不能换

```
P0 引擎地基 ── A. tileset 多行多列 + tile 索引 + 变体 + autotile + per-tile tint
             └─ B. 点阵字模渲染（整数吸附 + 1-bit 阈值）
                        │
P1 金标场景（只打 manor 一张）── 沉淀出规范 + 生成器 + 可自动量的验收门
                        │
        ┌───────────────┼───────────────┐
   P2 作物/农田     P3 UI 质感统一    （P1 的规范回流 57/51）
        └───────────────┴───────────────┘
                        │
P4 铺量：其余 7 张图按金标规范重做
                        │
P5 三宿主目验 + 发布门（docs/59）
```

- **P0 不能跳**：P1/P2/P4 的所有场景内容都写进 tilemap 与 sprite 数据，P0 的 `.scene` 编码一改，
  早写的图要重存一遍。先做 P1 等于给自己埋迁移。
- **P1 必须先于 P4**：8 张图一起改，中途一定发现规范要调，然后 8 倍返工。金标一张、沉淀工具、再复制。
- **P3 依赖 P0-B**：UI 换字是 P3 最大的一块观感收益，字模路径不通就先只做 HUD 换切图。

## 4. 引擎侧改造面（P0 的精确清单）

以下每条都带 `文件:行`，认领时照单施工。

### 4-A tilemap 寻址与地形生成

| 改动 | 落点 | 说明 |
|---|---|---|
| `tile_uv` 从「列号」改「索引 + 图集行列」 | `rustlua-ecs/src/tilemap.rs:91` | 新增 `atlas_cols/atlas_rows` 字段，索引 → (col,row) |
| 列数真源换掉 | `tilemap.rs:9 TILE_PALETTE: [[f32;4];6]` | 降级为"无贴图时的调试色板"，不再定义列数 |
| 上界 6 → 255 | `tilemap.rs:111 set_cell`、`:446` 解析器 | `tiles: Vec<u8>` 本身有空间，**类型不用换** |
| **`.scene` 编码迁移** | `tilemap.rs:343 to_component_str` / `:404 from_component_str` | 现在每格一个 ASCII digit，>9 无法表示。改成逗号分隔十进制 + 格式版本号；8 张 `.scene` 全部重存 |
| 渲染取 UV | `engine/src/host/runtime_scene/tilemap.rs:43 build_chunk` | 传图集尺寸 |
| per-tile tint | 同上 `:202`（overlay）、`:297`（world）的 `tint=[1.0;4]` 硬编码 | 顶点色**结构上已有**（`host/frame.rs:22,56` 的 `color:[f32;4]`），只需接数据 → 季节/湿润/阴影统一走这条 |
| 变体（同逻辑瓦多外观） | 新增 | **必须确定性哈希** `hash(x,y,seed)`，否则每帧抖、黄金对账门必红 |
| autotile | 新增 | 邻居掩码 → 索引查表。首版只做 **16 变体（4-bit 掩码）**，不做星露谷 47 变体全表 |
| 编辑器笔刷 | `editor/src/panels/inspector.rs:734,763,791,812`（`brush.min(6)`、`range(0..=6)`）、`panels/tilemap_tools.rs` | 去 clamp，调色板按图集网格出缩略图；网格维度现有 clamp 是 1..=256（`:716,720`），够用 |
| Lua API | `rustlua-scripting/src/script/api/tilemap.rs:130` | 参数已是 `u8`，只需放开 Rust 侧校验 |
| 既有测试 | `tilemap.rs:504-514`、`runtime_scene/tests/tilemap.rs:16` | 断言写死了 `1.0/6.0`，要改 |

**容量**：`tilemap_stress.rs:37` 默认 100×100=10,000 瓦 / 30 帧，编辑器上限 256×256=65,536 格。
40×23=920 格的图加变体和 autotile **不会**碰性能红线，这条不用担心。

### 4-B 点阵中文字模

现状：`font.rs:18 RASTER_SCALE = 96` px/em 出 MSDF；`text.rs:468` 用 **float 次像素**定位 quad；
`shader.rs:110` 已有一条 `sdf==2` 硬阈值 + Nearest 采样路径（今天只给 ASCII 5×7 位图用，`text.rs:273`）。

最小改动路径（不是重写）：

1. 接一款**像素中文字体 TTF**（真 glyf 轮廓，每个字形就是点阵画出来的轮廓）；
2. `TextLayout::build`（`text.rs:468`）加**整数像素吸附**：pen 位置与 quad 角都 round 到整数；
3. `font_size` 从任意 float 吸附到整像素（`ui.text_at` 的 `font_size: Option<f32>`，`api/ui.rs:38`；
   基准 `TEXT_BASE_PX = 12.0`，`text_metrics.rs:12`）；
4. 像素字体强制走 `sdf=2` 阈值档，关掉 `fwidth` 平滑（`shader.rs:77-108`）；
5. 子集化**复用现成通道**：`font_subset::subset_ttf`（`assetc/src/lib.rs:745` 打包期调用）
   就是 TrueType glyf 子集器。字表不是写死的：`char_collect` 实测收 4,623 字符
   （运行时语料 1,731 条 / 1,118 个不同字符），裁出的子集 597,932 字节——
   本条原写的"当前字表 471 字"是 plan 期的估算口径，已按 `jhyt_m30_cjk_text` ② 的实测读数更正。

> **授权已核（2026-10-08 定稿：SIL OFL 1.1，不是 MIT）**：缝合像素字体 Fusion Pixel Font。
> 本段原写 `license.spdx_id = MIT` ⇒ **MIT**，那是只看 GitHub API 得出的**误判**：`spdx_id` 描述的是
> 源码仓库（构建脚本），发布包内附的是 `OFL.txt`，且 TTF 的 nameID 13/14 自证
> "licensed under the SIL Open Font License, Version 1.1"。上游版权行**没有** Reserved Font Name，
> 子集化与改名因此不受条款 3 约束；条款 4/5 要求我们的子集继续用 OFL-1.1（不得转授权）。
> 字体文件已实际取回并核验表结构：有 `glyf`、无 `CFF `、`unitsPerEm=1200`、`fsType=4`
> （允许嵌入+子集化），复现与逐值见 `docs/58` §11 与 `assets/fonts/LICENSE-FusionPixel.txt`。
> 游戏当前字表也已不是 471 字：`jhyt_m30_cjk_text` ② 实测 `char_collect` 收到 4,623 字符、
> 语料 1,731 条 / 1,118 个不同字符，裁出的子集 597,932 字节（全量 7,040,712 的 1/11.8）。
> 结论写进 `58` §11 的资源授权表——`51` 明令"CC0/未授权素材不得漏进发布包"，
> 而 `60` 记的"资源授权表 ⚠️外部"至今未闭合（`licenses/ASSET_REGISTER.tsv` 仍未建，见 `58` §11 末）。

### P0 引擎地基（M72-01 … M72-03）

| ID | 工作包 | 交付判据（可自动量） |

| M72-01 | tileset 多行多列 + tile 索引 + `.scene` 编码迁移 | 一张 12×8 图集逐格 UV 断言；8 张 `.scene` 重存后 `preview_scene.py` 合成图与迁移前**像素级一致**（这是迁移正确性的唯一证据） |

| M72-03 | 像素中文字模（整数吸附 + 阈值档 + 字体接入与子集） | 12px 渲染"山庄炼药"四字的 alpha 直方图**只有 0/255 两档**（±1 容差）；缺字门：`chars.txt` 471 字逐字有非空字模 |

**代价 / 买不到的部分**：
- M72-01 改 `.scene` 格式会**打断 M59–M71 十几道黄金对账门**（它们钉死了矩形与绘制序）。
  这些门比对的是 UI 实体层，理论上不受 tilemap 编码影响，但**必须逐门跑一次**确认，不能假设。
- 4-bit autotile 只能做到"直边 + 4 种转角 + 4 种 T 形"，**做不到**星露谷那种不规则犬牙岸线——
  那需要 47 变体全表或手工装饰层。本轮明确用"autotile 打底 + sprite 装饰层压边"两条腿凑，
  装饰层走 M72-05 的散布生成器。
- 像素字体的**标点与数字**在 12px 下偏挤，长段落可读性会下降。这是像素风的固有代价，
  不是 bug；`51` 的"正文 10–12px"档位可能要上调到 14px，届时窗口内可用文字区变小。

### 8-A `manor` 当金标的连带面（裁定后补）

选 `manor` 意味着它是本轮被改次数最多的一张图：M72-01 换 `.scene` 编码要重存它、
M72-04 重画地表、M72-05/06/07 加装饰/前景/建筑、M72-08 又动它的农田层。三条处置：

- **P1 与 P2 在 `manor.scene` 上不撞车，撞的是同一个文件。** 实测这张图挂三个 Tilemap 组件：
  地表层（entity 1）用了 5 种取值，而**农田层（entity 2）与湿润层（entity 30）开局全是 0**
  （`{'0': 920}` ×2，由运行期犁地/浇水填）。所以 P1 只写 entity 1 + sprite，P2 只写
  entity 2/30 的 tileset 与作物 sprite，**改的是不同 component 行**，语义上正交。
  但文件层面必须**串行**：P1 先落，P2 在 P1 之后 rebase，否则同一张 `.scene` 两边各写一份要手工合。
- **顺序因此定死**：M72-01（编码迁移）→ M72-04…07（P1 地表与装饰）→ M72-08（P2 作物）。
  不把 M72-08 提到前面，是为了让农田层只经历一次编码迁移 + 一次重排，而不是三次。
- **图集预算要提前算**：`51` 定的是"每图 ≤1 张 1024×1024 图集"。`manor` 现在用 3 张 `192x32`
  地表面 + 一批散 sprite。P0 之后地表一族 4 族 ×16 变体 = 64 格（8×8 网格，256×256 就够），
  但加上农田/湿润/作物 29×5 阶段，一张 1024×1024 **装不下**。
  → M72-04 开工前先定"一张图几张图集"的放宽口径，并把结论写回 `51`，别等接完线才发现超预算。

选 `manor` 换到的好处也是实打实的：它是主场景、信息量最大，而且**是唯一能把地形/农田/建筑/
装饰/前景五类东西全压在一张图上的场景**——金标要沉淀的是可复制规范，那它就该覆盖最多的类别。
`village` 反而缺农田这一类。
