## 0. 一句话风格定义

**国风武侠 × 星露谷式 cozy 像素**：硬边无抗锯齿、32×32 世界格、64×64 导出角色帧、左上统一光源、有限墨色描边、低饱和宣纸/竹青/旧金色板、三层场景渲染、少半透明。玩家一眼能从剪影认出"这是武侠农家的山庄"，而不是任何别的游戏。

## 1. 全局像素总纲（可验收硬指标）

| 维度 | 可验收基准（量化） | 不合格判据 |
|---|---|---|
| 世界格 | **固定 32×32 px tile**，全项目地表/墙/物件统一 | 同图混用 16 与 32、或导出做了双线性模糊放大 |
| 角色导出帧 | **64×64 px/帧**（绘制 32×32，导出 ×2 最近邻，`ART_SCALE=2`），相机 zoom=2 时角色在屏上 128px | 帧高 ≠ 64、存在半透明缩放 |
| 描边 | **1 px 硬轮廓**，墨色 `#1F2328`（ink/900），4 邻域 | 描边 >1px、灰色描边、无描边 |
| 抗锯齿 | **全程关闭**，`FilterMode::Nearest`、不生成 mipmap、RGBA8/sRGB | 出现软边、ALIAS 模糊 |
| 光源 | **全局左上**，阴影落在右下方；统一方向，禁止同一批资产出现 2 种光源 | 角色脚下阴影方向与场景光源相反 |
| 调色板色数 | 单场景主色 ≤ **1 主色 + 1 强调色**；角色单帧色数 ≤ **12 色**（含描边与阴影） | 同一场景出现 ≥3 套互不协调色系 |
| 透明背景 | PNG-24 透明通道；禁止 JPG 源素材 | 白底/黑底、不透明背景 |
| 动画帧间隔 | 项目统一默认 **200 ms**（5 FPS 待机类）；快动作刀光可 **100 ms**（10 FPS）；同一动作全方向帧间隔一致 | 同 clip 不同方向帧数/FPS 漂移 |
| 渲染分层 | 背景（地面）/中景（作物·道具·建筑·NPC·敌人）/前景（树冠·屋檐遮挡玩家）三层 | 前景不遮挡角色、Z 序混乱 |
| 半透明 | 仅雨雪粒子与受击闪白允许；UI/角色/sprite 主体**禁止大面积半透明模糊** | 道具/面板用了高斯模糊或 <40% 不透明压字 |
| 性能预算 | 每地图 ≤ **4 张 atlas**，单张 ≤ **1024×1024**；贴图尺寸必须正好等于组件声明的 `atlas_cols × atlas_rows × tile`，未用到的槽位全透明；字体子集首包 ≥2000 常用字；音频 OGG 96 kbps | 单图 >4 atlas、尺寸与声明不符（切 UV 错位）、空槽留残留像素、字体超包 |

**图集预算为什么从 1 张放宽到 4 张**（M72-04 定，回写自 `51` 的旧口径"每图 ≤1 张
1024×1024"）：一张图按**角色**分，而不是一律合进一张——

1. `ground`：地表逻辑瓦（`manor` 现为 12 列 × 9 行 = 384×288，六族满块档 + 每族 16 格过渡）；
2. `farm`：农田 overlay（恒等寻址，6 列 × 1 行）；
3. `moist`：湿度 overlay，画在 farm 之上，只占第 1 列；
4. `crop`：作物图集，29 种 × 5 阶段 = 145 格，本身就要 12×13 以上。

合成一张的代价不是像素（145 + 108 + 12 格远小于 1024²），而是**批次与寻址**：引擎按 ECS
插入序排 tilemap 批次、web 端按 entity id 排，四层各自的 `atlas_rows` 不同，合并就得让
四个组件共享同一套行列声明，任何一层加格子都会挪动另外三层的条目号——四季换色（只换
`texture=`）与 M72-08 接作物线都会撞在这条上。分层之后每层独立扩，预算按层计。

上限仍是硬的：**每张 ≤1024×1024、每图 ≤4 张**。第 5 张必须先改这条口径再动手。

## 1.2 色阶与可读性契约（M72 补充，规范层，不宣称素材已完成）

锁定色板 token 是色相方向，**不是只允许八个 RGB 值**。下表按深→浅列出明确 sRGB hex；不使用含糊的“亮度 ±百分比”，也不宣称这些色值均已用于每张真实贴图。每族四档的 sRGB 相对亮度递增；这只是材质层次，不等于图集变体/可读性验收。

**这张表从 M72-04 起是机器可读的**：唯一口径在 `tools/terrain_ramp.json`，生成器
（`gen_terrain_tiles.py` 画地表、`gen_manor_art.py` 画建筑/道具、`gen_season_variants.py`
出四季）一律从表里取色，**不再在代码里现写 hex**。表与本文不一致时以表为准并回写本文；
`gen_terrain_tiles.check()` 会断言每族"深→浅"相对亮度单调递增、图集每个不透明像素都出自
本表，所以"改了文档忘了改生成器"这种分叉会被门拦下。

| 材质 | 深档（接触/缝隙） | 暗档（背光） | 中档（主体） | 亮档（左上受光） | 表里的族名 / 生成器常量 |
|---|---|---|---|---|---|
| 草 | `#4A6636` | `#5E7C46` | `#6F8F52` | `#7FA35E` | `grass` / GRASS_DARK / GRASS / GRASS_LIGHT / GRASS_HI |
| 土 | `#4E3A26` | `#63482F` | `#7C5C3E` | `#8F6E4A` | `dirt` / DIRT_WET / DIRT_DARK / DIRT / DIRT_LIGHT |
| 石 | `#5C5A52` | `#6E6B62` | `#8E8B80` | `#A5A197` | `stone` / STONE_MORTAR / STONE_DARK / STONE / STONE_LIGHT |
| 水 | `#2F4E6B` | `#3E6485` | `#5D82A0` | `#7FA3D4` | `water` / WATER_DEEP / WATER / WATER_LIGHT / WATER_HI |
| 青瓦 | `#2C363C` | `#3E4A52` | `#4A5560` | `#55626B` | `roof` / TILE_ROOF_DARK / TILE_ROOF / TILE_RIDGE / TILE_ROOF_LIGHT |
| 篱与视觉墙 | `#004030` | `#005030` | `#1E5B38` | `#2E6B45` | `hedge`（`53` §3.6 的深绿视觉墙就是本族深档） |

通用色（`utility`，不属于任何材质族）：墨线 `#1F2328`、宣纸 `#F2EAD8`、旧金 `#C9A05A`、
木器 `#4A3628`——与 §1.1 的 token 同值，列进表是为了让生成器只认一个来源。

**同一格内的第三档明度可以来自顶点色**：`Tilemap` 组件的稀疏 `tints=`/`tints_rgb=` 把整格
乘上 `#F2F5FF`（阴面，0.96/0.98/1.0）或 `#FFFCFC`（阳面，1.03/1.02/0.99）一类的系数。
顶点色是**乘法**而不是新色相，所以它能在"族只有四档"的前提下把大面积同材质地块读出
三档明度；用它冒充材质变体是作弊——它不改变任何一块瓦的构图。

草/土/石/水材质族交付至少四档，但不强迫每一块 tile 用满四色。湿土深档表达状态，不能只把所有干土整体调暗来冒充湿润接线。禁止把颜色数多当成材质完成：必须检查受光面、缝隙、岸线与同屏重复。大面积底色保持低频，装饰不侵入出生点、出口、农田操作格；装饰密度以实际相机视口而非整图数量验收。现有生成器已经有多档色值，真正缺口是统一规范、变体和运行时表现，不是“从未定义过色阶”。

### 1.3 像素单位、锚点与可读性硬门

1. **像素单位**：`1 px` 描边/纹理指 **32×32 绘制空间的 1 像素**；角色导出 `ART_SCALE=2` 后显示为连续 `2×2` 像素块，不能把导出 PNG 的 2px 边误判为 2px 绘制描边。角色单帧仍为 64×64；生成器绘制空间脚底基线是 `y=29`，导出帧对应像素行 `58–59`；旧 §3.1 的 `y=52` 与此不一致，本轮登记为锚点契约漂移，需后续按 sprite pivot、世界脚位与碰撞体联合核定，不能声称已对齐。
2. **剪影门**：角色、建筑、交互道具在 100% 与 50% 缩略预览下都能与相邻地面分离；主体边缘为绘制空间 1px `ink/900`，不得以半透明描边补救。
3. **对比门**：主体与其直接背景至少保持一个明度层级差；UI 文字使用 `paper/50` 或 `ink/900`，禁止低于 40% alpha 的正文。
4. **锚点门**：建筑/道具底边与 32px 世界格对齐；审计工具只能确认文件规格，锚点仍需预览或人工验收。
5. **遮挡门**：背景→中景→前景顺序必须显式登记；树冠、屋檐等前景可压角色，但不可覆盖交互提示与 HUD。现有 `scripts/world/depth.lua` 对actor使用 `order=-floor(y/2)` 并夹到±999；同一2世界单位桶内允许同序，跨桶必须随世界y递减，禁止以实体ID当空间深度。树干/树冠需要分别登记，测试玩家在其前后各至少跨一桶；工具不验证绘制序。当前 tilemap/scene 的底层限制不应被美术文档默认为已解决。
6. **软边门**：PNG 必须 RGBA8；主体 alpha 仅允许 0/255，雨雪与受击闪白另行登记例外。尺寸正确或目录存在，均不等于接线完成。
7. **色阶审计边界**：工具可检查 PNG IHDR、明确 `icon=`/`texture=`/`sheet=` 路径和注册表枚举；不能从文件名、目录或启发式“看起来像”推断场景已接线、素材已被运行时使用。

> 运行 `python tools/audit_art_assets.py` 得到确定性事实；`FAIL missing_asset` 表示注册/规范要求的文件不存在，`FAIL missing_wiring` 表示已有或声明应有的接线指向不存在/缺失字段。两者必须分开处理，`INFO` 仅为事实计数，不是通过门。

## 3. 角色规范（目标 16 NPC + 主角 3 套；现状 10 NPC + 主角 2 形象有序列帧）

### 3.1 序列帧硬指标（8 方向，2026-10-03 由 4 方向扩展）

- **目录**：`assets/art/characters/<char_id>/`，含 `static_<dir>.png`（8 张单帧兜底）+ 各动作条带 + `preview.png`。

## 4. 作物阶段 sprite（最大视觉缺口，目标 29 种）

- **地块**：作物每阶段占 1 个 32×32 tile；单阶段切静态 sprite，**生长切换不做动画**。
- **每阶段 sprite 序列**：种子图标 → 芽期 → 幼苗 → 成长 → 成熟 → 收获短动画（4–6 帧抖动+闪光）→ 枯萎（灰色降饱和、保留轮廓）。
- **现状**：`data/crops.lua` 注册 **24 种田/药作物 + 5 种果树 = 29 条**，当前 `stages=3`；**尚无 `assets/art/crops/` 目录，阶段 sprite 全部缺失**（现行共用 overlay 占位）。
- **目标规格**：每种 4–6 阶段独立 sprite + 品质变体（普通/银星/金星 3 档角标）+ 枯萎态；果树 5 种（桃/梅/枇杷/枣/银杏）树苗→成树→结果 3 态。
- **占位路径约定**：`assets/art/crops/<crop_id>/stage_<n>.png`（32×32，硬像素、左上光源）。

## 5. 物品 / 图标规范

- **尺寸**：32×32 px，硬像素、左上光源、统一 **1px 深色外描边**（保证在任意 UI 背景上可读）、透明 PNG。
- **硬像素量化（2026-10-06 固化，全资产通用）**：任何 AI 生成/外部委托交付的图标必须过硬像素量化——alpha 二值化（>127→255）+ 每通道 6bit 颜色量化，**禁止亚像素抗锯齿软边**（违反 §1"抗锯齿全程关闭"即不合格）。
- **路径**：`assets/art/items/<item_id>.png`（与各 `data/items*.lua` 的 `icon=` 字段逐一对齐）。
- **现状**：注册表 `icon=` 引用约 **130 处**（items.lua 82 + 料理 16 + 畜牧产物 7 + 钓竿 4 + 矿石宝石 11 + 阶段3 道具 10，另 23 鱼种待补 icon 字段），现有 `assets/art/items/*.png` **93** 张，其中 **85 张已替换为真实形态像素图标**（AI 生成+硬量化 78 张、程序化几何 7 张；2026-10-06 完成），缺口收窄至 ≈16 张（未被引用的扩展条目，待外部委托）。
- 武器/丹药/材料/任务道具/料理/鱼/矿石宝石全部同规格；HUD 状态图标复用 32×32。
