# 《江湖有田》角色序列帧设计

- 文档版本：0.1
- 本版同步：总策划案 0.2、美术资源方案 0.2、UI 资源设计 0.1
- 目标：把美术资源方案 3.2 节的"角色"要求，落成**可生成、可导入、可验收**的具体规格
- 资源现状：主角 2 套形象 + 7 名 NPC 已全部产出（9 角色 / 140 条条带 / 448 帧 / 186 个 PNG，约 210 KB）

## 1. 设计总则

1. **一动作一朝向一张条带**：引擎 `Animation` 组件的每个 clip 只采样**一整张 1×N 横向条带**
   （UV 为 `u=frame/cols..(frame+1)/cols`、`v=0..1`），因此"一个动作 + 一个朝向"必须单独出图，
   不能拼成多行图集；换朝向 = 换 clip，不是换 UV 偏移。
2. **32×32 帧、4 方向**：帧尺寸与世界 tile 1:1（32 世界单位），脚底基线固定在 `y=29`，
   角色脚底与碰撞球心（`Collider shape=ball;radius=12`）的关系与灰盒期一致。
3. **先轮廓后细节**：所有帧统一 1px 墨色描边（`ink/900 #1F2328`），保证在药田绿底、
   夯土、石板、水面等所有地表上都能读出剪影。
4. **一套色板**：角色配色与 UI 同源（见第 3 节），NPC 主色沿用 `scripts/data/npcs.lua`
   灰盒期的 tint 意图（粉=沈青萝、金=赵铁算盘、青=林小满……），避免"美术与数据各说一套"。
5. **最近邻、sRGB、透明底**：引擎精灵采样为 `FilterMode::Nearest`，纹理为 RGBA8/sRGB、
   不生成 mipmap；PNG 必须透明背景，禁止 JPG。
6. **数据与图分离**：中文显示名、身份说明、动画串放 `scripts/data/characters.lua`；
   文件名只用小写英文、数字和下划线。

## 2. 视觉基准

### 2.1 画布与骨架

| 项目 | 规格 | 说明 |
|---|---|---|
| 帧尺寸 | 32×32 px | 与世界 tile 32 单位 1:1，可在编辑器里直接对齐格线 |
| 脚底基线 | `y=29` | 阴影画在 `y=29..31`，不参与描边 |
| 头 | 7×7 px，居中轴 `x=16` | 面向东/西时整颗头右移 1px 做侧脸 |
| 躯干 | 10 行（`y=13..22`） | 宽度由体型 `half_w` 决定 |
| 腿/鞋 | `y=23..29` | 长衫/裙摆会盖到大腿，只露鞋与一截裤脚 |
| 描边 | 1px，4 邻域 | 由生成器统一后处理，手绘帧同样遵守 |

### 2.2 身高与体型分级

角色辨识度优先靠**剪影**，其次才是颜色：

| 分级 | `head_top` | 成品身高 | 使用者 |
|---|---:|---:|---|
| 高个 | 3 | 27 px | 顾长风（退隐镖师）、玄鹤（云游道士） |
| 标准 | 5 | 25 px | 主角、沈青萝、韩铁山、苏晚晴 |
| 偏矮 | 6 | 24 px | 赵铁算盘、林小满 |

| 体型 | `half_w` | 使用者 |
|---|---:|---|
| 清瘦 | 2 | 玄鹤 |
| 标准 | 3 | 主角、沈青萝、林小满、顾长风、苏晚晴 |
| 壮硕/丰满 | 4 | 韩铁山（铁匠）、赵铁算盘（商人） |

### 2.3 服装类型

`robe` 长衫（赵铁算盘、顾长风、苏晚晴、玄鹤）、`skirt` 上衣+裙（主角女、沈青萝）、
`shorts` 短打+裤（主角男、林小满）、`apron` 短褂+皮围裙（韩铁山）。
服装类型决定下摆高度，也决定腿部的可见长度，是"远看像不像那个人"的第二层信息。

## 4. 主角形象

| id | 形象 | 主色 | 轮廓要点 |
|---|---|---|---|
| `player_male` | 青衫少侠（默认） | 米白上衣 + 竹青裤/护腕 + 靛蓝交领 | 束发髻、背负木剑、标准体型 |
| `player_female` | 青衣女侠（可选） | 同上 + 旧金腰带 | 高马尾（走路时甩动）、裙摆外扩 |

设计取向：

- **素色短打**：主角是"刚接手荒废山庄"的少侠，服装不能比 NPC 更华丽，
  米白 + 竹青在药田/夯土地表上对比度稳定，且不抢 NPC 的身份色。
- **性别只改轮廓不改动作集**：两套形象共用全部 28 个 clip（动作帧数、FPS 完全相同），
  换人只换 sheet 路径，`Animation` 组件串结构不变。
- **自定义扩展路径**（对应总策划案 4.1 的"肤色/发型/服装主色"）：
  生成器里每个角色就是"骨架上色 + 发型函数 + 配件函数"的组合，
  新增配色 = 复制一条 `CHARACTERS` 记录改 `palette`，无需重画任何一帧。

设计约束：

- **不与地表撞色**：林小满的竹青与药田绿同色系，靠"黛蓝头巾 + 茶篓"补足辨识度；

- **数据同源**：新增第 8 个 NPC 时，本表加一行 + 生成器 `CHARACTERS` 加一条记录即可，
  命名与 `scripts/data/npcs.lua` 的 `persist_id` 去掉 `npc_` 前缀后保持一致。

## 6. 动作与帧表

| 动作 | 帧数（主角 / NPC） | FPS | 循环 | 用途 |
|---|---:|---:|---|---|
| `idle` | 4 / 2 | 6 | 是 | 待机呼吸；NPC 只做 2 帧省量 |
| `walk` | 6 / 4 | 10 | 是 | 行走；主角 6 帧含"接触-下沉-过渡"两轮 |
| `talk` | — / 2 | 4 | 是 | NPC 交互姿态（抬手 + 呼吸） |
| `hoe` | 4 / — | 8 | 否 | 锄地：举-落-触地翻土 |
| `water` | 4 / — | 8 | 否 | 浇水：提壶-倾斜-出水花-收 |
| `attack` | 4 / — | 12 | 否 | 攻击：蓄力-挥击(带刀光)-收势-站定 |
| `hurt` | 2 / — | 6 | 否 | 受击后仰；闪白由运行期叠加，不画进帧 |
| `faint` | 4 / — | 6 | 否 | 屈膝-跪-侧倒-躺地（末帧为倒地独立剪影） |

帧量对照与说明：

- 主角每套形象 28 条条带 / 112 帧（`idle 4 + walk 6 + hoe/water/attack 各 4 + hurt 2 + faint 4`，
  再 ×4 方向）；两名 NPC 各 12 条 / 32 帧（`(idle 2 + walk 4 + talk 2) × 4`）。
- 美术资源方案 3.2 给 MVP 的预算是"玩家 32–48 帧、NPC 12–20 帧"。
  本版按**全 4 方向 + 完整动作集**产出（主角 112 帧、NPC 32 帧），
  属于"首发级"帧量；若需要压到 MVP 预算，把 `idle` 降到 2 帧、`walk` 降到 4 帧、
  工具/战斗动作只保留 `s`/`e` 两个朝向即可（生成器改 `POSES`/`ACTIONS` 表）。
- 非循环动作（`hoe`/`water`/`attack`/`hurt`/`faint`）依赖引擎的 `take_ended()` 只触发一次的语义
  做"动作播完回到 idle"，脚本侧不要用帧计数重复判定。

## 7. 文件与命名

```text
assets/art/characters/
├── manifest.json                 # 机器可读清单（含引擎组件串）
├── _overview.png                 # 全角色 idle_s / walk_s 总览
└── <char_id>/
    ├── idle_s.png  idle_n.png  idle_e.png  idle_w.png     # 1×(4|2) 条带
    ├── walk_s.png  ...                                    # 1×(6|4) 条带
    ├── talk_s.png  ...                                    # NPC：1×2
    ├── hoe_/water_/attack_/hurt_/faint_<dir>.png          # 主角：1×(4|2)
    ├── static_s.png  static_n.png  static_e.png  static_w.png   # 单帧兜底（无 Animation 时用）
    └── preview.png                                        # 该角色全部条带放大 2 倍预览
```

- 命名：`<action>_<dir>.png`，全小写；`dir` 为 `s`（面向镜头）/`n`（背对）/`e`（朝右）/`w`（朝左）。
- `w` 朝向由 `e` 水平镜像生成，保证左右完全对称、不产生手工误差。
- `static_<dir>.png` 是给"没有 `Animation` 组件的实体"用的单帧图：直接放进 `Sprite` 的
  `texture=` 就是一张正常精灵（条带不能直接当 Sprite 贴图，会被整体压扁）。

## 8. 引擎接入

### 8.1 组件格式

```text
Animation  default=<clip>;clip:<name>:<sheet>:<cols>:<fps>:<looped>
Sprite     texture=<静态帧>;size=32x32;tint=1.000,1.000,1.000,1.000;sorting_layer=actor
```

带 `Animation` 的实体，渲染时用 clip 的 sheet 覆盖 `Sprite` 的 texture，`Sprite` 只负责
尺寸/排序，所以**两者必须挂在同一实体上**，且 `size` 用 `32x32`。

### 8.2 主角（已落地，见 docs/46）

7 张可玩场景的 `JianghuPlayer` 都已换成静态帧 + Animation 组件行，
**不再手写纹理路径**：由 `tools/character_art.py` 的 `player_art()` 从
`assets/art/characters/manifest.json` 取串（与 `data/characters.lua` 同源）。

```text
component	3	Sprite	texture=assets/art/characters/player_male/static_s.png;size=32x32;tint=1.000,1.000,1.000,1.000;sorting_layer=actor
component	3	Animation	default=idle_s;clip:idle_s:assets/art/characters/player_male/idle_s.png:4:6:true;clip:walk_s:...;clip:hoe_s:...
```

运行期由 `player.lua` 按 `state.appearance` 挂载/纠正（`sprite.set` + `animation.attach`），
每帧用 `animation.set(id, "walk_" .. dir)` 切状态、`animation.ended(id)` 判断动作播完 ——
完整设计、玩法接线点与验收见 [主角形象系统](47-江湖有田-主角形象系统.md)。

### 8.3 NPC 动画：缺口已闭合（方案 A 已落地）

`npc.lua` 通过 `entity.spawn(name, persist_id)` 在运行期创建 NPC，而 `entity.spawn` 只插入
`Transform` —— 历史上 Lua 侧没有"挂 Animation 组件"的 API，NPC 只能显示 `static_<dir>.png` 单帧。

**现状**：引擎已补 `animation.attach(id, component_str)` 与 `animation.clips(id)`
（`engine/crates/engine/src/core/script.rs` 的 `animation` 表，带单测
`runtime_spawned_entity_can_attach_animation`），三处运行期实体全部接上：

| 使用者 | 挂载点 | 状态切换 |
|---|---|---|
| 主角 | `player.lua` 的 `apply()` | `idle_/walk_<dir>` + `hoe/water/attack/hurt/faint` |
| NPC | `npc.lua` 的 `apply_art()` | `idle_/walk_<dir>`（按移动与主轴朝向） |
| 敌人 | `enemy.lua` → `data/enemy_art.lua` 的 `apply()` | `idle/walk/attack/hurt/faint` |

`sprite.get(id)` 可读回 `texture` 与 `animation_sheet`，验收能直接断言"现在渲染的是哪张图"。

## 9. 生成与验收

### 9.1 生成

```powershell
cd examples/game_jhyt
python tools/gen_character_sprites.py                 # 生成全部 + 刷新 manifest/lua + 自检
python tools/gen_character_sprites.py --only xuanhe    # 只重生成某个角色
python tools/gen_character_sprites.py --preview-scale 4
python tools/gen_character_sprites.py --check          # 只校验（尺寸/列数/RGBA/命名/lua 引用）
python tools/gen_character_sprites.py --ascii player_male walk s   # 把帧打印成字符画调参
```

- 生成器只依赖 Python 3 标准库（自带 PNG 编码器），**不需要 Pillow**。
- 形象/动作的唯一来源是生成器的 `CHARACTERS` 与 `POSES` 表；`manifest.json` 与
  `scripts/data/characters.lua` 都是它的产物，不要手改。

### 9.2 验收清单

| 检查项 | 标准 | 工具 |

## 10. 后续扩展

1. **敌人**：山贼/玄冥会打手/野兽可复用同一套骨架与 `attack/hurt/faint`，
   只需换色板、加面罩/刀；`data/enemies.lua` 已存在，接 `characters.lua` 即可。
2. **Boss**：帧尺寸升到 48×48 或 64×64，单独一份生成器参数（`FRAME` 目前是常量，需参数化）。
3. **头像**：对话头像 48×48 或 64×64，按同一色板出"平静/惊讶/生气"表情集。
4. **换装**：服装 = 色板 + 配件函数，可按季节/门派声望解锁；
   注意**换装必须重出条带**（像素画不能像骨骼动画那样运行时换部件）。
5. **8 方向**：当前 4 方向是引擎无翻转/无旋转帧的前提下的最优解；
   若改 8 方向，帧量翻倍，应同时评估"斜向行走是否真的必要"。
