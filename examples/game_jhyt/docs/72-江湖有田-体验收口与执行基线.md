# 江湖有田：体验收口与执行基线

## 1. 本轮结论与范围

本轮基于工作区源码核对，不把历史文档中的“验收通过”当成本轮实测结果。项目已经具备农业、交易、战斗、任务、存档等骨架，下一阶段应优先打通**玩家能够发现、理解并完成的药田经营闭环**，而不是继续增加独立系统。

交付分为三条线：本文负责策划与优先级；[数值审计](<73-江湖有田-数值审计与调优.md>)负责计算口径与恢复规则；[美术落地审计](<74-江湖有田-美术落地审计.md>)负责资源规格、缺口与接线证据。旧里程碑保留为历史记录；与本文冲突的“已可玩/已验证”必须按证据层级重新判断。

本轮不改现有 Tilemap/场景迁移，不承诺发行级手绘美术已完成，不改存档 provider 或教程顺序。

## 2. 产品主轴

**一块药田养活一座山庄，一次行医牵出一段江湖。**

- 经营提供稳定收入、药材与安全感；战斗用于守护、探索和获得稀缺材料，不成为日常强制打卡。
- 核心循环：种植/采集 → 留药或出售 → 炼药/委托 → 铜钱与关系 → 工具/山庄成长 → 次日新选择。
- 每日只突出一个主目标和一个可选活动；教程、七日目标、主线三者不能同时争抢“必须做”的优先级。
- 首发体验面：Windows PC、1280×720 横屏；32px 逻辑网格。四季系统存在不等于四季内容均完成可玩验收。

## 3. 证据分级：系统存在不等于玩家可玩

| 等级 | 判据 | 可对外描述 |
|---|---|---|
| 数据层 | 注册表/引用校验通过 | 已有设计数据 |
| 系统层 | 真实 API 正反例、存档往返通过 | 已实现规则 |
| 交互层 | 新档通过游戏输入发现入口、完成操作并获得反馈 | 可玩闭环 |
| 体验层 | 编辑器/运行器/发布包画面和输入验证，真人测时 | 达到体验指标 |

[主入口](<../scripts/main.lua>)注册了多个新增系统的存档与日结算，但这些调用本身不证明存在可用交互入口。[输入分发](<../scripts/ui/input.lua>)和[交互分发](<../scripts/systems/interaction.lua>)应与每个系统的入口逐一对账。矿脉、医馆、茶会等未在本轮完成输入到反馈的整链验证，不按“系统套件通过”直接标为可玩。

## 4. 新手与七日节奏

### 当前事实与本轮小修

- [教程表](<../scripts/data/tutorial.lua>)共16步；萝卜复习段在交付、制作之后，不是开局教程。保留顺序是因为[教程运行时](<../scripts/ui/tutorial.lua>)以数字索引入档，直接重排会把旧档指向别的任务。
- 新档背包没有萝卜种；货摊售价4文/粒、08:00–18:00营业。本轮明确购种路径，不增加免费物品和经济产出。
- 灵芝需7个有效成长日，第一天播种通常到第8天收；早期委托可由山道采集解决，不应让玩家误以为必须空等七天。
- [七日目标](<../scripts/data/goals.lua>)首日判断接受任意播种，文案改成“种下1株作物”；第七日物品名统一为“回复药”，不再写“回气散”。
- [M60样例](<../../../engine/crates/game/examples/jhyt_m60_tutorial.rs>)改用真实商店购买种子再进入种植段，不再直接注入萝卜种。仍跳过前九步、直接定位地块，因此不证明开局五分钟指标。

### 下一版新手方案（待实现，非本轮完成项）

| 阶段 | 玩家动作与反馈 | 退出判据 | 失败保护 |
|---|---|---|---|
| 0–2分钟 | 找到普通耕地、选工具、翻土播种浇水 | 真实输入完成一次播种浇水 | 有种子来源、土地类型与工具提示 |
| 2–5分钟 | 首次跨天、再浇水、收获快熟作物 | 新档到首次收获计时 | 允许提前睡觉；不靠调试跳步 |
| 5–15分钟 | 出售部分收成、保留一份、见药庐NPC | 钱包与任务进度可见变化 | 保留任务材料提示；不强制全卖 |
| 15–30分钟 | 采药→制作→交付 | 完整药田/采药到行医闭环 | 给替代材料来源；战斗可绕行 |
| 30–60分钟 | 建筑或工具成长选择、可选演武 | 玩家能解释下一目标 | 不用所有系统同时教学 |

这些分钟数是**目标**。计时从新档点击开始到真实收获，包含阅读、步行、菜单；暂停和离席另记，不以headless运行耗时替代。

重排前必须实现教程版本与稳定步骤ID迁移：旧档继续旧步骤或映射至等价动作；缺字段老档不强制重开；已领奖不重发。季节变化、破产、背包满、任务已提前交付均需负例。

### 七日目标定位

七日是软引导，而非错过一天永久失去内容的竞速挑战。当前实现按实际日结算；下一版需决定“错过补做”或“成长章节不绑日期”，并增加补领奖幂等与读档用例后才能改规则。本轮不偷偷改变奖励与存档键。

## 5. 数值与美术共同验收

- 不只看首茬利润/天：同时报告再生稳态收益、28天收获边界、每天浇水体力、出货到账日与任务占用材料。
- 数值恢复必须使用成长后的上限，不能吃药/打坐反而降属性；普通回复药恢复体力，不可因名字把它描述为生命药。
- 场景优先保住出生点→耕地→出货箱→村出口的可读性；装饰数量不是质量的替代，不能挡路或盖住交互对象。
- NPC 缺贴图、作物共用占位阶段、缺UI入口分别登记；不得把“文件存在”写成“已经接入”。美术明度/遮挡规则见[Style Bible](<57-江湖有田-Style-Bible.md>)。

## 6. 按收益排序的执行包

| 优先级 | 工作包 | 完成门 | 依赖 |
|---|---|---|---|
| P0 | 动态恢复上限与文档口径一致 | 满值/低值/成长上限正反例，原回归不退化 | 数值审计 |
| P0 | 首次种植前移与教程版本迁移 | 新档不跳步、两次跨天收获；旧档三类迁移 | 策划确定教程方案 |
| P0 | 可玩入口矩阵 | 每系统记录入口、操作、失败提示、反馈、存档证据 | 现有UI能力 |
| P1 | 山庄金标场景与NPC占位替换 | 通行/交互可读、资源审计、宿主截图 | 当前Tilemap迁移完成 |
| P1 | 四季农业经济仿真 | 明确初始资金/体力/交易/季末边界，不再用静态乘法代替年进度 | 数值审计 |
| P2 | 扩充其他场景与高级系统演出 | 复用金标规范后逐图验收 | P0/P1稳定 |

## 7. 发布前真人测试记录模板

每名新玩家记录：版本/分辨率/输入设备、首次翻土/收获/出售/制药时间、停滞位置和原因、买错/种错次数、战败次数、是否理解任务材料预留、下次想做什么。至少10人；公布中位数及最慢样本，不只均值。不会操作和不喜欢操作分别记录。

本轮仅完成源码级分析、小范围修复和针对性检查；未进行真人试玩、全量发行回归或三宿主画面验收。
