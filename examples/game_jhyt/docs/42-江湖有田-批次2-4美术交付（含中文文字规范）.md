## 1. 中文文字方案（本批的技术前提）

项目的美术工具链只依赖 Python 标准库（没有 Pillow / freetype），但美术里**确实需要中文字**。
落地方式：`tools/cjk_text.py` —— **Python ↔ Windows GDI+ 桥**：

```text
Python 写请求 JSON（文本/字号/模式） → powershell.exe 调 GDI+ 渲染并裁剪 → Python 读回 PNG → 二值化成美术像素
```

三个关键实现点（都是踩过的坑）：

1. **批量渲染**：`Add-Type System.Drawing` 每次要 1–2 秒；一段文字一次调用会把生成器拖到分钟级。
   现在 `prewarm()` 把一次生成用到的所有文字合并成**一次** PowerShell 调用。
2. **在 GDI+ 侧裁剪**：早期版本每段文字都建 2048×2048 画布，Python 要遍历 400 万像素裁边，直接跑超时；
   现在用 `MeasureString(GenericTypographic)` 量出字形框，只保存那一小块。
3. **磁盘缓存**：`.temp/cjk/<sha1>.png`，同一（文本, 字号, 模式, 粗细）只渲染一次，重跑很快。
   字号只用少数几档（招牌 11/12/13px、预览标签 11–13px、Logo 104px）以提高缓存命中。

字体用工程自带的 `assets/fonts/NotoSansSC-VF.ttf`（OFL），**不依赖系统是否安装**。
字形在 11px 起可读（自检图：`.temp/cjk/legibility.png`），招牌统一用 11–13px。

> **运行时也遵守同一条下限（M30）**：游戏内文字最小 13px（HUD 键位提示 13、HUD 面板 14、
> 反馈 16、引导/目标 15、对话正文/选项 18），场景 `Text` 组件最小 14px。
> "字号 ≥ 11px 且不溢出容器"由 `jhyt_m30_cjk_text` 逐条机器检查（静态扫描 + 运行时读回量宽），
> 排版契约见 `docs/49`。

**与 `docs/35` §1 的关系**：该条规定"文字一律运行时渲染，禁止把文字画进切图，唯一例外是标题 Logo"。
本批按需求把中文**烤进了招牌/匾额/木牌**。这是有意的取舍，理由是：

- 招牌文字属于**场景美术的一部分**（笔画粗细、木底对比、做旧程度都要和建筑一起调），
  用运行时 `UiText` 叠在世界物体上还要额外做投影/描边/随缩放，成本更高；
- 代价是招牌文案被固化：改店名要重跑生成器（成本可接受，因为生成器有缓存、改一行即可）。

如果后续确定要走运行时文字，把这些 `draw_plaque(...)` 调用换成"只画木底 + 运行时叠字"即可，
木底与金边逻辑已经收敛在 `cjk_text.draw_plaque()` 一个函数里。
