- 文档版本：0.2（M72-11 按金标规范重做后回写；§1、§7 的身份设计未变，§2–§6 的规格已全部换代）

- 目标：把美术资源方案 3.1 节的"村庄环境"落成**可生成、可验收、可复现**的第二张地图美术，
  并说明接入 `scenes/village.scene` 的方式

## 1. 与山庄的美术区分

同一套 32px 网格 / 1px 墨色描边 / 同一色板体系，但两个地方要有各自的身份：

| | 山庄（manor） | 云泽村（village） |
|---|---|---|
| 地表主色 | 夯土 + 青石院墙 + 石板路 | **青石板街 + 白墙黛瓦**，草地更深更杂 |
| 建筑 | 灰瓦土墙庄院（正房/柴房） | **徽派白墙黛瓦 + 马头墙**，商铺木板门面 + 招幌 |
| 环境母题 | 药田、池塘、晒场 | **山谷**：村北一条溪水 + 石桥 + 渡口木栈桥、竹林山石成山脊 |
| 边界处理 | 石砌院墙整圈 | 南侧白墙院墙 + 村口牌坊；北侧靠竹树与山石成山脊 |

参考对象是江南山村（云泽县），不出现任何具体现实村落或他人美术资产。

## 2. 地表 tileset

`assets/art/tilesets/village/village_ground.png`（**384×288 = 12 列 ×9 行 ×32px**；
M72-11 之前是 192×32 六列一行）。前六列仍是"族本体"，**列语义与山庄完全一致**（引擎
`TILE_PALETTE` 固定 6 个 kind，`terrain_ramp.json` 硬校验同名同序），第七列起是 autotile
的过渡档：`1 + kinds*span + (kind-1)*16 + mask`，6 族 ×17 档 = 102 槽 ≤ 108。
`autotile=1` 写进 `.scene` 的 Tilemap 字段，由引擎 `resolve_atlas_index` 与
`tools/terrain_kit.py`、`tools/preview_scene.py`、`plugins/webgl/web-runtime.js` 四处同解。

| 列 | 名称 | 村庄用法 | 与山庄同列的差别 |
|---:|---|---|---|
| 1 | 草地 | 村内空地、北岸 | 更深、更杂（山谷野草），带落叶与小三叶草 |
| 2 | 夯土 | **茶园**、田埂土路 | 偏沙、带耙痕（暗示茶垄），不是山庄的深夯土 |
| 3 | 石板路 | 主街 / 市集广场 / 中街 / 各院前 | 大块磨损石板 + 裂缝 + 两道车辙 |
| 4 | 院墙 | 村界墙 | **白墙 + 黛瓦压顶 + 青石墙脚**，替代山庄的石砌院墙 |
| 5 | 青瓦 | **村庄屋顶改用 6 列的 `slate`（黛瓦）族**，此列保留与山庄同语义 | 色调更冷，供马头墙压顶类需求 |
| 6 | 水 | 村北溪水 | 更清、有流向线与浅滩反光，替代山庄的池塘静水 |

盘上实测 kind 直方图 `{4 墙:160, 1 草:498, 3 石板:192, 6 水:38, 2 夯土:32}`，
`solid` 328 格，per-tile tint 非白档 618 格（复现：`python tools/scene_readings.py scenes/village.scene`）。
村庄换色走 `terrain_ramp.json:scenes.village`（`tea_soil` / `flagstone` / `plaster` / `slate`
四个族替山庄的 `soil` / `stone` / `wall` / `roof`），出图与色阶表同源，不在工具里写死 hex。

预览：`assets/art/tilesets/village/_ground_preview.png`（`_` 前缀 = 开发件，`assetc::is_dev_artifact`
判定永不进发布包）；四季对照 `assets/art/tilesets/village/season_preview.png`。

- 所有本体 `pivot=0.000,0.000`（= 左下角）、`sorting_layer=world`，transform 直接写世界坐标。
- 够不够格挂地面投影**不是名单**：总高 × `lighting.shadow_reach` ≥ `cast_shadow.min_reach_units`
  （¼ 瓦 = 8px）。村庄 8 栋里 5 栋够格各挂一件 `<名字>Shadow`，铁匠铺/茶摊/土地庙三栋
  整图 64px 高（reach 7.68）落在门槛之外 ⇒ 不挂。全图投影 12 件（含树/竹/山石）。

预览：`assets/art/buildings/_village_preview.png`（棋盘底 + 标签）。

## 4. 道具

道具的碰撞分**三档**（`tools/building_kit.py:SCENES["village"]["prop_collision"]`，默认 `root`）：
`root` 只实心锚点那一格（树/竹/罐/杆——冠梢那几格由遮断件盖人，本来就该走过去）、
`box` 按不透明像素框实心（摊位/山石/山门：本体真的横着占几格，只标锚点等于另一半能穿过去）、

**必须守住的契约**（`tools/gen_village_scene.py` 每次生成都自检，失败非零退出）：

1. `data/maps.lua` village.spawn = (19,2) 与三个出口格必须**非 solid 且从出生点可达**；
2. `data/places.lua` 里全部村庄地点格必须非 solid 且可达（NPC A* 用）；
3. `building_kit.SCENES["village"].openings` 声明的每个洞（南门 (19,1)(19,2)、山门 (10,20)）
   必须可站且可达——洞画对了但被别的东西围死，玩家一样出不去；
4. 桥面 x24..25&y16..17 必须可走，茶园整块必须是夯土（抖动冻住的复核）；
5. 任何实体锚点不许落在水格上，除非显式写 `over_water=True`（渡口/栈桥那类"本来铺在水面上"的）。

**美术把数据逼着改的四处**（都是"solid 真算之后原来那格确实是墙"）：

| 位置 | 旧值 | 新值 | 为什么 |
|---|---|---|---|
| `maps.lua` `village_to_forge.cell` | (26,10) | (27,10) | (26,10) 是搬进市集后的杂货铺屋顶最后一行 |
| `maps.lua` `forge_to_village.to_cell` | (26,11) | (27,10) | (26,11) 在铁匠铺自己 x25..28&y11..12 的占格里 ⇒ 出铺子等于塞进墙 |
| `places.lua` 三个 NPC 家 | 铺内 | (24,6) (22,7) (24,10) | 旧格落在杂货铺诚实占地的 30 格里 |
| 山门 sprite | (9,19) | (9,20) | 挪一格才让门洞 (10,20) 压在出口格上而不是压在墙上 |

**不可达格：本图 3 格，金标 manor 4 片 11 格**（这条判的是"与金标持平"，不是"必须为零"）。
本图 592 个非实心格里 589 格从出生点 (19,2) 可达，进不去的只有**北墙后 x6..8&y20** 那一窄条——
贴图上是墙外坡顶的草皮，画得出、走不到，不影响任何点位。渡口 x13..15&y18..20 是**可达的尽端空间**
而不是通路：从 x10..12 的 y18..19 走廊拐进去，北面是院墙（kind 4）、东面是 VillageHouseA
(x16..19&y18..20)、南面是溪水，VillageRockA 又把 (13,20)(14,20) 标成实心，走到底就是那块栈桥。
山门那一侧同理：VillageMountainGate 的框覆盖 x9..12&y20，只有声明的洞 (10,20) 可站。
manor 自己那 4 片：x16..19&y18（4 格）、x20..24&y20（5 格）、(38,5)、(38,8)。

## 6. 生成与验收

出图与装配（M72-11 起与山庄同一条管线，顺序即依赖顺序）：

```powershell
cd examples/game_jhyt
python tools/gen_village_art.py                              # 8 栋建筑本体/屋顶 + 6 类道具 + 总预览
python tools/gen_terrain_tiles.py --scene village            # 12×9 图集（只从色阶表取色）+ 预览 + 自检
python tools/gen_village_scene.py                            # 装配 village.scene（含契约自检）
python tools/set_terrain_autotile.py scenes/village.scene --freeze 2,14,33,17 --apply
python tools/set_foreground_occluders.py scenes/village.scene --apply   # 拆层遮断件上前景层
python tools/set_cast_shadows.py scenes/village.scene --apply          # 12 件投影贴片
python tools/set_scatter_decor.py scenes/village.scene --apply        # 326 件装饰散布
python tools/gen_season_variants.py --scene village          # 四季变体（换色不重画）
```

盘上对拍（不改写字节的那一组，`verify.ps1` 的 Python 段跑的就是这些）：

```powershell
python tools/gen_village_art.py --check          # 文件齐全 + 拆层逐字节对拍（查整张表，含 manor 那 13 张）
python tools/gen_terrain_tiles.py --scene village --check   # 色阶 / alpha / 16 过渡块 / 四边收口 / 空槽
python tools/building_kit.py scenes/village.scene --check   # 每格 solid 都有可视依据：328 == 328，缺 0 悬空 0
python tools/set_foreground_occluders.py scenes/village.scene --check
python tools/set_cast_shadows.py scenes/village.scene --check
python tools/set_scatter_decor.py scenes/village.scene --check
python tools/scene_readings.py scenes/village.scene   # §7 的量化读数 + D5 复核
python tools/check_scene_refs.py                 # references/ 零泄漏
```

`set_terrain_autotile.py` 没有 `--check`（它只写 tiles/tile_kinds/autotile 三处），判它幂等的方式是
重跑 `--apply` 之后场景字节不变，再由 `building_kit --check` + `jhyt_m72_building_footprint` 两把尺
量 solid。**改过 tiles / solid / 出口格 / 留白表之后必须重跑 `set_scatter_decor.py --apply`**：散布的
输入就是这几样（`read_ground` + `reserved_provider`），只改表不重跑段的话 `--check` 会报"盘上装饰段与
重算不一致"——这一条在本包提交前真实红过一次（3 行，entity 249），见 `tasks/done/M72-11` §village 验收证据。

## 7. 与美术资源方案的对应与后续

- 对应 3.1 的"村庄环境 2 套（MVP）"：本版先做 1 套（石板街/白墙黛瓦/溪水）；
- 对应 3.1 的"装饰物"：招幌、灯笼、摊位、山石、竹树共 5 类新增 + 3 类复用；
- 未做：客栈/祠堂等更多民居变体、四季与节庆装饰（灯笼串/春联）、村外山道与渡口对岸
  （山道属下一张地图 `mountain_path`，会复用本套 tileset 的 1/2/5 列）。

**已知取舍**：

1. 溪水只让石桥通行，是为了让"过河"成为明确的路线选择；如果后续要做"涉水/游泳"，
   需要引擎支持按地块类型的通行代价，而不是现在的 0/1 solid。
2. 北岸三栋建筑（民居 A/B、土地庙）目前只是场景体块，尚未接 NPC 日程与室内；
   接日程时把它们的地点格加进 `data/places.lua` 即可，契约自检会自动覆盖新格。
3. 茶园是"可走的夯土 + 茶垄纹理"，没有单独的作物 overlay；若要做可采摘茶树，
   参照山庄 `farm.lua` + FarmGrid 的做法加第二张 Tilemap。
