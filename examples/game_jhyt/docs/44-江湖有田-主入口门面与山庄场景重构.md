### 删场景的副作用：别忘了"引用"和"注释里的路径"

删掉 `title.scene` 之后编辑器报过一次
**「断链 · main.lua 依赖 scenes/title.scene 缺失」**，根因有三处，都是没清干净的引用：

1. `scripts/main.lua` 的"返回门面"函数里还留着**死分支**
   `if not scene.load("title") then return scene.load("main") end` —— 文件已经不存在，
   依赖扫描据此判定断链（运行期会回落，但这是必须清掉的旧路径）；
2. 同一段**注释里写着字面路径** —— 依赖扫描扫全文，**注释照样算依赖**；
3. `.cache/editor/hierarchy-state.json` 里还留着一份已删场景的编辑态（折叠状态）缓存。

现在：函数体只 `scene.load("main")`；注释改成"工程早期有一个独立的开始画面场景，现已删除"
（**不写具体路径**）；编辑器缓存里删掉该条目。

配套加了可复用的检查脚本 **`tools/check_scene_refs.py`**：

```powershell

python tools/check_scene_refs.py --all   # 附带列出 builds/、.cache/ 等产物里的旧引用
```

只认两种真实引用形态——带目录的字面路径 `scenes/<name>.scene` 与 `scene.load('<name>')`——
并额外校验 `scenes/*.scene` 头部的 `name=` 与文件名一致；这样不会把 `snapshot.scene`
这类 Lua 字段访问误判成场景（第一版就误报了一堆）。

> **产物提醒**：`builds/pc/jianghu_youtian/`（gitignore 掉的发布包）是改名/删场景**之前**打的包，

### 过程中被自检抓到的问题

1. **按钮几何写错**：`BUTTONS` 的第 4 个字段我按"高度"写（200），代码按"bottom"用 →
   `BtnExit` 直接到 y=800 越界；自检报出来后改成 top/bottom 语义。
2. **底图是 RGB 而非 RGBA**：门面自检一开始对底图也要求 RGBA；底图允许不透明 RGB，
   改为只对叠加层强制 RGBA。
3. **UI 预览"墨色横幅变白云"**：我的预览脚本用 `set` 覆盖而不是 src-over 混合，
   半透明叠层的 alpha 被写进结果，看图器在**白底**上合成 → 整块发白。
   资源本身没问题（实测像素是 `(11,14,20,150)`），是预览工具的问题，已改为 `over()` 混合。
4. **UI 控件总览撑爆引擎读图**：加入 1280×720 底衬后总览图到 4000×5800 ≈ 2300 万像素，
   `assetc import` 报 `Memory limit exceeded`（failed=1）；现在大幅底衬不进总览 + 总览固定 1×。
5. **回纹角饰做反了（评审指出）**：`meander_corner` 第一版把 `x0` 当成"方框参照角"、
   竖笔画在横笔**内端**，于是**左角的回纹朝里拐**，看起来是反的（右角凑巧像正常）。
   第二版改成三横三竖的平行格 —— 四角对称了，但成了"井字格"，不是回纹。
   第三版才做对：从外角出发的**方形螺旋**（横↔竖交替、每两段缩一格），`flip_x/flip_y`
   给出天然镜像；同时把调用点改成传**真实外角坐标**（左 3 / 右 252 / 上 3 / 下 68），
   画框四角同理传 `(22,22)/(1257,22)/(22,697)/(1257,697)`。
   教训：**角饰这类对称件，写完必须放大到 3× 逐个角看**，只看整体缩略图看不出朝向错。
6. **成对装饰没镜像（评审再次指出）**：竹节分隔两侧的回纹角饰都用了
   `ui_menu_ornament_corner`（同一张左上角朝向的图），所以**左右不对称**。
   修法：角饰出四个方向变体（`_corner` 左上 / `_tr` 右上 / `_bl` 左下 / `_br` 右下，
   外角与云纹一起镜像），场景里左用左上、右用右上，并把位置改成关于画面中线严格对称
   （左 416..480、右 800..864，内缘正好接住 480..800 的分隔线）。
   同时给门面生成器加了两条契约自检，防止复发：
   * 左右角饰**不得使用同一张贴图**；
   * 左右角饰的矩形必须关于 `REF_W/2` 严格对称（内缘、尺寸、纵向位置都要对得上）。

最终形态与"哪些账已进规范、哪些没有"：

| 包 | 交付 | 现在的判据落点 |
|---|---|---|
| M72-04 | 地表图集重做 + 色阶表（一张 `tools/terrain_ramp.json`，六个族各三档明度） | 门 `jhyt_m72_manor_terrain` 六段 |
| M72-05 | 装饰散布生成器（同种子逐字节可复现）+ 碎屑库 | 门 `jhyt_m72_scatter_decor` 五段（现 204 件 / 13 种 / 每屏中位数 41） |
| M72-06 | 前景遮断层 + 全局光投影，光向只认 `scripts/data/lighting.lua` | 门 `jhyt_m72_foreground_occlusion` 八段（现 11 件遮断物 / 16 件贴片） |
| M72-07 | **多格建筑的占地口径** + 不规则水池 + 门洞 | 门 `jhyt_m72_building_footprint` 五段（`solid` 359 格、缺 0 / 悬空 0） |

### 4.1 这一批定下来的四条硬口径（已回写 `57` §1.3 第 10 款、`51` §2.1）

1. **每一格 `solid` 都要有可视依据**：地表本身就是墙/水，或某个 sprite 的**不透明像素**压在那一格
   上。按 sprite 的 quad 矩形标是错的——建筑贴图四角几乎总是全透明，症状是"在屋外两步远的地方
   撞空气"。`solid` 同时是物理事实源（`scene_spawn.rs` 的 `solid_cell_colliders` 每个实心格挂一个
   静态 cuboid），所以这一条既是画面账也是玩法账。
2. **建筑 = 本体∪同名拆层屋顶 − 门洞**；树/竹/单件道具 = 单格根碰撞；装饰不参与碰撞。
   拆层只许换画面与遮挡，不许换碰撞——等价形式是"整图算的格集 == 本体∪屋顶"（门 §② 逐格比）。
3. **门洞是数据，不是感觉**：声明的洞格必须在自己的视觉框内、盘上必须真空着、贴图在那一格实测
   不透明占比 ≤ 0.35、且从出生点 BFS 走得到。南门 `(16,1)(16,2)` 是山庄↔云泽村的出口格。
4. **水池按岸线填水**（27 格 / 外接框 40 格 ⇒ 填充率 0.675），外圈草地刷石板做石砌岸；不许整框灌满，
   也不许再给建筑/水池整框刷 DIRT（DIRT 是 `farm.lua` 的"可开垦"判据，等于在房子底下留一片能种的地）。

### 4.2 过程中被自检与门抓到的问题

1. **生成器与盘上分叉**：药庐与地基从 x33 挪到 x16，`solid` 串留在原地不动 ⇒ 21 格真·悬空碰撞
   （玩家在半空中撞一堵看不见的墙）。根因是"数据改动只改一边"，所以本批定下的做法是
   生成器 import 就地工具、两边共用同一份表，门再作第三份独立实现复算。
2. **反面对照会空转**：计划里"把建筑 `solid` 扩到整个 quad 框，门必须红"这一条在盘上**抓不到东西**
   ——10 栋建筑的贴图都铺满了自己的画框，按框与按像素算出的格集逐格相同。改落在竹子上（按框会
   多出 5 格竹梢），并把这条读数登记进 `58` §13.5 而不是悄悄删掉对照。
3. **改地面会把别的门挤红**：石砌岸 + 石板晒场把草换成石板，每屏装饰中位数从 43 掉到 36（门槛 40）。
   补的是散布基线概率（`decor_kit.BASE_P`），不是门槛数字——这一步的理由写在 `decor_kit.py` 里。
4. **作物层的 id 抢了装饰的号段**：M72-08 把 `CropGrid` 追加在装饰之后（id 235），于是就地工具
   `set_scatter_decor.next_id`（"最高非保留 id + 1"）从 31 顶到 236，重跑生成器后 816 行装饰段
   整体改号、`--check` 红在跟装饰内容无关的地方。改成作物层在装饰**之前**取号（id 31，仍然追加在
   文件最后），生成器与工具重新同解。
5. **"格 → 图像行"的映射两边都写反了符号**：`building_kit.opening_holes` 与门侧都写作
   `h − wy0 − TILE − item.y`，正确式子是 `item.y + h − wy0 − TILE`；只在 `y==0` 时碰巧对，而南门
   正好贴在地图下边界上，所以盘上从没撞过它。两侧同法改正，读数不变（0.16）。
