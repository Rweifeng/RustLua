# 《江湖有田》主角形象系统（M21）

- 文档版本：0.1
- 本版同步：角色序列帧设计 0.1（`docs/36` §4/§8）、UI 资源实现与接入 0.2（`docs/38`）
- 目标：把已经产出的**主角序列帧真正接进游戏** —— 场景里不再是白方块，
  玩家能选形象（青衫少侠 / 青衣女侠），走路/劳作/战斗有对应动作，选择随存档持久化

## 1. 分层：数据 / 场景 / 运行期

| 层 | 位置 | 职责 |
|---|---|---|
| 清单 | `scripts/data/appearances.lua` | 玩家能选哪些形象、中文名、解锁条件、默认是哪个 |
| 本体 | `scripts/data/characters.lua`（生成） | 形象的序列帧：`static_<dir>` 单帧 + 一整套 `Animation` 组件串 |
| 状态 | `scripts/state.lua` 的 `appearance` | 当前形象 id，随 `save_manager` 的 `state` provider 落盘 |
| 场景 | 7 张可玩场景的 `JianghuPlayer` | 声明**默认形象**（编辑器打开就看到真人），不再用 `__white__` 灰盒 |
| 运行期 | `scripts/player.lua` | 按 `state.appearance` 挂载/纠正形象，驱动 `idle/walk` 与一次性动作 |

**为什么场景声明 + 运行期挂载两处都要**：
场景声明保证"打开编辑器/第一帧就是对的"；运行期挂载保证"形象能换、切图后能自愈"
（切图后实体重建，Animation 组件会丢）。两者用的是**同一串**（见 §3）。

## 2. 运行期（`player.lua`）

```lua
player.appearance_id()          -- 当前形象 id（坏档/未知 id 自动退回默认形象）
player.appearance_entry()       -- 当前形象条目（display/note/static_sprite/animation/clips）
player.appearance_options()     -- 可选列表（给 UI）
player.set_appearance(id)       -- 切换：校验 → 写 state → 立刻重挂；返回 ok, err
player.apply()                  -- 幂等挂载：sprite.set(单帧) + animation.attach(序列帧)
player.tick()                   -- 每帧：场景/形象变了就重挂；动作播完落回 walk/idle
player.play("hoe"|"water"|"attack"|"hurt"|"faint")  -- 一次性动作（非循环条带）
player.status()                 -- 诊断/验收：形象、朝向、是否在走、当前 clip
```

* **朝向换算**：玩法口径是 `up/down/left/right`（`state.facing`，farm/combat 都在用），
  条带是四向 `s/n/e/w`；世界 y 向上 → `up→n / down→s / left→w / right→e`，
  换算只在一处（`M.clip_dir`）。
* **是否在走**：不额外读物理速度 —— `player.set_velocity/stop` 本来就是移动指令的唯一入口，
  在那里记录 `moving` 与朝向即可（少一个引擎 API 依赖，也不会与刚体回写打架）。
* **动作优先级**：`M.oneshot` 期间不切 walk/idle，`animation.ended` 为真后清标记；
  形象缺少该动作（例如木人只有 idle/hurt）时 `play` 静默返回 false。
* **tick 的调用点**：`main.lua` 的 `update()` 里放在 `input.update()` **之后** ——
  输入决定朝向与是否移动，动画必须据此切换，顺序反了会永远慢一帧。

## 3. 场景接线（`tools/character_art.py`）

场景里的主角行不再手写纹理路径，而是从角色美术 manifest 取：

```python
from character_art import player_art
player_sprite, player_animation = player_art("player_male")
lines.append(f"component\t{player_id}\tSprite\t{player_sprite}")
if player_animation:
    lines.append(f"component\t{player_id}\tAnimation\t{player_animation}")
```

`assets/art/characters/manifest.json` 是 `tools/gen_character_sprites.py` 的产物，
与 `data/characters.lua` 同源；manifest 缺失时回退灰盒 sprite 并在 stderr 说明
（不让整条美术链崩掉）。

已接线的场景（7 张可玩场景全部）：`manor` / `village` / `combat_arena` / `mountain_path` /
`cold_spring_cave` / `interior_herb` / `interior_forge`（`main` 是纯 UI 门面，没有主角实体）。

## 4. 玩法接线点

| 触发 | 动作 | 位置 |
|---|---|---|
| 翻土 | `hoe_<dir>` | `farm.lua` 的 till 分支 |
| 浇水 | `water_<dir>` | `farm.lua` 的浇水分支 |
| 普攻/武学起手 | `attack_<dir>` | `combat.lua` 的 `M.attack` 玩家分支 |
| 玩家受击 | `hurt_<dir>` | `combat.lua` 玩家掉血分支 |
| 玩家战败 | `faint_<dir>` | `combat.lua` 玩家致死分支（先播倒地再处理战败流程） |

## 5. 引擎侧改动

| API | 说明 |
|---|---|
| `animation.attach(id, component_str)` | 运行期给实体挂 Animation（`docs/36` §8.3 的方案 A，上一轮已落地，本轮是它的第一个大用户） |
| `animation.clips(id)` | 查出该实体可用的全部 clip 名（验收/诊断） |
| `sprite.get(id)` | **本轮新增**：读回渲染用的 `texture` / `size` / `pivot` / `tint`，以及 `animation_sheet`（Animation 当前 clip 的条带，即**真正渲染**的那张图）；M35 起还回读 `sorting_layer` / `order`（见 `docs/45` §6 第 13 条） |

`sprite.get` 的存在让验收能直接断言"实体上现在真的是哪张图"，而不是间接猜测。

## 7. 已知阻塞（并发在制品，与本系统无关）

跑驱动时发现 **`scripts/main.lua` 调用了 `input.load_settings()`，但 `scripts/input.lua`
还没实现它**（M20-08 玩家改键的在制品）。这会让 `boot_game` 阶段直接抛
`attempt to call a nil value (field 'load_settings')`，**当前所有验收驱动**（含
`jhyt_smoke` / `jhyt_m17` / `jhyt_m19_ui` / `jhyt_m20_audio`）都会在这一步失败。

处理方式：`jhyt_m21_appearance` 在**自己的 runtime 里**按需补一个最小桩
（`if type(input.load_settings) ~= 'function' then ... end`，返回 true = 用引擎默认），
所以本驱动不依赖对方的在制品；对方实现落地后这段自动变成空操作。
**没有**去改 `scripts/input.lua` —— 那是对方的设计空间（`main.lua` 注释写明语义
"同 `audio.load_settings`"）。

## 8. 后续扩展路径

要加"肤色 / 发型 / 服装主色"这类自定义，只需两步：

1. `tools/gen_character_sprites.py` 的 `CHARACTERS` 加一条（骨架上色 + 发型函数 + 配件函数的组合），
   重跑生成器 → manifest 与 `characters.lua` 自动多出该形象；
2. `scripts/data/appearances.lua` 加一行（中文名 + 解锁条件）。

运行期与暂停菜单会自动多出一项，**不需要改任何 Lua 逻辑**。
