# 《江湖有田》UI 资源实现与接入

- 文档版本：0.2（按模块分目录）
- 本版同步：UI 资源设计 0.1（`docs/35`）、美术资源方案 0.2、引擎 UI 现状
- 目标：把 `docs/35` 第 10 节的切图清单落成**按模块组织、已产出、可抄接入串、可复跑验收**的资源

## 1. 目录划分

按 `docs/35` 第 7/8 节的功能模块分目录，根目录 `assets/art/ui/`：

```text
assets/art/ui/
├── manifest.json           模块 → 文件清单 + 该模块用到的 common 控件（代码侧只读这个）
├── _preview_controls.png   全切图 2× 放大，按模块分组带标签
├── _preview_mock.png       按 §7/§8 布局拼出的效果图 + 9-slice 缩放检查
├── common/    24 个  共用控件：面板 3 / 按钮 4 / 槽位 2 / 输入框 / 标签页 2 /
│                      键位框 / 勾选 2 / 滑杆 2 / 箭头 3 / 关闭 2 / 分隔线 / 面板印章
├── hud/       14 个  主界面（§7）：状态条框 + 三色填充 + 三属性图标 + 铜钱 +
│                      天气 3 + 状态图标 2 + 头像框
├── backpack/   5 个  背包（§8.1）：五档品质框（凡/良/上/珍/传世）
├── dialogue/   3 个  对话（§8.3）：128 头像框 / 继续箭头 / 选项引导符
├── shop/       2 个  商店（§8.2）：数量步进器 −/＋
├── quest/      2 个  任务（§8.4）：目标状态点（未完成 / 完成）
├── skills/     1 个  武学（§8.5）：招式卡片底板
├── build/      2 个  建筑放置（§8.6）：可放置 / 冲突的占位格
├── save/       2 个  存档（§8.7）：存档槽底板 / 截图占位块
└── settings/   2 个  设置（§8.8）：开关两态
```

共 **57 个切图 / 10 个模块**。

### 划分原则

1. **共用控件只存一份**，放 `common/`：面板、按钮、槽位、输入框、标签页、勾选、滑杆、
   箭头、关闭、分隔线、面板印章 —— 这些被背包/商店/任务/存档/设置同时使用。
   如果按模块各存一份，改一处木纹就要改十处，且十份迟早会不一致。
2. **模块目录只放该模块专属切图**：品质框只服务背包图标语义、天气只服务 HUD、
   占位格只服务建筑放置等。
3. **模块用到的 common 控件写在 `manifest.json` 的 `uses_common` 里**，
   这样"按模块找资源"仍然完整：打开 `backpack` 从 manifest 就能看到它由
   `backpack/ui_quality_frame_*.png` + `common/ui_panel_main_9s.png` + …组装而成。
4. `docs/35` §10 清单里**没给切图但布局明确需要**的小控件本次一并补齐：
   标签页、开关、数量步进器、任务状态点、建筑占位格、存档槽与截图占位、
   对话头像框/继续箭头/选项引导符、HUD 头像框、招式卡片底板。

## 2. 视觉规格（实现口径）

- **色板落值**：`docs/35` §3 的 token 直接写死在生成器里（`ink/900 #1F2328`…`indigo/300 #7FA3D4`），
  切图不允许出现色板外的颜色；描边统一 `ink/900` 1px，光源左上 45°。
- **状态表现**（§6.1）：
  - normal / hover：同一张切图 + 引擎 `color` 提亮（`ink/700`）；
  - pressed：**单独切图** `ui_btn_primary_pressed_9s` —— 底色压到 `#8F2E1F`、
    顶端 1px 内阴影、内容下移 1px（只调暗一档在小尺寸下分不出来，实测过）；
  - disabled：引擎侧 50% 透明 + 文字 `paper/500`；
  - focused：外扩 2px `gold/500` 焦点框（引擎侧画，不做切图）。
- **9-slice 边界**：切图只在边界区画装饰，**中心区保持纯色**（会被双轴拉伸，
  放噪点会拉成条纹）；四边只在拉伸方向上走纹理（上下边横纹、左右边竖纹）。
- **进度条**：`hud/ui_bar_frame_9s.png` 中心**透明**（框叠加在填充之上）；
  填充用 `4,0,4,0` 只横轴拉伸，两端圆头不变形。
- **未完成态目标点**：最初用 `ink/800` 实心挖空，深色面板上几乎看不见，改成 `paper/500` 圆环。

## 3. 引擎接入事实（改接线前必读）

| 需求 | 引擎能力 | 结论 |
|---|---|---|
| 场景里放 9-slice 面板/按钮 | `Image` 支持 `nine_slice=l,r,t,b`（`core/ui.rs` `UiImage`） | **可直接用**，见 §4 |
| 运行期（Lua）画 9-slice 面板 | `ui.image(id,x,y,w,h,texture,r,g,b)` 把 `nine_slice` **写死 `None`** | **当前做不到**，见 §5 |
| 面板底/格子 | `ui.panel`（纯色）/ `ui.grid`（格子可带 texture） | 现有对话/商店盒子用的是 `ui.panel` 纯色 |
| 文字 | `ui.text_at` / `Text` 组件 | 文字一律运行时渲染，切图不含字 |

**静态 UI（标题页、设置页这类场景内控件）现在就能用新切图；
对话/商店这类运行期浮层要等 Lua 九宫格 API 才能用同一套框体。**

## 5. 引擎缺口：Lua 侧九宫格

`core/script.rs` 的 `ui.image` 构造 `DynamicUiImage` 时把 `nine_slice` 写成 `None`，
而 `DynamicUiImage` 本身**已有 `nine_slice` 字段**（`core/ui.rs`）。建议最小改动：

```rust
// 现状
ui.image(id, x, y, w, h, texture, r, g, b)
// 建议新增（旧签名不变，向后兼容）
ui.image9(id, x, y, w, h, texture, r, g, b, left, right, top, bottom)
```

落地后 `scripts/dialogue.lua` 的 `ui.panel("dlg:box", ...)` 与
`scripts/shop.lua` 的 `ui.panel("shp:box", ...)` 即可换成
`ui.image9(..., "assets/art/ui/common/ui_panel_paper_9s.png", 1,1,1, 16,16,16,16)`，
对话与商店就和 HUD/场景用同一套框体（`docs/35` §12 验收第 1 条）。

## 6. 生成与验收

```powershell
cd examples/game_jhyt
python tools/gen_ui_art.py            # 生成 57 个切图（按模块落目录）+ manifest + 两张预览
python tools/gen_ui_art.py --check    # 校验尺寸/存在性，并检查根目录无旧扁平切图残留
```

| 验收项 | 标准 | 工具 |
|---|---|---|
| 切图尺寸 | 与 §10 规格表逐项一致 | `gen_ui_art.py --check` |
| 目录结构 | 根目录只有 manifest + 两张预览，切图全在模块目录 | `--check`（残留检查） |
| 模块完整性 | 每个模块在 `manifest.json` 里有 files + uses_common | `manifest.json` |
| 透明背景 | 图标/品质框/条框中心透明 | `_preview_controls.png` 目视（棋盘底） |
| 9-slice 无接缝 | 0.75×/1.0×/1.5× 三档下边框不裂、小尺寸不糊 | `_preview_mock.png` 缩放检查行 |
| 色板一致 | 只用 `docs/35` §3 token | 生成器色值为常量，改色只改一处 |
| 资源链路 | `assetc scan` / `import` / `--check-deps` / `game --check` | 引擎 CLI |
| 无烤字 | 除未产出的 `ui_title_logo.png` 外无文字 | 人工 |
