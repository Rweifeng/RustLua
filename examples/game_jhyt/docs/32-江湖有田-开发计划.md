# 《江湖有田》开发计划与引擎补强路线

- 文档版本：0.3
- 目标：在当前 RustLua 引擎能力上，以可验证的垂直切片为核心，逐步交付 PC 首发版本
- 组织方式：里程碑 + 可验收任务，不把尚未存在的引擎能力当作已完成能力
- 本版重点：补充依赖关系、任务完成定义、测试门槛、缺陷分级和版本退出条件

> 当前工作区执行增补见[体验收口与执行基线](<72-江湖有田-体验收口与执行基线.md>)：优先修复恢复上限、明确教程购种/土地类型与旧档兼容，再做可玩入口矩阵和山庄金标；不以新增系统数量替代交互完成度。数值/美术检查及其限制分别见[数值审计](<73-江湖有田-数值审计与调优.md>)和[美术审计](<74-江湖有田-美术落地审计.md>)。

## 1. 开发原则

1. 先做“种田—修炼—社交—探险—睡觉”一条完整链路，再扩充内容。
2. Rust 只下沉稳定、性能敏感和需要一致性的底座；Lua 负责规则、内容和流程。
3. 每个新系统先写 headless 测试或最小 Demo，再接编辑器和美术。
4. 先 PC，WebGL 作为独立验收目标；微信小游戏不进入首发承诺。
5. 存档、地图状态和资源发布优先级高于华丽表现。
6. 每个里程碑必须有可运行构建、验收步骤、已知限制和回滚点。

### 1.1 Lua 模块职责规范

1. `scripts/main.lua` 只作为游戏总入口，负责生命周期注册、模块初始化、流程编排和模块调用。
2. 具体功能必须拆分为独立 Lua 模块，按职责放置在 `scripts/` 的**按层子目录**下；配置表统一放置在 `scripts/data/` 下。
3. 状态管理、玩家控制、背包物品、输入处理等逻辑不得堆积到 `main.lua`，应由对应模块实现并由入口调用。
4. 模块通过 `require` 引入，模块应返回自身接口或配置表，避免依赖未声明的全局变量。
5. 新增系统时先确定模块边界，再接入 `main.lua`；不得为了短期方便绕过模块拆分。

#### 目录分层（模块名 = 相对 `scripts/` 的路径，目录用 `.` 连接）

| 目录 | 放什么 | 例 |
|---|---|---|
| `scripts/core/` | 状态容器、存档、音频总线等底座 | `core.state`、`core.save_manager`、`core.audio` |
| `scripts/player/` | 主角自身：实体、背包、属性、武学、关系声望 | `player.player`、`player.inventory`、`player.stats` |
| `scripts/world/` | 世界模拟：地图、NPC、日程、日历天气、任务、对话 | `world.map_manager`、`world.npc`、`world.quest` |
| `scripts/systems/` | 玩法系统：农田、采集、建造、制作、战斗、敌人、交互、商店 | `systems.farm`、`systems.combat`、`systems.shop` |
| `scripts/ui/` | 表现与输入：HUD、输入分发、各面板、新手引导 | `ui.input`、`ui.hud`、`ui.pause_menu` |
| `scripts/data/` | 纯数据注册表（叶子，不含运行逻辑） | `data.maps`、`data.quests.index` |

`main.lua` 与 `validate_data.lua` 固定留在 `scripts/` 根目录：前者是 `project.toml` 的
`main_script`，后者是 `game --check` / `editor --check` / 编辑器领域数据面板的约定入口，
搬迁需要改动 Rust 侧约定且无收益。

完整的模块清单、跨层依赖方向、加载期循环依赖约束与迁移对照见
[`scripts/README.md`](../scripts/README.md)。

## 2. 工作包与职责

| 工作包 | 主要实现 | 产出 |
|---|---|---|
| 引擎底座 | Rust | 快照、寻路、战斗、建筑、事件、编辑器工具 |
| 游戏规则 | Lua | 作物、NPC、任务、对话、经济、武学和剧情 |
| 内容数据 | JSON + Lua | 物品、作物、NPC、任务、对话、地图和配方 |
| 场景制作 | 编辑器 | 山庄、村庄、山道和室内地图 |
| 美术音频 | 外部资源 + 原创 | 可替换的 PNG、OGG/WAV、字体和许可证记录 |
| 质量发布 | PowerShell + CI | 检查、测试、PC 包和 WebGL 包 |

## 2.1 任务状态与完成定义

每项任务必须标记为：未开始、进行中、待验收、已完成、阻塞或取消。只有达到“已完成”才允许作为后续阶段依赖。

任务完成必须包含：

- 代码、脚本或数据已进入约定目录；
- 至少一个自动化测试、headless 测试、Demo 或可复现手工步骤；
- Debug/Release 构建均通过；
- 相关日志、错误信息和存档迁移行为可追踪；
- 新增资源已登记来源、许可证和使用位置；
- 已知限制已写入里程碑验收记录；
- 不新增未评估的 P0/P1 问题。

### 2.2 缺陷分级与处理门槛

| 等级 | 定义 | 处理要求 |
|---|---|---|
| P0 | 崩溃、无法启动、存档损坏、核心流程不可完成、数据丢失 | 立即阻断合并和里程碑验收 |
| P1 | 主要系统错误、任务无法推进、战斗结果错误、发行包缺资源 | 版本退出前必须清零 |
| P2 | 局部体验问题、低概率显示或音频问题 | Beta 前完成关键项，剩余项记录规避方案 |
| P3 | 轻微视觉、文案或易用性问题 | 排入迭代池，不阻断 MVP |

## 3. 阶段计划

### 阶段 A：产品锁定与预研

**目标**：锁定 MVP，防止项目变成无边界的“武侠版星露谷”。

**进入条件**：项目目录、引擎基线和当前 farm smoke 可正常启动。

**任务**：

- 确认名称、视觉方向、首发 PC 和内容边界；
- 固定 32×32 逻辑 Tile 规格；
- 固定时间、体力、内力、金钱和声望的最小数值模型；
- 建立数据表字段和命名规则；
- 建立资源许可证登记表；
- 用现有 `farm_smoke` 复核耕作、成长、收获、商店和存档现状；
- 用 placeholder 资源制作 3 张灰盒地图；
- 建立风险清单和每周验收模板。

**验收**：

- 能从新工程目录启动一个无美术占位项目；
- 3 张地图可切换；
- 文档中的 MVP 内容没有未决的核心范围争议；
- 所有候选外部资源都有许可证状态，授权不明资源标记为禁止使用。

**主要风险**：美术风格未定导致返工。解决办法是先锁定 Tile 尺寸、色板和角色比例，再采购资源。

- **退出条件**：MVP 范围、数据字段、地图灰盒和资源许可流程均已确认；核心范围不再通过口头方式变更。
- **依赖关系**：阶段 B 只有在 A 的存档字段、地图 ID 和资源目录冻结后启动。

### 阶段 B：P0 引擎补强——持久化、网格和事件

**目标**：让地图状态、实体状态和跨天结算不会因切图或存档丢失。

**进入条件**：阶段 A 退出条件全部满足；至少有山庄、村庄、山道三张灰盒地图和稳定地图 ID。

**Rust 任务**：

1. 稳定 `PersistId`：为玩家、NPC、建筑、作物、容器和关键交互点提供项目级 ID（B-1，引擎侧已完成 API，待补编辑器显示）。
2. `WorldSnapshot`：统一序列化入口 `world.save/load`。引擎键值（`save.load/commit`）已交付且为严格 `save_version=1` 门；**迁移钩子 `on_migrate` 已在引擎兼容层收口时移除**，快照版本迁移改由游戏侧自带 `version` 字段处理。游戏侧统一路径已落地为注册中心 `scripts/save_manager.lua`（见 [34-引擎能力缺口与执行backlog](34-引擎能力缺口与执行backlog.md) B-2）；引擎级 `world.save/load` 仍缺失。
3. Tilemap 状态快照：保存 tile 值、solid、meta 和地图版本（`map.schema`/`map.state` 已交付，B-3；meta 跨重启依赖脚本写入 `map.state`）。
4. 地图状态版本化：为 `map.state` 增加结构化 schema 和错误信息。
5. A* 网格寻路：以 Tilemap solid 为阻挡，支持四方向、八方向可配置和路径失败诊断（B-4 已交付）。
6. Lua 事件总线：将 `ItemAdded`、`MapEntered`、`TimeReached`、`AttackHit` 等事件安全暴露给 Lua（B-5 已交付）。

**Lua 任务**：

- 编写 `save_manager.lua`（已落地：`scripts/save_manager.lua` 注册中心 + `main.lua` 触发/恢复闭环，见 [34-引擎能力缺口与执行backlog](34-引擎能力缺口与执行backlog.md) B-2）；
- 编写 `map_state.lua`；
- 编写 `calendar.lua` 和跨天结算顺序；
- 编写数值配置模块，接入 [《江湖有田》数值设计案](33-江湖有田-数值设计案.md) 中的玩家属性、作物、配方、战斗、奖励和关系数据；
- 编写事件监听注册和调试日志。

**编辑器任务**：

- 显示 PersistId；
- 检查重复 ID、缺失 ID 和不可保存组件；
- 提供地图状态调试面板。

**验收**：

- 种下作物、浇水、切图、退出、重新启动后状态一致；
- 建筑、箱子库存和 NPC 关键状态不会复制或丢失；
- 在障碍地图中寻路结果稳定；
- 旧版本存档可迁移或明确拒绝并保留原文件；
- 连续睡觉 30 天无状态漂移。

**回滚点**：在所有业务状态接入统一快照前，保留现有 `save.blob_*` 路径作为临时兼容层；统一 `world.save/load` 落地并过验收后删除临时分支。

- **退出条件**：完成 30 天无漂移测试、切图/重启恢复测试和旧存档迁移测试；P0 存档问题为零。
- **下游依赖**：阶段 C、D、E 均依赖本阶段的实体 ID、地图状态接口和事件命名冻结。

### 阶段 C：P0 战斗底座与最小武学

**目标**：实现可复现、可调试的近战战斗，而不是只移动生命值。

**进入条件**：阶段 B 的事件总线、固定时间步和地图碰撞查询可用。（0.3 核对：固定时间步 `FixedTimeStep` 60Hz 已接入主循环与编辑器预览；事件总线 B-5、A\* B-4 已具备，见 [34-引擎能力缺口与执行backlog](34-引擎能力缺口与执行backlog.md)。）

**Rust 任务**：

- `combat.attack_begin/end`；
- hitbox 创建、销毁、攻击帧和命中去重；
- 伤害、击退、硬直、无敌帧和死亡事件；
- 伤害来源、目标、招式 ID 和帧序号写入事件；
- 使用现有 physics overlap/raycast，不重新实现物理引擎；
- 将战斗时间与固定时间步绑定，避免帧率影响结果。

**Lua 任务**：

- 招式数据表；
- 玩家状态机：Idle、Move、Attack、Recover、Hit、Dodge、Dead；
- 山贼 AI：巡逻、发现、追击、攻击、受击和返回；
- 伤害公式和掉落表；
- 体力、内力和药剂消耗。

**验收**：

- 玩家能完成移动、普攻、轻功、受击和死亡；
- 一次攻击不会对同一目标重复造成多次伤害；
- 30/60/120 FPS 下同一输入序列结果一致；
- 敌人能从可达路径追击玩家；
- 战斗结束后掉落、经验和存档状态正确。

**风险**：当前物理系统不是完整战斗系统。若 hitbox 迟延或命中不稳定，优先使用显式网格/矩形查询作为战斗判定，而不是继续堆叠复杂刚体。

- **退出条件**：固定输入序列在 30/60/120 FPS 下结果一致；战斗日志可重放关键命中；P0/P1 战斗问题为零。
- **下游依赖**：阶段 D 的任务奖励、装备属性和 NPC 敌对行为必须使用本阶段冻结的战斗事件。

### 阶段 D：P1 玩法系统——NPC、任务、对话和装备

**目标**：把技术 Demo 变成有目标、有关系、有反馈的游戏。

**进入条件**：阶段 B、C 退出条件满足；事件命名、地图入口和实体查询接口冻结。

**Rust 任务**：

- NPC 导航执行器和路径缓存；
- 2D Collider 编辑器；
- 2D Animation 编辑器最小字段；
- 统一事件和命令边界；
- 装备属性计算的只读查询接口。

**Lua/数据任务**：

- NPC 日程 JSON；
- 对话节点 JSON 和条件表达式；
- 任务状态：未接取、进行中、可交付、完成、失败；
- 好感、师徒和门派声望；
- 装备槽、武器基础属性和招式解锁；
- 礼物、订单、商店和资金；
- 第一章主线任务链。

**验收**：

- NPC 可按日程在山庄、村庄、医馆间移动；
- 玩家完成任务后能改变关系和地图状态；
- 对话选项能读取和修改全局变量；
- 装备一把武器后攻击属性真实生效；
- 数据表错误能指出文件和字段，而不是运行时静默失败。

- **退出条件**：用纯数据新增 1 个 NPC、1 条任务和 1 段对话，无需修改 Rust 核心代码；错误数据能在加载阶段定位；关系、任务和装备状态可存档恢复。
- **下游依赖**：阶段 E 只使用本阶段验证过的 NPC、任务、对话和装备 schema，不新增临时格式。

### 阶段 E：MVP 垂直切片

**目标**：交付一段从开始到结算都可玩的 30–60 分钟体验。

**内容**：

- 山庄、云泽村、青云山道 3 张地图；
- 玩家、沈青萝、顾长风、赵铁算盘 3 个 NPC；
- 稻谷、灵芝 2 种可种植对象；
- 药庐 1 个建筑；
- 商店和药炉；
- 山贼 1 种敌人；
- 基础刀法和追风步；
- 1 条主线、3 个支线订单；
- 晴天和雨天；
- 7 天可重复日循环；
- 存档/读档和死亡回家；
- 基础中文 UI、音效和音乐。

**内容指标**：

- 至少 20 件物品；
- 至少 10 个配方；
- 至少 12 个可交互点；
- 至少 30 条 NPC 对话；
- 至少 1 个可见结局分支；
- 关键流程不依赖编辑器开发环境。

**验收**：

新玩家可在干净 PC 发行目录中完成：创建存档 → 开垦土地 → 种植 → 进入村庄 → 接任务 → 进山战斗 → 回收获物 → 制作药剂 → 睡觉 → 第二天读取状态 → 完成主线节点。

- **退出条件**：MVP 验收剧本可由未接触项目的新玩家独立完成；关键流程完成率达到 100%；不依赖编辑器、源码目录或开发机绝对路径。
- **冻结内容**：MVP 期间只修复问题，不新增地图、核心系统或第二条主线；新增内容进入 Alpha 排期。

### 阶段 F：Alpha——内容扩展与稳定性

**目标**：扩展到第一章完整内容，解决阻断性问题。

**进入条件**：MVP 垂直切片退出条件满足；核心数据 schema 冻结；已有可回滚发行包。

**内容**：

- 寒泉洞小副本；
- 5–6 个 NPC；
- 4–6 种作物/药材；
- 4 种敌人和 1 个 Boss；
- 青云门入口和训练场；
- 4 个节气事件；
- 完整第一章结尾；
- 基础设置、音量、键位、窗口模式和存档槽。

**工程任务**：

- 大地图编辑和 Tilemap 批量操作；
- 资源导入失败的准确状态显示；
- package 临时目录构建、校验后原子替换和失败回滚；
- 固定 Rust toolchain；
- 统一仓库内 `game`、脚本默认路径和 `RUSTLUA_GAMES_DIR` 约定；
- 自动化存档兼容测试。

**验收**：

- P0/P1 缺陷清零；
- 连续运行 4 小时无崩溃和明显资源泄漏；
- 100 次存档/读档循环通过；
- 资源缺失时显示明确路径和修复建议；
- 发行包不依赖源码、target 或开发机绝对路径。

- **退出条件**：第一章主线可从新档完成；P0/P1 缺陷清零；100 次存档/读档循环和 4 小时稳定性测试通过；缺失资源有明确报错和回滚机制。

### 阶段 G：Beta——体验、可访问性与平台验证

**目标**：让非开发者可以稳定完成游戏并反馈体验。

**进入条件**：Alpha 退出条件满足；至少有一份可分发的 Windows 测试包和反馈记录模板。

**任务**：

- 新手引导和任务追踪；
- UI 自动布局、滚动容器、键盘/手柄导航；
- 中文文本审核、字体覆盖率和文本溢出检查；
- 音频分组音量；
- 性能 HUD 和基础 profiler；
- Windows 多分辨率、窗口缩放和 DPI 测试；
- WebGL 最小真实浏览器测试；
- 重新评估是否值得做微信小游戏适配。

**WebGL 进入条件**：

- Rust WASM 构建稳定；
- 不依赖桌面文件系统和桌面音频特性的核心流程可运行；
- 外部 Fengari 依赖可本地化或有明确网络失败提示；
- 浏览器支持输入、音频解锁、存档替代方案和资源加载；
- 至少在 Chromium 和 Firefox 完成启动、切图、种植和存档验证。

- **退出条件**：外部测试者可从新档完成主线核心流程；关键 UI 操作不依赖开发者说明；Windows 多分辨率通过；WebGL 仅在进入条件全部满足时单独出包，不影响 PC 发布。

**微信小游戏进入条件**：

只有在完成专用 JS/WASM 入口、文件系统适配、触摸输入、资源包格式、音频限制、登录/存档策略和真实真机测试后，才从“预留平台”升级为开发目标。否则从编辑器发布选项中隐藏，避免误导。

### 阶段 H：Release Candidate 与首发

**目标**：产出可回滚、可复现、授权完整的 Windows 发行包。

**进入条件**：Beta 退出条件满足；发布候选分支只允许修复问题，不接受新功能。

**发布门**：

- `cargo fmt --all -- --check`；
- `cargo clippy --workspace --all-features -- -D warnings`；
- `cargo test --workspace --all-features`；
- Debug/Release 构建通过；
- `assetc scan/import/--check-deps/package` 全部通过；
- `game.exe --pack pack --check` 通过；
- 干净目录启动测试通过；
- 许可证清单、Credits 和第三方声明齐全；
- P0/P1 问题为零；
- 发行包可在没有 Rust 环境的 Windows 机器运行。

**最终退出条件**：连续两次从干净目录构建并完成发布门检查；安装包、版本号、变更记录、Credits 和许可证清单一致；回滚包可在发布失败时恢复；无 P0/P1 问题。

## 7. 最小执行顺序

必须按以下依赖顺序推进：

```text
MVP 锁定
→ PersistId / Snapshot / Tilemap 状态
→ A* / 事件总线
→ 战斗 Hitbox
→ 建筑占用
→ NPC 日程 / 任务 / 对话
→ 垂直切片
→ 编辑器效率工具
→ Alpha 内容
→ Beta 平台和体验
→ Release
```

不能先投入大量角色和场景美术，再发现存档、寻路或战斗底座无法承载核心玩法。
